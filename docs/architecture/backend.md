# 后端设计

后端按业务职责组织成模块化单体。员工和资源由各自模块维护，对话与考核组织业务，一次模型和工具处理由执行层协调；这些模块在同一进程和业务库内协作。

## 目录结构

```text
backend/
├── app/
│   ├── main.py                 # 服务入口，创建应用实例
│   ├── bootstrap.py            # 组合服务，管理数据库与后台处理的启动和关闭
│   ├── config.py               # 汇总并校验应用配置
│   ├── api/                    # 请求、响应、依赖装配与统一错误处理
│   │   ├── routes/             # 按用户操作组织接口，调用所属业务服务
│   │   └── streaming.py        # 持续读取并推送已保存的回复状态
│   ├── auth/                   # 身份、会话与权限
│   ├── employees/              # 岗位、技能关系、固定工具和知识装配
│   ├── skills/                 # 技能编辑、发布与版本内容
│   ├── model_connections/      # 模型连接、凭据与配置修订
│   ├── capability_catalog/     # 技能与工具服务的联合查询
│   ├── conversations/          # 对话、消息、工作受理与正式回复保存
│   ├── evaluations/            # 考核批次、答卷与评分
│   ├── execution/              # 一次执行的状态、调度、动作、预算和成果
│   │   ├── service.py          # 受理执行、组合授权、提交成果与终态
│   │   ├── scheduler.py        # 扫描已提交工作，管理后台执行的生命周期
│   │   ├── runner.py           # 协调单次执行、看护与资源收尾
│   │   └── context.py          # 向智能体提供受限的动作与进度接口
│   ├── agent/                  # 适配官方模型工具循环、技能与检查点
│   ├── builtin_tools/          # 文件、知识、结果补读与工具发现的调用入口
│   ├── mcp/                    # 外部工具服务、工作连接、清单和实际调用
│   ├── knowledge/              # 资料入库、索引、检索与证据
│   ├── files/                  # 原件和成果字节的保存、保留与清理
│   ├── environments/           # 隔离代码环境的申请、使用与回收
│   ├── llm/                    # 聊天和向量模型客户端适配
│   └── infrastructure/         # 数据库、凭据及公共技术机制
├── migrations/                 # 正式数据库升级脚本
├── tests/                      # 业务、协议、依赖与故障场景的隔离测试
├── datasets/                   # 题库、检索样本与来源说明
├── experiments/                # 独立实验，不直接代表产品能力
└── pyproject.toml              # 依赖、开发工具与工程配置
```

业务模块通常把数据结构放在 `models.py`，输入输出放在 `schemas.py`，操作与事务放在 `service.py`；查询较复杂时另用 `queries.py`。按实际职责拆文件，不要求所有模块具有相同层数。模型定义留在所属模块，迁移注册入口只汇总元数据。

## 请求怎样完成一项业务操作

应用启动时，`bootstrap.py` 创建具体服务并连接依赖；接口层取得已装配的服务，完成协议转换，业务服务负责校验和数据变化。服务不依赖页面连接，也不接收框架请求对象。

事务围绕业务目的组织。例如保存员工时，岗位、技能、固定工具和知识配置一起提交；受理对话时，输入、空回复、执行记录与关联一起提交。参与服务复用同一事务，避免各自保存后留下不完整状态。

写事务只包围短步骤。模型调用、远端工具、文件解析与向量生成放在事务外，提交前重新核对版本和资格。当前使用 SQLite 与同步数据库会话，异步入口中的同步操作转到工作线程，数据库会话不在后台任务之间并发共享。

## 业务、执行与框架怎样协作

对话与考核决定业务结果的含义，执行层管理一次处理，框架适配驱动模型和工具循环。后台领取已受理工作，通过受限接口检查动作许可、预算并保存执行事实；资源模块继续拥有各自的数据和生命周期。

执行结束先保存成果与终态，对话再形成正式回复，考核再接纳答卷并评分。临时保存失败只重试相应阶段。这样可以复用执行规则，又让业务完成条件留在所属模块，对话与考核各自核对成果接纳资格。

当前后台与接口在同一持锁进程中运行。这样的组织便于本地部署和事务协作；拆成独立进程时，需要重新设计领取、跨进程协调和恢复。进一步实现见[执行模块](../../backend/app/execution/README.md)，开发约定见[后端手册](../engineering/backend.md)，部署和备份见[运维指南](../guides/backend-operations.md)。
