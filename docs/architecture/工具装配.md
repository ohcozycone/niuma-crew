# 工具装配

接入工具服务后，仍需确认操作清单，并为员工选择必要操作。装配范围决定员工获准做什么；按需发现决定本轮向模型展示什么，两者分开维护。

## 从服务到员工操作

| 步骤               | 决定什么                                   |
| ------------------ | ------------------------------------------ |
| 登记服务           | 连接地址、传输方式与可信程序入口           |
| 准备工作连接       | 以哪个固定组织账号调用，凭据由后端保管     |
| 读取并确认工具目录 | 接受哪些真实操作定义，更新前核对差异       |
| 装配员工           | 选定工作连接、具体操作、已有范围规则和预算 |

例如，员工只需读取 Notion 材料时，应检查服务提供的搜索和读取操作，按任务选择；无须将创建、修改或删除操作一起装配。页面、空间等资源范围能否强制落实，取决于工具参数、后端已有规则和上游账号权限，不能只靠一段提示词宣称实现。

读取目录不执行业务工具；确认目录也不自动授予员工。远端定义改变后，需要重新核对，不能让旧许可无提示地指向新操作。具体行为见[工具规则](../reference/mcp.md)。

## 按需展示获准工具

员工配置限定候选范围，执行开始时冻结目录依据。模型先取得常驻基础能力和发现入口，需要时搜索获准目录，后续模型请求再取得命中操作的完整定义。

当前使用本地全文索引查询工具目录，记录每次模型请求实际可见的工具集合；未展示或未获准的名称不能靠猜测执行。发现不会扩大员工权限，服务端调用时仍检查当前许可和定义依据。

这减少首轮工具定义的注入量，同时增加搜索、选择和补充上下文的成本。关键词匹配质量、额外轮次和完整任务费用需要分别测量，不能只比较首轮上下文大小。实现见[工具发现](../../backend/app/runtime/agent/tool_discovery.py)，限定样本的历史实验见[发现验收记录](../records/工具按需发现验收.md)。

## 失败与操作边界

工具返回失败、网络超时和外部动作结果未知，处理方式不同。写入可能已发生时，不能把超时直接解释为未执行，也不能自动重放。停止执行同样不能撤销已发生的外部操作。

本机程序与隔离代码环境承担不同信任边界。通用调用层负责授权、记账和结果记录，各业务工具仍拥有自己的参数与结果语义。接入步骤见[工具与环境接入](../guides/agent-tools.md)，内部协作见[工具实现](../../backend/app/resources/mcp/README.md)。
