# 回答证据边界复验

日期：2026-11-10。结论：两版新说明均未采纳，原提示文件已完整恢复；上一阶段的结果交付改造保留。本记录不代表整体质量验收通过。

## 1. 修改目标与处置

只尝试补清“满页不证明截断、查询结束不证明工作区完整、未知不等于零、已知总量可以直接报告”。未修改工具发现、工具定义、结果交付、预算或权限，也未增加答案拦截、正则改写和隐藏纠错模型。

首版将说明改得更通用，原案例10次中有2次重新将page称为文章，未采纳。第二版恢复原有类型规则，仅追加分页和范围说明；仍出现未知被写成零及未声明的游标调用，未采纳。当前生产提示文件哈希与上阶段一致，运行代码冻结核对也通过。

## 2. 方法与实际请求

先在独立临时应用中，以假模型走真实发现、工具门、保存和交付，捕获结果已经返回后的末轮上下文。六个场景都确认完整原文进入上下文，并加载同一套5个Notion工具；Notion与Tavily来源分别保存。

随后用同一Kimi模型交错发送旧/新说明。每对实际HTTP请求除该说明外必须一致，共两轮、每轮35对；70对的请求哈希核对全部一致。结果预期没有喂给模型；模型提出的工具调用只记录，不执行、不接下一轮，也不自动修复。因此耗时与费用仅指这一轮生成，不是完整Run。

原案例每版10次，其余场景每版各5次：上游明确仍有后续结果、当前查询结束但非全量、完整8篇列表、明确总数137、明确总数0。首轮70次均返回；第二轮32次返回、38次限流，后四类场景未完成规定样本，保持未验收。

模型凭证只用于认证，不进入输入或报告；发送内容只有合成问题/回包及获批工具说明。开发库只读验收所需模型连接和冻结目录；运行、文件与checkpoint使用临时存储。离线捕获入口现在只读仓库样本，不读取开发库或密钥。

缓存冷热未人为控制。第一对与后续配对的命中不同，不能把均值变化全归因于新说明。按缓存输入权重0.1、输出权重3，分别汇总所有10对及第2—10对的实际usage，见[摘要](data/回答证据边界-复验摘要.json)；不是Kimi Code实际额度，也不是完整任务费用。限流失败没有返回用量，保持未知，不计为零。

第二轮在首次限流后仍按预定清单发送了后续请求，这是试验脚本的缺口，未将它描述成自动重试或有效模型回答。现已改为首个429保存后结束，离线用例确认仅发一次请求；没有再请求真实模型。最终离线捕获六类场景通过，提示/发现/交付34项定向回归通过；静态、文档与站点检查以本次交付结果为准。

## 5. 结论与复现

没有证据支持把这两版规则留在系统中，因此已完整撤回。当前证据能确认：完整信息已经交付，本次Kimi样本仍会数错、混淆未知与零，或提出未声明的参数；不能据此要求结果保存层增加裁剪。两次小修复没有达到零错误目标，本轮停止继续叠加说明，也不将结果归咎于限流——已有成功返回的明确反例足以否决。

若继续要求精确统计或严格证据保证，需另行决定：让来源提供明确总量/可枚举能力，或评估模型及可核验的回答形式。此处未实施新能力，也未验证其他模型。已知总量及明确零的第二版样本受限流影响，不能宣称没有过度保守回归。
