# 员工管理页与考核契约

适用首版员工管理与 BFCL Python 单调用考核。页面位于 `/agents/:id/home`，原 `/agents/:id` 配置页与 `/conversations/:id` 对话页继续使用。

## 页面入口

员工目录头像、姓名、卡片“查看员工”和收藏导航进入管理页。顶部使用圆拱头像、姓名、简介与状态，下面是紧凑的技能、已装知识库和完成对话统计；数量来源与权限见[员工资源摘要](agent-resource-summary.md#员工个人页统计)。默认对话记录，员工考核为第二个栏目。任务记录、定时任务、长期记忆当前只显示建设中，不出现模拟业务数据。对话记录复用共享历史组件，按员工及当前用户的授权范围读取；点开后进入完整对话页，并保留返回员工页上下文。

## 考核协议

| 接口                              | 行为                                                                       |
| --------------------------------- | -------------------------------------------------------------------------- |
| GET /api/evaluations/suites       | 返回固定题库、题数、版本、来源和测试范围，不返回标准答案                   |
| POST /api/evaluations             | 提交agent_id、suite_id、sample_count及client_request_id，返回202及批次摘要 |
| GET /api/evaluations              | 按agent_id查询本人的批次，支持offset和limit                                |
| GET /api/evaluations/{id}         | 返回批次摘要和分页题目，limit最多100，默认20                               |
| POST /api/evaluations/{id}/cancel | 显式取消未结束批次，保留历史，重复取消无额外执行                           |

批次标识使用现有12位数字序列，用户提交标识为UUID。题数为1—400，每名用户最多两个未结束批次。创建和执行要求runs:create，查询要求runs:read，取消要求runs:cancel；资源范围始终是当前用户。题数、员工及题库相同的请求重发返回原记录，复用标识改变参数返回409。

服务固定题目、答案、评分器和专项配置依据。抽样由提交标识确定，并保存实际题目。首次记录同一批次，重新考核产生新标识；界面“同题库与题数再次考核”会重新抽样，不承诺逐题相同。

当前专项保留岗位指令、组织规则和模型，关闭真实工具、技能与个人知识装配；这不是原岗位全部资源的端到端考试，也不直接作为官方榜单成绩。每题通过正式执行入口产生独立Run，无对话消息，不继承上题状态。执行期间配置改变或授权失效时，剩余题目停止。

## 状态和报告

批次为queued、running、cancelling、completed、failed或cancelled；题目为pending、running、passed、failed、error或cancelled。题目状态是考试进度，不代替Run终态。格式错误计未通过，运行/评分异常计error，Run成功与否不由考核分数决定。

取消先与当前执行状态在同一写事务核对。执行已经提交终态、尚未评分的题目保留答卷并完成评分；仍在执行的题目请求取消，未受理题目直接取消。重复取消不覆盖已经评分的结果。

报告分别列计划数、完成数、已评分数、通过、未通过、异常与取消数；通过率使用通过/已评分。题目详情提供原始输入、答卷、运行标识、运行状态与评分依据；只有完成评分的题目才提供可接受答案。完整配置快照及秘密不返回浏览器。

后台扫描器由应用lifespan管理，复用现有执行Worker。关页只停止观察；重启扫描已有批次及Run关联，避免重复受理。当前使用同一应用和数据库，不需要额外部署微服务。结构与验证入口见[评测模块](../../backend/app/evaluations/README.md)。
