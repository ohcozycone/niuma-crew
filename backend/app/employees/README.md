# 员工配置与装配

数字员工是平台保存的一份岗位配置：它描述姓名、职责和工作指令，并选择使用的大脑、技能及工具。比如「材料整理员」可以使用共享的整理方法，同时只获准读取指定材料。用户发起具体工作后，对话和执行模块才会根据这份配置运行模型。

这里的「装配」就是把可复用资源选入岗位，并保存参数和许可。模块同时服务两类操作：管理员修改岗位及装配，使用者为岗位已有的工具许可选择本人账号。

## 模块设计

### 岗位、资源和使用者分开保存

员工表保存岗位资料和模型连接标识。员工与技能的关系另存启用状态、参数及关系版本；工具许可另存操作定义、资源范围、预算和账号模式；个人绑定再记录「哪位使用者为哪份许可选择哪条连接」。模型密钥、技能包和工具账号都有自己的所有者，不随员工复制。

这种结构使一项技能可以被多个岗位复用，也使同一岗位能代表不同成员访问各自账号。例如修改整理方法的正文由 skills 完成；把某员工的整理参数改为「按负责人分组」则修改员工关系；成员换绑个人资料服务账号，只影响其本人绑定，不改变岗位许可。

### 一次员工保存怎样完成

1. API 把当前身份、表单字段和预期版本交给 `AgentService`。服务检查员工操作能力；模型选择、技能选择还分别检查对应能力。
2. 服务在一个短事务中取得写入资格，读取员工并检查创建者编辑权及 `expected_revision`。这避免两个编辑者同时用旧资料覆盖彼此。
3. 服务检查姓名、模型引用和完整技能关系；工具许可也仅通过这份员工配置整体保存。`replace_assignments` 新增、更新或删除关系，并校验启用关系的参数；`apply_grants` 校验已确认工具、操作定义和范围。
4. 岗位资料、技能关系、工具许可共同提交，返回已确认详情；任一环节失败整笔回滚。客户端只持有摘要时不能把它当完整编辑数据提交。

公开展示、目录摘要、管理详情和运行使用摘要各有自己的字段集合。查询按用途生成结果，不先加载含完整工作指令和账号选择的管理详情再随手删字段；资源数量由真实关系计算，不能由前端另存一份。

### 怎样把配置交给执行

执行侧 configuration 调用 `assembly.py` 捕获员工技能装配事实，再调用 `assembly.py` 捕获工具许可并解析本次使用者的账号，固定方法内容、关系版本和工具依据。实际动作前继续检查员工是否启用、模型选择和已用装配是否仍有效。

快照保持本轮内容稳定，当前检查保持撤权有效；二者解决不同问题。个人绑定只接受本人、同服务、启用且操作定义相容的连接。共用账号由员工创建者维护，其他使用者没有个人绑定时不会借用创建者的个人账号。

## 目录与职责

```text
employees/
├── models.py                      # 保存岗位、员工技能关系、工具许可与个人绑定，使共享资源和每人账号选择分别有稳定关联
├── schemas.py                     # 定义员工编辑输入及公开/管理/运行摘要，明确哪些字段可写、哪些只供展示和引用
├── access.py                      # 根据员工创建者决定谁能编辑，允许管理员维护没有创建者的历史岗位
├── service.py                     # 组织员工创建、查询、修改和删除；检查版本与资源引用后，在同一事务保存资料及完整装配
├── assembly.py            # 从当前装配捕获本轮技能内容和关系版本，并在执行中检查员工、模型选择及已用技能关系
├── tool_grants.py                 # 在员工保存事务中校验和替换工具许可，提供连接删除引用保护
├── organization_rules.py          # 保存全员规范正文和版本，不负责跨资源工作准备
└── tool_account_bindings.py       # 为已有个人模式许可保存/解除本人连接，检查账号归属、同服务及操作定义相容性
```

## 与其他模块协作

[skills](../skills/README.md) 提供可执行方法定义和参数规范；[model_connections](../model_connections/README.md) 提供模型连接；[mcp](../mcp/README.md) 拥有账号、秘密和已确认操作。本模块拥有选择关系及许可，不替资源服务修改本体。

[执行资源组合](../execution/README.md) 捕获跨资源配置和复核当前许可；对话负责输入和最终交付；[auth](../auth/README.md) 提供可信身份及权限策略，数据库提供共同事务。跨模块协作使用调用方事务，不因运行者缺少配置管理权就拒绝已获准的内部读取。

## 生命周期与维护入口

已有对话引用的员工拒绝硬删除，应停用保留历史；删除只清理员工关系，不删除共享技能或大脑。UUID 用于稳定关联，可修改的业务编号不承担关联职责。同库查询承担引用保护和安全投影，资源拆成远端服务时必须重新设计这些一致性条件。
