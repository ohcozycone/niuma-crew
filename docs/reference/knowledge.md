# 知识库、文档与检索

当前实现为本人知识库的原件上传暂存、手动后台处理、逐文件关键词发布、原件下载、来源阅读与三种检索测试。页面入口 `/knowledge`；已支持当前用户为共享员工装配多个本人库、跨库受管检索及正式聊天引用；团队共享和后台增量向量仍待实施。模块职责与运行边界见[后端知识模块](../../backend/app/knowledge/README.md)，页面见[前端知识模块](../../frontend/src/pages/knowledge/README.md)。

## 用户流程与持久化

用户创建业务知识库，进入库内选择 UTF-8 Markdown/TXT 并上传。原文件复用 files 的持久磁盘、摘要和账号配额；当前本机目录在工程外，部署位置由 FILES_DIRECTORY 配置决定，见[文件配置](../guides/backend-operations.md)。客户端不能提交服务器本机路径。

上传只校验格式、编码、大小并保存原件，不切分、不调用模型。上传确认后文档为“待处理”，可下载原件，详情的document为null、chunks为空，不参与检索。演示导入同样保存为待处理原件。文件服务先保存但未成功关联的原件按暂存周期清理；已被知识文档引用的文件不会被附件清理器删除。

用户确认资料后手动提交处理批次，后台按单文件并发解析、切分与分词；计算不占写事务。每个文件的固定正文、来源块、Chunk和FTS5在同一事务发布，成功一个即可检索一个，不等整批结束。重处理前旧内容继续可用，失败保留旧内容；新关键词发布时仅清除该文件的旧向量，不混用新旧Chunk。后续向量仍通过现有独立构建入口生成，本期关键词任务不自动调用Embedding。

处理批次和文件子任务持久化，冻结原件摘要和最终规则，同文件只允许一个活动任务。服务重启后继续排队项，原执行中项标为中断并允许手动重试；局部失败不撤回其他成功文件。取消或删除使迟到任务失去提交资格；删除仅清理目标文件派生数据。生产由应用lifespan启动单文件KnowledgeWorker，使用与部署Runner锁配置相邻的进程锁；测试注入runtime.enabled=false时不启动后台扫描器，可直接驱动处理服务。

库设置有修订保护，名称/用途与切分覆盖一起保存；默认800字符、120字符重叠。覆盖可空，合并后必须重叠小于切分长度；长度范围100～2000字符，重叠0～1000字符，短章节阈值0～2000且不能超过长度减重叠。短章节阈值默认取200与长度减重叠的较小值，0关闭合并。产品按Unicode字符计长，不称为模型token；上限也保证当前Embedding单条字节预算。新设置只影响后续任务，不自动重切旧文件；恢复默认通过清空覆盖表达。

切分先保留ATX Markdown章节与完整标题路径，按空行、换行、中文标点、空格到字符递归拆分；长度包含原文标题、空白和重叠。仅相邻且具有同一实际父标题标识、各自短于阈值的章节可合并，合计不超过长度减重叠的预算。不同顶级章节、父子导言、长章节不合并；代码围栏内的标题不作为章节。同名父标题的不同出现不能混为一组。合并片段保留所有标题、连续原文和多来源区间；该规则基于结构，不保证内容语义相近，阈值也不是承诺的最小片段长度。

处理弹窗可临时调整三项规则、选择目标文件预览，显示总片段数、长度范围、短片段/合并数量和逐片原文及来源。预览每页20片段，通过offset翻页，只读取一份已保存原件，不生成索引、作业或外部模型调用；每账号每分钟30次。文件或规则变化立即隐藏旧预览，取消过时请求并忽略迟到结果。提交明确rules后后台冻结同一值，不受之后的库设置变化影响；临时值不写回库默认。预览为可选检查，不要求逐片批准。

当前每文件128 KiB、每库200文档/5000片段、每账号100库。原件数量在上传时检查，片段数量在逐文件发布时检查；预览和处理的切分计算也在超过单文件5000片段时提前终止，提示调整规则。文件总量另受files配额约束。当前不提供原件在线编辑、文件替换或版本历史；同名不同内容是独立文档。

## 身份与接口

管理员和成员具有 knowledge:use，只访问本人库；resources:all 不绕过这个所有者检查。游客不得列库、检索或下载原件；列表与单条采用同一范围。服务操作也校验 Actor，不能仅依赖路由隐藏按钮。

接口定义以[schemas](../../backend/app/knowledge/schemas.py)及运行 OpenAPI 为准，以下路径均以 `/api/knowledge-bases` 为前缀。

| ------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| GET /、POST /                                          | 本人库列表；创建提交 name、description、UUID client_request_id                                                               |
| GET /{kb_id}                                           | 库信息、文档与片段数量                                                                                                       |
| PATCH /{kb_id}                                         | expected_revision、name、description、可空chunk_size/chunk_overlap/min_section_chars；保存元数据及字符规则覆盖，不重建索引   |
| POST /{kb_id}/processing                               | 202持久入队；client_request_id、可选document_ids、reprocess、rules（三项明确字符规则）。未指定文件默认处理待处理/失败/中断项 |

创建与上传按请求标识幂等；相同库中的相同原始字节去重，不以文件名推断覆盖。处理批次也按提交标识幂等，改变文件集合、reprocess或明确rules复用标识返回409；重试同一提交返回原批次及规则快照。失败文件重新处理使用新批次；网络未知结果重试沿用原提交标识。库更新修订过期返回409并保留表单。

错误类型、状态码遵循[统一错误规则](../../backend/app/api/README.md#应用错误分类与-http-转换)：无许可为 403，不存在或不属于当前用户为 404，大小/格式/编码/空正文/容量不符合要求为 422，分词版本不兼容为 409，上传过频为 429。网络失败不能直接判断服务端未执行，先读取或用同一标识重试。

## 来源与检索边界

文档保存固定正文和不可变摘要版本，切片包含文档 ID、版本、来源块及 `[start,end)` Unicode 码点区间。浏览器通过库/文档/片段 ID 打开同一原文，不能按相似文字或列表序号猜位置；来源返回链接保留原检索问题。资料文本不作为系统指令执行。

BM25 使用相同 jieba 词法规则建立、查询索引；分词器、词典与 SQLite 版本摘要不兼容时拒绝混用。FTS5 排名分数越小越靠前，不是相关概率或模型置信度。FTS5 是共享业务数据库内的虚表，返回候选严格约束当前库；词频统计使用该 FTS5 表的整体语料，不承诺库间独立评分。没有召回不等于资料足以回答，也不会触发全局换库。

总览显示库名、用途、文档数和更新时间，窄屏单列；库内优先显示文档状态、关键词覆盖、查找和手动处理。设置经按钮弹窗维护，处理前可调整临时规则并分页预览；弹窗正文独立滚动，提交入口始终可见。失败/中断项可单独重试，任务记录可查看或取消。处理中观察页面轮询，离页不影响服务端作业。

上传队列由身份作用域工作台持有，在应用外壳提供非模态浮层；目标库和上传标识固定，SPA切页、切页签或收起面板继续上传。队列串行发送，失败可单项重试；成功确认才显示“原件已保存”。刷新/关页可能中断未完传输并给离开提示，不承诺断点续传或跨标签页接管。取消不证明服务端没有保存；切换身份清空队列并尽力取消在途传输，迟到结果不得进入新身份。库内检索测试仍优先展示方式、问题及来源；规章制度仍是独立全员指令能力。

## 硅基流动向量接入

管理员在知识库“检索测试 → 检索设置”弹窗管理向量模型，选择「硅基流动 · BGE-M3」后填写 Key，保存并测试真实固定短文本；使用者在同一弹窗选择已启用连接、建立向量索引。大脑页面只管理数字员工的对话模型。已有向量连接继续可用，无需重新录入 Key；向量连接可在不同知识库间复用。页面明确说明此操作向硅基流动发送当前库片段，查询时发送问题。地址与模型固定，不将聊天 Key 转发到向量服务。

正式链路使用 `OpenAIEmbeddings` 发送原文，每批最多8条，单条保守限制UTF-8 8192字节（不是模型token计数）；产品片段最多2000字符、问题最多1000字符。验证返回数量、1024维、有限数值和非零范数后归一化。SDK不自动重试，HTTP超时20秒、不跟随重定向、不使用环境代理，原始上游错误不回显。

`knowledge_vector_indexes` 保存模型连接/配置修订、来源摘要、generation、Chroma collection 名与向量空间指纹；`knowledge_vector_memberships` 只保存该代有效片段及文档版本，不再保存数字数组。向量由本地持久化 Chroma 管理，使用官方 cosine HNSW 近似 Top-K，不再通过 Python 遍历全部向量。索引默认在业务数据库旁的 `knowledge-vectors/`，可用 `KNOWLEDGE_VECTOR_DIR` 覆盖；同一目录只能由一个进程使用。返回 `cosine_distance_lower_better` 距离，越小越靠前，不是回答置信度。

构建为同步有限请求，每进程仅一个构建，批次之间检查 120 秒总预算与连接修订；当前网络调用可能延至自身超时后才报告总预算耗尽。外部调用和 Chroma 构建位于 SQLite 写事务外：先在不可见的新 collection 写入已生成的向量并核对成员，再在短事务中复核资料、索引 generation 和模型/凭证修订，切换指针与成员。Chroma 不自行生成第二次 Embedding，也不下载默认模型。失败清理半成品并保留旧指针，旧代等在途读取释放后回收。进程退出不恢复未完成构建；HTTP 断线不证明发布失败，重新读取状态后再决定是否重试。

向量有效范围以当前实际 Chunk 与当前代成员关系计算，原件暂存不会使已有向量失效。删除一个文件保留其他文件向量；新文件关键词发布或重切文件后，剩余向量可形成 partial 覆盖，混合检索的 BM25 覆盖全部可用关键词内容，语义路径只覆盖有效向量。删除/重切先在业务事务移除成员，查询前用成员 ID 过滤并在返回后复核；Chroma 物理清理失败不恢复成员，启动时重新清理。页面显示有效覆盖数，无向量时禁用向量/混合；构建仍整体替换所选库的可用向量，尚未实现异步增量向量任务。

模型配置变化使向量过期；换Key不重算向量，在途构建/查询按凭证修订拒绝旧结果。停用连接不可检索，被引用连接不能删除。上游失败不静默回退BM25。构建每账号每分钟3次，向量与混合查询共用每分钟30次额度；构建失败保留旧索引。

混合检索生成一次问题向量，通过 Chroma 取得向量候选，再在来源/权限复核事务中取得 BM25 候选，各最多 30 条。官方 `langchain-classic` 的 `EnsembleRetriever` 以 RRF（c=60、等权、chunk_id 去重）合并；同分沿用官方输入顺序，不维护第二份公式。返回 `score=null`、`score_kind=rank_only`，页面显示融合排序第 N 项；BM25 仍返回原分数。默认返回 6 条，最多 20 条。融合不调用模型，也未新增 Reranker。

关键词路径在后端公共 `lexical_search` 内对 query 使用 jieba 精确模式、HMM=False 分词，与文档处理规则一致；向量路径把同一 query 原文交给受管 Embedding 接口。测试页传页面输入，按需 Agent 传模型生成的工具参数；两者复用同一检索核心，模型组织 query 不等于后端分词。服务就绪前核对 Chroma 发布指针并清理孤立 collection；当前 collection 缺失时移除无效索引元数据并显示需要重建，不回退旧引擎。

页面将模型、索引管理收进“检索设置”弹窗。索引未建立、过期或连接停用时，向量与混合选项禁用，BM25 仍可使用；带未就绪模式的深链接保留问题并提示设置，不发送查询。构建期间不能关闭弹窗，模型草稿保留原有离开保护。

当前结构由 [0023 迁移](../../backend/migrations/versions/0023_knowledge_chroma.py) 替换旧 0014 向量表：直接删除旧数字数组和索引指针，保留原件、正文、片段、关键词及对话，不转换、不双写。已有库需要重新建立向量索引。

## 迁移、样例与验证

正式结构由Alembic0013、0014及[0015](../../backend/migrations/versions/0015_knowledge_processing.py)维护；0015保留旧正文/片段/向量，已处理文档迁移为关键词可用，新增处理批次与子任务，并修正原文档表两个唯一键重名。[0016迁移](../../backend/migrations/versions/0016_knowledge_chunk_preview.py)仅新增可空短章节覆盖，不重写旧正文/片段/向量。旧排队任务没有新版规则标记时仍按原不跨章切分。FTS5及shadow表由迁移显式管理。备份需包含业务数据库与持久原件，不能只备份索引。

前端静态差旅正文已移除。现有差旅清单与评分资料继续保留在 datasets 作为可复现教学输入；只有用户显式导入的 documents 原件进入实际库。技术演示生成器见knowledge_demo.py，四份技术资料明确标注虚构；评分参考答案不进入索引。

[API/持久化测试](../../backend/tests/test_knowledge_library.py)、[页面流程测试](../../frontend/src/pages/knowledge/knowledgeFlow.test.tsx)与[迁移测试](../../backend/tests/test_migrations.py)覆盖当前链路。

手动处理、恢复及全局上传的实际验证见资料建设闭环记录，核心回归见[处理测试](../../backend/tests/test_knowledge_processing.py)与[上传队列测试](../../frontend/src/state/knowledge/uploadQueue.test.ts)。

公开样例分为两组：通用技术手册只验证接线，虚构企业资料包含专有业务事实，用于后续 Agent 回答质量测试。题目和答案均在库外；真实向量索引与本机导入结果见记录，不能把文档命中率当作回答正确率。

## 员工个人装配与正式问答

每位登录用户可在员工页或对话工具栏的“我的知识库”为同一共享员工选择最多10个本人库，独立设置检索时机、方式与全局Top-K。此设置不写员工岗位Prompt或共享员工草稿，不把资料共享给其他使用者，普通成员无需员工编辑权。共享员工卡片的知识数量仍不表示当前用户的私有装配数，个人入口显示实际数量。团队分享不在当前能力内。

GET/PUT `/api/knowledge-bases/employee-bindings/{agent_id}`读取/原子替换当前用户设置。PUT包含expected_revision、knowledge_base_ids、mode(on_demand/always)、strategy(auto/bm25/vector/hybrid)、top_k(1—12)。未保存时revision=0，重复库/非本人库/无许可拒绝；409保留表单并提供载入最新。响应包含本人库的已处理/向量覆盖目录，无权限读取他人设置。保存后新任务使用新值，使用旧修订的在途任务停止并要求重新发送。

会话接受事务捕获库目录与个人设置修订，将名称/用途编码为资料数据并加入本轮知识使用规则，实际StructuredTool定义另行注册，员工原岗位指令保持原文。原件未处理仅显示待处理，不直接提供正文给员工。管理员向他人拥有的对话发消息时，如选择了自己的个人知识，接受即拒绝，避免把私库内容写入他人会话；已有历史正文仍遵循现行会话访问权限。

on_demand由模型按岗位、目录、对话及工具定义选择是否搜索，不保证所有相关问题都调用。always在本轮首次进图前，通过稳定且幂等的宿主工具动作执行一次预检索，再把结果放入当前输入；长问题使用前1000个字符作为查询，完整问题仍送入模型。恢复从持久结果复用前仍复核权限和来源，不重复调用向量API。两种模式都保留后续检索/补读能力。

知识提示词按检索时机、证据使用和引用分区。内部具体事实、标准和流程从知识资料取得依据，公开时效信息与实时业务数据分别使用已提供的 Web 或业务工具，同一问题可组合来源；外部信息不能替代内部制度依据，内部原文不转发到外部搜索。回答在结论附近引用支持它的本轮证据，区分内部规定、外部事实和推断；片段不足时补读，资料冲突时说明差异及适用条件，无法判断时保留不确定性。无命中、待处理和技术失败不等于不存在相关规定。上述语义要求由提示词指导，现有程序校验仍只检查来源身份、授权和链接配对。

连续追问可沿用本轮重新核验的历史知识来源。接受事务只从同一对话实际选入上下文的成功回复取得来源Run，knowledge核对同用户、同员工、成功状态、当前挂载库及完整Chunk快照，只采纳历史正文中编号与地址匹配的引用。按最近上下文优先、当前Top-K、18KiB及剩余上下文预算选取；将片段、原编号及来源Run冻结到knowledge.history_evidence，并在本Run重新登记证据，原文片段随当前问题提供给模型。按需模式可据此回答或补读，不必重复搜索相同事实；always仍执行本轮搜索。

未通过核验、超出预算或未选入上下文的旧来源不获得本轮引用资格。失效编号和链接从送模的历史副本移除，并提示重新检索，已交付消息不改写。核验与新任务接受在同一事务完成，执行过程显示“核对历史知识来源”及可打开的原文链接，不冒充新检索、不调用Embedding或额外模型。恢复、每次模型/工具动作及发布继续检查重新登记的证据；接受后来源被删除或重切仍会停止本轮。不能按模型输出的任意旧编号在发布时临时导入来源。

`search_knowledge(query, library_ids?)`默认查全部本轮挂载库，library_ids只可收窄；`read_knowledge_source(evidence_id, offset?)`只补读本轮已登记的固定证据片段，包括重新核验并登记的历史来源，单次最多2000字符，不提供任意文档全文或文件路径。调用参数不能指定用户或员工身份。知识工具为专用binding，走相同begin_tool/guard_tool/complete_tool、预算、取消及RunAction记录，不套用MCP许可，也不走未登记旁路。

工具参数及字段说明统一定义在[KnowledgeSearchInput、KnowledgeReadInput](../../backend/app/knowledge/schemas.py)，注册和冻结快照中的 JSON Schema 由这些 Pydantic 模型生成，不再手写第二份约束。library_ids 省略或为 null 时使用全部本轮挂载范围，提供列表时必须非空且只能收窄；实际执行继续验证模型、当前授权和证据归属。Schema 描述不能完全代替运行时校验，例如纯空白问题和 UUID 格式仍须由实际模型拒绝。

auto对具备有效向量的库采用混合，其余采用BM25；真正上游故障明确返回失败，不伪装成无命中。指定向量/混合不会静默降级。不同库的候选按名次融合，不能直接比较不同原始分数/向量空间；所有库合计最多top_k片段及约18KiB结果，返回每库空库/待处理/无命中/部分覆盖/故障状态。检索只使用已发布的文件。

知识证据独立保存在knowledge_run_evidence，记录Run、库/文档/Chunk、正文版本和完整片段快照，不复制到普通source文件下载通道。每次模型/工具动作、补读、缓存复用及最终发布检查装配修订、库归属与已取得的Chunk仍存在且快照相符；重切即使文档version未变也可识别。删除、卸载或旧证据失效后停止当前任务，不能通过旧编号恢复读取。已交付历史正文不因卸载而自动抹除。

模型从结果取得本轮K证据编号与`/knowledge/{库UUID}/documents/{文档UUID}?chunk={64位片段ID}`，应逐字引用来源。模型仅漏写开头`/`时，knowledge的finalize_answer只在Markdown链接编号及补全路径与本轮登记证据逐字配对的情况下补回，再进行完整引用校验；不调用模型、不修改自然语言，动作原始输出保留。未知K编号、未经本轮重新登记的其他Run来源、编号与来源错配、其他路径改写、任何scheme（包括sandbox:和外站host）以及额外fragment均拒绝正式交付。前端仅允许严格站内知识路径，点击后仍进行当前所有者检查。SDK返回及发布事务分别完成规范化与验证，最终消息保存规范化后的正文；知识任务失败不发布未验证的部分正文，流式草稿不代表成功。引用校验只能证明来源身份和当前可访问，不能证明自然语言结论的语义支持；不添加隐藏模型修复或自动生成“已依据”声明。

最终回答中的知识来源按官方Base UI Inline Citation组合显示为紧凑圆角标签，以已保存成功动作的实际来源标题命名；缺少标题时显示“知识来源 N”。悬停、键盘聚焦或点击打开来源卡片，展示标题、章节和最多600字符片段，“查看原文”在新标签页定位同一片段。每份回答只对解析后的实际知识链接按首次出现顺序编号，同一精确地址去重，代码示例、普通外链及无效相对路径不参与。回答完成后，末尾Sources显示可展开的“引用了 N 个来源”，不计入仅检索但未引用的候选；流式期间隐藏此汇总。存档、复制文本及后端验证仍使用原始证据编号和地址。

卡片打开时通过片段接口重新读取当前所有者可访问的单个Chunk，标题最多300字符、章节最多600字符，不批量预取或读取整篇文档，不调用模型或Embedding。文档/库/片段不匹配、版本失效或删除返回404；前端在读取或失败时隐藏缓存片段，失败可手动重试。读取资源归当前身份的KnowledgeStore，共用同地址在途请求，每次重新打开重新核验；关闭或卸载后取消无人订阅的请求，切换身份释放缓存。历史有效引用直接使用同一展示，无须重新生成回答。
