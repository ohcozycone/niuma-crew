## 目标与使用方式

本项目首先作为个人系统学习智能开发的实践载体。路线以 LLM 应用与 Agent 工程为主线，同时练习借助 AI 完成设计、编码、调试和验证。商业定位与企业收益仍见[定位与验证草案](../proposals/README.md)，不是本路线的验收门槛。

本轮知识库建设的功能设计建议见Notion 分层方案导航，覆盖导入、双索引、混合召回、来源与轻量真实评测。本文 L1—L3 仍是分步学习路径，不要求先完成所有学习任务才建设混合检索；全文子迭代不代表本轮功能已全部完成。

以知识助手贯穿学习：资料进入系统，形成固定依据，交给模型或检索流程，产生有证据的回答，再通过实验判断改动是否有效。每阶段交付可运行增量、失败案例和学习记录，不以员工数量、调用量或功能数量衡量掌握程度。

按里程碑推进，不预设工期。已有代码与历史测试可作为阅读材料，但不能替代本人对链路的解释、修改和故障定位。本文维护学习顺序；字段、接口、权限与运行规则仍在对应设计维护，不产生第二份契约。

顺序为 L0 → L1 → L2 → L3。L1 稳定后可穿插 L4 的标准内容小实验；通用 MCP 不是知识助手前置。L5 建立在稳定单 Agent 与工具执行上；L6 在基线可测量后再做。

L1 前置轻量脚本和人工评分，L2 深化实验、题集和模型比较。正式评测作业与页面仍按[知识助手开发顺序](../proposals/README.md)建设，不把脚本称为完整评测平台。新增模型前更新[模型连接设计](../reference/model-connections.md)中的协议、能力与验证，不把改地址等同于兼容完成。

## 每个阶段怎样学习

1. **先解释与预测**：写出输入、输出、状态、失败边界与预计改善的指标；说明一个备选方案及不采用的原因。
2. **做最小实验**：对未知机制先用小脚本或固定样例验证，记录环境、结论和限制；实验不冒充正式实现。
3. **接入同一应用链路**：复用模型解析、问答、授权和计量，不为演示复制第二套提示词或执行路径。
4. **借助 AI 实现并审查**：AI 可协助找代码、实现与排错；本人核对接口、数据流、关键差异和断言，能解释核心实现。
5. **检查失败与反例**：保留正常案例及能推翻错误假设的案例；回答质量靠证据和人工判断，不靠测试替身输出。
6. **复盘再推进**：记录结果、意外、代价、未解决项，以及下次只改变的因素。

学习记录优先写入对应设计的实际验证与取舍部分，跨阶段心得可放本人笔记。不为每次操作创建空模板，不把猜测直接升格为产品需求。

## 验证分层

| 层次           | 回答的问题                                   | 保留的证据                                             |
| -------------- | -------------------------------------------- | ------------------------------------------------------ |
| 确定性代码验证 | 格式、归属、状态、预算和引用定位是否符合契约 | 有意义的单元/API/交互测试，失败输入与预期              |
| 真实集成验证   | 模型、工具和持久化是否真的接通               | 环境、版本、真实调用结果、用量与失败                   |
| 回答效果实验   | 是否正确、有充分支持、值得采用               | 固定资料与问题、人工评分、错误归因、耗时和费用已知程度 |
| 本人掌握验证   | 能否独立判断和维护系统                       | 解释链路、预测改动影响、定位未知故障并验证修正         |

快照保留依据，不保证模型逐字复现；固定配置仍需记录波动。引用位置合法不等于语义支持，技术成功不等于答案正确。公开开发题作联调与回归，独立效果验证另用未参与调参的题。
