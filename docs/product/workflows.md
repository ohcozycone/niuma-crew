# 使用流程

管理员准备共享员工、模型和资料；成员使用员工完成工作。以下名称和材料均为练习示例，需要自行创建。

## 配置一名可以工作的员工

由管理员操作。先准备可用模型和岗位指令，技能、知识库及外部工具按工作需要添加。

1. 打开“大脑配置”，新增聊天连接，选择服务预设，填写名称、模型标识和 API Key，保存并检查连接。检查的是模型目录，能否生成内容还要通过实际对话确认。
2. 打开“数字员工”创建员工。在“基础配置”填写名称、岗位简介并选择大脑，在“指令与知识”填写工作指令，例如：“从材料中整理行动项；缺少负责人或期限时列为待确认，不自行补写。”
3. 需要固定方法时，在“能力库”新建技能，或导入包含 `SKILL.md` 的 ZIP 包（最多 12 MiB），核对预览后点击“确认导入并编辑”；回到员工“能力装配”，点击“添加能力”选入技能，按需要填写非秘密参数。
4. 需要外部操作时，选入已接入并确认工具列表的工作连接，勾选具体操作，配置调用上限及已有范围约束。知识库在“指令与知识”的“员工参考知识”中选择。
5. 点击“保存配置”。各面板的添加、移除和修改先保存在员工草稿中，主保存后才生效。回到目录确认员工处于可接单状态，再用一条文字消息验证。

配置不完整时可以先保存草稿；未装配可用大脑或已暂停接单的员工不能开始工作。需要恢复时，在员工卡片操作中选择“恢复接单”。保存发生版本冲突时先核对最新配置，再处理保留的草稿。

指令用于说明职责和做法；具体工具许可由所选操作、工作连接和服务端范围约束决定，不能通过提示词扩大。

## 发起对话并取得结果

使用管理员或成员账号登录，选择一位可接单且已配置可用大脑的员工。首次验证用普通文字即可。

1. 在“数字员工”点击员工名称或头像，进入主页的“对话记录”，点击“新对话”；也可以打开已有对话继续追问。
2. 提供本次材料和成果要求。比如要求整理会议中的负责人、行动项、期限及待确认事项，练习材料见本页下方。
3. 需要附件时点击“添加文件”，等待上传完成并核对发送区的文件列表。已装配技能可在“选用技能”中指定；不选时由员工自动判断。
4. 发送后等待正式回复。执行日志可以查看模型、检索和工具动作；排队或执行中表示尚未完成。
5. 核对回复与原材料。有成果文件时下载并打开检查；有知识来源时查看引用片段，确认它支持相应结论。

同一对话一次处理一个活动请求。断线后先重新打开原对话查看状态；发送结果不明时核对原请求，避免重复交办。

## 停止、断线与重试

| 遇到的情况                   | 怎样处理                           | 需要知道的结果                                                                   |
| ---------------------------- | ---------------------------------- | -------------------------------------------------------------------------------- |
| 想结束当前处理               | 点击“停止生成”，等待状态结束       | 已发生的外部写入不会撤销；排队中的工作可直接取消                                 |
| 页面关闭或网络断开           | 重新打开原对话                     | 后台可能继续执行，恢复页面不会重新发送问题                                       |
| 发送超时，受理结果不明       | 使用“核对并重试原请求”             | 页面沿用原提交标识和输入，先核对已受理记录                                       |
| 最后一条回复失败、取消或中断 | 查看原因，修正配置后点击“重试回答” | 保留旧记录，按当前配置重新执行；只有最后一次失败或停止的执行可重试               |
| 后端重启                     | 回到对话查看恢复结果               | 只有满足存档和配置条件的普通聊天可恢复，其余显示中断；不要假定外部工具会继续执行 |

停止或重试前，先核对可能已发生的外部操作。重新执行可能再次调用模型、工具并产生费用。

## 接入工具并绑定使用账号

由管理员在“能力库”接入 MCP 服务，准备组织工作连接，再为员工选择具体操作。所有使用者共用员工固定的连接。

1. 在“能力库”点击“添加能力 → 添加 MCP 服务”，进入接入页后填写名称和服务地址；也可以用“快捷导入”回填客户端配置。HTTP 服务的认证方式在访问设置中选择；可信本机程序需由部署者先开启支持。
2. 根据服务选择无认证、密钥或浏览器授权，填写必要信息后点击“保存并测试”或“保存并连接账号”。浏览器授权需在服务方页面确认。
3. 在“可用工具”核对返回的名称、说明和参数，点击“确认工具列表”。已有连接使用“检查工具更新”“应用工具更新”维护；新增工具不会自动授予员工。
4. 打开员工“能力装配”，点击“添加能力”，选择工作连接并勾选必要操作。设置“每项工具调用上限”，需要时填写界面支持的范围约束，完成面板编辑后点击员工的“保存配置”。
5. 发起一项实际工作，在执行日志中检查工具是否调用、返回是否满足要求。读取工具列表不会执行业务操作，不能替代这一步。

成员无需另绑个人账号。认证失效时由管理员更新工作连接；更换认证或工具定义后，重新读取、确认工具列表，并核对员工装配。部署与授权示例见[工具与环境](../guides/agent-tools.md)。

## 从附件到成果文件

平台直接提供受控文件读写，无需在能力库装配文件插件。代码执行由部署环境决定，管理员可在员工“能力装配”顶部查看是否就绪。

1. 在发送区添加文件，上传成功后会自动加入本次输入列表；不需要的文件可移除。复用已有文件时展开“选择本对话已保存的文件”。上传入口每份最多 10 MiB，每次最多选择 16 份，后端还会检查总量与账号配额。
2. 写明要处理的材料、处理方式和成果格式，例如：“读取这份 CSV，按部门汇总金额，将结果保存到 `/outputs/`，并给出下载文件。”
3. 查看执行日志中的文件读取、写入或命令结果。未配置沙箱时只能使用文本工作区：单份输入最多 128 KiB，输入总量和可写工作区各有 512 KiB 限制；二进制处理与运行程序需要沙箱。
4. 正式回复出现成果文件后下载并打开核对。模型给出的临时路径或“已生成”文字不能代替可下载的成果。

上传附件不会自动入库供后续检索。停止或失败时，临时文件未必已保存为成果；文件还受保留期限和访问权限限制。代码环境的配置与验收见[沙箱部署](../guides/agent-tools.md#部署-opensandbox)。

## 修改全员规章制度

由管理员打开“全员规范”，在“制度正文”编辑 Markdown，点击“保存规范”。所有员工后续提交的任务自动采用这份规则，无需逐个装配；留空保存会清空全局正文，员工自身工作指令继续保留。

已排队或执行中的任务保留提交时的规范。更新后的新一轮对话、重试和考核采用各自受理时的规则。

多人同时修改时，页面会保留草稿并提示版本冲突。先查看最新正文，再选择“载入最新版本”或“用当前草稿替换最新版本”；前者放弃本地草稿，后者需要确认后保存。

## 管理知识资料并核对来源

由管理员维护组织知识库。资料只有完成分片和索引后，才能参与检索。

1. 打开“知识库”，新建资料库并进入库详情。在“文档”页点击“上传文件”，选择 UTF-8 Markdown/TXT，每份不超过 128 KiB，再点击上传面板内的“上传文件”开始传输。成功后文档显示“待分片”。全局上传浮层可查看进度，站内切页可继续；关闭浏览器会中断未完成上传。
2. 勾选要处理的文档。需要修改规则时，在规则摘要旁点击“调整”，设置分片长度、重叠和合并阈值，并预览首份所选文档。确认弹窗后仍需点击“分片并建关键词索引”提交处理。
3. 在“分片记录”查看结果。后台按文件处理，可离开页面；失败或中断的文件可单独重试，相同内容和规则的完整结果会复用。
4. 在“检索测试”输入问题，检查是否命中预期内容；点击来源查看正文和片段位置。此页只检索资料，不生成回答。
5. 移除文档会同时移除相关片段与索引。知识库不会自动绑定员工，需要在员工配置中选用。

需要语义检索时，打开“检索设置”，添加或选择向量模型，然后点击“建立向量索引”或“更新向量索引”。当前支持硅基流动 BGE-M3，名称与 Key 在向量连接中配置。操作针对本库全部已分片文档，与文档页勾选无关；每次会将全部现有片段发送到向量服务重新编码，产生相应用量，期间保持页面打开。成功后“检索测试”自动使用关键词与语义混合检索；没有可用向量的资料使用关键词检索。

## 为员工装配知识并问答

1. 管理员打开员工“指令与知识”，在“员工参考知识”选择组织知识库，最多 10 个。
2. 选择“检索时机”：按需检索由模型决定何时查询；每次回答前检索会先查一次，模型仍可继续补查。设置“每次检索的片段上限”（1 至 12，多库合计），点击“保存配置”。
3. 用该员工提问，在执行日志中检查“检索知识库”“读取知识来源”等动作和结果。未处理文件不会进入检索；按需模式下模型也可能不发起查询。
4. 点击回答中的来源，核对原文是否支持结论。来源已更新或删除时，重新检索，不继续沿用旧引用。

所有成员使用员工保存的同一套知识配置，对话侧只读展示。权限、版本和引用的详细规则见[知识规则](../reference/knowledge.md)。

## 第一次对话的练习

发送以下文字即可，无需文件、技能或外部工具：

> 会议决定：王明周五提交预算，李华明天核对名单；上线日期尚未确定。请整理行动项，分别列负责人、事项、期限及待确认内容。

检查回复是否保留两项已分配工作，把上线日期列为待确认，并且没有编造具体日期。若需要绝对日期，在下一轮补充会议日期后再要求转换。

## 查看员工考核

管理员或成员可在员工主页打开“员工考核”，发起专项测试。员工需处于可接单状态并已配置可用大脑。

1. 点击发起考核，确认当前项目“工具调用专项 · BFCL”，填写抽样题数（1 至 400，默认 5）。每题会调用真实模型并消耗用量。
2. 点击“开始考核”，在批次详情查看进度。展开题目可查看问题、答卷和评分依据，也可打开“查看执行详情”。
3. 查看“已评分通过率”，计算方式为通过题数除以已评分题数；运行异常和取消分别统计。需要终止时点击“取消考核”，剩余题目不再继续受理。
4. 比较结果前先核对题库、评分器、员工配置和模型。每批会重新抽样，重新发起不保证得到相同题目。

当前考核检查函数调用提议，保留岗位指令、全员规范和模型，关闭真实工具、技能及员工知识。它不验证实际工具执行或完整岗位任务。关闭页面不会取消已受理批次；退出登录、授权失效或考核配置变化会停止后续题目。
