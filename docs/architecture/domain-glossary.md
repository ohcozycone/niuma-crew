# 当前领域术语

本文定义已实施产品概念，避免把页面、数据记录和运行机制当作同一分类。

初次了解平台先看[产品说明](../product/README.md)。这里统一产品用词与代码名称：技能（Skill）和工作方法是同一对象；大脑是界面对模型连接的称呼。员工选择模型和技能、获得具体工具许可，使用者通过对话提交工作，系统为每次处理建立运行。每次实际操作形成动作，最终结果交付到回复消息。

| 产品名称       | 代码或协议名称         | 定义与边界                                                                           |
| -------------- | ---------------------- | ------------------------------------------------------------------------------------ |
| 大脑／模型连接 | ModelConnection        | 可被多位员工复用的模型配置与加密凭据；不是岗位指令，也不是当前运行。                 |
| 全员规章制度   | OrganizationRules      | 当前部署共享的一份工作规范，在每次提交时进入固定输入；不授予工具权限。               |
| 工具服务       | McpService、MCP        | 已登记的外部操作来源；与某个使用者的访问凭据分开。                                   |
| 工具账号连接   | ToolConnection         | 连接服务所需的身份及配置；当前也用于受控原生工作区连接，不把所有连接都等同远程服务。 |
| 工具清单       | approved_catalog       | 对某条连接已发现并确认的操作及说明依据；确认清单不自动扩大员工许可。                 |
| 员工工具许可   | AgentToolGrant         | 岗位获准操作、资源范围及预算；账号绑定只选择身份。                                   |
| 个人账号绑定   | PersonalToolBinding    | 使用者为已有员工许可选择本人相容连接；不复制员工或修改共享岗位权限。                 |
| 固定配置／快照 | AgentSnapshot、RunSpec | 接受时记录的本轮输入与资源依据；不携带秘密，不替代持续授权。                         |
| 能力目录       | capability_catalog     | 技能与工具服务的联合检索结果；不拥有统一修改或执行生命周期。                         |

| 名称                                | 含义                                       | 边界                                                   |
| ----------------------------------- | ------------------------------------------ | ------------------------------------------------------ |
| Agent / 数字员工                    | 有岗位指令、模型装配和方法装配的配置主体   | 不拥有对话队列或 SDK 执行宿主                          |
| Skill / 工作方法                    | 可装配、版本化并按需读取的指引             | 读取成功不等于已完成用户工作                           |
| Conversation / 对话                 | 用户与一位员工持续交流的容器               | 管归属和内容顺序，不管模型循环                         |
| Message / 消息                      | 一段用户输入或一份助手回复记录             | 接受时即可有空助手正文，不另存执行状态                 |
| Run / 处理尝试                      | 系统针对输入进行的一次可靠处理             | 拥有预算、状态、动作及完整执行成果；不拥有正式对话回复 |
| RunAction / 动作                    | 一次实际模型、工具、方法或校验操作         | 模型提出工具请求不算工具执行成功                       |
| response_id / 回复标识              | 助手 Message 的 ID                         | 是公开操作目标，没有 Response 表                       |
| AssistantMessageView / 助手回复视图 | 服务器从消息、状态和动作组织的页面读取格式 | 是读取结构，不是另一份内容实体                         |
| Thread / 执行线程                   | SDK 连续交流的消息及状态范围               | 同一对话承载多份 Run，不是单次调用或业务历史表         |
| Context / 模型上下文                | 一次模型请求实际采用的指令、消息和工具     | 可被摘要和裁剪，不等于完整历史或 checkpoint            |
| Checkpoint / 恢复存档               | SDK 内部状态和继续执行的位置               | 不替代 Message 历史，出现完整文字也不自动代表成功      |
| Actor / 当前主体                    | 已确认的用户或游客及会话信息               | 不包含 HTTP 请求或数据库                               |

一次失败重试复用原用户 Message，新增 Run 和助手 Message；原失败记录继续存在。Thread 已作为 SDK 状态范围和 Run 关联字段使用，没有另建业务会话表；Turn、Task、Goal 没有额外实体。后续能力仍需以实际产品需求确定边界。

Conversation、用户 Message 和 Run 使用同一持久数字号段，固定 12 位；助手回复直接复用执行侧的 Run ID，所以 `Run.id == 助手 Message.id == response_id`，但两条记录仍分别保存执行事实与正式业务内容。前端只生成 UUID 幂等键；业务 ID 由后端创建并返回。

RunService 负责 submit/cancel/complete；RunWorker 负责后台队列、在途任务和服务生命周期；RunTask 负责一次 Run 的加载、领取、准备、执行、看护、资源释放与成果提交。AgentContext 是 SDK 可用的受限操作协议，不是新增持久实体。

## 基础工具与工作文件

- 工具连接：一份受管的工具来源、非秘密配置及独立凭证身份；连接成功不等于工具已经授权。
- 工具许可：员工获准使用的具体操作、定义依据、资源范围和预算，独立于工作方法内容。
- 工作区：本次处理可见的输入、来源、中间文件与输出的受控视图；临时工作副本不等于持久文件。
- 沙箱资源：本次处理独占的隔离环境及其申请、归属、期限和清理责任；与执行某条命令是不同概念。
- 持久文件：具有稳定引用、归属与内容依据的保存结果；正式交付还需要和消息建立业务关联。

当前规则见[基础工具契约](../reference/agent-tools.md)。

标准 Skill 包、MCP 服务定义、账号连接与员工装配已实现，当前规则以[技能模块](../../backend/app/skills/README.md)及下方 MCP 契约为准。技能库改造方案保留早期目标与术语，未实施或已撤回的方向不作为当前模型。

当前 MCP 服务定义、账号目录、员工许可与个人绑定见 [MCP 契约](../reference/mcp.md)。员工定义共享，使用者只绑定账号，不复制员工；OAuth 授权和续期已接入。早期私人员工、广场与复制方案已撤回，不作为当前领域模型。

能力目录是工作方法（Skill）和工具服务（MCP）的可检索清单。条目表示某项方法或服务已经登记，列出条目不等于获准使用；员工装配、账号绑定和执行许可分别检查。两类条目共用检索所需的概要信息，各自的业务定义和生命周期仍然独立。
