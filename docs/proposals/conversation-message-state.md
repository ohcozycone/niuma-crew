## 目标与领域关系

Conversation 是一次完整会话的容器，包含多条 Message。用户 Message 表示输入；助手 Message 关联一个 Run，展示该次尝试的回答与状态。Run 包含多条 RunStep。重试复用用户 Message，创建新的 Run 和助手 Message，不覆盖失败尝试。

改造前 history 仅返回正文和执行摘要，步骤组件展开后另外请求详情。目标是 history 一次返回当前消息页的正文和完整公开 Run（包含 steps），SSE 发送相同 Run 结构，正文与步骤在同一次状态合并中更新。原始 checkpoint 和工具结果仍留在后端，继续使用公开白名单投影。

## 实施增量

1. Message DTO 使用 `run: RunRead | null` 明确助手消息关联；RunRead 增加完整 steps。history 在选定消息页后批量读取关联步骤，避免每条消息各查一次步骤。
2. Run 查询、命令响应和 SSE 使用同一公开投影。重连取得完整快照即可恢复所有已保存的步骤；重复、乱序和迟到历史不得覆盖更新的正文或步骤。
3. 会话统一管理命令和 Run 观察，步骤读取与本地分页不控制网络请求。后续[双入口改造](conversation-hooks.md)将公开访问收敛为 useConversation/useMessage，内部继续复用这些职责。
4. 消息状态直接保存公开 Run，移除另造的 execution 摘要及当前模型与步骤二次拼接。保留未变化步骤对象引用，避免每个片段重新渲染全部步骤。

## 边界与验收

消息历史仍按消息分页，步骤随所属助手消息返回；界面的步骤分页在本地执行。独立步骤 API 保留为兼容读取入口，正式前端不再调用。完整快照增加流量，沿用现有保存间隔、输出与执行预算，不在本轮新增 delta 协议。

验收覆盖历史初次加载、翻页和定位携带步骤，SSE 正文与步骤同步、终态和重连恢复、乱序拒绝、旧行引用保留、重试隔离、折叠与分页无额外步骤请求，以及现有权限和敏感信息边界。生效规则合入[对话契约](../reference/conversations.md)、[运行契约](../reference/runtime.md)与[模块说明](../../frontend/src/pages/conversations/README.md)，实际验证进入 records。
