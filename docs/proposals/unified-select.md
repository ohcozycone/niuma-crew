# 下拉选择统一入口

设计状态：已采纳。实施状态：已实施。更新日期：2026-10-31。

生效规则见[输入、选择与反馈](../../frontend/src/design-system/components.md#输入选择与反馈)，实际检查与未覆盖项见[验收记录](../records/unified-select.md)。本轮无剩余迁移项。

## 范围与增量

当前 29 处下拉选择已共用 Base UI，但业务与设计展示混用完整 Select 拼装和 SelectField，部分选项同时维护在 items 和 SelectItem 中。

统一以 SelectField 为完整入口：单一 options 数据、当前值与变更回调；保留名称/ID、required、禁用、说明/错误关联、触发器尺寸与宽度，提供前置图标、独立已选文字和必要的弹层定位配置。Select.tsx 继续作为内部基础适配，业务不再拼装 Trigger、Content、Item，也不再使用 option 子节点解析。

迁移全部正式页面、共享业务组件与 React 设计展示。员工模型连接保留加载/失败期间的值、失效选项、禁用和刷新；向量选择保留模型标识；服务/账号保留条件选项与权限限制。操作菜单、主题单选菜单、Tabs 和只读布局研究 HTML 保持对应语义，未新增另一套选择框实现。

## 实施与验收

外观定位修订：已实施并通过定向测试和浏览器核验。用户截图显示默认的已选项重叠对齐遮住了触发器文字。共享弹层改为默认从触发器下方展开、起始边缘对齐并保留间距；空间不足时由 Base UI 翻转或限高。展开时完整保留图标、已选文字和箭头，仍由共享适配统一控制。

1. 扩展现有 SelectField，集中选项渲染与图标，不新建并行组件。
2. 全部调用点迁移到配置入口，删除双份选项与旧 children 解析。
3. ESLint 阻止业务直接依赖内部 Select 和原生 select/option，并覆盖正反例。
4. 验证标签/描述、表单值、required、禁用、键盘、长文案、模型失效与刷新，以及既有页面回归；运行静态检查、全量前端测试、生产构建、文档检查和浏览器核验。

现行规则合入设计系统，实际结果进入验收记录；不改变接口、草稿保存或搜索防抖行为。
