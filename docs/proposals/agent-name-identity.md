## 增量与职责

员工名称在当前部署的员工目录内唯一，包含停用员工；沿用已有输入去首尾空白规则，按保存后的字符串精确比较，英文大小写不同视为不同名称。UUID 继续承担关联职责，名称允许修改。创建和改名在原写事务内检查，数据库唯一索引保护直接写入和并发；重名返回 `409 agent_name_conflict`，员工编号冲突继续独立报告。

提交运行时由平台自动生成姓名身份段，仅使用 `name`，不自动拼接岗位或分类。身份段与公司规则、员工工作指令组合并计入输入大小，最终提示词固定在现有快照中。身份问答优先使用员工姓名，无需每轮自我介绍；明确询问底层模型时如实说明，不能确认时不猜测。姓名按数据引用，不将姓名内容解释为工作指令。

## 迁移与兼容

新增正式迁移，不改写已生效的初始迁移；增加名称唯一索引，保留员工、关联、对话与存档。在线升级先检查旧库重名并明确拒绝，要求人工处理后重试，不自动重命名或删除。离线 SQL 同样由唯一索引拒绝已有重名。降级仅移除索引。

已接受的运行继续读取原快照，不补写姓名；改名影响后续新提交和显式重试，同键重放及重启恢复继续原身份。

## 验收

覆盖创建与改名重名、空白归一、自身同名无变更、停用员工占名、并发创建与改名、失败时配置及装配回滚、直接 SQL 唯一约束；验证新库、旧库数据保留、重名升级回滚、降级和离线 SQL。提示词覆盖空规则与空指令、特殊姓名、输入预算、改名后新旧运行及重放；真实模型回答单独记录，不以假模型证明遵循率。

生效规则见[员工接口](../reference/agent-configuration/api.md#员工接口)、[运行契约](../reference/runtime.md#接受快照与幂等)与[数据库迁移](../guides/backend-operations.md#数据库迁移)；实际结果见[验收记录](../records/agent-name-identity.md)。本增量无剩余实施项。
