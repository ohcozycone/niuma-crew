# 工程评审可靠性修复与验证

日期：2026-11-02。实施基线：本地首次提交 `5c1e9bc`，分支 `codex/engineering-review-fixes`。[增量方案](../proposals/engineering-review-reliability.md)。依据当前源码、全量离线测试及故障注入实施；评审建议均重新核对，不以历史结论替代当前实现。

## 修复范围

1. 建立修复前 Git 基线，保留本地 `.workbuddy` 记忆在提交外；修复 13 处指向缺失历史文件的 Markdown 链接，保留原路径及证据缺失说明。
2. HTTP 故障回归按现行中间件验证安全 500、关联 ID 和回滚；另直接调用业务服务，继续断言未知 IntegrityError 原样传播。技能磁盘失败不产生半份技能。
3. Tab 守卫以 JSX 属性区分静态宽度/外部 margin 与内部视觉覆盖，允许既有侧栏的 w-full，不改页面样式；动态值仍需明确处理。
4. lifespan 用分层 AsyncExitStack 保证生产任务先于资源服务停止；每项启动尝试前登记清理，数据库和 MCP 在创建后立即登记释放。单项/多项关闭故障及部分启动、构造失败后继续清理，异常链保留。知识 worker 任务异常仍释放进程锁。
5. ConversationPreparation 明确必需连接、checkpoint 和执行回调；RunSpec 显式声明接受时的元数据并受构造类型检查，存储快照继续运行时校验。准备层纳入 mypy；Agent 仍只接收 RuntimeControl，宿主的 RunControl 不扩展 Agent 协议。
6. 已知业务错误子类沿 MRO 映射最近分类；未知 ServiceError 保持 500。现有表驱动守卫补 llm 和 api 方向，并识别相对、包成员和别名导入。
7. 更新当前架构、知识入口和工程覆盖说明；源码调查保留 2026-10-31 快照，显式退出当前能力和验证结果的权威入口。
