## 目标与当前基础

统一回答中的资源引用，覆盖知识片段、网页、消息、附件、业务记录、代码和生成文件。证据引用、实现导航、成果下载和相关链接共享资源标识与展示入口，同时保留各自资格、权限和生命周期。统一协议不要求统一搜索引擎，也不把所有资源迁入知识库。

## 统一模型与术语

### 基本区分

| 对象                          | 含义                                           | 不承担的职责                               |
| ----------------------------- | ---------------------------------------------- | ------------------------------------------ |
| 资源 Resource                 | 可识别的文档、消息、网页、记录、文件等对象     | 不表示已经读取、真实可靠或允许引用         |
| 证据 Evidence                 | 一次实际取得的固定信息及其来源、位置和获取过程 | 不证明自然语言结论得到充分支持             |
| 本轮资源绑定 RunResource      | 当前 Run 可使用的资源或证据句柄，以及指定用途  | 不是长期访问凭证，不随正文自动继承到下一轮 |
| 证据交付记录 EvidenceExposure | 某次模型请求实际提供了哪份证据的哪些内容       | 不声称模型理解、记住或采信了内容           |
| 回答引用 AnswerReference      | 固定回答中的一个引用节点与本轮绑定的关系       | 不以 UI 标签样式判断证据资格               |

“来源”是资源在证据中的角色，不再另建一个与 Resource 重复的 Source 实体。“上下文”是模型输入集合，不是资源类型：它包括行为指令、用户陈述、历史回答和证据。检索是取得资源的方式；工具是能力或传输边界，都不直接决定证据类型。

知识库是资源的集合与管理方式，不把 knowledge、MCP、vector 放进同一资源类型枚举。资源种类、所属系统、获取方式和内容表示分别描述。

### 资源标识 ResourceRef

资源标识是嵌入记录的类型化值，首期不建设独立的全局资源目录或 URL 索引。

| 字段组 | 建议内容与含义                                                      |
| ------ | ------------------------------------------------------------------- |
| 身份   | `kind`、`namespace`、`key`：资源种类、来源系统及该系统中的稳定标识  |
| 版本   | 可选 `revision`；没有上游版本时明确未知，不能拿取得时间假装上游版本 |
| 展示   | 有界标题、媒体类型；原文地址可空，由来源适配器校验后提供            |

`kind` 按实际接入逐步支持 message、document、web_page、record、code_file、file、tool_observation。`namespace` 区分知识模块、会话、具体业务连接与仓库，不放入账号秘密。同一文件作为上传、读取依据或生成成果时保持文件身份，用途另行描述。

同一个公开 URL 可以对应多次内容不同的取得结果；相同 URL 在不同账号或连接下也可能返回不同内容。跨身份不根据 URL 或内容哈希自动合并权限。内容哈希只能说明固定字节相同，不能替代来源身份。

### 固定证据 Evidence

| 字段组   | 建议内容与含义                                                                                      |
| -------- | --------------------------------------------------------------------------------------------------- |
| 身份     | `evidence_id`、协议版本、`resource_ref`                                                             |
| 内容     | `content_ref`、内容哈希、媒体类型及阅读表示版本；指向不可变内容，不要求复制全文                     |
| 定位     | `locator`：针对固定内容的类型化位置，另保留有界的人类可读位置说明                                   |
| 信息性质 | `representation` 和 `basis`：搜索摘要、原文摘录、结构化结果、执行结果；用户提供、来源观测或派生信息 |
| 获取过程 | 原始 `run_id`、可空 `action_id`、获取方式、取得时间；资源有业务生效时间时另存，未知保留未知         |
| 派生关系 | `derived_from` 与生成动作：摘要、转录、抽取、统计所依赖的证据，不按自然语言猜依赖                   |

`content_ref` 只允许受管内容位置：既有知识固定快照、既有工具结果中的固定部分、files 保存的只读内容或有界内联文本。内联文本是逻辑表示，具体持久格式实施时再定。现有可变知识 Chunk 不能单独充当不可变内容引用；需引用 Run 内已冻结的快照。诊断 request/response 文件不进入此通道。

定位按类型定义，不能全部塞进自由文本：

| 内容                 | 定位示例                                             |
| -------------------- | ---------------------------------------------------- |
| 消息、文本、知识片段 | 消息/文档版本、块、文本范围                          |
| 代码                 | 仓库或受管文件身份、提交或快照哈希、文件路径、行列   |
| 网页                 | 本次取得快照、段落或文本范围；URL 只是原文入口       |
| 表格与记录           | 固定工作簿版本和 sheet/range；固定查询结果与行键、列 |
| 音视频或图片         | 固定媒体及时间段、页或图像区域                       |

原件、规范文本、OCR 和转录是不同表示；定位必须指向对应表示及其版本。只有文字范围的 OCR 不凭空提供原 PDF 的页码或精确图片区域。

固定内容大小与实际提供给模型的范围分开。保存完整网页而只提供前几段时，证据可以指向完整快照，但本轮引用资格仅覆盖已交付的表示和范围。搜索只返回摘要时，只登记搜索摘要，正文未知；不能事后重新抓网页并冒充当时取得的内容。

`basis` 不使用模型自报的置信度。用户陈述保留“用户提供”归属；助手历史回答不是独立事实依据。可追溯摘要和计算结果保留派生关系；普通脚本任意读取文件时，不根据执行命令猜测出完整依赖链，只记录实际可确认的关系及未知部分。

### 本轮资源绑定 RunResource

| 字段组   | 建议内容与含义                                                           |
| -------- | ------------------------------------------------------------------------ |
| 身份     | `run_id`、不可猜测或严格校验的 `reference_id`、协议版本                  |
| 目标     | 固定 `resource_ref`、可空 `evidence_id`、目标定位                        |
| 用途     | `usage`：citation、implementation、output、related                       |
| 衔接     | 获取动作、原来源 Run、可空原绑定 ID；历史复用时登记新的本轮绑定          |
| 核验依据 | 来源模块的类型化授权定位与已核验版本，不保存长期有效的 `authorized=true` |

每个绑定只表达一个用途，同一资源用于“实现入口”和“证据引用”时可建两个轻量绑定，共享固定内容。模型不能通过改链接参数把 related 升级成 citation。

| 用途           | 资格要求                                                 | 展示含义                               |
| -------------- | -------------------------------------------------------- | -------------------------------------- |
| citation       | 存在固定证据；引用范围已交付模型；当前运行与来源核验通过 | 支持附近表述的依据，但不声明语义已验证 |
| implementation | 来源模块确认实现位置与版本，支持当前权限下定位           | 实现导航；不能据此宣称行为测试通过     |
| output         | 文件已可靠保存，并列入本轮经过检查的正式成果             | 成果入口；临时路径不能充当可交付文件   |
| related        | 目标经受管登记，但不满足或未申请证据资格                 | 相关资源入口，不计入证据来源数量       |

本轮绑定的可用状态按操作实时计算。读取、用于新模型请求、最终发布、历史预览、原文跳转与下载分别复核相应权限；句柄、哈希和访问过的 URL 都不是授权凭证。

output 绑定允许唯一的准备阶段：宿主从成功文件操作或受管输出清单中确认当前 Run 的规范 `/outputs` 路径，预留句柄并交给模型；此时目标明确标为待收集，无下载能力。最终收集返回规范输出路径到正式文件 ID、哈希的精确映射，再一次性封存绑定，之后不可换目标。不能只按文件名匹配，也不能把模型任意拼写的路径视为已登记。文件未取得或未进入正式成果清单时发布失败。没有预留句柄的成果仍可进入既有成果区，不自动在自然语言中补插引用；无需为补句柄增加隐藏模型回合。

这种准备阶段只允许 output，用于声明将交付的最终成果，不授予 citation 资格。输出在准备后被覆盖时，句柄指向最终收集的文件，展示封存后的版本；需要证明修改前后代码事实时，必须另行保存对应固定证据。

### 证据交付记录 EvidenceExposure

交付事实来自工具内容管理线在最终请求准备阶段产生的同一份交付清单，引用侧消费而不重新决定范围。以下描述所需信息，不预定独立存储或另一套请求状态机；是否增加持久字段以框架适配后仍缺失的业务核验需求为依据。

记录当前 Run、模型动作、证据标识、表示版本和交付范围，也记录提供给模型的资源句柄。文字范围统一为规范表示中从零开始、右端不含的 Unicode 字符范围；前端 UTF-16 与后端字符索引显式转换，行号和时间定位另用各自单位。

记录依据是最终组装、裁剪和摘要后的模型输入，不是检索 Top-K 或工具原始输出。工具返回、预检索、临时资料消息、历史导入和分页补读都通过同一交付规则。工具结果里的大 JSON 若在预览中被截断，未完整提供的候选不因此取得引用资格。

准备请求时持久记录交付意图，随后关联发送状态及模型响应；准备、发送失败、发送结果未知不能伪装成成功响应使用过的输入。只有回答对应请求及其可信上下文链上的交付记录参与核验。上下文压缩后，保留并重新注入有预算的证据片段；只剩摘要的内容不能继承完整原文的交付范围。

这是业务追溯数据，不能依赖当前可失败、可缺失的诊断证据采集。初期可记录统一提供的有界证据单元，避免先建设对任意自然语言 token 的精确追踪。

### 回答引用 AnswerReference

每次出现的引用记录正文版本、正文哈希、引用节点序号、来源文本范围、`reference_id` 和用途；同一绑定出现多次保留多个节点。文本范围使用与规范正文一致的 Unicode 字符索引，前端按契约转换。记录对应的是完成规范化后的不可变正文，不复用流式草稿的偏移。

正文标记保留引用位置，规范引用清单负责目标和用途。完整正文与引用清单必须一起保存，不能把两者作为独立可编辑事实。读取清单时按当前权限筛选展示字段，不能向无权用户泄漏标题、路径或摘录。

### 存储归属建议

ResourceRef 不单独建全局表。Evidence、RunResource 和 EvidenceExposure 先映射到现有知识证据、结果文件、消息、模型动作和交付清单；只有原生机制不能表达所需业务事实时再增加最小持久字段，不预定三套独立存储。AnswerReference 首期作为版本化的最终回答清单随 `Run.result_data` 保存；需要跨回答引用分析时再拆表。逻辑对象不要求一一对应数据库表。

保留现有 `output_files` 结构和文件关联，它们仍决定正式交付与下载资格；output 引用只是对这些成果的另一种呈现。`safe_details.sources` 可保留有界的资源句柄摘要以展示过程，正式引用读取不再依赖遍历全部动作拼装。

## 模块职责和依赖

公共引用职责包括统一协议、本轮绑定与引用解析；是否聚合为 `app.references` 在框架差额和真实跨来源复用确认后决定，不先新建空模块。证据交付由现有模型入口与官方消息机制共同提供，引用侧仅消费。以下为逻辑职责，不预定独立服务、全局抓取、搜索或文件存储系统：

| 模块                  | 负责                                                         | 边界                                                         |
| --------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| references            | 证据/绑定/交付记录、统一预览投影、最终引用解析与资格检查     | 不读取任意路径，不绕过来源权限，不解析供应商私有结果         |
| knowledge             | 入库、切分、索引、检索；固定片段导出、来源版本与员工范围核验 | 公共引用不能替代知识管理授权，普通成员仍只能读获准片段       |
| files                 | 原件、资料快照与成果的可靠字节、哈希、配额和清理             | 不依据引用标签自动授予下载权；诊断文件维持专用通道           |
| conversations         | 消息来源读取、历史输入选择、会话权限和成果接纳               | 不负责公共证据存储；不能通过引用获得其他会话消息             |
| mcp 与具体来源适配器  | 连接调用、参数授权；明确的来源字段映射和内容性质声明         | 通用 MCP 不按工具名猜网页，也不保证任意返回都可抽取 citation |
| builtin_tools / agent | 将已登记的句柄和有界证据装入真实输入，解析工具正常反馈       | 模型不自造来源事实、读取权限、上游版本或文件下载地址         |
| execution             | Run 生命周期、动作/预算、取消、模型请求关联、恢复和完成事务  | 不反向导入 conversations；不新增第二套发布状态机             |
| bootstrap             | 按来源种类装配读取、核验和预览委托，连接执行完成回调         | 不在业务模块中动态发现或构建另一套插件系统                   |
| frontend              | 安全解析引用节点、共用标签、按类型预览、统计和复制           | 不从域名、文件后缀或标签文案推断证据资格                     |

公共模块定义最小来源委托：描述资源、确认固定内容、按操作核验、读取有界预览及提供可执行入口。各来源实现委托，bootstrap 组合。执行侧通过注入的引用操作使用它；references 不导入具体 RunService、会话服务、HTTP 或 SDK。Run 读取范围和动作关系通过已装配的查询/核验入口提供，防止 execution 与 references 相互依赖。

外部来源的通用原结果继续原样保存。明确接入的网页、代码或业务适配器从结果生成类型化资源与证据；未知格式只保留普通工具结果，不自动扫描所有文本 URL 生成“已验证来源”。新增协议映射应声明版本，恢复使用已保存结果与对应映射，不偷偷重新执行外部操作。

当前 `execution/evidence.py` 是运行诊断，而本方案的 Evidence 是回答依据。实现时通过文档和类型命名明确两种语义，不为本次功能机械重命名已有诊断链路。

## 正文协议、读取与展示

### 首期正文协议

建议继续使用 Markdown 链接，不复制 Codex 的所有指令语法，也不要求模型输出 HTML。平台在登记绑定后提供完整规范链接，逻辑路由形如 `/references/{run_id}/{reference_id}`，模型逐字使用给出的句柄和地址。

路径只承载平台绑定，真实网页 URL、内部记录标识和文件路径保存在受管目标中。用途固定在绑定记录，不由链接文本或查询参数改变。普通 HTTP(S) 链接继续作为普通链接，不自动进入 Sources；用户粘贴 URL 尚未读取时最多作为 related，不自动变成 citation。

后端按 Markdown 语法树提取真实链接，前端消费同一协议及解析夹具。代码块、行内代码、转义文本、嵌套链接示例和普通外链不被增强；不把现有正则无限扩展成通用引用解析器。未知内部引用、跨 Run 未登记绑定、目标错配与用途不符均不能作为正式引用发布；给出明确失败，不额外调用模型修复。

首期保留SDK已有标准内容块及Citation annotations，对已支持来源归一成同一绑定与AnswerReference；Markdown作为兼容和无原生引用模型的输入形式。两者共享最终清单，不增加自定义inline指令作为第三套协议，也不要求立即支持所有供应商。供应商偏移按对应文本块及原单位映射，不直接当成平台正文或源文档坐标；任意annotation目标不因此获得平台权限。

### 读取能力

具体 API 名称在实现时定，先冻结四种能力：按 Run 查询有界引用目录；按绑定读取固定证据预览；定位受管资源或原文；对已发布成果执行下载。所有入口独立校验当前身份，目录可读不等于正文、原文或附件都可读。

预览可用性与原文可用性分别表示，不能用单一 failed 同时代表撤权、源删除、快照缺失、网络未知或缺少预览能力。标题、URL、查询和摘录同样可能敏感，不只保护正文。

### 前端投影

| 用途           | 行内展示与卡片                                                       | 汇总                         |
| -------------- | -------------------------------------------------------------------- | ---------------------------- |
| citation       | 来源标题；内容性质、定位、取得时间或版本、已保存摘录、获准的原文入口 | 实际证据来源                 |
| implementation | 文件名与行号；固定版本的代码位置和可用入口                           | 可选实现清单，不计证据来源   |
| output         | 文件名；类型、大小和正式成果入口                                     | 复用成果区，不重复计证据来源 |
| related        | 有界标题或域名；普通目标导航                                         | 不计证据来源                 |

标签外壳、键盘交互、加载和错误状态可以共用；预览主体按类型扩展。来源读取放在身份作用域的公共引用 Resource 中，共用在途请求，重新打开复核，切换身份清缓存；不因重开卡片自动抓网页或调用模型。

流式阶段依据已登记目录渲染暂存标签，未知或未闭合标记保持等待/普通文本状态，不抢先赋予可访问能力。完成后以正式正文和引用清单替换草稿，Sources 再统计；失败或未接纳输出保持未完成标识。

引用节点按出现顺序编号；同一绑定重复出现不增加来源数。首期来源单元按固定证据身份去重，不按 URL 合并不同版本或不同权限范围。若将同一文档的多个片段视觉分组，必须明确区分“证据条目数”和“文档数”，不让编号与汇总口径矛盾。

复制和存档保留标准 Markdown 与规范链接，不序列化 React 标签。独立来源页执行同样授权，链接不是脱离账号即可访问的分享令牌。

## 从获取到正式回答的流程

### 正常链路

1. **受理与选取历史。** conversations 或 evaluations 按当前规则创建 Run。固定员工配置、输入文件和实际选入的历史；历史资源重新授权并建立本轮绑定，不从旧答案任意 URL 导入证据。
2. **获取资源。** 知识检索、文件读取、外部调用等沿现有受管动作执行。来源模块检查资源范围，网络与耗时解析仍在数据库事务外；工具成功只表示调用结果，不表示全部内容已取得。
3. **固定并登记。** 保存不可变字节或确认现有固定快照，提取有界证据与定位，再在短事务提交证据、绑定和对应动作结果的关联。登记幂等键包含 Run、获取动作、结果项和映射版本；同 Run 重试不重复抓取、扩大范围或重复登记。
4. **装入模型。** 上下文装配选择有预算的内容，将句柄、规范链接、内容性质和片段交给模型；记录最终交付范围及模型动作。分页补读追加范围，持久化完整内容但未交付的部分不获得原文引用资格。
5. **生成回答。** 模型用平台提供的规范链接引用；系统从生成结果解析节点，不从 Top-K、工具 sources 数量或所有外链推算引用数。模型返回的标题只能影响正文文字，不能覆盖来源身份和权限元数据。
6. **提交 Run 成果。** 在现有 `RunService.complete` 的完成路径规范化正文，核对绑定、用途、交付、来源版本和当前权限；同时检查 output 引用确实属于通过验证的 `output_files`。最终正文、引用清单、成果文件关系所需信息与 Run 终态原子保存。语义支持不在此阶段伪装成已验证事实。
7. **业务接纳。** conversations 在原有独立事务重新核对工作资格、保存正式消息、关联成果；只接纳已固定的引用清单，不重新抽取外部结果或重新调用模型。接纳失败沿现有机制重试，不重写成功 Run。评测复用引用结果，由评测自己的接纳规则决定答卷状态。
8. **展示与阅读。** 消息读取返回正文和有界引用投影；前端渲染标签，打开时取预览，导航或下载时再次授权。后续来源变化只改变当前可访问状态，不改写已交付正文。

工具资料有持久化义务，引用资格也有持久化义务。已要求登记的证据保存失败时不能向模型发放可引用句柄，不能把这种失败当作可忽略的诊断采集失败；需要时可保留调用原结果并明确报告不可引用。

模型输出已经引用的内部句柄无法核验时，正式成果整体按引用校验失败处理，不静默降级为普通外链、删除引用后发布或生成“已经验证”的声明。未适配工具仍可正常返回普通结果，这与登记失败是不同情况。

### 四种来源示例

1. **知识片段。** knowledge 取得组织制度固定片段，导出原有 Run 快照并提供知识核验委托；统一绑定用于 citation。历史阅读不要求员工仍挂载该库，继续使用来源 Run 及当前资料规则；新轮使用则检查当前员工范围。
2. **网页搜索。** 已知适配器从原结果取得网页身份和搜索摘要，登记 snippet 证据。随后真正读取网页时登记另一份原文证据及获取动作；摘要和正文不互相覆盖，也不因 URL 相同混为一份。
3. **用户消息与附件。** conversations 导出当前可用消息的固定原文，files 提供选定附件；消息属于 user_provided，附件清单仅授权导航，实际读取的内容才登记交付范围。历史助手答复需追溯原证据，不能变成新的独立事实来源。
4. **生成文件与代码。** 写入沙箱路径只是临时资源；宿主可为已确认的输出预留 output 句柄，最终响应后收集并可靠保存文件，再精确封存和校验正式成果清单。代码导航固定到可持久读取的快照、已接入仓库提交或正式文件；现阶段沙箱生命周期不允许把任意临时路径交给用户长期打开。“代码已修改”与“测试已通过”分别引用代码和执行观测。

## 权限、版本与生命周期

### 三种授权分开

| 操作             | 核验依据                                                                          |
| ---------------- | --------------------------------------------------------------------------------- |
| 当前 Run 使用    | 当前发起者工作资格、员工配置、冻结资源范围、连接/文件许可及来源版本               |
| 阅读历史回答来源 | 当前回答/Run 读取范围与来源读取规则；不自动要求员工仍装配原能力，也不绕过资料权限 |
| 新一轮复用       | 实际选入历史、当前工作范围、来源有效性、时效要求和预算；重新绑定并交付            |

注册表记录来源权限定位，不创造另一套 ACL。公开网页快照也属于取得它的 Run，不能据“公开”推断整份工具返回或查询参数都可跨用户共享。私有系统至少检查对应来源连接与当前主体资格；仅有平台许可不证明上游对象当前仍可访问。

对依赖上游的实时授权，适配器在事务外完成必要检查，再以有界有效的核验结果和本地修订进入短事务；不能在 SQLite 写事务中访问网络。无法确认上游实时权限时明确 unknown 或拒绝相应能力，不能承诺跨系统绝对原子授权。

### 版本和时效

固定快照表示“当时取得什么”，当前来源状态表示“现在能否读取/使用”，业务有效时间表示“信息适用于何时”。三者独立。快照完整性哈希不证明来源真实性，也不能自动证明没有过期。

知识库首期保持现有规则：原文档或片段失效时来源读取失败，不因通用快照机制默认开放旧版本。其他来源可由明确的来源策略允许阅读保留快照，同时标注原文不可用；不建立全局统一的删除后继续可读规则。实时记录新轮复用通常需要重新获取，不能以曾在上下文出现作为当前状态依据。

### 保留与恢复

已发布引用持有必要的固定内容；活动 Run 持有尚未发布的证据；跨轮复用建立显式持有关系。files 的引用查询由装配层扩展，字节可按现有机制复用，但内容去重不合并权限。解除持有后按既有保留策略回收，不增加永久保存所有候选的默认承诺。

外部删除、隐私删除与撤权仍可使固定内容不可读；保留最小引用墓碑说明不可用，不回填秘密或改写历史正文。保留期限、配额及删除联动需在来源策略中明确。

同 Run 恢复复用已保存证据、绑定和映射版本，再检查资格；外部操作、沙箱和工作区的现有不可自动重放限制继续有效。本轮上下文证据变化时按现有记忆重置机制处理，不能拿 checkpoint 内旧句柄恢复引用资格。

## 兼容、实施切面与验收

当前讨论没有决定全面实现 SQL、邮件、代码仓库、OCR 或音视频检索。它们只用于检验模型是否能扩展，首期只为实际接入类型注册委托。

1. **冻结公共契约。** 确认五个逻辑对象、来源核验操作、用途、正文链接、交付范围及最终清单。以知识片段、网页摘要、用户消息和成果文件的实例验证，不先改搜索算法。
2. **迁移现有知识展示。** 先让统一读取和展示委托现有知识证据，保持其权限、版本及旧路径兼容；正式切换后避免两套登记长期双写。迁移如何映射旧 K 编号与新绑定需单独制定迁移脚本与夹具。
3. **接入明确外部能力。** 选择有稳定结构的工具验证摘要/正文差异、原结果保留和正常分页，不声称自动支持任意 MCP。
4. **扩展成果与上下文引用。** 接入既有正式文件、可定位的用户消息；未来代码导航必须先有持久代码资源读取能力。

历史正文和既有 K 链接保持不变，经来源 Run 的精确登记映射委托旧知识读取入口。旧普通外链不会补造已抓取证据；缺少足够事实的历史仅保留普通链接。旧结果缺交付记录时不能反推“模型已读完整正文”；新轮使用需显式提供获准内容。

设计验收重点：相同 URL 的不同快照、同页不同片段、跨账号连接、摘要与正文、工具结果被裁剪、中文和 emoji 偏移、代码块中的标记、未知/跨 Run 句柄、引用未交付范围、普通链接与成果数量分开、接纳重试、撤权与来源删除、临时沙箱路径、诊断缺失与业务证据失败，以及保留/回收的一致性。以上是未来实现的验收要求，本次没有执行这些功能测试。

待评审决策：首批来源适配器范围；知识兼容迁移策略；各来源保留与时效策略；证据条目或文档分组的用户计数口径；外部权限无法实时确认时的降级能力。本文已给出推荐的统一模型，不把这些尚未确定的产品策略写成现行规则。
