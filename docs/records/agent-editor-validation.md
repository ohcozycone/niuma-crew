## 2026-10-30 保存确认、修订与离页保护

用户报告新建和编辑保存后不返回、继续报修订冲突、离开仍提示未保存。通过正式 AgentEditorPage、WorkspaceDataProvider、EditingProvider 和 Layout 的路由集成回归复现；修复前新增的四组场景全部失败。之前的保存 Hook 和接口测试没有覆盖这条“保存完成到离开表单”的完整协作。

确认的问题与修复：

1. 页面在保存 Promise 返回后立即导航，表单尚未清除 dirty，离页保护因此拦截；表单的保存基准也从未更新。现在提交返回完整员工记录，表单采用新基准及修订、清理草稿，再发出导航回调。
2. 保存响应中的新 revision 没有进入表单，留在原页再次提交会使用旧版本，产生真实 409；服务端的冲突保护本身没有放宽。真实失败继续保留草稿，由用户核对后采用新修订。
3. 外壳导航判断捕获上一次渲染的 dirty，并发更新时仍可能误拦截已确认的保存。现在实际导航读取同步 isDirty/isSaving；订阅快照继续驱动提示显示。
4. 成功目的地沿用任意 from，可能离开员工目录。现在成功统一回员工列表，保留来源列表的条件并显示成功反馈；取消仍遵循原来源。重复提交有同步锁，成功使用 replace，避免回退到旧编辑页。
