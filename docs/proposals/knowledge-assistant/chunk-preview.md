# 短章节合并与处理预览

设计状态：用户已授权实施。实施状态：已实施；现行契约见[知识库](../../reference/knowledge.md)，实际结果见[验收记录](../../records/knowledge-chunk-preview.md)。日期：2026-10-31。

本增量延续[资料建设闭环](document-processing.md)，改善标题密集资料的片段完整性。保留现有规则切分，不使用模型；完整向量增量和员工挂载不在本次范围。

## 实施边界

1. Markdown解析补充父章节标识和完整标题路径。仅相邻、具有同一实际父章节的短章节允许合并，不按标题文字猜测同一父节点；不同顶级章节、父级导言、长章节及代码块内伪标题不会被误并。
2. 合并保留连续原文和所有来源区间，受切分预算约束；短章节不强行凑到最小长度。最小阈值支持0关闭，暂从200字符起用代表性资料验证；较小字符预算下默认阈值收敛到无重叠预算，不以该数值宣称普适最优。
3. 平台默认加库级覆盖。处理弹窗可临时调整字符上限、重叠和短章节阈值，修改后重新预览；不将临时值隐式写回库设置。
4. 按所选文件预览统计与分页片段，展示长度、原文、章节来源和合并标记；预览不发布正文、Chunk、BM25或向量，不创建任务、不调用外部API。单次只解析一份已有受控原件，防止批量预览放大内存。
5. 后台处理和预览复用同一解析/切分入口，提交时冻结明确规则。原件不可覆盖，删除及所有权仍复核；改变规则或预览文件时失效旧预览，取消请求并忽略迟到响应。首期预览可选，不增加逐片人工审批。
6. 旧快照继续可读，旧排队任务缺少新规则时沿用原不跨章节切分；新任务使用新规则。既有向量仅在用户实际重处理对应文件后清理。

## 验证

覆盖同父合并与跨父拒绝、长短组合、重复标题、代码围栏、边界与重叠、原文连续重建和多来源映射；验证预览无写入、分页、权限、临时规则、实际结果一致、旧任务兼容及删除竞态。用仓库内制度、流程、技术手册及补充FAQ样例比较阈值、片段数量和典型BM25命中，记录收益与局限；不将关键词命中等同于语义或回答质量。
