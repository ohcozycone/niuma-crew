# 数据库错误识别与业务冲突边界验收

日期：2026-10-26。适用快照：当前工作区，仓库尚无可引用提交。范围为 SQLite 错误识别、配置服务中的业务冲突转换、删除保护及故障测试。

## 实际改动

- 新增 [数据库错误识别](../../backend/app/infrastructure/database/errors.py)，封装 SQLite 驱动类型、错误码、完整唯一列列表及 BUSY/LOCKED 扩展码判断；不依赖业务模型，也不生成业务提示。
- 员工创建和修改只转换明确的名称、编号重复；模型连接创建和修改只转换明确的名称重复。其他完整性异常保留原异常身份并继续抛出。
- 技能删除在同一写事务中取得写入资格、读取实际装配并作业务拒绝；模型连接删除保留实际员工和活跃运行引用检查，移除通用完整性异常兜底。
- HTTP 层复用基础设施的繁忙识别，保留 503、Retry-After 与安全响应；未知完整性异常保持服务端错误，不返回 SQL、表名或约束细节。
- 新模块纳入增量 mypy，现行职责及错误规则已合入[数据库说明](../../backend/app/infrastructure/database/README.md#数据库错误与业务错误)、模块入口和工程手册。

## 验证结果

后端全量 `make test-backend`：455 项通过，包含本次新增的 39 项技术识别和业务错误边界测试。

已实际执行：底层错误识别测试 10 项通过；业务错误边界、数据库、员工存储、配置接口和模型连接定向测试共 122 项通过。Ruff、格式及覆盖 9 个源文件的 mypy 检查通过，文档链接检查通过。

新增故障覆盖使用真实 SQLite 错误，验证单列及组合唯一约束、主键、NOT NULL、CHECK、外键、未知驱动、缺失错误码、BUSY_SNAPSHOT 和 LOCKED。业务边界包含 24 种未知异常与操作组合，确认异常身份不变、事务完全回滚；另验证已知冲突仍返回原业务错误、未知错误的 HTTP 500 不泄露数据库详情。

## 限制

测试只操作隔离数据库，没有修改开发数据库、执行部署迁移或访问真实模型服务。本次未修改前端，未重跑前端测试。错误识别目前只支持已明确实现的 SQLite 情况，不代表其他数据库驱动已经适配；数据库结构及对外成功响应未改变。工作区同期进行了应用错误和对话查询职责整理，测试使用当时已同步的实现。
