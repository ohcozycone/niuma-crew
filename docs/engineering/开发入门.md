# 开发入门

前后端与文档站在同一仓库维护，安装、启动与检查统一从根目录执行。

## 基础技术栈

| 范围           | 主要技术                                                 | 用途                                 |
| -------------- | -------------------------------------------------------- | ------------------------------------ |
| 前端页面       | React、TypeScript                                        | 组织页面、表单和持续更新的对话       |
| 路由与构建     | React Router、Vite                                       | 页面路由、开发服务和静态资源构建     |
| 组件与样式     | Base UI、Tailwind CSS                                    | 复用控件交互，统一语义样式           |
| 前端共享数据   | Context、细粒度订阅                                      | 按身份管理记录、请求与更新           |
| 后端接口       | Python、FastAPI、Pydantic                                | 提供接口、校验输入输出并连接业务服务 |
| 业务存储       | SQLite、SQLAlchemy、Alembic                              | 保存业务关系、组织事务和数据库升级   |
| 智能体执行     | LangChain、LangGraph、DeepAgents                         | 模型工具循环、技能、文件能力与检查点 |
| 工具与代码环境 | MCP、OpenSandbox                                         | 接入外部操作与隔离代码环境           |
| 知识检索       | 中文分词、全文索引、Chroma                               | 关键词与向量召回、结果融合           |
| 测试与检查     | Pytest、Vitest、Ruff、Mypy、ESLint、TypeScript、Prettier | 行为验证、类型与代码风格检查         |
| 文档站         | Next.js、Fumadocs                                        | 发布仓库正文、检索与阅读导航         |

依赖与版本分别见[后端清单](../../backend/pyproject.toml)、[前端清单](../../frontend/package.json)和[文档站清单](../../docs-site/package.json)，安装使用仓库中的锁文件。

## 目录结构

```text
niuma-crew/
├── backend/                 # 后端模块化单体
│   ├── app/
│   │   ├── main.py          # 服务导出入口
│   │   ├── config.py        # 汇总并校验应用配置
│   │   ├── bootstrap/       # 服务装配、模型注册与启停
│   │   ├── api/             # HTTP 接口与协议转换
│   │   ├── cli/             # 命令行维护入口
│   │   ├── applications/    # 对话、考核与配置摘要
│   │   ├── runtime/         # 执行宿主、Agent、工具适配及普通契约
│   │   ├── resources/       # 员工、技能、连接、知识、文件与环境
│   │   ├── auth/            # 身份、会话与权限
│   │   ├── infrastructure/  # 数据库、模型 API、凭据加密、线程与日志
│   │   └── common/          # 普通值、错误和校验基类
│   ├── migrations/          # 数据库升级历史
│   ├── tests/               # 行为、架构边界和兼容性检查
│   ├── datasets/            # 题库、样本与来源说明
│   └── experiments/         # 独立实验
├── frontend/                # 页面、组件与前端数据管理
├── docs/                    # 平台介绍、技术原理与开发维护正文
├── docs-site/               # 文档网站与正文发布脚本
├── scripts/                 # 跨端启动、检查与开发辅助脚本
├── deploy/                  # 部署与外部运行环境配置
└── Makefile                 # 安装、启动、检查和构建的统一入口
```

前后端按各自运行方式组织代码：前端以页面、共享状态和组件为主，后端以业务应用、执行和资源所有权为主，不要求两端使用相同层级。`resources/` 是后端管理的业务资源，前端静态文件位于 `frontend/public/`；文档站是独立的发布工程。

修改页面从前端对应业务目录进入，修改 HTTP 协议从 `backend/app/api/` 进入，业务流程、执行策略和资源规则分别回到所属模块；修改文档回到仓库正文。详细目录与核心协作分别见[前端设计](../architecture/frontend.md)和[后端设计](../architecture/backend.md)。

## 环境设置

### 环境准备

| 工具    | 要求                     | 检查命令            |
| ------- | ------------------------ | ------------------- |
| Python  | 3.12 或更高版本          | `python3 --version` |
| uv      | 管理后端环境和锁文件依赖 | `uv --version`      |
| Node.js | 22.12 或更高版本         | `node --version`    |
| pnpm    | 11                       | `pnpm --version`    |
| make    | 执行仓库统一命令         | `make --version`    |

### 安装与初始化

```bash
make setup
make db-upgrade
make admin-create
```

`make setup` 按锁文件安装前端、后端和文档站依赖，并在缺失时从示例创建 `backend/.env`。数据库升级单独执行；已有管理员可跳过账号初始化，密码按终端提示输入。

配置项、密钥与数据路径见[后端运维](../guides/backend-operations.md)。隔离代码环境按需要配置，接入方法见[工具与环境](../guides/agent-tools.md)。

### 启动与访问

```bash
make dev
```

| 入口     | 本地地址                                               |
| -------- | ------------------------------------------------------ |
| 平台页面 | `http://127.0.0.1:3000`                                |
| 后端接口 | 默认从 8000 端口开始，实际地址见终端                   |
| 接口说明 | 后端地址下的 `/docs`                                   |
| 文档站   | 单独执行 `make dev-docs`，访问 `http://127.0.0.1:3001` |

浏览器请求通过同源 `/api` 进入后端。平台启动后，配置模型连接并绑定员工，即可验证一次真实对话。Ctrl+C 结束本次启动器创建的前后端进程。

分端启动、生产预览及开发检查见[开发命令与排错](../guides/local-development.md)。

## 设计系统

界面统一使用语义颜色、文字尺度和基础控件。颜色、间距与圆角由 `frontend/src/design-system/theme.css` 维护，用途由 `spec.ts` 登记；页面不再定义一套相同用途的数值。

- 先按标题、正文、字段和辅助信息组织层级，再增加必要的边界与强调。
- 页面组合已有控件；相同操作保持一致的键盘、焦点和反馈行为。
- 未保存、提交中、成功与失败要能区分，失败保留可恢复的输入。
- 外壳管理导航，页面管理内容宽度与主要滚动，组件适配自己的容器。窄屏先调整分栏和信息顺序。
- 修改后一起检查日夜主题、窄屏、键盘焦点、长内容和主要状态。

需要选色、调整布局或复用组件时，再查阅[颜色与主题](../design/colors.md)、[布局与响应式](../design/layout.md)和[组件与反馈](../design/components.md)，各页提供真实示例。
