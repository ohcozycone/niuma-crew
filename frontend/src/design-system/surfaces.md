# 共享表面、圆角与组件归属

本文定义当前复用边界；颜色和数值仍只由 [theme.css](theme.css) 提供。设计目录的业务样板复用正式组件，排版目录提供局部曲线对比。

表面组件不代替组件内容和空间类型。完整类型、内部预算与容器职责分别见[组件分类](component-catalog.md)和[布局规范](layout.md)；共享空间规则已接入正式组件，实际检查见布局验收。

## 工作台主表面

桌面侧栏与整页共用 canvas，右侧主工作区使用 surface、细边界和 roomy 圆角，顶栏融入同一表面，并保留底部1px细分隔线；侧栏不再使用整高分隔线。主工作区外框与顶栏分隔共用独立的 `--os-workspace-border`，比普通控件边界更弱。外壳使用 `workspace-surface` 管理外框，`workspace-region` 只负责查询容器；根节点也使用后者，不能将外框几何写入它。768px 及以下主工作区全宽且无外框，侧栏保持抽屉行为。

资源卡片的raised变体使用 `raised` 底色，日间比浅暖灰工作区的 `surface` 更明亮，使用暖白与细边界表达集合；默认不增加阴影，悬停仅使用轻微柔和阴影。`CardContent` 消费 `--os-card-padding`（16px）统一员工与知识资源卡片留白。表单、菜单、焦点和状态继续使用自身语义。

## 卡片为何曾经不同步

此前三条实现路径没有共用表面组件：员工卡片消费 `card-border-width`，旧技能详情卡片把宽度写成 1px，能力目录的 CapabilityCard 又直接采用通用 border 色且没有卡片阴影。共享部分令牌不足以保证外观同步。

现在 [Card](../components/ui/Card.tsx) 是卡片表面的唯一所有者，员工、知识库、技能详情、能力目录、大脑连接、工具目录、装配行、配置分区和设计样板均通过它消费表面规则。业务组件继续负责内容与操作，不把不同业务的数据、请求或权限合并成一个大组件。

| 接口                     | 用途                                                                                |
| ------------------------ | ----------------------------------------------------------------------------------- |
| `Card variant="raised"`  | 资源列表卡片，共用 1px 实色外框、raised表面和轻微悬停阴影，默认无阴影               |
| `Card variant="outline"` | 配置分区、集合边界与信息面板，保留边框而不增加抬起阴影                              |
| `Card variant="muted"`   | 次级说明区域，使用次级底色且没有外框                                                |
| `Card variant="empty"`   | 虚线占位与空态边界                                                                  |
| `Card variant="plain"`   | 内嵌已有表面的内容集合，无边框、底色和阴影；`radius="none"` 表示无需第二层圆角      |
| `CardContent`            | 员工与知识库资源卡片共用的内容容器及标准留白；业务组件负责内部排版和必要窄屏覆盖    |
| `CardFooter`             | 资源卡片底部的分隔线、间距和动作行结构                                              |
| `as` / `radius`          | 保留 article、section、form、details、ul 等原生语义，按用途选择卡片、面板或控件半径 |

外层 Card 不拥有业务内部布局。CardContent 统一资源卡片的内容留白，数值消费已有空间令牌；员工卡片保留自身窄容器覆盖。姓名与说明、技能展开、模型状态、凭据管理和许可验证仍在对应业务组件中维护；页面只传布局、内容和状态样式，不另写整套卡片边框、表面和阴影。选中、错误边框仍可按实际状态覆盖。弹窗、气泡、头像和输入组合属于其他组件类型，分别沿用已有组件，不伪装成资源卡片。

## 完整功能组合的接入

| 入口                                                          | 组件拥有的完整内容                                           | 消费者负责                          |
| ------------------------------------------------------------- | ------------------------------------------------------------ | ----------------------------------- |
| [PageTabs](../components/common/PageTabs.tsx)                 | 页面/面板线型 Tab 的整行基线、列表、标签、计数、活动线与换行 | 选项、选中状态、URL、内容和右侧摘要 |
| [FormField](../components/common/FormField.tsx)               | 标签、控件关联、辅助/错误文字及 aria、统一间距               | 控件值、校验结果、事件和业务规则    |
| [AccountMenuButton](../components/auth/AccountMenuButton.tsx) | 首字头像、用户名/角色、箭头和整行交互样式                    | 身份内容、菜单开合与退出流程        |
| DialogContent                                                 | 中央弹窗默认纵向滚动；侧面板采用自身主体滚动                 | 内容与业务操作，选择布局变体        |
| DropdownMenuItem                                              | default/destructive 语义样式；分组标题默认排版               | 菜单文案、行为、权限和禁用理由      |
| EmptyState                                                    | default/compact 密度与完整空态结构                           | 当前空态原因、重置/创建操作         |

新增通用视觉差异先扩展对应组件的语义变体，样板直接消费正式组件。className 用于外部宽度、集合排版或必要业务状态并不构成漂移；反复覆盖内部字号、底色、边界和间距时，应把缺失的完整组合归回组件。业务封面等独立造型可以完整包装基础组件。已批准并落地的 [KnowledgeCard](../pages/knowledge/KnowledgeCard.tsx) 复用员工卡片相同的 Card、CardContent 和 CardFooter；所有自建库使用同一通用知识图标，当前为用户认可的2号文件夹透明图片，已按要求移除拟人眼睛，按48px方形留位等比显示，名称、用途和文档数负责区分资源，不按库名推断分类插画。页面只传 library，由完整组件持有图文与整卡导航。

Tab 的源码守卫按 JSX 属性解析：TabsHeader/List/Trigger 可声明静态宽度及外部 margin（含响应式前缀），内部颜色、字号、边框、阴影、圆角和 padding 继续归共享组件；动态 className 需先改成可核查的放置方式或组件语义接口。该守卫仅覆盖这组明确规则，不替代视觉验收。

## 圆角覆盖范围与统一接入

改动前的扫描覆盖 182 个自有前端 TS、TSX 与 CSS 源文件，排除测试、生成文件与 SVG 原画目录：66 个文件包含 201 处圆角样式声明，另有 11 处原生单选 select。这是改动前快照，不将生成图形的曲线计作 UI 圆角。

| 场景                                   | 当前入口                     | 统一曲线接入方式                                               |
| -------------------------------------- | ---------------------------- | -------------------------------------------------------------- |
| 资源卡片、配置面板、集合外框           | Card 与命名圆角工具类        | 可通过统一形状令牌接入；边框和阴影沿同一曲线绘制               |
| 按钮、徽标、普通菜单项                 | 现有基础组件                 | 命名圆角工具类提供同一形状入口，保留各自半径                   |
| 输入、文本域、Select、搜索和输入组合   | 基础控件与 rounded-field     | 遵循 shadcn 普通圆角；字段半径 8px，输入组合保留容器半径       |
| 菜单、弹窗、Tooltip、问题预览浮层      | 对应正式浮层组件             | Portal 挂到 body 后读取根令牌；不依赖页面容器继承 corner-shape |
| 搜索、能力装配行、页面空态             | 共享组合组件                 | 通过基础控件与 Card 接入，不维护第二套边框                     |
| Markdown 代码块、表格与库浮层          | 官方样式接口与圆角别名       | 标准 radius 别名转接项目令牌，不修改第三方 JS                  |
| 消息气泡与单角变化                     | Bubble、命名半径与单角工具类 | 保留气泡尾部半径关系，整体形状入口由基础圆角提供               |
| 圆形状态点、开关滑块、圆形头像、加载环 | rounded-full                 | 保持圆形，不套用超椭圆矩形规则                                 |
| 角色圆拱、帮助气泡、登录场景           | 独立造型登记                 | 与常规表面分开验收，见下方例外                                 |

普通圆角使用 tiny、small、soft、control、panel、card、roomy 七个语义半径。原先 xs/sm/md/lg/xl/2xl/3xl 的相同数值已归入这些角色；应用代码使用语义名称，标准别名仅供第三方样式接入。图库控制按钮的零散 7px、代码区 10px 已分别收敛到 control、panel。

`--os-corner-shape` 是统一曲线入口，正式界面默认使用 **round 普通圆角**，与表单曲线一致。主要层级为控件 8px（control）、信息面板 12px（panel）、资源卡片与中央弹窗 16px（card）、桌面工作区外框 24px（roomy）；tiny / small / soft 用于小标记、菜单内项和气泡局部。统一的是用途层级与曲线，而不是把每种尺寸都设为同一个半径。资源卡片使用 1px 实色边界，字段保留自身输入边界。

命名圆角工具类同时声明半径和形状，Portal 读取根令牌；`rounded-field`、`rounded-full` 与 `rounded-none` 显式使用 round，保持表单、圆形和直角语义。文档站与 Markdown 渲染器的标准半径别名也映射到这些尺度，登录表单外框使用 card。

设计目录“排版与尺度”的曲线开关默认关闭，开启仅用于比较超椭圆，不改变正式主题。曲线或半径变更需检查两主题、窄屏、键盘焦点、嵌套背景、滚动裁切和 Portal；源码统一不代替实际浏览器验收。

## 独立造型与防回退检查

例外按文件和原因登记在 [spec.ts](spec.ts) 的 cornerShapeExceptions：员工卡片和配置页的圆拱、帮助气泡的不对称四角。圆形元素与 SVG 图形资源不在常规矩形表面替换范围内。

[surfaceContract.test.ts](surfaceContract.test.ts) 防止业务组件重新直写卡片边框与阴影、重新引入原生 select 或零散标准圆角类；新增自定义轮廓需要登记原因。集成测试直接渲染员工、技能详情和能力卡片，检查它们使用同一底座并保留操作；表单、Select 与搜索测试覆盖提交语义、ref、条件选项、禁用项和清除行为。
