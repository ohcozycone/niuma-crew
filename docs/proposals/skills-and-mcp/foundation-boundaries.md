本轮沿用现有模块化单体、对话入口、单宿主 Runner 和 Agent 循环。新增 `tools`、`files`、`sandboxes` 三个有独立资源所有权的模块，随对应阶段落地，不预建空目录。它们分别管理工具连接、持久文件、临时执行环境。

可以这样理解这条边界：对话层决定“这次工作用什么、最后交付什么”，执行宿主决定“现在还能不能做、预算够不够、进展如何保存”，Agent 运行层负责“模型下一步选哪个工具”，具体模块负责把操作真正完成。

## 1. 哪些地方复用，哪些地方增加职责

| 位置             | 本轮负责                                                                   | 不承担的职责                                                  |
| ---------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------- |
| `api`            | 工具连接、员工许可、文件上传下载的 HTTP 接口；沿用对话接受、停止和观察入口 | 不调用模型、运行命令或持有沙箱会话                            |
| `agents`         | 员工工具许可及其修订；与员工配置同事务保存，校验引用有效                   | 不管理工具连接秘密，不代替工具服务执行请求                    |
| `skills`         | 工作方法、内容和既有激活依据                                               | 不因方法文字提到某工具就授予权限                              |
| `conversations`  | 冻结本轮工具与输入；组合当前授权；最终正文、文件关联和终态的发布           | 不接管 MCP 协议或容器生命周期                                 |
| `execution`      | Run 调度、动作、预算、取消、恢复及工具结果记录                             | 不认识 Tavily、OpenSandbox、具体文件后端或业务场景            |
| `agent_runtime`  | 模型循环、官方文件工具装配、普通工具适配、SDK 事件转换；调用宿主控制接口   | 不取得 ORM Session、Actor、RunStore 或凭证库                  |
| 新增 `tools`     | 原生工具目录、MCP 连接及目录审核、秘密解析、MCP 实际请求与结果规范化       | 不拥有员工许可，不启动 Run，不发布对话                        |
| 新增 `files`     | 不可变文件字节与元数据、暂存、大小/哈希校验、受控读取和孤立文件清理        | 不拥有助手消息、Run 终态或沙箱工作副本                        |
| 新增 `sandboxes` | OpenSandbox 环境申请、资源记录、配额、停止与回收；提供已登记的环境句柄     | 不启动模型，不接受模型决定 Docker 参数，不调度第二套 Run 队列 |
| `bootstrap`      | 创建并注入上述服务、客户端和受控回调；启动维护、关闭资源                   | 不放业务判断，不通过包导入隐式启动服务                        |

现有 CI 专用链路在本轮保留。基础能力完成后再单独讨论迁移，不让普通工具接入依赖 CI 报告、Task/Goal 或工作流编辑器。

## 2. 拟议代码组织与依赖方向

下面只列职责发生变化的入口。协议、实现和持久化按实际需要拆文件，不要求每个模块照搬一套层级。

```text
backend/app/
├── api/                         # 现有 HTTP 入口，增加通用管理与文件接口
├── agents/                      # 增加工具许可的聚合保存与修订
├── conversations/               # 扩展准备、组合授权、发布
├── execution/                   # 扩展工具动作、结果、预算和恢复分类
├── agent_runtime/               # 装配工具、文件后端和 SDK 中间件
├── tools/                       # 新增：连接、目录、秘密和外部工具调用
│   ├── contracts.py             # 普通工具描述、调用与结果类型，无 ORM/SDK 导入
│   ├── service.py               # 连接管理、目录批准和当前修订检查
│   └── adapters/                # MCP 官方适配；原生实现按真实需要登记
├── files/                       # 新增：持久文件存储及受控读写
├── sandboxes/                   # 新增：环境资源服务及 OpenSandbox 生命周期适配
└── bootstrap.py                 # 组装具体实现与服务生命周期
```

依赖按以下规则组织：

1. `agents` 保存许可时调用 `tools` 的目录/连接校验；`tools` 不反向读取员工配置。运行时由 `conversations.authorization` 组合员工许可、连接修订、文件归属等规则，传入现有授权回调。
2. `execution` 继续只接收准备、授权、发布等受限回调。新增工具操作通过 `RuntimeControl` 协作，不允许 `agent_runtime` 绕过它直接写动作或预算。
3. `agent_runtime` 可以使用无 ORM 的工具契约和注入的调用接口。MCP SDK 对象留在工具适配器内部；Deep Agents 中间件和文件后端 SDK 对象留在 Agent 适配侧，均不传入 `execution`。
4. `files` 和 `sandboxes` 不导入 `conversations` 或 `execution` 的服务来反向驱动业务。需要判断 Run 是否仍活动、某文件是否被引用时，通过组装时注入的窄查询接口取得普通数据；资源操作不改写 Run 终态。
5. 跨模块原子保存由所属业务入口组织，参与者使用调用方提供的同一 Session；网络请求、文件大块传输和秘密解密均在写事务外。继续使用现有数据库设施，不新建全局 application/use_cases 层。

这延续了当前[导入边界测试](../../../backend/tests/test_runtime_boundaries.py)的方向。实施时补充新模块检查，避免把依赖藏进公共类型或回调闭包后形成反向业务调用。

## 3. 跨边界只传什么

以下名称表示拟议契约，不是已经存在的接口。连接与许可的详细字段继续以[目标字段字典](../agent-capabilities/data.md#工具定义连接与装配授权)为唯一维护位置；这里定义协作语义。

| 契约             | 必要信息                                                                                     | 提供方 → 使用方                          |
| ---------------- | -------------------------------------------------------------------------------------------- | ---------------------------------------- |
| `ToolBinding`    | 工具稳定标识、来源连接、名称、描述/schema 摘要、连接/目录/许可修订、有效范围及预算、恢复类别 | 准备过程 → Agent 装配及宿主授权          |
| `ToolInvocation` | 本轮绑定标识、模型调用标识、规范化参数及摘要、所属模型动作                                   | Agent 工具入口 → `RuntimeControl`        |
| 工具执行许可     | 宿主保存成功的动作标识、本次有效限制、截止时间；只在本次调用内有效                           | `RuntimeControl` → 工具调用入口          |
| `ToolOutcome`    | 成功/失败/未知、受限摘要、结构化结果、来源与持久结果引用、确定的用量                         | 工具调用入口 → 宿主记录及模型            |
| `FileRef`        | 文件 ID、内容哈希、大小、媒体类型；已检查的本轮归属                                          | 文件服务/准备过程 → 工作区与发布过程     |
| 沙箱资源引用     | 资源申请 ID、归属 Run、服务身份、远端 ID、期限与清理状态；不含管理密钥                       | 沙箱服务 → 受信文件/命令适配器及维护任务 |

工具的实际 JSON 参数用于授权校验，日志只保存必要的安全摘要。模型只能提交工具参数，不能自带绑定、执行许可、路径权限或连接修订来覆盖宿主捕获值。执行许可是内部协作数据，不是可交给模型再次使用的令牌。

SDK 在这里指已经安装或将安装的开发库，例如 LangChain、Deep Agents 和 OpenSandbox Python 库。“SDK 适配”就是把这些库的调用和返回值接到上述契约上，不表示平台已经内置了联网服务或隔离环境。

### 一次调用只有一个记账入口

在现有 `RuntimeControl` 上增加专门的工具开始/完成及已存结果读取能力；可以采用 `begin_tool(invocation)`、`complete_tool(permit, outcome)` 这样的接口，具体签名由实现中的类型维护，不把通用 `start` 的任意字典当最终授权契约。

`begin_tool` 在一个短事务内完成当前身份与许可复核、预算扣减和动作创建。保存失败时不执行工具。真正调用由 Agent 侧工具入口在事务外触发：MCP 转给 `tools` 适配器，文件/命令转给已经装配的受控后端。完成后，工具入口先经注入的文件接口保存长来源等大内容，再调用宿主完成接口，将有界结果、文件引用和动作完成状态一起提交，最后才将工具消息交回模型。工具适配器不直接写执行账本。

技能读取与普通工具都经过这一入口，但按操作归属分别处理：`/skills/` 的读取沿用被冻结技能的许可与完整正文激活规则；普通文件按独立文件工具许可校验。不能把所有 `read_file` 都当作技能激活，也不能给同一调用重复扣两次通用工具预算。

## 4. 数据与状态由谁维护

| 数据或资源                                     | 唯一写入所有者                     | 关键边界                                                       |
| ---------------------------------------------- | ---------------------------------- | -------------------------------------------------------------- |
| `tool_connections`、候选和已批准目录、密文凭证 | `tools`                            | 目录发现不自动批准；凭证只在受信调用侧解析                     |
| `agent_tool_grants`、员工配置修订              | `agents`                           | 校验连接和目录后与员工修订同事务保存；Skill 不代授权限         |
| Run 冻结依据、当前组合授权                     | `conversations`                    | 保存非秘密引用与有效值；旧 Run 不跟随新配置换身份              |
| Run、动作、预算、工具结果记录                  | `execution`                        | 状态与计数原子保存；长内容用引用，不把 checkpoint 当业务结果库 |
| 文件字节、不可变元数据、暂存状态               | `files`                            | 字节先可靠保存，再提交元数据；未引用字节可清理                 |
| 用户输入文件、助手输出文件与消息的关联         | `conversations`                    | 与输入接受或最终发布同事务提交；发布前的文件不能冒充已交付     |
| 沙箱申请、实际远端身份、期限与清理债务         | `sandboxes`                        | 先登记申请再创建；销毁失败可持续重试，不丢失远端归属           |
| 临时工作目录、运行中的进程                     | 沙箱后端                           | 不作为持久交付；不得跨 Run 复用                                |
| SDK checkpoint                                 | `agent_runtime` 的 checkpoint 适配 | 用于可验证恢复；不替代文件库、工具结果和消息发布               |

首版持久文件使用部署者配置的受控数据目录，存放在沙箱以外，由文件服务生成存储引用，不接受用户给宿主绝对路径。与应用数据库一起纳入备份。以后替换为对象存储不应改变文件 ID、授权或消息关联契约。

文件按“保存字节 → 提交元数据 → 建立业务引用”处理跨存储事务。最终发布前，文件服务完成输出取回、大小/哈希校验及暂存；发布事务只核对暂存结果并关联消息，不在事务里下载沙箱文件。事务回滚时不出现指向缺失字节的已发布回复，剩余未引用文件由保留策略清理。

上传时验证上传者及额度；选择输入和下载时由对话层检查当前会话读权、所选文件归属，文件服务再按受信引用读取。不能仅凭知道文件 ID 下载，也不让文件服务反向调用对话业务。网页原始材料也由文件服务保存，`execution` 记录查询、取得时间、逐页状态及来源引用；Agent 文件后端只提供本轮只读投影。

## 5. 搜索、文件、代码分别怎么走

### 5.1 搜索与网页

1. 管理员配置 MCP 连接并批准候选目录；员工只获准其中的搜索或提取工具。
2. 接受 Run 时从本地已批准目录冻结绑定，不在接受事务里等待外网。
3. 先通过 `begin_tool` 原子复核当前身份、修订和预算，保存动作，再由工具适配器在事务外复查远端目录。发现失败或目录失配也结束这次动作并保留已消耗预算，不能在记账前先发出网络请求。
4. 目录一致后，通过宿主对本次许可的复核入口检查网络等待期间是否已撤权或取消；不重复创建动作或扣预算。按冻结的连接身份解析秘密并实际调用，不能透明切换到新凭证。检查与请求之间仍有不可消除的外部竞态；请求已发出后不承诺撤回。
5. 工具适配器将 Tavily 等服务返回规范化；工具入口经文件接口保存长正文，宿主完成接口保存有界结果与引用，之后供 `/sources/` 分段读取。源服务错误不能由一段模型回答替代为成功。

MCP 会话的打开/关闭是 `tools` 的资源职责；Run 取消通过调用接口传递取消信号。搜索服务凭证留在工具适配侧，不进入模型参数、checkpoint 或沙箱环境。

### 5.2 文件与技能读取

仍只装配一套 Deep Agents 官方文件工具。Agent 层先按路径解析操作归属，再申请宿主许可；后端再次强制检查路径、真实归属和读写权限，不能只在工具说明里写限制。

| 文件区域                   | 持久来源/工作副本                | 读写和安全归属                                           |
| -------------------------- | -------------------------------- | -------------------------------------------------------- |
| `/skills/`                 | 本轮已冻结技能内容               | 技能读取规则；完整正文成功读取才激活                     |
| `/sources/`                | 本轮取得资料的只读投影           | 来源引用及受控后端；工具返回文字不能更改许可             |
| `/inputs/`                 | 已选持久文件的只读投影或沙箱副本 | 文件归属、路径校验；有代码能力时还须在沙箱系统层只读     |
| `/workspace/`、`/outputs/` | 虚拟文本后端或本 Run 独占沙箱    | 文件工具许可；沙箱后端再校验真实路径、符号链接和资源限额 |

选择虚拟还是沙箱工作区在接受时固定。只有文本操作的阶段可以使用 StateBackend；一旦本轮提供 `execute`，文件和命令必须从首次工作区访问起使用同一沙箱。普通文件工具不新增第二套 `/skills/` 读取实现；替换现有“非技能工具全部拒绝”的中间件分支，同时保留技能正文完整读取约束。

### 5.3 沙箱与代码执行

模型只看到获准的文件操作和 `execute`。创建、停止、销毁是平台管理资源的操作，不作为模型工具公开，也不让模型挑选 Docker runtime、管理端点或宿主挂载。

1. Agent 装配阶段创建本地后端代理，不偷偷启动远端环境。第一次需要沙箱的操作取得宿主工具许可后，代理调用 `sandboxes` 申请/取得本 Run 环境；内部创建消耗资源配额，不额外伪造一条模型工具调用。
2. `sandboxes` 校验被冻结执行配置、当前部署就绪及资源配额，先保存申请，再通过 OpenSandbox 生命周期接口创建；保存远端 ID 和归属，装入获准输入。不同线程或重复请求只能取得同一份申请的明确结果，创建结果未知时先核查，不再盲建。
3. 受信适配器将已登记环境接给 Deep Agents 后端，`execute` 与文件工具共享它。第三方后端若会隐式创建/重建环境，须改为使用受控创建入口或已登记环境，不能绕过资源记录。
4. 命令结束后取得退出码、有界日志和输出清单；产物经文件服务保存。`execute` 成功只代表该命令完成，不直接将 Run 标为成功。
5. 发布或退出前停止遗留工作负载，保存回收责任；沙箱服务执行销毁并确认。产物未取回时不能先销毁再尝试收集。

生命周期 SDK 适配归 `sandboxes`；与 Deep Agents 协议相关的文件/命令后端装配归 `agent_runtime` 适配侧。二者共享同一已登记环境，不各自维护一份远端 ID。同步 SDK 通过受控异步桥接使用，取消等待不等于底层线程和进程已经停止。

具体 Linux、Docker、gVisor、网络、配额和开源交付分工只在[自托管附录](opensandbox-self-hosted.md)详细维护。部署选择已经确定，目标主机上的实际隔离能力仍须验收。

## 6. 取消、失败和重启的分工

| 情况                         | 谁处理                                  | 必须得到的结果                                                         |
| ---------------------------- | --------------------------------------- | ---------------------------------------------------------------------- |
| 许可被撤销、员工或连接停用   | 对话组合授权 + 工具开始事务             | 阻止后续调用；已经发出的请求如实记录，不能声称撤回                     |
| 工具动作或预算保存失败       | `execution`                             | 不发起工具操作，不创建沙箱                                             |
| 工具超时、用户取消           | 执行宿主发停止信号；适配器中止请求/进程 | 等待有界停止；拿不到确定结果记为未知；始终保留清理责任                 |
| 工具已完成，但结果未可靠保存 | `execution` + 结果存储                  | 不向模型交付为已确认完成；副作用可能发生时不自动再执行                 |
| 输出取回或最终发布失败       | 文件服务 + 对话发布器                   | 不发布成功回复；不出现可下载的虚假输出；暂存文件可清理                 |
| 沙箱销毁失败                 | `sandboxes` 维护任务                    | 保留资源身份、到期时间、失败原因，重试并可观察；达到资源上限时阻止新建 |
| 应用退出或重启               | 现有 Runner 恢复 Run；沙箱服务恢复清理  | 根据持久记录区分活动/遗留资源；不凭内存推断所有权，不误删其他部署环境  |

沙箱维护任务只回收已经登记的资源，不是一套新业务调度器。它在应用生命周期启动时扫描，运行时周期重试，关机时有界清理。撤权或登录失效会阻止新业务操作，但不应阻断平台停止进程、回收自有环境。输出尚未发布时，撤权后不继续把它包装成成功交付。

发布前必须完成必要输出保存、停止工作负载及持久登记清理责任。删除环境失败可以形成独立的待清理状态，不回滚已经可靠发布的结果；运营记录应显示残留，不能显示为“全部已释放”。

首版恢复采用明确的能力范围：

- 旧 v2 普通聊天保留现有可验证恢复路径，缺少新工具字段不能被解释为自动授权或一律不兼容。
- 新的只读工具 Run，仅在调用指纹、连接/目录依据、已存结果及 checkpoint 对应关系可验证且当前仍有权时复用结果。允许重新尝试的只读操作重新申请预算。
- 采用沙箱工作区的 Run 在进程重启后中断并回收；不恢复旧容器继续执行。涉及 StateBackend 写入的 Run 首版也采用中断策略，直到能证明文件状态与工具消息一致恢复后再放开。
- 不再按工具名字 `read_file` 决定能否重试。恢复类别来自受信工具定义与本次操作；未知命令和外部写入不自动重放。

## 7. 前端与未来扩展的边界

本轮只需在现有管理/对话区域提供工具连接及测试状态、员工工具许可、上传/选择输入、输出下载、真实工具步骤及来源。状态以宿主记录为准；工具返回 HTML 或模型说“已完成”不能触发任意页面逻辑。

沙箱部署参数放部署配置和运维指引，不做给模型填写的动态表单。未就绪时说明缺少环境并关闭相应能力，搜索和普通文件不因此整体失效。

| 后续新增内容                           | 通常怎么接                                 | 是否需要改平台代码                                  |
| -------------------------------------- | ------------------------------------------ | --------------------------------------------------- |
| 同一受支持协议下的新 MCP 搜索/业务工具 | 新建连接、审核工具目录、授予明确许可       | 不改 Agent 循环；无法由通用范围规则约束时需受信适配 |
| 使用已有工具的新工作方法               | 编写 Skill 内容并配置已有许可              | 不因新增方法修改后端流程                            |
| 新的原生基础工具                       | 增加受信实现和登记，沿用调用/授权/记录契约 | 需要代码与验证；不为它另造 Runner                   |
| 新沙箱供应商或文件存储服务             | 实现已有资源/存储接口并验证替换            | 需要适配；对话、消息和工具许可语义应可复用          |
| 专门按钮、输入表单、报告或固定流程     | 之后确定产品组织方案                       | 本轮不承诺任意界面都能零代码生成                    |

这里降低的是接入重复成本，不是承诺任意工具和任意业务都零代码。内置文件/命令是平台基础设施；外部 MCP 是配置式接入；业务方法先复用已有能力。无需现在引入可上传任意后端代码的插件执行框架。

## 8. 如何分批实施并集中 review

设计可以一次 review，实施仍按主方案 T0–T4 逐批验证，每批有能观察到的完整结果。

| 阶段 | 主要修改位置                                                          | 必须守住的边界                                                          |
| ---- | --------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| T0   | `tools`、`agents`、对话准备/授权、RuntimeControl/RunStore、工具中间件 | 原生/MCP 共用入口；先原子记账再调用；SDK 不进入执行核心                 |
| T1   | MCP 适配、最小来源保存与只读文件投影、步骤展示                        | 一个真实搜索/提取链路；秘密隔离；目录变化和大小限制；不等待全套附件功能 |
| T2   | 完整 `files`、对话附件关联、上传下载、文件后端                        | 文件归属、先存字节再引用、发布事务、沙箱外持久保存                      |
| T3   | `sandboxes`、bootstrap 维护、部署模板和就绪检查                       | 实际 runsc、申请可追踪、资源受限、取消与遗留环境回收                    |
| T4   | Deep Agents 沙箱后端、`execute`、产物收集、恢复分类                   | 文件与命令同环境；命令不冒充 Run 成功；未知执行不自动重放               |

T1 的来源存储属于 `files` 的最小实现；T2 在同一模块补附件能力，不另建一套来源存储。T3 在接入 Agent 前用受控技术冒烟验证环境，T4 再验证真实模型调用。所有表结构走正式迁移，不能以启动时建表代替升级。

实施检查至少覆盖：

1. 扩展现有导入边界测试，阻止 Agent 访问业务数据库/身份，阻止执行宿主导入具体工具 SDK，阻止资源模块反向驱动对话。
2. 真实 SQLite 竞争/故障测试：撤权发生于目录发现期间、并发耗尽预算、记录失败时零外部调用、结果保存失败时不继续交付。
3. 工具与文件测试：同名工具消歧、普通读取不激活技能、越界/符号链接/跨会话拒绝、来源和附件刷新后仍可查询。
4. 沙箱测试：创建成功而登记中断、同步 SDK 取消、进程遗留、输出收集失败、销毁失败、启动清理和租约到期；确认不会删除其他部署资源。
5. 兼容测试：旧 v2 聊天恢复、已完成结果展示、新写操作/代码 Run 的中断策略，继续验证现有 CI 链路。
6. 目标 Linux 上真实验证隔离、网络和资源限制；实际搜索服务与命令冒烟单独记录。文档检查或假上游不能代替这些验收。

本轮 review 只需决定基础能力范围、模块归属、跨边界调用、数据/资源生命周期和实施顺序是否成立。SDK 锁定版本、目标镜像、主机可达性与限额实测属于实施验证项，不把未验证结果写成已经具备的能力。
