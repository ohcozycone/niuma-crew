# 内置网页访问

## 范围与边界

基于本机 main `5ba3dc11` 实施。`web_search` 通过博查发现公开页面，`web_fetch` 通过 Jina Reader 读取公开页面，两项能力共用员工级 `allow_web_access`，缺省关闭。配置由管理员在员工装配中保存；服务密钥仅由服务器环境配置，不进入员工响应、执行快照或日志。

它们是 `runtime/tools` 的内置工具，不创建 MCP 服务、连接或许可，不加入 MCP 按需发现目录。既有 MCP 路径仍按用户批准的实际目录、连接和工具许可执行，不猜测服务商名称或专有返回字段。历史 MCP 数据不转换、不删除。

## 执行契约

- 只有员工授权与服务配置同时满足时捕获工具。每次模型调用、工具执行、结果读取与恢复继续核验当前员工授权；关闭开关使旧工具结果和旧线程能力失效。
- 搜索结果只标为摘要；网页正文另有来源地址、获取时间和截断标记。不把搜索摘要当成已读取正文，也不把供应商 200 状态当成目标网页成功。
- 网络调用有超时、响应字节上限，无隐式重试；失败作为明确的失败工具结果。取消立即中止异步网络等待；发布前再次授权。
- 只读取公网 HTTP(S) 地址，拒绝用户凭据、私网/保留地址、内网 DNS、查询字符串和 fragment 等可能携带敏感数据的地址。公开查询参数首版不支持，避免把分享令牌或私人搜索内容发送给第三方。
- 所有搜索和网页内容是不可信资料，不能授予权限、改变任务或触发额外操作。内部资料及密钥不得复制到外部搜索。

## 配置与验证

使用博查 Web Search JSON API 和 Jina Reader JSON 输出。只运行假 HTTP/假 DNS 的契约测试，不使用真实密钥，不修改开发数据库。迁移只增加缺省关闭的员工列，保留原数据。具体供应商请求与验证结果在实施记录维护。

## 供应商契约与信任边界

- [博查官方 MCP 实现](https://github.com/Bocha-Labs/bocha-search-mcp/blob/master/src/bocha_search_mcp/server.py)使用 `https://api.bocha.cn/v1/web-search`。通过 POST JSON 发送 query/count/freshness/summary，Bearer 密钥只发该官方域。兼容官方另一域 `api.bochaai.com`，拒绝任意配置地址。
- [Jina Reader 官方说明](https://github.com/jina-ai/reader)支持 POST `https://r.jina.ai/` JSON url，Accept JSON 输出。使用 `X-Respond-With: markdown`、`X-No-Cache: true`、`X-Base: final`，并以 `X-Assert-Status-Code: 200` 要求目标页 HTTP 200。
- [Jina 官方选项定义](https://github.com/jina-ai/reader/blob/main/src/dto/crawler-options.ts)区分外层 API 状态与目标状态；模型不把 HTTP 200 或 code 200 自行推断为目标状态证明。Reader 拒绝目标状态时工具返回失败，不暴露供应商错误正文。
- Jina 自身会处理目标重定向，平台不能控制其逐跳网络解析。平台只保证本方提交前拒绝不安全地址、不传 cookies/用户凭据/代理设置、对返回的最终地址再次验证；这不是 Jina 全部内部请求的 SSRF 保证。验证码、内容完整性和网页真实性仍不能由状态码证明。
- 截断只表示本次最多返回指定字符数，不表示已读全文。结果正文内的链接和指令不自动触发后续请求。语义上的隐私不能被词法检测完全识别，因此模型必须遵循仅公开信息的发送规则，管理员只应对适合外部资料检索的员工授权。
