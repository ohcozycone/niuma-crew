# 可选独立反向代理

当前默认 `make start` 仍由单个 Uvicorn 同源交付页面与 API。这里的 [Nginx 模板](nginx.conf.example)是可选配置，没有安装、启动或替换用户机器上的服务；本机未安装 Nginx/Caddy，语法检查与真实停应用验收尚未执行。配置文件存在不表示独立停机页面已部署。

## 接入

1. 在仓库根执行 `make build`，确认 `frontend/dist/failures/` 含 404、500、502、503、504 HTML 及六张 PNG。文档使用同源主题与公开文案，脚本和 React 均不可用时仍保留文字和链接。
2. 将模板复制到自己的配置位置，替换全部 `/ABSOLUTE/PATH`。示例代理监听 `127.0.0.1:3000`，后端独立监听 `127.0.0.1:8000`；避免再运行同端口 `make start`。本机可用 `make dev-backend` 验证，正式服务应使用单个非 reload 的 `app.main:app` Uvicorn 进程和 `--no-proxy-headers`。
3. 对自己复制的文件执行 `nginx -t -c /绝对路径/nginx.conf`，检查成功后按自己的服务管理方式启动代理。模板不管理进程、数据库迁移、证书或 HTTPS；公网部署另配 TLS、可信站点和 Secure Cookie。后端 `AUTH_ALLOWED_ORIGINS` 必须包含浏览器实际访问的代理来源。
4. 后端必须保持单个 worker；共享数据库的 Runner 不允许以增加 worker 扩容。代理保留原始 Origin、Host 和 Cookie，清除不可信转发头，不会伪造用户地址来影响登录限流。

## 交付边界

已知业务页面与正常资源继续交给 FastAPI，保留其压缩、缓存、ETag、GET/HEAD 和真实 404。应用返回的 JSON 错误、OAuth 303、SSE 不被代理错误页替换，SSE 禁用缓冲。仅代理自身的连接/等待错误使用本地静态 502/503/504；API 与资源失败使用 JSON，带真实状态与请求关联 ID。没有维护开关或维护原因，不展示“正在维护”。

模板对缺少 Fetch Metadata 的旧客户端使用无扩展名安全路径和 HTML Accept 降级；路径识别采用保守 ASCII 范围，编码路径在应用不可达时可能得到 JSON。正常应用仍由 FastAPI 的完整识别规则处理。错误文档和图片来自代理本地构建目录，图片缺失也保留文字按钮。浏览器 DNS/TLS、代理自身或主机整体不可达时，本站无法提供首访错误页。

访问日志默认关闭；Linux 模板将错误日志写入 `/dev/null`。上游连接失败的错误日志也可能包含带 OAuth code 的完整请求行，关闭访问日志或提高错误日志级别都不能消除该风险。需要持久化时，先接入安全过滤，移除请求行、查询参数及凭据，再配置受控的保存位置与保留期限。当前默认不落盘日志，不代表代理可观测性已经完备。

代理只接受符合 `[A-Za-z0-9._-]{1,64}` 的诊断 ID，其余生成新值；后端再次校验。ID 不承担认证、Run 身份或业务幂等。

## 安装代理后的隔离验收

1. 使用独立端口和复制配置启动代理与后端，验证三个深链、API 正常响应、正常资源 gzip/Brotli、ETag/304、HEAD、405/Allow；确认后端语义 503 与 OAuth 303 没有变成 HTML。
2. 在隔离环境停止后端，保持代理运行。用带 `Sec-Fetch-Dest: document` 的 GET/HEAD 访问业务路径，确认真实 502、本地 HTML、无 HEAD 正文、图片仍可读取；API、资源路径与非文档 Fetch Destination 必须得到 JSON 502。
3. 以受控假上游验证代理 503/504，检查真实状态、`no-store`、`nosniff`、关联 ID。普通 HTTP 错误不表示写入一定未生效，页面只能先核对提交结果。
4. 恢复后端，验证原路径可重新读取，SSE 首个事件及时到达、断开订阅不取消运行。清理隔离进程，不停用户已有服务。

上述验收需要已安装的真实代理；当前仅交付模板和可执行步骤，不能据此记为通过。
