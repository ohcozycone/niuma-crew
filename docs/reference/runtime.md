# 当前运行、步骤与读取

本页维护已实施的执行契约。公开操作围绕对话与回复，内部 Run 负责一次处理尝试。字段由[公开读取结构](../../backend/app/conversations/schemas.py)、[内部记录](../../backend/app/execution/models.py)和迁移维护。

## 接受、快照与幂等

接受在一个短事务中保存对话、用户输入、空助手 Message、Run、冻结输入和绑定。client_request_id 的唯一范围是发起用户和操作；同键同摘要返回原记录的当前读取结果，不同内容返回冲突。重放先于当前容量和配置检查。

接受时固定岗位、规则、方法内容、装配身份、模型修订、输入上下文和预算；启动与动作前仍复核当前会话、员工启停、模型装配/修订、已激活方法和本次资源。固定内容不意味着权限也固定。

共享准备属于 conversations/preparation；请求服务负责请求键、准确目标和原子接受。执行宿主只得到已经准备的运行函数及授权、发布回调。

## checkpoint、历史与恢复

历史和后续上下文直接读取 Message，不访问 SDK。每个 Run 使用自己的 checkpoint，恢复原 Run 的冻结输入、开始时间、已用预算、已激活动作与累计未知用量。

可信且待继续的普通 Agent 存档可继续；可信完成标记且 Run 仍活动时只补发布，不再调用模型。缺失、不兼容或不支持恢复的存档不自动重放，收束为 interrupted。已终止 Run 不因存档有完整文字而改写。

SDK 提交与业务提交分开：SDK 内部完成只是候选依据，正式成功以业务事务为准。未完成模型请求可能重发并重复计费，未报告的用量保持未知。当前不提供多主机租约或通用外部副作用重放保证。

## 实际 SDK 与预算

普通 Agent 使用 LangChain、Deep Agents 文件工具与 SQLite checkpoint；原生/MCP 工具、文件与沙箱已接入，范围、预算、来源和部署条件见[基础工具契约](agent-tools.md)。新快照版本为 3，保留旧 v2 兼容；原生写入、沙箱和首版外部工具 Run 不在重启后自动重放。

模型次数、方法读取次数、上下文字节、可见正文/思考字节、输出 token、总时限和图步数各自受限。图步数不等于模型次数。模型动作开始前，在同一写事务复核许可、扣减次数并保存动作；失败时不发出外部调用。

## 本轮允许与实际使用

接受时捕获可用方法，显式选择可预加载，其他按需读取。装配重建即使复用相同 ID 也通过 created_at/revision 被识别。已激活方法集合从成功动作恢复；授权检查合并既往与本次申请，发布前重读持久动作。

一次模型的工具请求只是意图。工具实际开始、成功返回及方法激活分别记录；失败或未知结果不冒充已经加载。

## 外部读取证据与长结果

MCP 返回的原始结果持久保存。模型收到有界预览、`result_id` 和字符游标，可用派生的 `read_tool_result` 继续读取本轮结果；不必为了读取刚返回的数据另装文件工具。该入口只接受本 Run 的结果编号，保留来源工具的绑定并在每次读取前复核当前许可，不能读取另一轮、附件或任意宿主路径。读取独立记账并共享 Run 总预算，不重新执行外部业务操作。源文件路径的 `read_file` 授权仍单独检查。

对于明确“读取/提取/阅读”并带目标 URL 的输入，发布前核对成功的结构化提取来源以及模型收到的结果范围。零调用、错误目标、仅搜索摘要或长结果尚未读完时，以 `external_read_unverified` 准确失败，不发布“已经读取”的候选回答；普通 URL 格式讨论不触发此规则。此首版识别是保守的明确请求规则，不是任意任务的自然语言验收器；支持常见 `results[].raw_content` 及 Tavily Extract 的提取结构，其他格式需要补结果语义映射。超过预算的长页面应缩小范围，不能假装完整处理。

“取得提取文本”不保证网页内容完整、未被登录页替代或解释无误。`full_text` 不因非空文本而成立。页面分别展示提取文本与搜索摘要，实际调用和内容语义正确性分开验证。上述检查通过不能代替真实模型和外部服务行为评测。

## 流式回答与思考展示

SDK 片段在 agent_runtime/streaming 解析、拼接和识别工具轮；普通 ContentUpdate 跨过边界。RunControl 负责缓冲与保存频率，Store 只保存普通字段。

页面只观察已提交内容，不直接转发未持久化 token。完整响应覆盖暂存片段，结束后的迟到更新不能覆盖。思考按 UTF-8 字节截断并保留截断标记，恢复时仍占原预算。

助手视图 content 已由服务端选定：活动时为当前可见草稿，成功为 Message 的完整正文，其他终态为允许的部分正文或空串。前端不再选择模型轮，也不把工具正文当聊天回复。

## 前端与读取模型

首屏 snapshot 在真实 SQLite 读事务中组合当前摘要、员工安全摘要、连续消息页与提问摘要。接受、核对、历史、单回复与 SSE 共用助手视图。对话摘要的 version 来自 Conversation.revision，回复 version 来自 Run.revision。

GET、停止和 SSE 的 ResponseSnapshot 同时返回当前对话摘要与回复。前端分别合并两个版本；晚到的旧回复或旧首屏不能回退活动目标。公开标识 response_id 就是助手 Message ID，没有新 Response 表。can_retry 同时考虑当前操作权限、回复状态和输入是否仍受支持；前端不根据失败状态自行开放退役记录的重试。

## 取消、故障与历史

排队停止可直接提交取消并释放占用；运行停止先记 cancelling，由看护关闭执行。显式停止精确指向回复，迟到请求不能停止下一次工作。SSE 断线只释放观察连接。

取消优先于迟到成功。成功正文、输出文件关联、Run 终态和占用在一次发布事务提交；失败全部回滚。普通故障只保留执行器明确给出的允许片段，不能兜底取最后工具轮。撤权不增加可见正文。

发布或过程存储失败时停止后续动作并使宿主降级；存储恢复后按既有 persistence_unavailable 失败策略收束，不承诺同进程自动重试候选。重启补发布只适用于仍活动且完成存档可信的原 Run。

## CI 与后续知识能力

CI 对话诊断试验已退役。专用执行、报告/反馈及配置入口移除；保留的旧消息和共享 Run 只读，can_retry=false，不能被当作普通工作恢复或重试。新普通消息、通用 MCP 与 GitHub 登录继续使用各自入口，见[退役说明](ci-diagnosis/README.md)。

知识、Task、Goal、多引擎和业务工作流引擎尚未实现，不能从当前目录或 SDK 能力推断为已开放。未来新增业务来源先定义自己的接受/发布，再比较确有必要的共享。

## 模块时序调度

页面 → 对话 router → ConversationService → 准备/准入/内容写入 → queued。

调度器 → 协调器 → 共享授权与冻结准备 → Agent → RuntimeControl 的动作与过程保存 → 候选 → PublishRun 原子发布。

页面 → snapshot/历史/回复/SSE → 同一查询实现读取已保存状态。实现入口见[后端架构](../architecture/backend.md)，实际学习顺序见[观测流程](../learning/observing-runtime.md)。
