# 前端设计

前端按页面和交互组织代码。页面处理本次输入，共享数据层维护当前身份下的服务端记录副本，后端决定权限、业务事实与实际执行。

## 目录结构

以下列出主要入口与业务目录，省略就近维护的测试文件、说明和图。前端沿用页面、组件与状态组织方式，后端的 `applications/`、`runtime/` 和 `resources/` 不直接复制到前端。

```text
frontend/
├── index.html                   # 网页入口
├── vite.config.ts               # 开发服务与生产构建
├── package.json                 # 依赖、脚本和检查命令
├── public/                      # 图片、字体等静态资源
├── scripts/                     # 主题、品牌等资源生成与构建脚本
└── src/
    ├── main.tsx                 # 启动应用、加载全局样式与主题
    ├── router.tsx               # 路由、页面布局和访问边界
    ├── Layout.tsx               # 工作台外壳、身份数据范围与编辑保护
    ├── globals.css              # 样式入口与全局基础样式
    ├── pages/                   # 路由页面及其私有组件、逻辑和测试

    │   ├── organization-rules/  # 全员规范
    │   ├── signin/              # 登录
    │   ├── help/                # 使用帮助
    │   ├── avatars/             # 头像展示
    │   └── design-system/       # 真实组件与交互示例
    ├── components/              # 跨页面复用的控件和业务组件
    │   ├── ui/                  # 基础交互库适配与统一外观
    │   ├── common/              # 通用布局、阅读与反馈
    │   ├── auth/                # 身份提示与访问反馈
    │   ├── avatars/             # 头像展示与选择

    ├── state/                   # 有明确共享范围与生命周期的数据
    │   ├── workspace/           # 当前身份的数据实例、配置摘要及跨业务更新关系
    │   ├── shared/              # 请求、缓存、订阅与刷新基础
```

只服务一个页面的组件和逻辑留在对应页面目录；有真实跨页面复用后再提取。基础控件不承担业务请求，通信与普通类型不反向依赖页面。文档站是独立工程，复用这里的视觉定义与真实示例。

## 依赖与状态边界

| 调用方         | 可以使用                                        | 保持的边界                                               |
| -------------- | ----------------------------------------------- | -------------------------------------------------------- |
| 入口与路由     | 页面入口、布局与共享能力                        | 负责挂载和访问边界，不承接具体页面业务                   |
| 业务页面       | 同一业务的私有代码、共享组件、状态、Hook 和通信 | 不直接导入其他业务页面的私有实现                         |
| 共享组件       | 共享组件、状态、Hook、通信和普通类型            | 不反向依赖页面，基础 `ui/` 控件不承担业务请求            |
| 共享状态       | 状态基础、Hook、通信和普通类型                  | 不依赖页面或展示组件；跨业务刷新由 `workspace/` 明确组合 |
| 通信与普通类型 | `lib/` 内必要的普通能力                         | 不依赖 React 组件、页面和状态实例                        |
| 设计示例       | 共享能力及业务显式导出的示例入口                | 正式页面不反向导入示例实现                               |

这些依赖由[ESLint 边界规则](../../frontend/eslint.config.mjs)约束。边界规则检查允许的模块引用；具体请求顺序、订阅和错误恢复仍由各业务状态与行为测试验证。

共享配置表单位于 `components/configuration/`；导航配置摘要由 `state/workspace/workspaceData.ts` 读取，配置保存仍由对应业务操作负责。

前端保存当前界面的草稿与已确认记录副本，后端应用和资源模块拥有长期业务事实。页面发送命令后观察已提交状态，不能把组件卸载当成取消执行，也不从界面状态推断后端事务已经成功。

## 页面怎样使用和保存数据

地址保存筛选、分页和可返回的位置，编辑器保存未提交草稿，共享数据层保存服务端已经确认的记录。例如员工编辑中的岗位、技能、工具和知识属于同一份草稿，弹层完成只修改草稿，主保存统一提交；冲突时保留输入供核对。

共享数据采用固定实例，通过上下文传递，组件按记录或查询订阅变化。一次员工收藏可以同步到列表和侧栏，而正文片段更新只通知相关消息。写入由数据所有者协调，并刷新受影响的查询，页面不各自维护一份共享结果。

身份切换会重建数据范围并忽略旧请求结果；主题偏好独立保留。上传队列属于身份范围，站内切页不取消上传。请求竞争、缓存与清理的细节统一见[共享数据实现](../../frontend/src/state/README.md)。

## 对话怎样提交和持续更新

对话模块用一个交互范围组织发送确认、历史与回复观察，消息组件只订阅自身内容。发送结果未知时核对原请求，观察断线时重新读取状态；后台执行不随消息组件卸载而结束。

消息顺序与高频正文分别通知，减少整段对话的重复更新。显式停止才提交取消命令，错误与恢复由原状态所有者处理，展示组件不自动重发工作。具体协调见[对话实现](../../frontend/src/pages/conversations/README.md)。

页面和业务组件组合现有控件，视觉值来自统一主题；加载反馈表达等待，不接管请求与权限。代码组织、依赖和检查要求见[前端手册](../engineering/frontend.md)。
