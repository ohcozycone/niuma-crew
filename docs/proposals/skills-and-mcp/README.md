## 1. 目标与依据

技能库管理标准 Agent Skill，MCP 独立接入工具；普通对话与明确选择技能共用一个 Agent 执行循环。CI 诊断作为使用该机制的示例，新增技能通常只增加内容和配置，不新增业务路由、永久模式或专用 Agent 循环。

2026-10-27 范围更新：基础能力接线已有实现，技能库组织与标准包管理按[官方复用复审版方案](unified-capability-library.md)推进；工作流产品形态和 CI 迁移仍后续单独处理。降低制作成本是保留的方向，不等于现在就建设配置化表单、固定步骤或报告系统；[后续讨论入口](../configurable-workflows.md)不作为工具接入前置。

明确需求是标准兼容、可持续扩展、简单使用和企业收益。首批行业、客户需求频率、付费意愿和差异化效果尚未验证，另见定位文档；它们不作为已确定需求写入底层结构。本次交付是设计，不包含生产实现或迁移执行。

CI 凭证从部署配置归位到工具连接的先行增量见[迁移设计](ci-connection-migration.md)：沿用下述连接与独立员工许可，先保留现有 CI 循环和证据检查；它可以先于完整 S2/S3 交付，不等同于通用 MCP 或统一执行已经实现。

普通对话的通用工具、搜索与网页、文件、Sandbox 和代码执行，具体方案及 T0–T4 接入顺序见[基础能力接入方案](official-agent-tools.md)，模块归属、调用契约与生命周期见[架构边界](foundation-boundaries.md)。原生工具与远程 MCP 共用连接许可及执行边界，搜索/网页优先验证官方 MCP，直接库集成为备选；代码执行已选定[自托管 OpenSandbox＋Docker＋gVisor](opensandbox-self-hosted.md#接入方式opensandboxdockergvisor)。[开源交付分工](opensandbox-self-hosted.md#开源交付平台与使用者的分工)明确平台内置适配、授权、预算、文件和回收机制，使用者配置部署环境、服务凭证、执行额度与业务 Skill。基础接线已实现，现行规则见[基础工具契约](../../reference/agent-tools.md)，实际结果见[实施记录](../../records/agent-foundations.md)；不依赖完整标准包或 CI 迁移。

2026-10-23 核对 [Agent Skills 规范](https://agentskills.io/specification)、[宿主接入说明](https://agentskills.io/client-implementation/adding-skills-support)、[MCP 架构](https://modelcontextprotocol.io/docs/learn/architecture)与[工具规范](https://modelcontextprotocol.io/specification/2026-07-28/server/tools)。标准负责内容格式和通信，平台负责员工选择、实际授权、运行和交付。支持矩阵以真实验收为准，不从规范存在推断当前兼容。

本设计取代旧方案中“所有工具都由提供者代码静态注册”“所有工具必须依附技能授权”“CI 永久使用专用执行循环”的目标限制。联合主键、修订、快照、取消和实际动作中仍有价值的规则可复用；物理结构不构成新设计约束。

[后端领域与执行重设计](../backend-architecture/README.md)进一步提出统一 `execution` 所有权、独立产品内容存储及专业结果校验。标准 Skill、通用 MCP 和 CI 示例化方向不变；本文沿用的 `runs/runtime/RunStep` 名称及先保留旧执行器的阶段建议须与该草案统一后实施，不能据此要求兼容旧结构。

## 3. 对象及归属

| 对象         | 负责什么                                     | 与其他对象的关系                                      |
| ------------ | -------------------------------------------- | ----------------------------------------------------- |
| Skill        | 何时使用、工作方法、示例和必要资源           | 内容采用标准 Agent Skills；可无工具，也可使用多个工具 |
| 技能库记录   | 展示别名、来源、当前内容指针、维护与兼容信息 | 管理同一份 Skill，不创造第二种技能语义                |
| 技能内容制品 | 一次确定的原始目录、文件清单和内容摘要       | 供多个员工复用，旧运行引用旧制品；不等于发布审核中心  |
| 员工技能配置 | 选用技能、启停、非秘密参数和可选依赖映射     | 保留每员工每技能一份配置；不复制共享内容              |
| MCP 连接     | 服务地址、传输、认证、工具目录与配置状态     | 一个连接可供多员工获准使用；存在连接不代表已授权      |
| 员工工具许可 | 允许使用哪个连接的哪些工具、资源范围及预算   | 可以独立于 Skill；多个 Skill 可复用同一许可           |
| 工具需求     | 方法所需能力与可选工具映射                   | 帮助就绪检查，不从文本自动获得账号或权限              |
| Run / Step   | 本轮获准依据和实际发生的动作                 | 沿用持久化、幂等、取消和历史读取                      |

员工可以只选纯指引 Skill、只获得 MCP 工具许可，或两者组合。不给每个 MCP 工具制造一个空 Skill。技能选择不扩大员工许可。标准正文的工具需求用于兼容/就绪提示，强制安全范围来自员工工具许可及宿主固定的本轮约束，不依赖模型声称调用属于哪个 Skill。

原始标准包是内容真源。页面编辑最终生成同一份 SKILL.md 和资源；数据库中的摘要、输入输出介绍是派生展示或平台附加说明，不与正文成为两套可分别修改的执行规则。上游包保留原名与相对路径，平台显示别名与内部 ID 用于中文展示和同名消歧。

平台可独立保存参数表单、依赖映射和交付检查的附加配置，不强制改写第三方 frontmatter。标准的 compatibility 与实验性 allowed-tools 用于兼容提示和需求检查，不作为授权来源。外部包导入不要求先填写平台私有清单。

## 4. 兼容范围与扩展边界

| 能力                      | 首个通用版本的设计范围                                    | 超出范围时的行为                                  |
| ------------------------- | --------------------------------------------------------- | ------------------------------------------------- |
| SKILL.md                  | 校验标准元数据，保留原文；自动或显式按需激活              | 格式不合法则给文件级原因，不静默修改原包          |
| references 与文本资源     | 保留目录，按需受控读取并记录实际资源摘要                  | 缺文件、越目录或超预算明确失败                    |
| assets                    | 保留原文件，按宿主支持的文件类型提供                      | 不支持的类型展示限制，不冒充已使用                |
| scripts                   | 可保存和检查；执行能力单独分期                            | 必需脚本无运行器时不可执行；不把读取脚本当执行    |
| 远程 MCP                  | 通用 Streamable HTTP 客户端、工具发现与调用               | 协议、认证或内容类型不支持时给具体原因            |
| 认证                      | 首批 none、Bearer 和受保护自定义头；标准 OAuth 为下一增量 | OAuth-only 服务在实现前显示未支持认证，不能标就绪 |
| stdio MCP                 | 后续由受控运行节点管理程序、依赖与退出                    | 普通 Web 表单不能令主服务执行任意 command         |
| MCP resources / prompts   | 与 tools 分开建设和验收                                   | 不从 tools 接通推断全功能兼容                     |
| sampling / elicitation 等 | 后续根据真实需求增加交互与等待态                          | 未支持的回调明确拒绝                              |
| 写入与外发                | 首批集中验证只读；之后统一增加确认、幂等和未知结果处理    | 未有对应保护的写操作不进入可调用目录              |
| 其他宿主插件              | 可识别但不承诺 hooks、agents、LSP 等兼容                  | 展示不支持组件；核心依赖缺失则阻止可用            |

“通用”指同一类已支持协议和认证下，新增兼容服务不需新增服务专用业务代码，不表示首版支持所有 MCP 功能、所有技能脚本或所有内网环境。

## 5. 技能库与使用流程

### 日常使用

业务使用者从“交办工作”进入，选择已有员工或工作模板，提供任务与资料，查看结果并接受或要求修改。模型、Skill 与 MCP 设置集中给配置维护者，不要求每次交办重新装配。对话保留自然语言入口，技能显式选择作为可选辅助。

### 技能库

保留 /skills 入口，页面分“技能”和“工具连接”两个 Tab，避免增加并列的技术导航。是否改左侧名称在视觉实施时统一，不影响对象边界。

技能 Tab 提供搜索、导入与新建。卡片展示用途、来源、就绪摘要和“已配备给 N 位员工”，不把关联数称为实际使用次数。主要动作是查看和添加给员工；在当前技能下选员工并配置后保存，不跳转员工列表重新找技能。

详情先回答适用工作、示例和交付要求，再按需展开方法、资源与高级配置。输入、输出和示例可以写在标准正文中；确需机器强制校验的输出约束另有明确配置，不能把展示文字声称为已强制执行。

导入支持上传标准目录包及固定提交/版本的受控仓库来源。首批可先实现上传包，仓库来源作为后续同一导入接口的适配，不承诺任意 URL、付费市场或私有安装器。导入检查路径、文件数、体积、必要元数据、资源依赖和宿主兼容；不运行安装脚本。兼容报告与来源摘要在确认采用前可见。

新建默认只需名称、何时使用和工作方法；按需增加资源、示例和模板。参数规范与依赖映射放高级设置。日常使用界面根据参数规范生成仓库、日期等业务字段，无需填写 JSON；高级作者仍可编辑 schema。

### 工具连接

管理员添加远程地址、认证并测试，读取真实工具目录。界面分别显示“已配置”“连接验证结果”“待审核工具变化”，不将有凭证等同于连接成功。工具名、用途和数据访问范围可查看，技术 schema 在高级区域。

连接测试本身是有授权的网络读取，不顺带授予员工工具权限。为员工选择明确工具和连接后保存；不支持工具的自动全选授权。新发现工具默认未授权，目录更新显示差异并显式批准。

### 员工配置

同一配置页分别选择技能和工具许可；所选技能有依赖时提供补齐向导。参数表单只在非空规范时显示；无参数技能直接添加。缺连接、缺权限、宿主不支持和内容错误给不同修复动作。

Tab、搜索、分页和选中详情保存在 URL；未保存草稿、修订冲突、身份切换、保存中导航保护沿用当前工程契约。维护者可查看配置状态，游客/member 继续只读安全投影，秘密和内部目录不公开。

## 6. 模块职责与统一执行

| 模块          | 职责                                                            |
| ------------- | --------------------------------------------------------------- |
| skills        | 导入、标准内容、资源制品、当前指针、兼容检查和派生展示          |
| agents        | 员工技能配置、工具许可与依赖映射的原子保存                      |
| tools         | 通用 MCP 生命周期、目录发现、工具调用、秘密注入及原生工具登记   |
| files         | 持久文件字节、不可变元数据、暂存与受控读取                      |
| sandboxes     | 临时环境申请、远端身份、配额、停止和清理                        |
| agent_runtime | 构造本轮目录，按需加载，驱动模型/工具循环，装配 SDK 后端        |
| execution     | 持久化真实步骤、工具结果、预算和终态；沿用现有执行宿主          |
| conversations | 冻结输入、组合授权、最终正文及文件关联的原子发布                |
| 领域组件      | 可选的专业工具、范围解释和交付检查；不复制 Runner 或 Agent 循环 |

1. **接受**：校验身份、员工、幂等、额度及明确选择的技能；没有技能也允许使用已获准工具。
2. **固定依据**：捕获技能制品、参数、获准工具和 schema 摘要、连接及许可修订；保存非秘密快照和待执行 Run。网络等待不占数据库写事务，提交时只使用已审核且可追溯的本地目录。
3. **发现与激活**：模型先获得方法摘要和获准工具；需要时读取标准正文及相对资源。显式选择先加载，缺依赖不得静默跳过。工具集体积受预算限制，不把全服务工具无差别送模。
4. **工具往返**：同一 Agent 循环调用 MCP 或内置工具。宿主将短别名映射到确定的连接、上游工具名和获准摘要，避免同名串线。
5. **实时复核**：调用前校验会话、启停、许可、连接修订、schema 和参数；首次连接及每次工具调用前在事务外检查当前远端目录，再注入秘密。内容保持本轮固定，撤权立即阻止后续动作。外部请求已发出时不承诺撤回。
6. **记录**：持久化真实激活、资源读取和工具调用的安全摘要与返回依据。无动作不补造轨迹；工具返回与包内容均不能改写平台授权。方法中的范围建议不能自动成为安全控制；如平台附加配置声明强制任务限制，宿主在接受时合并到本轮许可交集，冲突拒绝，不按事后推测的技能归属选择限制。
7. **完成检查**：通用检查覆盖有效输出、预算、取消和持久化；可选受信领域检查覆盖特定结果要求。未执行必需检查不能宣布该工作成功。
8. **交付**：结果、消息和终态原子提交。失败、取消与中断沿用现有 Run 状态；写操作结果未知时不自动重放；后续重试重新捕获配置。

不以员工名称、技能 ID 或新增 work.kind 为每项工作选择一套 Agent 程序。已有业务入口可以转换为普通交办参数，通用执行器不增加 CI/客服/财务分支。

技能内容制品、连接目录和许可的字段由[字段字典](../agent-capabilities/data.md)维护，读写和错误语义由[运行契约](../agent-capabilities/runtime.md)维护。本版不增加同技能多实例、公开市场、评分计费或自动升级发布中心。能力组织、表单、报告及固定流程的具体形式见[后续讨论](../configurable-workflows.md)，当前不据此增加实施依赖。

## 7. 通用 MCP 与权限的真实边界

MCP 工具由管理员批准的连接动态发现；内置函数和领域校验器仍由受信代码注册。两者使用共同调用契约，不为每个 MCP 工具手写 provider 实现。

批准目录保存工具名称、描述、输入/输出 schema 及影响行为的元数据摘要。新工具不自动加入旧许可；已有获准工具发生相关描述或 schema 变化时，旧许可暂停该工具，管理员复核后更新摘要。新版本工具不可冒充旧契约。运行首次连接及每次 tools/call 前，在事务外重新发现当前远端工具，与本轮获准摘要比较；失配停止受影响工具并生成待审核候选，不能校验则不继续该调用。协议支持的目录变更通知可使缓存立即失效；只有实现可验证的失效机制后才减少重复发现。检查与调用间仍有竞态，相同描述/schema 的上游实现变化也无法由摘要证明不变；记录这一限制，不声称彻底锁定远端版本。

只读注解和 JSON Schema 不足以证明操作无副作用或资源隔离。首批采用已审阅工具与最小权限凭证；未知语义默认未授权。对任意服务，优先让上游凭证强制限定业务范围。需要仓库级等平台限制时，使用受信参数约束或领域适配器；无法证明可强制执行的范围不能仅写在提示词里。

连接地址由管理员配置并经过部署网络策略校验；默认阻止访问本机元数据等敏感地址、任意重定向和未批准目标。企业内网须由部署者显式启用对应受控网络路径；不是通过新增技能代码放行。标准 OAuth、令牌加密、连接引用授权与未来个人委托分别建模，不把 GitHub 登录当工具授权。

包的相对路径、解压路径与符号链接必须限制在技能根目录；原始包、资源和模型返回的 URL 不因被读取就获得任意下载或执行权限。秘密只在获准调用时解析，不进入标准包、非秘密参数、目录、快照和步骤。

## 8. CI 诊断如何成为示例

| 当前专用部分                         | 目标归属                                             |
| ------------------------------------ | ---------------------------------------------------- |
| CI 方法正文与报告示例                | 标准 Skill；结构化报告规范与展示由工作流配置声明     |
| GitHub MCP 服务与凭证                | 可配置通用连接，三项工具的获准目录                   |
| 员工 ci_repository                   | 技能参数中的默认目标，以及独立工具许可的强制资源范围 |
| 手写模型/工具循环                    | 统一 Agent 或固定步骤执行，由工作流配置选择          |
| attempt/head_sha、日志引用与覆盖检查 | 复用现有受信领域工具或交付检查                       |
| 普通对话/CI 永久模式切换             | 由工作流配置生成快捷入口与表单，提交进入通用执行路径 |
| CI 历史报告与一次反馈                | 保留当前历史数据及访问规则，不伪造新通用记录         |

模型按 Skill 调用获准 GitHub 工具；原有领域组件继续固定调查对象、验证日志归属及结束时一致性。若直接透传原始工具无法保留既有保证，可复用已有受信包装工具；它们是可复用操作，不是再次创建独立 Agent 流程。

CI 示例可引用一个登记的受信交付检查；通用执行器只处理“运行声明的检查集合”，不按 CI 技能 ID 分派。检查实现不能来自未审查技能包中的任意 Python 模块。普通技能无需自定义检查代码；只有新增专业算法、强制范围解释或特定业务验收时才开发对应组件。

迁移应使用相同输入比较新旧证据、授权、取消、预算与报告。真实回归通过后移除旧专用执行分支；历史可读，旧活跃 Run 先排空或中断。不长期双写两套仓库参数和权限，也不将旧运行无损重放作为承诺。

## 9. 分期与验收

| 阶段            | 可交付范围                                                  | 完成判据                                                              |
| --------------- | ----------------------------------------------------------- | --------------------------------------------------------------------- |
| S1 标准内容     | 标准包导入、不可变资源、纯指引/文本参考、技能与连接分离设计 | 第三方含 references 的 Skill 无新增业务代码完成加载；旧方法迁移可核对 |
| S2 通用远程 MCP | 首批认证、动态目录、独立员工许可、统一调用与参数表单        | 第二个非 GitHub 服务仅配置即可真实使用；同名工具与目录变化测试通过    |
| S3 CI 示例迁移  | 统一循环、领域检查、旧入口转换与历史保留                    | CI 同等证据/权限验收通过，删除旧特殊排除和专用循环分支                |
| 后续增量        | OAuth、受控 stdio、隔离脚本、写入确认等                     | 分别定义环境、身份、取消、恢复及真实产出验收，不提前标兼容            |

S1/S2 是扩展能力底座，不成为所有企业场景的共同前置；现有项目知识助手仍可按最短闭环验证价值。不先支持所有插件形态再寻找用户。

| 验收场景                         | 必须观察到的结果                               | 当前结果 |
| -------------------------------- | ---------------------------------------------- | -------- |
| 导入带相对参考文件的第三方 Skill | 原包保留、按需读取固定资源、无新业务路由       | 未实施   |
| 新增第二个非 GitHub MCP          | 只新增连接和许可；普通对话真实调用至少两项工具 | 未实施   |
| 不配 Skill，仅使用 MCP           | 获准工具正常调用；无需空技能占位               | 未实施   |
| 两连接各有 search 工具           | 调用、秘密和审计不串连接                       | 未实施   |
| 两员工复用同一 Skill             | 参数/连接可不同，不能越用对方许可              | 未实施   |
| 上游新增或改变工具               | 新操作未自动授权，改变的获准契约停止待复核     | 未实施   |
| 缺少脚本运行器或必需依赖         | 明确不可执行，不伪造工具结果                   | 未实施   |

| CI 经统一入口执行                | attempt、来源、引用、覆盖及反馈保证保留        | 未实施   |
