# 身份、会话与访问控制

本模块确认当前来访者是谁，以及这个身份可以执行什么操作。例如成员能够使用共享员工，并不意味着可以读取其他成员的对话。账号是长期身份，会话代表一次可过期、可撤销的访问；具体资源归属由业务模块提供。

## 模块设计

### 浏览器会话怎样变成可信身份

管理员以本地密码登录，普通成员通过已配置的 GitHub OAuth 登录，游客可取得只读会话。浏览器只持有随机 token，数据库保存摘要、期限、撤销状态和账号关联。每次解析都检查会话及账号状态，再生成 `Actor`，其中只携带可信用户/游客、角色和会话信息。

使用服务端会话使退出、禁用及改密码可以让旧访问失效；代价是身份解析依赖数据库，客户端凭证不能离线证明它仍有效。会过期的会话 ID 不承担业务所有权，运行同时记录发起用户与会话，分别用于归属和持续授权。

### 密码与外部登录怎样进入同一套账号规则

昂贵的密码哈希计算在写事务外执行；签发会话前，在短写事务重新检查密码哈希和启用状态，避免并发改密码或禁用后仍发出有效会话。token 只在提交成功后交给调用方。

GitHub 适配验证 state、PKCE 和上游身份，只取得稳定外部 ID 与账户名，交给会话服务在一个事务建立站内关联和会话。上游 token 用后丢弃，不保存为模型或工具凭据。管理员账号与普通成员同名也不合并，本机初始化只检查是否已有管理员。

### 认证、操作许可和资源范围如何组合

`service.py` 解析身份；`permissions.py` 将角色映射为操作能力，未知角色无能力。业务入口先检查操作，例如是否能读取对话，再提供资源所有者检查范围；拥有读取能力不等于能读所有记录。不可访问资源返回不存在，列表与单条查询须应用相同范围。

管理员在通用资源策略中拥有全平台访问能力，知识库另按所有者严格检查；成员可使用共享员工及本人对话/工具账号和知识库，游客仅有公开展示能力。身份策略不导入业务模型；员工创建者编辑权、能否重试等条件由所属服务继续判断。当前是代码内固定映射，自定义角色和多租户需定义新的身份上下文及范围。

### 请求解析与后台检查为什么分开

`resolve(token)` 为请求解析，并按间隔记录用户活动；`resolve_session(id)` 供后台只读复核，不延长活动期限。否则运行心跳会让闲置会话永不过期。后台使用同一套权限策略，持续检查当前许可，登录成功不会形成永久执行权。

认证失败与权限不足使用不同错误。游客回退只捕获认证失败，数据库/身份服务故障不能被解释为「再建一个游客」。Cookie、来源和 HTTP 错误转换仍在 API 层。

## 目录与职责

```text
auth/
├── actor.py                       # 保存已确认的用户/游客、角色和会话信息，供业务与后台共享，不携带 Cookie、密码或数据库会话
├── service.py                     # 验证登录、签发/解析/撤销会话并维护账号，把密码和外部登录统一成站内身份
├── permissions.py                 # 将角色映射为能力并检查操作与资源范围，保持纯策略，不读取 Cookie、数据库或业务表
├── models.py                      # 保存用户、外部身份关联及登录会话，区分长期账号、外部稳定标识和短期访问
├── github.py                      # 处理 GitHub 登录起点和回调校验，从上游取得稳定身份后交给会话服务
├── config.py                      # 校验来源、Cookie、安全期限及 GitHub 配置，使不完整配置在接入前暴露
└── cli.py                         # 供部署者初始化或维护管理员账号，不通过公开注册接口暴露本机维护能力
```

## 与其他模块协作

API 读写 Cookie、检查 Origin 并把认证结果交给请求依赖；各业务服务消费 Actor 和权限策略，再判断实际资源归属。执行宿主通过注入的授权流程使用后台身份复核。本模块依赖数据库及密码/OAuth 技术库，不导入员工、对话或技能模型。

## 当前取舍与维护入口

管理员保留密码登录，成员通过 GitHub 注册登录；邀请注册和多租户尚未接入。请求限速在 API 的单进程内存中，重启会重置，多进程不共享；扩容需明确可信来源和共享限速。
