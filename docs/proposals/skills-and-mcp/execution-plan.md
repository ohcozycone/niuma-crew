## 1. 本次实施与明确后置

### MCP 管理可用性增量（2026-10-29，已实施，验证收尾中）

用户反馈现有匿名连接无法补 Key、服务可重复创建且不可删除、连接和目录操作命名难理解。本增量沿用服务定义、个人凭据、员工许可的内部边界，页面统一表达为服务信息、访问设置和可用工具：

1. 服务登记的 `env_keys` 作为管理员允许账号提供的业务环境变量名称；匿名账号可使用空子集，凭据账号可使用声明子集。已有声明值的连接仍须完整提供其选定字段，不能注入未声明键或运行时控制变量。服务所有者可补充字段；移除仍被连接使用的字段时拒绝，启动命令与参数继续不可原地替换。
2. 账号访问设置支持明确地从匿名切到 Key、修改 Key、切回匿名；stdio 用密码字段逐项编辑环境值，HTTP 可编辑认证方式。秘密不回显；不修改秘密时保留旧值，身份变化清空目录并增加修订，旧 Run 不得继续借用旧授权。
3. 相同名称（去空白、忽略大小写）或同一接入定义不能新建；以 SQLite 写锁串行核对名称和 HTTP 目标/stdio 启动参数，旧数据不自动合并或删除。服务地址和程序不同不能仅靠名称猜测同一厂商。旧式直接建 HTTP 连接也复用已有目标，不能绕过服务查重。
4. 提供服务与本人连接删除，校验所有者和预期修订。已被员工装配或个人绑定的连接拒绝删除；服务含其他人的连接时拒绝级联删除。没有引用时才删除本人连接与服务，前端先明确确认，不自动卸载员工。
5. 目录按钮改为读取工具列表/检查工具更新、确认工具列表/应用工具更新、暂不更新；预览显示新增、修改、移除数量，不与生效目录混淆。远端无变化时直接显示已是最新，不再产生无意义的确认。忽略更新不回滚远端，不自动扩大员工许可。

验证覆盖匿名与凭据切换、字段白名单、凭据不回显、旧授权失效、重复与并发创建、带引用删除拒绝、无变化发现，以及相应真实表单交互；变更不新增厂商适配器或数据库表。

实施统一能力库与添加菜单、MCP 手填/导入和详情编辑、员工大脑移位及装配摘要、标准 Skill 多文件导入/创建/编辑/导出、完整正文与资源投递、服务级说明传递、可信 stdio 子进程、结果分页与明确外部读取任务的执行核验。保留 Token、共享员工定义、个人/明确共用账号及逐工具许可。

最新取舍采用官方 SDK 管理受信 stdio 子进程：只有管理员能登记程序定义，部署默认关闭该模式；账号参数仍按使用者隔离，结束关闭进程组中的后代。它拥有宿主账号权限，不表示已隔离。普通用户不能提交启动命令，平台内置脚本执行固定走当前 OpenSandbox 通道。可信范围同时包含 MCP 程序及其暴露工具的实现：若管理员登记可任意执行 Shell 的 MCP，它仍会在宿主执行，平台不能从通用 schema 判断业务代码的安全性。任意第三方执行器应在后续隔离后端中支持。

OAuth、员工复制/广场、插件市场、Docker MCP Gateway、容器 stdio 后端、独立沙箱微服务重建、跨节点和预热池均不在本次实施范围。它们是此前探索方案，不是用户必须承受的额外建设。已有 OpenSandbox 的文件/命令边界保留；不将 MCP 子进程计为沙箱容器。

## 3. MCP 数据与运行

### 接入表单与技能目录增量（2026-10-29，已实施）

实际结果、迁移、浏览器与未覆盖范围见[本轮验收](../../records/portable-capability-onboarding.md)。

MCP 接入只保留同一张表单，服务信息右侧的“快捷导入”打开 JSON/文件弹窗；解析、选择服务、确认覆盖后仅回填草稿，不执行程序或保存秘密。支持受限客户端配置和官方 Registry 服务描述；不支持的传输、参数模板和多头认证必须明确报错，不静默丢弃。描述可提供凭据字段说明、必填和秘密属性；真实值只在账号层。保存定义、创建访问设置、测试连接和首次确认目录在同一流程完成，但数据库事务与外部连接检查分开；部分成功时保留已创建资源与明确重试入口。OAuth 后置。

Skill 新增可配置 `SKILL_LIBRARY_DIR`，默认运行后端的系统用户目录 `~/.agents/skills/`，与使用该目录的命令行安装器互通；这是官方指南推荐的目录约定，不是包格式强制的位置。管理员主动同步才登记到平台共享能力库，不自动扫描、发布或装配；云端的 `~` 属于服务用户，不是浏览器访问者。部署方可显式改用独立持久目录；原先采用数据库同级目录的部署需配置保留原路径或迁移完整包，不静默合并目录。数据库保留稳定 ID、展示别名、员工关系与发布清单；现有字节存储保留不可变运行版本。上传/创建/编辑写入同一目录，管理员同步从目录发布；未变化跳过，更新保留别名与装配，源缺失标记但不删已发布版本。协议名与目录名一致，别名不改源包。既有无目录技能在同步时导出并关联，若同名不同内容则报冲突。仅同步不装配、不执行代码、不安装依赖。

目录和数据库之间不伪称分布式原子事务：应用写入使用跨进程文件锁、完整暂存与替换，数据库失败恢复旧目录；发现外部文件修改时拒绝平台覆盖并提示先同步。同步对每个包独立验证、记录结果，单包失败不影响其他包。删除仍先检查员工引用；删除目录仅限平台已关联、内容仍与发布依据一致的包。读取有大小/文件数/路径和链接边界，运行始终读取发布清单，不临时扫描磁盘。

验收包括配置导入不启动、单表单密钥和失败重试；标准目录多文件/二进制往返、幂等同步、外部修改冲突、名称碰撞、缺失源、关联保留、旧 Run 快照及正式迁移的数据保留。

服务定义采用明确的传输分支：HTTP 保存 URL，stdio 保存程序、参数和非秘密环境要求；不把 command 当 URL。常见 mcpServers JSON 归一到同一表单，导入不启动程序。环境秘密在账号层加密，不进入服务、目录、快照或浏览器持久草稿。

管理员登记的 stdio 定义可供使用者建立本人账号连接；普通使用者不能改变程序/参数或访问另一人的秘密。使用结构化 argv，不通过 shell 拼接。显式配置最小环境和私有临时工作目录；账号 env 禁止 PATH、解释器加载及代理等启动控制键。固定启动包版本或解释器，提供停止、超时、最大实例数与有界等待。SDK 协议实现复用；因 SDK 可能遗漏已退出主进程留下的后代，附加极薄的同组回收启动器，不另建 supervisor 服务。不承诺回收主动脱离进程组的恶意守护程序，这也是只支持可信服务的原因。

服务说明是可选的上游内容：单独捕获、限定长度、随候选/确认依据保存，再明确送入模型。工具描述与原始输入/输出定义保留；上游说明不能覆盖身份、权限和平台规则。目录变化不自动扩大员工许可。

目录发现使用短期会话；实际调用同一 Run/实际账号复用实例，Run 结束、取消或停服关闭。状态不跨不同用户/Run 自动共享。并发限制控制实际进程数，不是登记配置数，远程 HTTP 不启动本地进程。

## 4. Skill 资产与兼容

导入 ZIP 的载体是平台约定，内容遵循 SKILL.md 目录标准。先在临时区校验大小、文件数、路径、重复项和链接，再解析元数据与预览，确认后可靠保存文件与数据库引用；导入不执行脚本或安装依赖。

在线创建与导入共用同一资产：SKILL.md 为正文来源，可新增/编辑 scripts、references 与文本文件，二进制资源提供上传/预览/替换。元数据、清单和内容依据在数据库，字节在可配置磁盘目录。文件版本用于 Run 一致性，不复制员工；原有技能 ID 和装配关系保留。

旧的名称、简介和工作指引继续兼容；输入说明、输出说明、示例编译进完整正文。中文展示名与协议名分开；分类、启用和员工参数属于平台配置，不伪装成标准必需字段。既有表单/接口不得静默丢字段。

只披露获准目录，正文和支持文件按需读取。脚本实际执行前，把冻结包放入同一 Run 沙箱的只读技能目录，文件工具与 Shell 的路径一致；输出进入 workspace/outputs。执行不自动改写共享资产，不因上传 allowed-tools 等字段增加员工权限。

## 5. 执行可靠性

保留自由对话和普通问答，不全局强制调用工具。明确指定的 Skill 使用已有 pin；明确读取目标网页的任务捕获目标要求，通过实际来源与调用记录核验，缺证据时进行一次有界补执行或准确终止，不发布假“已读取”。自然语言识别保持保守，URL 出现本身不等于必须抓取。

保留全部工具结果；长结果提供有界的本轮结果读取通道，不给模型不可读取的路径，也不为读取结果自动授予宿主文件权限。预览、提取文本、实际读取范围与完整正文分别表达；full_text 不再仅凭非空内容宣布完整。

程序只能核对确实调用、目标、状态与来源覆盖，不能保证生成的每一句解释正确。用固定离线轨迹与脚本化模型测试验收这些强约束，真实模型行为评测和真实外部服务联调单列证据。

## 6. 前端交互

能力库保留名称与两行摘要，底栏类型图标加文字、启停状态左对齐，查看配置居右。工具栏为搜索、类型、数量、刷新与添加菜单；菜单为添加 MCP、创建 Skill、导入 Skill 技能包。内置工具为次要入口。

MCP 创建用统一表单和快捷导入弹窗，导入仅回填；面包屑当前项准确，正文无重复返回，标题右侧取消/保存并测试。编辑动作说明范围；连接检查/Token 更新/目录确认保持明确提交，取消只丢弃未提交表单。工具目录默认摘要，名称和说明纵向按需编辑，原始名始终保留。

大脑移入基本信息头像右侧，窄屏上下排列；去配置大脑为下划线导航，刷新为低权重动作。员工能力装配只显示已装配摘要；添加时选择，配置时展开，MCP 内部操作不全部平铺。局部完成只更新草稿，员工主保存才统一提交。复用已有 Base UI/令牌/真实组件并补设计样板。

## 7. 实施次序与验收

1. 完成独立评审，记录发现、取舍与修订，不把评审通过当作实现完成。
2. 后端 MCP：传输和秘密分支、官方 stdio 生命周期、服务说明；独立正式迁移，覆盖旧库数据、账号、拒绝和取消。
3. 后端 Skill：标准包、存储与接口、旧内容转换、运行时只读加载和沙箱文件分发；迁移与清理引用明确。
4. 前端能力库/MCP/Skill 编辑与员工装配；与后端 DTO 对齐，不使用假字段和假保存。
5. 补执行证据与长结果读取，覆盖零调用假成功、目标不符、部分结果、读取越权与失败。
6. 整合后独立代码 review，修复发现，运行静态、定向和必要回归、构建与文档检查。
7. 业务库修改前备份；在隔离环境验证迁移和端到端流程，再切换本机开发服务，浏览器验证主题/窄屏/真实页面并打开交付入口。

状态以本文件和实施记录逐步更新，已生效规则回写 reference 和模块入口。真实 Token、外网环境、Docker/gVisor 不可用时如实区分未覆盖项，不以离线测试冒充部署验收。

## 8. 独立评审结论与采纳修订

2026-10-29 分别评审 MCP 后端、Skill 资产与运行、前端装配。结论是模块化单体足够，不增加服务、插件框架或独立文件权限系统。以下修订进入实施基线：

1. stdio 登记权限与现有 tools:update 分开，只有管理员可改启动定义，部署默认关闭；全部导入 env 值视为账号秘密，服务只保留所需键。复用 SDK 的进程组关闭能力并实测孙进程，stderr 不直接进应用日志，不再另写 supervisor。HTTP 保留原接入路径，新增 mcp_stdio 分支。
2. Skill 独立内容寻址目录，数据库只存完整正文与清单；Run 冻结摘要而非二进制。首版不做 GC，避免误删活跃 Run 引用；包名与稳定 ID 运行路径分开，资源读取不冒充技能激活。
3. MCP 页头保存只提交当前服务/展示草稿；Token、目录确认各自明确提交，取消不能撤销历史提交。员工面板完成只改页面草稿，主保存仍是唯一装配事务。
4. 已装配 Skill 按 ID 读取详情，不依赖当前搜索页；CI 专用装配继续保留真实仓库配置并纳入摘要。
5. 明确网页读取目标但没有成功提取证据时准确失败，不增加第二套 Agent 循环或无法验证的通用语义识别。长结果读取是派生的本轮结果能力，复核原工具许可，不等于宿主 read_file 授权。

评审通过不代表代码已完成，实际回归、迁移和 UI 证据记录在交付验收中。

## 10. 完整流程与失败处理

1. 管理者在能力库添加 MCP：手填或导入后登记一份定义；普通使用者可接远程服务，只有管理员可登记部署已开启的可信 stdio 程序。
2. 创建个人或明确共用账号，Token/env 只进入账号密文。发现目录才连接远端或临时启动子进程；读取工具与服务说明，编辑显示别名，确认候选。失败保留旧目录，不给员工增加许可。
3. 员工装配选择已确认账号/操作和个人或共用模式，Skill 则选择同一共享资产并填写其真实 schema 参数。面板取消不修改草稿，完成不写库；员工主保存统一检查并提交。
4. 使用者发起对话，Run 冻结岗位、Skill 正文及文件摘要、目录和账号依据；主循环仍在后端。缺个人账号只在请求该操作时提示连接，不借用创建者的凭据。
5. 远程工具走受控 HTTP；stdio 按本 Run 与实际账号开进程并复用；读取 Skill 本身不执行代码。只有平台 execute 的实际调用才申请 OpenSandbox 并投递已激活资产。
6. 工具结果先保存再送回模型；长结果用本轮游标读取。外部读取缺成功来源、错误目标或覆盖不足时准确失败；预算耗尽不继续无限补执行。现有 CI 专用取证流程保持自己的契约。
7. 正式成果保存后再回收环境，成功以发布事务为准。取消、超时、账号/工具撤权立即停止后续动作；沙箱回收异常也尝试关闭 stdio，失败记录不伪装成成功。

Mac 和 Ubuntu 共用平台代码及数据结构。可信 stdio 要求目标机器已安装启动器/解释器并使用可解析的固定包版本；OpenSandbox 仍按既有环境配置与验收运行。没有为了本轮 stdio 重建本地虚拟机、独立服务或容器池。
