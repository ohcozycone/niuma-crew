## 目标与实施前差异

以下差异与视觉过程保留原型阶段的设计依据；当前实现及未覆盖部署项以[统一接入标准](../reference/failures.md)和实施记录为准。

让用户知道发生了什么、当前工作处于什么状态、下一步能做什么。沿用 NiumaCrew 的暖灰底、橙色局部强调、日夜主题和克制的工具界面。错误插画使用生图模型，以简洁且有趣的独立画面表达错误含义，错误码与文案独立排在右侧；不把现有头像与附加图形拼接作为已认可方向，不为每个错误码单独做页面。

当前已有七类应用错误、`detail.code/message`、可选 `Retry-After`、路由错误出口、身份边界和若干局部错误组件。缺口是展示分散、客户端故障没有完整分类、等待头未透传给调用方，以及首次 HTML/JS 加载之前的兜底缺少同源设计。

当前事实以代码为准：

- [router.tsx](../../frontend/src/router.tsx) 中 NotFound 与 ErrorPage 是简易文字页；工作台内容层与外壳层已有不同错误出口，登录和帮助缺少显式配置的同源出口。
- [http.ts](../../frontend/src/lib/api/http.ts) 的 ApiError 当前只有 message/status/code，fetch 失败以内部 status=0 表达，未区分超时与一般连接失败，也未保留 Retry-After/request ID。
- [AuthBoundary](../../frontend/src/components/auth/AuthBoundary.tsx) 已分别处理身份加载失败和无权限；身份请求失败不能被当作未登录。
- [ResourceStatus](../../frontend/src/components/configuration/ResourceStatus.tsx)、[ConfigurationConflict](../../frontend/src/components/configuration/ConfigurationConflict.tsx) 已有局部重试和保留草稿的基础。
- [frontend_delivery.py](../../backend/app/api/frontend_delivery.py) 只向页面白名单回退 index.html，未知路径、API 和缺失资源不回退。这意味着生产环境直接访问未知 URL 与应用内导航到未知 URL 的出口不同。
- 生产当前由 FastAPI 同时交付页面和 API。进程整体不可达时，首次访问无法依靠同一进程返回自定义错误页。

下面的场景分类覆盖当前系统的主要可观察失败与必要部署边界；具体根因可无限增加，按同一种恢复方式归并即可。`—` 表示没有新的 HTTP 响应；`client_*` 是拟新增的浏览器分类，绝不是 HTTP 状态或已存在的后端错误码。表中引号内文案为拟采用文案，不代表当前已显示。

## 场景、错误码、文案、配图与原因

展示层级：**整页**用于没有可用正文；**区域**用于一个模块失败；**行内**用于字段、按钮或消息；**横幅**用于可继续阅读时的降级。相同 HTTP 状态根据业务 code 和调用上下文选择恢复动作。

### 入口、资源与权限

| 场景                                        | HTTP / 稳定分类                                                                                                                                                       | 建议文案与操作                                                                                                                             | 展示 / 配图               | 原因与边界                                                             |
| ------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------- | ---------------------------------------------------------------------- |
| 1. 地址写错、旧书签、未知页面               | 直接访问 404；SPA 内无新 HTTP / `client_route_not_found`（拟增）                                                                                                      | **这个页面没有找到**。请检查地址，或返回数字员工继续使用。主操作「返回数字员工」                                                           | 整页 / 寻找               | 无法知道原本要找什么，不自动跳走、不把 404 画成系统故障                |
| 2. 员工、技能、大脑详情不存在或不可见       | 404 / `agent_not_found`、`skill_not_found`、`model_connection_not_found`、`resource_not_found`                                                                        | 按资源说明，如「**没找到这位数字员工**」「**没找到这个技能**」。内容可能已移除，或当前账号无法查看。主操作「返回所属列表」                 | 内容区域 / 寻找           | 保留模块上下文；不区分私有资源不存在与无权查看，不泄露存在性           |
| 3. 对话、消息、回复、运行记录不存在或不可见 | 404 / `conversation_not_found`、`message_not_found`、`question_not_found`、`response_not_found`、`run_not_found`、`conversation_run_not_found`、`ci_result_not_found` | **这条记录暂时无法访问**。请返回记录列表，重新选择要查看的内容。「返回对话记录」                                                           | 内容区域或消息局部 / 寻找 | 单条问题定位失败不清空整段对话；缺少报告不等于对话不存在               |
| 4. 附件、输出或技能文件不可读取             | 404 / `file_not_found`、`skill_file_not_found`                                                                                                                        | **这个文件暂时无法获取**。文件可能尚未发布、已移除或无法访问。「重新检查」/「返回对话」                                                    | 文件行 / 寻找小图标       | 当前 404 不证明永久删除，不能擅自展示“文件已过期”或返回 410            |
| 5. 尚未登录、登录会话过期                   | 401 / `authentication_required`                                                                                                                                       | **请登录后继续**。首次未登录：「登录账号后即可继续使用。」会话过期：「当前登录状态已失效，请重新登录。」「去登录」；支持时提供「游客浏览」 | 统一转登录 / 通行         | 保留经 safeReturnPath 校验的 next；不要另建一套登录表单                |
| 6. 用户名或密码错误                         | 401 / `invalid_credentials`                                                                                                                                           | **账号或密码不正确，请重新输入。**                                                                                                         | 登录表单行内 / 无大图     | 这是凭据输入失败，不触发“会话过期”跳转或清空整个表单                   |
| 7. 已登录但没有页面或操作权限               | 403 / `permission_denied`、`agent_edit_denied` 等                                                                                                                     | **当前账号没有访问权限**。请使用有权限的账号，或联系管理员确认。「返回数字员工」/「切换账号」                                              | 页面内容或操作行内 / 通行 | 有效身份仍保留；按钮按实际权限显示，不承诺一定可以申请权限             |
| 8. 权限或个人连接在使用中被撤回             | 403/409，或 SSE `access.revoked`，或 Run `actor_session_invalid`、`tool_access_revoked`、`skill_access_revoked`                                                       | **访问状态已改变**。请重新确认登录或当前配置后继续。「重新确认」                                                                           | 横幅 / 通行               | SSE 事件、HTTP 与运行终态各有出口；不能把一般上游故障当作撤权          |
| 9. 登录状态读取失败                         | — / `client_connection_failed`，或 503 等真实状态                                                                                                                     | **暂时无法确认登录状态**。当前无法连接服务，请稍后重新连接。「重新连接」                                                                   | 整页简化外壳 / 连接或检修 | 此时身份未知，不能降成游客、误报未登录或进入跳转循环                   |
| 10. 第三方登录被取消、校验失败或不可用      | OAuth 303 回登录页 / `github_failed`、`github_unavailable`、`github_origin_mismatch`                                                                                  | 取消时「**此次登录未完成，可以重新发起。**」；服务失败时「**暂时无法使用 GitHub 登录，请稍后重试或使用账号登录。**」                       | 登录局部 / 通行小图标     | 当前协议通过登录参数传递错误，不能改写成整页 500；不回显供应商敏感原文 |

### 浏览器、静态资源与网络

| 场景                                                         | HTTP / 稳定分类                                              | 建议文案与操作                                                                                   | 展示 / 配图                         | 原因与边界                                                                                        |
| ------------------------------------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------ | ----------------------------------- | ------------------------------------------------------------------------------------------------- |
| 11. 浏览器报告离线                                           | — / `client_offline`（拟增）                                 | **网络连接似乎断开了**。请检查网络，连接恢复后再试。「重新连接」                                 | 首次进入用整页；已打开用横幅 / 连接 | navigator.onLine 只是提示，恢复事件后仍需请求确认；保留当前已显示内容                             |
| 12. fetch 失败、API 域名无法解析、连接被拒绝、跨域或代理阻断 | — / `client_connection_failed`（拟增）                       | **暂时连接不上服务**。请检查网络，或稍后重新连接。「重新连接」                                   | 根据请求范围 / 连接                 | 浏览器通常无法可靠区分网络、DNS、CORS 与服务停机；不要断言是用户网络或后端宕机                    |
| 13. 客户端等待超过期限                                       | — / `client_request_timeout`（拟增）                         | 读取：「**这次等待有点久，请重新加载。**」；写入：「**还无法确认是否提交成功，请先检查结果。**」 | 原请求区域 / 等待                   | 必须区分读取超时与写入结果未知；请求超时不等于服务端没有执行                                      |
| 14. 页面分包加载失败、发布后旧标签页引用旧 chunk             | 常见资源 404，或 — / `client_chunk_load_failed`（拟增）      | **页面资源未能加载**。请重新加载页面后再试。「重新加载页面」                                     | 内容区域或根兜底 / 检修             | 只有构建版本变化等明确证据才称“发现新版本”；不能所有 import 失败都自动刷新                        |
| 15. React 渲染、路由加载器异常                               | — / `client_render_failed`（拟增）                           | **这个页面出了点问题**。可以重新打开此页面，或返回数字员工。「重新打开」/「返回数字员工」        | 最近可用边界 / 检修                 | 先保住外壳；组件错误不伪装成 HTTP 500；重置边界不保证修复确定性代码缺陷                           |
| 16. 返回了 HTML、损坏 JSON、缺少关键字段或不兼容响应         | 可能 200 或错误状态 / `client_invalid_response`（拟增）      | **没有收到可用的服务响应**。请稍后重试；持续出现时可复制问题信息。「重试读取」                   | 原请求区域 / 检修                   | response.json 成功不代表数据有效；不把代理 HTML 原文插入 UI                                       |
| 17. 可选图片或头像加载失败                                   | 资源 404 或 — / 资源级分类                                   | 保留员工名称，使用当前默认头像；必要时提供「重新加载图片」                                       | 图片自身 / 无大图                   | 装饰性资源失败不升级成页面故障；错误页插画自身失败也应隐藏并保留文字按钮                          |
| 18. local/sessionStorage 被禁止或容量不足                    | — / `client_storage_unavailable`（拟增）                     | **当前浏览器无法保存恢复信息**。刷新或关闭前，请复制需要保留的内容。「复制内容」                 | 仅影响恢复能力时提示 / 无大图       | 内存中的输入继续可用；不能声称“草稿已保存”，更不能通过不停刷新恢复                                |
| 19. 浏览器缺少必要能力或禁用了 JS                            | — / `client_unsupported_browser`（拟增）；JS 关闭用 noscript | **当前浏览器暂不支持此页面**。请使用支持所需功能的浏览器，或启用 JavaScript 后重试。             | 静态简页 / 检修小图标               | 按功能检测，不凭 UA 随意拒绝；可选外观能力应降级而不阻断                                          |
| 20. 首次访问站点即 DNS/TLS/连接失败                          | 无本站响应 / 浏览器网络错误                                  | 浏览器自己的错误界面；站内无可执行文案                                                           | 本站无法覆盖                        | 主机名未解析、TLS 未建立或整站无响应时，站点的 HTML/图片/React 都尚不可用；不承诺自定义离线首访页 |

### 服务、依赖与容量

| 场景                                | HTTP / 稳定分类                                                                                                                          | 建议文案与操作                                                                                       | 展示 / 配图             | 原因与边界                                                               |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- | ----------------------- | ------------------------------------------------------------------------ |
| 21. 本服务内部未知异常              | 500 / `internal_error`（拟增安全兜底）                                                                                                   | **服务处理遇到了问题**。请稍后重试；持续出现时，可向维护人员提供问题编号。「重试读取」               | 首屏整页或原区域 / 检修 | 当前未知异常未统一该 code；新增时需记录异常与关联 ID，不能吞错或返回堆栈 |
| 22. 服务繁忙或必要依赖暂不可用      | 503 / `database_busy`、`runtime_unavailable` 等                                                                                          | **服务暂时不可用**。请稍后再试；有等待建议时显示「建议 N 秒后重试」。「稍后重试」                    | 请求范围内 / 检修       | 不在没有运维信号时宣称“正在维护”“正在抢修”；依赖错误可能需要人工修复     |
| 23. 计划维护                        | 503 / `maintenance`（拟增，仅来自明确维护开关）                                                                                          | **服务正在维护**。维护完成后即可继续使用。仅有可信计划时显示预计时间。「重新检查」                   | 网关静态整页 / 检修     | 与意外故障分开；不编造恢复时间，API 仍应保持 JSON 错误协议               |
| 24. 网关无法连接上游或收到无效响应  | 502 / 网关分类；`client_gateway_unavailable`（拟增前端归类）                                                                             | **暂时无法连接服务**。请稍后重新连接。「重新连接」                                                   | 整页或区域 / 连接       | 502 来自网关层；当前应用的工具/模型上游失败仍沿用既有 503 或 Run 错误    |
| 25. 网关等待应用响应超时            | 504 / 网关分类；`client_gateway_timeout`（拟增前端归类）                                                                                 | **服务响应超时**。读取可重试；刚提交过操作时，请先检查结果。                                         | 原区域 / 等待           | 不等于写入失败，不自动重放 POST；不能通过取消浏览器请求断言任务已取消    |
| 26. 请求过于频繁                    | 429 / `rate_limited`                                                                                                                     | **操作有点频繁，请稍后再试。** 有 Retry-After 时按其倒计时。「N 秒后重试」                           | 操作行内或区域 / 等待   | 没有等待头时不给虚构倒计时；倒计时结束仅允许重试，不自动重复写入         |
| 27. 执行、订阅或沙箱容量已满        | 429 / `run_capacity_exceeded`、`subscription_limit`；503 / `sandbox_capacity_exceeded`、`stdio_capacity_exhausted`                       | 执行：「**当前执行名额已满，请稍后再试。**」订阅：「**打开的对话连接过多，请关闭其他窗口后重试。**」 | 对话操作或横幅 / 等待   | 容量拒绝不等于任务已入队；不展示不存在的队列名次或百分比                 |
| 28. 工具/MCP/模型连接读取失败       | 503 / `tool_connection_timeout`、`tool_connection_failed`、`tool_upstream_failed`、`tool_dns_failed`、`stdio_session_closed`；Run 见后表 | **暂时无法连接这项服务**。请稍后重试；持续失败时检查连接配置。「重试连接」                           | 连接卡片或消息 / 连接   | 限定故障服务范围，不把单项依赖问题升级成整站不可用                       |
| 29. 服务器密钥或模型/工具凭证不可用 | 503 / `model_credentials_unavailable`、`tool_credentials_unavailable`                                                                    | **当前连接配置需要检查**。请由有权限的人员检查凭证后再试。授权用户显示「检查配置」                   | 连接区域或消息 / 装配   | 503 也可能无法靠等待修复；不能自动高频重试，不能回显 Key 或加密细节      |

### 输入、保存与状态冲突

| 场景                                   | HTTP / 稳定分类                                                                                                     | 建议文案与操作                                                                                                   | 展示 / 配图                 | 原因与边界                                                                          |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- | --------------------------- | ----------------------------------------------------------------------------------- |
| 30. 字段或业务参数不合法               | 422 / 框架字段列表；`input_required`、`skill_parameters_invalid` 等                                                 | **请检查标记的内容后再提交。** 字段旁给出具体原因并定位首个错误                                                  | 表单行内 / 无大图           | 字段错误应在输入处解决，不跳转错误页；保留用户输入                                  |
| 31. 消息、上传文件或请求体过大         | 413 / `request_too_large`；422 / `input_too_large`、`file_too_large`、`file_quota_exceeded` 等                      | **内容超过当前大小或存储限制**。请缩小文件或精简内容；存储不足时请联系管理员检查。只有服务端已公开限制时展示上限 | 上传行或输入框 / 无大图     | 保留传输检查与业务校验的现行差异，不统一改成 413                                    |
| 32. 内容格式不支持或请求来源无效       | 415 / `unsupported_media_type`；403 / `invalid_origin`                                                              | **请求未能提交**。请从本站重新打开后重试；持续出现时联系维护人员。                                               | 操作行内 / 无大图           | 通常是客户端或部署配置问题，不提示用户“申请管理员权限”，不自动退出登录              |
| 33. 配置被别人更新、修订冲突           | 409 / `configuration_revision_conflict`、`rules_revision_conflict` 等                                               | **这份配置已被更新**。当前输入仍在页面中，请核对最新版本后再保存。「查看最新版本」                               | 表单内 / 装配小图标         | 先比较修订再由用户决定；禁止自动覆盖服务器最新内容                                  |
| 34. 重名、资源被引用、操作时机不允许   | 409 / `agent_name_conflict`、`model_connection_in_use`、`skill_in_use`、`conversation_busy`、`retry_not_allowed` 等 | 随 code 给具体原因，如「**名称已被使用，请换一个。**」「**仍有员工使用这项配置，请先解除关联。**」               | 相关字段或操作行内 / 无大图 | HTTP 相同但恢复动作不同；不能统一显示“刷新重试”                                     |
| 35. 员工停用、缺模型、技能或沙箱未就绪 | 多为 409/422，依赖分支可为 503 / `agent_inactive`、`model_not_configured`、`skill_not_ready`、`sandbox_not_ready`   | **这位员工还没准备好接单**。具体说明缺少哪项配置；授权者「去配置」，其他用户「返回员工目录」                     | 员工工作区 / 装配           | 业务前置条件失败，不画作服务器崩溃；同 code 在不同边界有不同 HTTP，按真实响应记录   |
| 36. 写入断网、超时，结果未知           | — 或 502/504 / `client_submission_unknown`（拟增，状态）                                                            | **还无法确认是否提交成功**。请先检查服务器结果，再决定是否重试。「检查结果」                                     | 当前表单或消息 / 等待小图标 | 普通保存读回修订核对；对话使用原 client_request_id 核对与同键恢复，不能换键自动提交 |
| 37. 客户端与接口版本不兼容、方法不支持 | 404/405 等真实响应 / `client_api_mismatch`（拟增，仅有契约证据时归类）                                              | **页面与服务暂时无法正常配合**。请重新打开页面；持续出现时联系维护人员。                                         | 原区域 / 检修               | 普通业务 404 不等于版本错误；API/静态资产缺失不能收到 index.html                    |

协议补充：当前静态交付还可能返回 **406**（Accept-Encoding 没有可接受的资源编码），应说明“当前请求无法读取页面资源”，保留 `Vary: Accept-Encoding`，不归类成权限或业务内容不存在。**405** 保留 `Allow` 头；未知 4xx/5xx 按请求上下文安全兜底，不猜测业务原因。**410** 仅适用于服务端能确认永久移除的未来契约，当前资源 404 不升级为 410。代理请求读取超时可能返回 **408**，它与浏览器自行停止等待、上游响应超时 504 分开记录。

### 恢复交互

1. 404默认不自动跳走，可明确开启8秒返回并随时取消，页面不可见时暂停。示例返回各自所属列表；正式接线仅在有可靠本站来源时提供上一页返回。
2. 读取失败提供有界的手动重试。预览可切换“下一次检查已恢复”来检查成功与未恢复两种结果；不请求真实接口。
3. 429和503只有在示例明确提供`Retry-After: 8`时才显示倒计时。按截止时间计算，结束后仅允许手动重试，不自动重复写入；无等待头时不编造秒数。
4. 读取超时与提交超时使用不同文案和动作。提交后结果未知先“检查结果”，不把超时等同于失败，也不重新POST。
5. 配置问题按是否具备配置权限显示检查配置或返回入口。修订冲突显示服务器最新版本时保留当前草稿。
6. 插画失败应保留完整错误码、文字与按钮；不再用插画替换任何数字。除已有成功恢复证据外，不声称草稿已保存或数据不会丢失。

## 技术实现链路

以下为原始总体链路。当前具体增量、标准、评审与实施范围以[统一接入方案](error-handling-integration.md)为准；用户已认可404配图和弹性排版，并授权独立评审通过后直接实施。

### 从访问到恢复的完整过程

1. **浏览器建立连接。** DNS/TLS 尚未完成时由浏览器处理。若有独立反向代理，代理可在自身正常、应用不可达时给页面导航返回静态 502/503/504 页面；本站源进程和代理同时不可达仍无法展示。
2. **静态交付决定页面还是资源。** 已知页面继续按当前白名单交付 index.html。未知的人类页面导航返回真正 404 的品牌静态页；API、`/assets`、品牌、头像路径以及资源扩展名请求保持原资源语义，不用 SPA HTML 掩盖失败。分类需结合路径、请求方法及明确的文档导航信号，不能只凭 Accept 包含 HTML。GET/HEAD、405、压缩与缓存规则保留。
3. **HTML 启动前兜底。** index.html 放最小内联样式、文字/重载链接、noscript，以及有界启动观察。若入口 JS 未完成启动，超时后先显示“加载时间较长”，存在明确脚本失败信号时再显示“页面资源未能加载”。不能仅凭加载慢认定版本错误。React 成功挂载后撤销启动兜底。核心文案与按钮不依赖 React、主 JS、业务接口或远端字体。
4. **React 路由分层捕获。** 根边界负责根故障，Layout 内的子边界保留工作台外壳；404 通配路由放在正确外壳层级。登录、帮助、设计系统等独立入口都有明确出口。懒加载异常交给可提前加载的兜底组件；异步事件与 Hook 内请求仍由其拥有者处理，不能期待 React ErrorBoundary 捕获全部异步错误。
5. **统一 HTTP 客户端解析。** request 保留真实 status、安全 code、字段定位信息，增加 Retry-After、请求关联 ID 与客户端故障原因。同时兼容现有 detail 对象、422 数组、JSON 错误、代理 HTML/空体和未知响应。明确主动取消与超时两类 AbortSignal；调用者取消不提示，超时才归类等待失败。成功关键 DTO 在边界验证必要字段，不对全部接口引入无价值的大框架。
6. **身份与授权。** 只有本站明确会话失效才进入登录；`invalid_credentials` 留在登录表单，`invalid_origin` 不清会话，503 不降成游客。权限变化取消旧请求并清理相关身份域状态。继续复用 safeReturnPath，恢复地址不接受站外 URL；普通权限拒绝不会触发登录死循环。
7. **页面拥有者选择恢复方式。** HTTP 层输出事实，页面按“首屏读取/刷新/写入/订阅”和当前是否有数据决定整页、区域、横幅或行内。稳定 code 优先细分动作，再按 status 兜底。未知 code 不能直接映射成全局 500，也不能靠 message 字符串匹配。
8. **服务端产生公开错误。** 业务继续抛七类 ServiceError，由 API 层转换 HTTP。未知异常增加安全 500 envelope 与日志关联，记录真实 traceback 后返回通用 message；框架 HTTPException、422、OAuth 和已开始的 SSE 保留各自协议。不得把所有 Exception 都转换为 503 或误吞取消信号。
9. **重试与写入核对。** 有界重试仅用于可安全重复的读取，建议最多自动重试两次，使用退避和抖动，遵守 Retry-After；手动按钮也要防止并发点击。写操作不由通用 HTTP 层自动重放。普通保存读回版本核对；现有对话按原幂等键查询接受结果，已接受继续订阅，未确定时按已有同键恢复契约处理。已失败 Run 的显式重试使用新键，并遵守许可和未知副作用边界。
10. **对话与实时恢复。** SSE 中断先只读拉取持久化 snapshot，再恢复观察，保留 conversation scope 与单调 version 合并。断线不 POST 新任务。建流后的故障使用事件/断流协议；模型、工具、预算、持久化异常进入 Run.error，不能事后修改原接受响应的 HTTP 状态。取消成功与断开连接分别验证。
11. **观测闭环。** API 与代理透传同一经校验的 request ID，执行问题额外关联 conversation/run ID。建议记录状态、code、路由模板、版本、时长与来源；不收集正文、输入文件、Token 或带敏感查询参数的完整 URL。前端故障在后端不可达时只做有界本地暂存与降级日志，不依赖故障中的接口才能显示错误页；新建上报端点、访问控制和保留期限属于后续实施设计。

### 前端数据与组件职责

建议在现有 ApiError 上增量扩展，不引入新的全局错误路由跳转器，也不把所有局部失败塞进全局 Context。

```ts
// 拟议结构；不是已实现 API。status=0 是当前兼容值，归一化时转为 null。
type Failure = {
  source: "http" | "network" | "client" | "run";
  status: number | null;
  code: string;
  message: string;
  retryAfterSeconds?: number;
  requestId?: string;
};

type FailureContext = {
  operation: "initial-read" | "refresh" | "mutation" | "subscription";
  hasUsableData: boolean;
  resource: "agent" | "skill" | "conversation" | "file" | "other";
};
```

Failure 只保存事实。纯映射函数结合 FailureContext 产出标题、说明、配图 key 和动作语义；实际 reload、核对提交、打开配置由页面拥有者提供。组件不请求接口、不凭 503 自动判定可重试、不推断页面权限。

### 三条典型链路

1. **后端暂不可用：** `/agents` 的 HTML/JS 已加载 → auth/me 或目录读取失败 → HTTP 客户端识别无响应/真实 502/503 → 身份边界或列表 Hook 判断影响范围 → 连接/检修配图 → 用户重新读取原资源 → 成功后回原视图。不是先退出登录再循环跳转。
2. **内容不存在：** 已知详情路由能加载 → 对应 API 返回 404 + resource code → 原内容区域展示寻找配图 → 返回相应列表并保留筛选/来源。直接输入未知页面 URL 则由静态交付返回 404 文档；SPA 内未知路径由 router 通配处理，视觉相同但 HTTP 层不同。
3. **提交后网络断开：** 客户端保留原输入、原请求键 → 展示“结果待确认” → 查询请求或读回修订 → 已成功则展示服务端事实；未明确成功时才按具体幂等契约恢复。不会因为错误页的“重试”重复交办任务。
