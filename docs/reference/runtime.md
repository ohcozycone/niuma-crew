# 运行、动作、恢复与证据契约

Run记录一次工作的执行事实，业务另行接纳成果。本页维护跨来源执行、观察、取消、恢复和诊断读取；对话消息规则见[对话契约](conversations.md)。

## 接受、快照与幂等

接受在一个短事务中保存对话、用户输入、空助手 Message、Run、冻结输入和绑定。client_request_id 的唯一范围是发起用户和操作；同键同摘要返回原记录的当前读取结果，不同内容返回冲突。重放先于当前容量和配置检查。

接受时固定岗位、规则、方法内容、装配身份、模型修订、输入上下文和预算；启动与动作前仍复核当前会话、员工启停、模型装配/修订、已激活方法和本次资源。固定内容不意味着权限也固定。

员工固定配置由 execution/snapshot 捕获，RunTask 创建真实客户端和受限资源。execution/service 提供应用事务内的受理、取消和完成；对话应用组织当前输入、已接纳执行标识及业务关联，再调用内部受理操作。执行可复用不等于直接开放客户端创建 Run，当前没有独立任务 HTTP 提交入口。RunWorker 只提交执行事实，不调用对话发布来完成 Run。

## 运行观察与结果持有

对外提交、读取、停止、重试、SSE 和成果下载统一由对话应用提供，见[对话契约](conversations.md)。执行模块不提供独立 HTTP 路由或另一套 RunRead 投影。应用通过内部受理和取消操作参与自己的事务；执行宿主通过 complete 保存成果与终态。

公开 Python 操作也接收可信 Actor 并检查 runs 能力和记录归属，不能绕过 HTTP 授权。当前后台继续沿用发起会话及资源许可复核策略；本次不擅自引入服务身份、离线委托或改变登出语义。

Run 的 result_text/result_data 是执行成果，Message 是应用接纳后的正式回复。执行输入和成果文件引用随 Run 保留，应用接纳前也不被文件清理误删；删除 SDK checkpoint 不影响成果。当前不提供 Run 自动过期或删除接口，持有随相应 Run 存在，不以 HTTP 回包送达为成功条件。

对话回复增加 acceptance（pending/accepted/failed）及 acceptance_error，表达应用处理，不是另一份执行状态机。接纳暂时失败只重试同一份成果。正常续接只选择成功且已接纳、接纳无错误的 Run；模型上下文从该执行的 SDK 存档读取。前端在 pending 时继续订阅，显示执行已完成、正在保存回复；不把接纳失败显示成 Agent 失败。

## 调度与并发计数

一次被接受的输入建立一条 Run；幂等重放、打开对话和观察连接不新增 Run。不同用户或不同对话使用同一位员工时，各自的输入、历史、资源依据和成果属于各自 Run。累计工作数量与当前同时执行数量分别计算。

全平台不再设置 Run 同时执行数量上限。[RunWorker](../../backend/app/runtime/execution/scheduler.py) 在服务就绪时调度已接受 queued 记录，并用在途任务表防止同一 Run 重复启动。队列容量、单用户未结束容量、同一对话只接受一份活动工作、动作预算、时限和资源许可仍分别生效；取消总量门槛不扩大任何资源权限。

原 `RuntimeConfig.concurrency / RUN_CONCURRENCY` 已移除或不再读取。当前配置入口见[运行配置](../../backend/app/runtime/execution/config.py)；已确认的文件职责与方法协作见[运行管理标准](../records/README.md)。

## checkpoint、历史与恢复

页面历史只读取业务 Message，不访问 SDK。连续对话的每次输入仍创建独立 Run，但共用稳定 Thread。正常追问仅新增当前问题，从最近成功且已接纳 Run 的明确 checkpoint 接续 SDK 消息、完整配对工具消息、官方技能 pin 消息与摘要。新 Run 单独初始化文件、技能发现缓存和用量；恢复同一 Run 则不重置这些工作。失败或取消分支不作为后续起点；没有基点时只使用当前输入；选定基点却线程不符或没有存档时明确拒绝，不从 Message 回填。

同一 Run 重启恢复时，按线程和 app_run_id 查找属于本轮的最新可信 checkpoint，保留冻结输入、开始时间、已用预算、已激活动作与累计未知用量。页面历史不是执行恢复的替代品。知识内容或授权范围改变时保守重置执行记忆，正式历史仍保留。单纯增加可用技能或工具保留普通记忆；移除或修改已存在的技能/工具及关键配置时重置。

可信且待继续的普通 Agent 存档可继续；可信完成标记且 Run 仍活动时只补执行成果保存，不再调用模型。缺失、不兼容或不支持恢复的存档不自动重放，收束为 interrupted。已终止 Run 不因存档有完整文字而改写。

SDK 提交与业务提交分开：SDK 内部完成只是恢复依据，Run 成功以执行成果及终态事务为准，应用接纳另行提交。未完成模型请求可能重发并重复计费，未报告的用量保持未知。当前不提供多主机租约或通用外部副作用重放保证。

## 实际 SDK 与预算

普通 Agent 使用 LangChain、Deep Agents 文件工具与 SQLite checkpoint；基础文件、MCP 工具与沙箱已接入，范围、预算、来源和部署条件见[基础工具契约](files-and-environments.md)。新工作使用快照版本 8，同一 Run 自动恢复仅接受版本 8；旧活动 Run 应在升级前排空，未排空者明确中断，历史记录仍可读；虚拟文件首次修改前仍可按可信存档恢复，开始修改后标记不可重放；沙箱和外部工具 Run 不在重启后自动重放。

模型次数、方法读取次数、上下文字节、可见正文/思考字节、输出 token、总时限和图步数各自受限。图步数不等于模型次数。模型动作开始前，在同一写事务复核许可、扣减次数并保存动作；预占失败时不发出外部调用。工具同样共享 Run 总调用次数；额外的单工具限次只按授权策略执行，知识工具不附加固定限次。MCP 的许可限次及未配置时的既有默认值保留。

持久模型预算只剩一次时，该次请求移除工具，要求依据已有证据回答并说明未完成部分；不再启动摘要占用这次额度。此时仍经过原有输入、输出、授权和原子次数检查，不增加额外模型调用。模型若仍返回工具请求，明确失败而不执行。该收尾只保证限定条件下保留回答机会，不代表任务已全量完成，也不保证外部服务、容量或输出错误时仍可成功。

## 官方记忆、摘要和用量

连续线程通过官方 SQLite Saver 保存。平台提供数据库路径和 Run 归属回调，不复制框架存档格式。SummarizationMiddleware 按估算消息 token 阈值生成摘要并保留近期消息；当前阈值默认 16384，保留 4096，可用 RUN_SUMMARY_TRIGGER_TOKENS、RUN_SUMMARY_KEEP_TOKENS 配置。保留预算必须小于触发预算，配置在接受时冻结。

摘要使用官方选择、保留和状态更新算法，关闭摘要请求前额外的默认历史裁剪，避免长工具消息将原任务裁空后替换成“无法摘要”的占位文本。选定历史完整交给受管摘要入口；入口仍先检查现有上下文字节、当前授权及次数，超限停止而不替换历史。模型调用计入本 Run 的次数、总时限和实际用量。仅剩一次额度时跳过摘要，其他已启动摘要的故障仍按运行失败处理，不能把内部摘要作为正式回复。摘要缩短上下文，不压缩历史 checkpoint 数据库，也不删页面消息；极大单条消息、工具定义及系统指令仍可能触发已有上下文字节限制。

实际 token 读取标准 usage_metadata，已知值用官方 add_usage 累加；中断和未报告项保留未知。平台持久动作账本统一限制本 Run 的模型调用尝试，包含普通回答、摘要、失败和结果未知的请求，重启不重置；不再装配重复的 ModelCallLimitMiddleware，也不叠加 ToolCallLimitMiddleware。所有实际工具仍走现有持久动作门。当前不是用户余额/金额扣费系统，未启用通用自动重试。

## 本轮允许与实际使用

接受时捕获可用方法，显式选择可预加载，其他按需读取。装配重建即使复用相同 ID 也通过 created_at/revision 被识别。已激活方法集合从成功动作恢复；授权检查合并既往与本次申请，发布前重读持久动作。

一次模型的工具请求只是意图。工具实际开始、成功返回及方法激活分别记录；失败或未知结果不冒充已经加载。

Agent 创建时声明 AgentRuntimeContext，每次调用及恢复通过官方 context 参数传入本轮 host 与 run_id。工具中间件读取 ToolCallRequest.runtime，核对所属 Run、工具注册和调用 ID；内部工具按本 Run 注入窄回调，通用工具门继续核对官方运行上下文。运行上下文不属于模型可填写的参数，也不进入持久消息状态或 checkpoint；恢复时由新建的本轮执行对象重新传入。

动态 MCP 保留远端参数 Schema，通过官方 request.override(tool=...) 为每次调用绑定独立执行函数，不修改共享工具实例，远端名为 runtime 的业务字段仍作为普通参数传递。调用 ID 仅用于关联；实际许可仍由平台在授权、预算和动作记录的同一事务中申请，缓存复用也先复核授权。单次许可和调用信息留在本次调用栈中，结果保存成功后才返回模型；同步知识读取取消时仍等待所属线程退出，再由 Task 收尾。

本轮重新核验的知识证据、预检索结果、输入文件清单及记忆重置说明，通过官方模型中间件临时补充，补充消息不写回 checkpoint，用户原文不变。历史知识引用的清洗只作用于临时视图中的基点消息，不改本轮新证据、用户输入或持久消息，也保留结构化内容块。最终模型权限、体积和预算检查包含补充资料。保留旧消息不扩大旧结果编号的读取范围。

## 工具发现与实际可见范围

员工固定组织连接与知识范围，受理事务捕获版本；发起用户仍决定工作访问和审计身份，不用于重新选择资源。工具更新的候选清单只有应用确认后才进入员工授权范围。运行搜索只查询本 Run 冻结的已授权工具，不联网补目录或自动切换账号。

基础文件、条件沙箱 execute、条件知识和结果读取常驻。存在外部候选时提供 search_tools，默认返回 5 项、最多 10 项；MCP 完整定义及适用服务说明在命中后的下一次模型请求展开。候选最多 128 项，显式投影连同来源说明最多 1 MiB；分别以 tool_candidate_count_exceeded/tool_candidate_bytes_exceeded 拒绝受理。模型原有 128 KiB 上下文字节预算独立生效，包含历史、临时资料、实际工具及说明，不因候选增加而放宽。

发现结果先持久化，成功后才更新官方图状态。并行搜索合并后重新检查整体请求容量，超限不发模型请求。实际可见工具清单与模型动作原子保存；工具调用必须属于产生它的父请求可见集合，并继续通过当前授权检查。猜名、同批搜索后立即调用及缓存命中都不能绕过这一限制。

搜索索引使用关键词匹配，不保证中文词直接命中英文描述；模型可在正常规划中生成英文或双语 query。没有隐藏翻译模型、自动全量回退或搜索失败后的授权扩张。发现动作仍记作 tool_call，通过 category=tool_discovery 记录匹配、待加载、耗时及版本。query 与可恢复反馈受诊断权限控制。

同一版本续聊沿用 conversation:v8:<id>；升级前的线程不读入新图。旧成功基点经过归属核对后，新轮以新线程显式重置工作上下文；正式对话和旧来源阅读记录保留。未知快照不自动恢复，外部 MCP 与沙箱的重放限制不变。

## 外部读取证据与长结果

MCP 返回先保存原始协议与冻结文本。中小结果完整交付；大文本复用官方 FilesystemMiddleware 生成预览及 `/sources/large_tool_results/` 只读路径，模型按需使用 `read_file` 或 `grep`。SDK 路径只关联已有归档，不再复制一份长正文；路径关联随原工具动作可靠保存，同 Run 重建后仍可读取。每次读取复核当前授权与 Run 归属，不能通过路径取得另一轮资料，也不重跑远端业务操作。

`read_tool_result` 继续提供旧结果编号与冻结文本的字符分页，仅接受本 Run 已保存结果，复核来源工具当前许可。MCP 结果的移存和原生读取反馈同时提供可调用的归档编号；仅对本轮已提供字符读取工具且来源受支持的结果展示该能力：`read_file` 的行偏移无法到达被截断单行的后半段时，可从字符 offset=0 开始，再按返回的 next_offset 继续。旧格式和版本 2 的冻结文本保持不变，不重排 JSON 或变更游标。字符游标表示本地文本位置，不是上游业务分页；文本完整也不证明业务集合完整。新反馈不再强制包装固定 3,000 字符预览。

字符读取的 offset 为非负整数，limit 为期望的正字符数。正文每次最多返回 8,000 UTF-8 字节，不另用 12,000 字符上限拒绝较大请求；end 和 next_offset 根据实际返回文本计算，不能用请求的 limit 推算下一页。Schema、描述与后端按同一含义处理。工具执行中可修正的 tool_arguments_invalid 保存为失败工具反馈供模型处理；取消、撤权、持久化故障、结果未知及其他执行错误仍按原规则收束，不泛化为可重试结果。

官方结果移存阈值从本轮现有输入字节预算推导，不将 SDK 的字符近似当成真实 token 数。各结果移存不代替整个请求的容量检查；官方摘要后仍超限时明确拒绝，不再静默裁剪或破坏 JSON。输入字节按公开模型侧消息和工具投影估算，排除仅应用侧的 artifact；该估算不是精确供应商 HTTP 大小、模型窗口或费用。输出限制、任务限次和权限规则保持独立职责。

通用反馈规范化只处理格式与状态，不再截取 24 KiB。文件/知识继续使用自己的存储与原生读取入口；工具门记录 SDK 处理后的实际反馈和必要来源元数据。read_file 的请求行数不一定等于实际返回范围，不能从请求参数或显示行号推断精确原文坐标。普通工具结果不会自动注册为回答引用。搜索摘要、网页正文与实际读取范围由能力契约和返回证据明确表达，不根据服务名或私有字段猜业务完整性。

新结果保存格式版本 2，包含来源绑定、原始内容、状态和冻结的分页文本。文本内容与多模态块、结构化 artifact 分别保留；大 artifact 不重复注入模型正文。旧结果沿用原有通用文本投影供读取，保持旧游标，不重新调用外部服务。通用执行层不以自然语言正则或私有网页字段阻断成果提交；工具成功、内容完整和回答准确仍需分别核验。

## 流式回答与思考展示

SDK 片段在 agent/streaming 解析、拼接和识别工具轮；普通 ContentUpdate 跨过边界。RunContext 负责缓冲，RunTask 看护保存频率，Store 只保存普通字段。

页面只观察已提交内容，不直接转发未持久化 token。完整响应覆盖暂存片段，结束后的迟到更新不能覆盖。思考按 UTF-8 字节截断并保留截断标记，恢复时仍占原预算。

助手视图 content 已由服务端选定：活动时为当前可见草稿，成功且已接纳时为 Message 的完整正文；成功但尚未接纳时可展示已保存执行成果，标记为 draft；其他终态为允许的部分正文或空串。前端不再选择模型轮，也不把工具正文当聊天回复。

## 取消、故障与历史

排队停止可直接提交取消并释放占用；运行停止先记 cancelling，由看护关闭执行。显式停止精确指向回复，迟到请求不能停止下一次工作。SSE 断线只释放观察连接。

取消与完成竞争由运行公开操作在短写事务中裁定。Run 的完整正文、结构化成果和终态一起提交；对话另行保存正式回复、文件关联并释放业务占用。已经成功的 Run 不因应用拒收、接纳失败或迟到取消而改变。普通故障只保留执行器明确给出的允许片段，不能兜底取最后工具轮。撤权不增加可见正文。

执行成果或过程存储失败时停止后续动作并使宿主降级，存储恢复后按 persistence_unavailable 收束；重启补成果仅适用于仍活动且完成存档可信的 Run。对话接纳失败不降级执行宿主，不重跑模型；应用扫描持久关联恢复处理，暂时错误按指数退避重试，最长间隔 60 秒，明确权限/资源拒绝记录为接纳失败。

## CI 与后续知识能力

CI 对话诊断试验已退役，专用执行、报告/反馈及配置入口移除；本次重建不再保留旧消息、Run 或运行时兼容分支。新普通消息、通用 MCP 与 GitHub 登录继续使用各自入口，见[退役说明](../guides/backend-operations.md)。

独立业务 Task、Goal、多引擎和业务工作流引擎尚未实现；内部 RunTask 只执行一次 Run，不代表新增业务任务实体。不能从当前目录或 SDK 能力推断这些业务能力已开放。未来新增业务来源定义自己的输入与结果接纳，复用既有执行公开接口。

## 执行证据

独立执行详情复用既有 Run/RunAction 与业务关联。每次真实模型请求、SDK 响应及工具申请/反馈可按私有文件引用查询；不改变提交、恢复、接纳或考核评分。详细[字段、权限、保存和故障语义](runtime.md)。

## 采集内容与含义

1. **wire_request**：实际发送的 JSON，包含 system/messages/tools 与模型参数。每轮单独保存，所以第二轮能看到上一轮工具反馈。它是经凭证字段脱敏后的请求证据。
2. **sdk_response**：SDK 合并并解析后的响应，包含正文、工具申请、可用的供应商思考字段、响应元数据及用量；不是原始网络 SSE 字节流。
3. **model_error**：调用没有得到完整响应时，记录已分类的错误码，不保存上游异常正文。取消/进程被杀前未完整采集的响应可能缺失，动作状态与已有过程文字仍保留。
4. **tool_request**：模型申请的参数、授权状态，以及平台实际传给工具处理链的参数。包括技能读取对 offset/limit 的改写；SDK 内部后续注入的对象和默认值不伪造为已观察值。
5. **tool_response**：实际反馈给模型的内容、状态、附加数据和来源。外部工具的大原始结果继续使用既有 source 文件，页面提供下载入口；历史结果可复用原 result_payload，但明确标成恢复记录。
6. **思考内容**：只展示供应商实际返回的可见字段或标准 reasoning 块，默认折叠，未提供时不建立空展示区；摘要截断沿用原预算，不承诺模型内部完整思维。

证据文档包含 `schema_version=1`、`capture_stage`、脱敏规则版本和 `payload`。已知密码、API Key、Cookie、Authorization、令牌等结构化字段及 Bearer 字符串被遮盖，也处理嵌套 JSON 字符串；这不是对任意自然语言秘密的自动识别。实际执行输入不会被脱敏函数修改。

## 数据保存与故障边界

- 数据库只增加 RunAction 的 nullable `request_file_id`、`response_file_id`，均引用现有 StoredFile；StoredFile 的 purpose 增加 `evidence`，没有新增表。
- 证据正文在现有文件目录保存，字节先写入并完成同步，再把文件登记和动作引用一起提交。事务失败产生的未持有字节由原 FileCleanup 清理；已被动作持有的证据保留，不当作临时孤立文件清理。
- evidence 不进入普通附件、source 列表、模型文件选择或 SDK 工作区。普通上传/产物配额与证据配额分开。
- 每文件沿用 `FILES_MAX_FILE_BYTES`；证据每 Run 默认 64 MiB、每所有者默认 512 MiB，分别由 `FILES_MAX_EVIDENCE_RUN_BYTES`、`FILES_MAX_EVIDENCE_OWNER_BYTES` 配置。达到上限后本次证据可能缺失，不影响原对话和考核执行。
- **证据属于诊断扩展**：采集失败保留安全诊断事件，不替换动作结果或阻断外部调用；原动作事实、工具恢复数据及成果事务失败的处理不变。页面明确区分未采集、不可读、无权限和预览截断。不能把「未采集」解释为「没有发送」。
- 开启运行器时，核心执行日志写到 runner.lock 同目录下的 `logs/execution.jsonl`，每文件 5 MiB，保留 3 个轮转文件。只保存时间、级别、日志来源、Run、动作键、事件、错误码及安全的异常类型/源码位置，不复制消息正文、异常字符串或任意日志参数。目录/日志写入故障不阻断业务。最多有界读取四个文件、返回最近 200 条匹配事件；未开始采集的旧运行、进程硬退出和已轮转事件可能没有日志。

## 查询接口与权限

| 接口                                                                                | 用途                      |
| ----------------------------------------------------------------------------------- | ------------------------- |
| `GET /api/conversations/{id}/responses/{response_id}/trace`                         | 指定回复的执行详情        |
| `GET /api/conversations/{id}/trace`                                                 | 该对话最近一次执行        |
| `GET /api/evaluations/{batch_id}/cases/{case_id}/trace`                             | 本人考题的执行详情        |
| 对应指定回复/考题路径后接 `/trace/actions/{action_id}/evidence/{request或response}` | 下载该动作的完整证据 JSON |

详情接受 offset、limit（1—100）、action_id。返回 run、configuration 概要、actions 分页、failures（全 Run 失败总数及前 20 项）、selected 动作详情、can_inspect_inputs 和 logs；对话还返回原问题、交付保存状态与同题最近 20 次执行尝试。列表不携带其他动作的完整证据文件。单个证据最多内联预览 256 KiB，更大文件显示截断并提供完整下载。响应均为 `Cache-Control: no-store`。

模型动作增加 metrics 数值投影：usage（输入、输出、总量及 reasoning_tokens）、usage_source、output_limit 和 output_limit_field。用量优先提取已保存响应，缺失时回退动作已记录用量；输出上限仅从实际请求的 max_completion_tokens 或 max_tokens 提取。仅有诊断权限时读取证据，受限或截断证据不补造数值；普通身份继续只使用已有公开动作用量。仅投影当前页、失败步骤和显式所选步骤，同一次查询复用证据读取，不新增采集或数据迁移。

所有读取先要求 runs:read；对话还要求 conversations:read 并核对归属和回复关联；考核只读当前用户的批次，核对考题和 Run。完整模型输入、工具载荷和技术日志额外要求 agents:read 与 organization_rules:read，当前对应管理员。普通成员只得到已有公开动作信息，下载再次授权。客户端不能提交任意 file_id 越过业务关联。

前端按身份和资源隔离数据；切换动作取消前一次请求；活动执行每 2.5 秒串行刷新，终态停止。对话执行成功与回复保存成功分开展示；考核评分继续在原报告里查看，进入详情不创建对话、不重跑考题。

## 快照版本与实现入口

当前版本和支持集合由[执行契约常量](../../backend/app/runtime/contracts/runs.py)维护，当前快照为版本8且只恢复该版本；旧个人资源线程在新一轮显式重置工作上下文，正式历史保留。不支持的恢复输入明确中断。升级运行代码前按[运维指南](../guides/backend-operations.md)核对活动工作和备份。内部控制链见[执行机制](../../backend/app/runtime/execution/README.md)。

## 失败分类与步骤定位

Run 终态由执行事实决定，公开文案由应用读取时生成；字段含义及类型归属见[失败契约](failures.md#执行失败事实与应用文案)。工具失败保留明确错误码，unknown 仍表示结果未确认。存储故障继续走原协调重试，不转成普通业务拒绝。该调整沿用现有表、动作关系、快照版本和历史数据。
