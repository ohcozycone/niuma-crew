# 知识库技术验证增量

状态：用户已授权 POC，核心组件与离线验证已实现，两例 BM25 + 真实 Kimi 问答已核对；用户选择暂不接入 Embedding，保留接入入口，真实向量效果后续验证。正式上传 API、业务表和页面尚未接入。路线与详细方案继续以 [Notion 导航](implementation.md)为准。

## 本轮范围

1. 在现有后端增加可复用的知识加载、切分、FTS5/Chroma、混合召回和引用校验核心，由独立实验命令调用。
2. 仅显式加载教学资料清单中的 documents；评分材料留在评测侧。支持 TXT/MD、文字 PDF 与 DOCX 的受控样本；格式夹具不代表真实复杂文档验收。
3. 独立持久目录保存不可变制品；验证重开、范围/空间不匹配、损坏与失败构建，正式业务 SQLite 发布指针在后续增量实现。
4. smoke 使用明确标注的假向量，仅验证真实 Chroma/FTS5 接线。语义效果必须使用实际 Embedding API；不将假向量成绩作为选型依据。
5. 真实检索评测保存两路候选、送模区间和引文覆盖；答案语义支持仍需人工评分。现有题集为未审核公开开发题。

## 实施与验收

- 新依赖隔离在 backend 的 knowledge-poc 依赖组并同步锁文件；不默认改变线上应用启动。
- 来源采用固定正文 Unicode 区间；重复段落、emoji、代码中的标题和 DOCX 表格顺序需有针对性测试。
- 外部调用使用明确配置、独立 Embedding 凭据、有限超时和关闭自动重试；不将现有聊天 Key 发送到其他地址。
- 真实模型、真实 PDF/DOCX 不可用时保留可执行入口，记录缺失项，继续完成其余验证。

本轮结果在 records 与 Notion 实验页记录；核心模块说明维护实际命令和边界，不复制整套方案。
