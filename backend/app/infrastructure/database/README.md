# 数据库连接、事务与技术错误

员工保存、消息接受和结果交付都需要一组数据库变化共同成功。这个模块提供连接、事务和共同存储类型，让业务服务能够在一个短事务中完成这些操作；具体权限、资源归属和错误含义仍由业务所有者决定。

## 模块设计

### 事务入口与业务操作如何分工

`Database` 依据明确配置创建 SQLAlchemy 引擎和连接池，业务用 `database.transaction()` 取得 Session。Session 是当前这组数据库操作的上下文；事务入口统一提交、异常回滚和释放。跨模块共同保存时传递同一 Session，参与者不能各自提交。

例如对话同时写入输入、空回复和 Run 关联，哪些数据必须一起成功由 conversations 决定，数据库提供共同提交机制。模型请求、工具调用、文件解析和密码计算放在写事务外，因为它们耗时且外部效果无法由数据库回滚。

### SQLite 的读写竞争如何处理

当前连接使用 WAL，读取可与写入并行，但同一时刻仍只有一个写事务。对于「先读当前引用，再修改/删除」的路径，只靠服务里先查再写不足以避免竞争。

`transactions.py` 的 `reserve_writer` 在业务读取前通过调用方提供的表取得写入资格，不依赖某张对话表。锁随同一事务结束释放；已经读到旧 WAL 快照后再申请，不能修复旧快照。业务顺序与数据库唯一/外键约束共同维护一致性，公共工具不会自动使任意查询正确。

每个请求或后台步骤拥有自己的 Session，不能并发共享。`check_same_thread=False` 让连接适配工作线程，不表示 Session 可被多个任务同时使用。显式事务设置覆盖普通操作、DDL 和保存点；连接初始化临时切换后执行 PRAGMA，再恢复原事务方式。

### 共同字段、模型注册与迁移

`base.py` 提供 ORM Base 和约束命名，`fields.py` 统一 UUID、UTC 时间及列表/文本存储，减少业务模块同类数据的编码差异。领域模型保留在所属目录；注册文件反向导入它们，只为 Alembic 收集元数据，业务不能从这个聚合入口取得模型。

应用启动只打开连接，不自动建业务表或升级。结构变化在部署/维护阶段执行正式迁移，使备份、回填和检查有独立时机。更换数据库需核对隔离、字段、索引和迁移，ORM 不等于数据库差异已经消失。

## 目录与职责

```text
database/
├── session.py                     # 配置连接与连接池，提供统一事务上下文，在成功/失败时提交或回滚并释放 Session
├── transactions.py                # 在业务读取前为指定表取得 SQLite 写入资格，配合调用方事务和数据库约束处理读后写竞争
├── errors.py                      # 识别驱动包装的唯一约束和 busy/locked 等技术错误，给业务与 HTTP 层提供窄范围判断
├── base.py                        # 声明共同 ORM 基类及约束命名，使领域模型和迁移共享元数据约定
├── fields.py                      # 统一 UUID、UTC 时间、列表和文本等存储约束，减少不同模块对同类值的编码差异
└── models.py                      # 导入领域模型以收集迁移元数据，不集中定义业务表，也不作为业务取模型的入口
```

## 与其他模块协作

领域模型和服务依赖本模块的基类、字段及事务；应用配置组合 `DatabaseConfig` 和其他路径；Alembic 使用注册元数据。基础设施不反向调用业务服务，数据库注册的反向导入是限定装配用途。

凭据和运行器锁路径由应用配置单独提供，不从数据库地址猜测。连接 URL 的解析与应用/Alembic 共用规则见[后端配置](../../../../docs/guides/backend-operations.md#数据库与本地文件配置)。

## 数据库错误与业务错误

[errors.py](errors.py) 集中识别 SQLAlchemy 包装的 SQLite 驱动异常。唯一约束必须同时匹配错误码、表和完整列列表；错误文本、驱动类型或错误码不符就不识别。SQLite 未提供可用的约束名称，因此列匹配细节留在此处，不扩散到业务模块。BUSY、LOCKED 及其扩展码统一判断为数据库繁忙，HTTP 层再选择暂不可用响应。

本模块不依赖业务模型、不查询冲突记录，也不生成“员工名称已存在”等业务提示。员工和模型连接服务只转换明确的字段唯一冲突；无法解释的 CHECK、NOT NULL、主键、其他唯一约束和外键异常原样抛出。未知异常不会被包装为可刷新解决的 409。

删除保护依据当前实际关联，在同一事务取得写入资格后检查；数据库外键继续兜底。不能仅凭一个无法定位引用对象的外键异常就推断员工或技能装配状态。所有失败仍由原事务入口回滚，不在异常识别器中重试或另开事务。

[技术识别测试](../../../tests/test_database_errors.py) 使用实际 SQLite 约束及 WAL 锁错误；[业务错误边界测试](../../../tests/test_database_error_boundaries.py) 验证已知冲突、未知异常身份、完整回滚及 HTTP 脱敏。

## 使用与验证入口

```python
with database.transaction() as session:
    # 本次必须共同成功的读取、校验与写入使用这个 session。
    ...
```

外键检查继续保护直接数据库写入，隐藏 SQL 参数减少异常携带敏感值，但 API 仍须脱敏。[数据库测试](../../../tests/test_database.py)、[迁移测试](../../../tests/test_migrations.py)和[错误边界测试](../../../tests/test_database_error_boundaries.py)核对实际 SQLite 行为；当前事务/字段规则迁往其他数据库需重新验证。
