# 布局、容器与响应式规范

更新日期：2026-11-01。状态：**已接入正式外壳、共享组件与页面**。实际验证与限制见实施验收；早期尺寸原型的设计证据保留在设计核验。

本规范从[组件分类与空间预算](component-catalog.md)推导页面组合，适用于工作台及相关独立页面。数值是有明确内容目标的项目设计决策，不是行业统一值，也不声称已完成用户研究。颜色、字体、形状和动效继续由现行设计系统维护。

## 设计目标与取舍

1. 页面位置与基本空间关系可预测，切换业务时沿用相同的外框和对齐线。
2. 给宽内容足够空间，同时根据内容类型管理阅读、编辑与扫描密度；不以“所有组件同宽”冒充一致性。
3. 当内容装不下时改变结构，而不是缩小字号、隐藏主操作或设置整页最小宽度。
4. 用组件预算确定列数，再推导容器范围；断点要有内容触发原因，不能只因为框架存在 `sm`、`xl` 就直接套用。
5. 保留现有视觉身份与成熟组件，统一空间职责。柔和工作台试版的存档、验证与恢复见试版验收。普通业务任务不引入无限宽画布；真正需要横向空间的表格、代码由内部承担滚动。

## 空间尺度与留白

沿用项目已有的 4px 基础步进。小组件使用 4 / 8 / 12px，中等组合使用 16 / 20 / 24px，大区块使用 32 / 48 / 64px。48 / 64px 在迁移时可由已有 24 / 32px 成倍引用，不为了数字数量扩充令牌。

| 空间关系                                             | 目标间距 | 选择原因                                           |
| ---------------------------------------------------- | -------- | -------------------------------------------------- |
| 标签或状态文字内部、图标微间距                       | 4px      | 表达同一信息单元，不形成新的内容组                 |
| 图标与文字、按钮组、标签到控件                       | 8px      | 关联明确，仍能区分可操作对象                       |
| 行内独立单元、紧凑段落、资源卡片内部组               | 12px     | 扫描频繁的信息保留紧凑密度                         |
| 小容器 padding、装配行 padding、窄屏卡片 padding     | 16px     | 320px 屏幕扣除外围后仍留下内容空间                 |
| 部分能力卡片 padding                                 | 20px     | 按内容类型保留适度留白，员工与知识资源卡片使用16px |
| 配置面板 padding、普通网格 gap、页头到内容、字段组间 | 24px     | 将独立任务单元分开，且能参与列宽预算               |
| 大区块之间、常规消息之间、宽工作区单侧留白           | 32px     | 表达段落/任务层级，不靠叠加卡片制造分组            |
| 整页空态上下、独立阅读区的主要章节间隔               | 48px     | 较低信息密度的停顿空间，不作为列表每行的间距       |
| 专用场景的大分区                                     | 64px     | 只用于独立阅读/展示；普通表单不默认采用            |

外层 gap 与内层 padding 不互相替代。例如相邻两张卡片的间距只有网格 gap，不能再给每张卡片叠加外边距；面板中的字段组也不再套一份页面 gutter。光学修正可以保留，但必须说明资产或几何原因，不能成为任意值的通用出口。

字体与控件沿用现行角色和 32 / 36 / 40px 基本高度，具体类型的命中区、内容上限与状态见组件分类。空间密度由任务类型决定，本轮不增加用户密度开关。

## 四层空间所有权

| 层级           | 管理什么                                             | 不管理什么                     |
| -------------- | ---------------------------------------------------- | ------------------------------ |
| 外壳 Shell     | 导航、全局顶栏、右侧可用区、全局高度与滚动归属       | 员工卡片最小宽度、文章行长     |
| 页面 Frame     | 最大外框、居中、外围留白、标题/列表/分页的共同对齐线 | 字段长度、气泡比例、浮层宽度   |
| 区块 Region    | 资源网格、主辅布局、字段组、文件目录与编辑区         | 基础控件内部 padding           |
| 组件 Component | 内容、内部间距、状态、命中区、必要的紧凑结构         | 与浏览器的距离、整页 max-width |

浮层是独立的视口定位空间，由库处理 Portal、避碰与焦点；它不是某张卡片内的第四层页面外框。Provider 与数据 Hook 不参与几何决策。

| 模式           | 工作方式与外框                                              | 当前路由/消费者                                             | 选择原因                                                                     |
| -------------- | ----------------------------------------------------------- | ----------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 资源目录       | 公共工作台外框 + 按类型分列的网格或内容行                   | `/agents`、`/skills`、`/brains`、`/conversations`、知识资料 | 对象扫描与跨对象比较，支持稳定的页头、查询和分页                             |
| 配置工作区     | 公共外框 + 主辅布局/字段面板；普通字段局部限宽              | 员工配置、`/tools`、个人工具连接、规章制度                  | 页面位置一致，表单与复杂操作按内容安排                                       |
| 文件编辑工作区 | 公共外框 + 文件目录/编辑器                                  | 技能创建与编辑                                              | 编辑区应优先获得足够横向空间，文件导航可折叠                                 |
| 对话工作区     | 按视口分级的水平外框 + 独立消息滚动和输入；内容内部分类测量 | `/conversations/new`、对话详情                              | 同时容纳普通文字、代码、表格、文件和执行过程                                 |
| 独立阅读       | 外部页面可用公共上限，文章内部使用阅读列                    | `/help`、长文预览                                           | 持续阅读与工作扫描不同，不用目录网格决定行长                                 |
| 专用场景       | 按任务独立构图，共享基础控件与空间尺度                      | `/signin`、`/avatars/svg`、`/design-system`、开发样板       | 登录、资产检阅和规范导航具有自己的信息结构，不能反向成为任意业务页的宽度例外 |
| 宿主内嵌       | 不附加页面外围留白或公共最大外框                            | 历史弹窗、装配面板、配置预览、错误反馈                      | 空间已由宿主分配，避免叠加两套 gutter                                        |

没有新增看板、无限画布、左右聊天侧栏等功能要求，本规范不为它们预建模式。若未来确实出现，需要先给出内容预算及现有模式不足的原因。

## 员工编辑工作区

员工配置在公共页面外框上采用 `--os-agent-editor-max`（1280px，包含外围留白）限宽并居中，避免指令与普通字段在大屏中被过度拉长；不改变目录页的1536px预算。指令与知识使用 `agent-instructions-layout`，净宽达到1008px后并列主编辑器与 `--os-agent-context-width`（280px）辅助栏，间距沿用24px；不足时辅助内容在编辑器之后。280px辅助栏只承载折叠规则、短说明和入口，不替代350px员工卡片预览。数值统一维护在 `theme.css`，`spec.ts`登记用途。

基础配置沿用350px卡片预览预算，两栏间距40px，左侧字段组间距32px；圆形头像与名称式大脑入口按剩余宽度换行，名称/分类按字段容器预算重排。员工编辑操作沿用共享页头的actions区域，放在标题右侧，窄屏自动换行；无底部固定或粘性操作条。具体按钮状态及离页保护见[员工模块](../pages/agents/README.md)，本轮范围见增量方案。

## 从组件推导公共上限

### 先明确密度目标

首版资源目录在足够大的屏幕中，员工/简单能力卡片最多四列，复杂连接卡片最多两列。这是本项目面向角色识别、配置状态与操作的密度选择；不是“四列符合某个心理学定律”的结论。卡片只需短标题与数字的其他产品可能适合更多列。

| 约束                                                 | 来源                             | 对外框的要求                     |
| ---------------------------------------------------- | -------------------------------- | -------------------------------- |
| 四列员工卡片，每张至少 320px，列间 24px，外侧各 32px | C09 的人物、姓名、状态与操作预算 | W ≥ 4×320 + 3×24 + 2×32 = 1416px |
| 简单能力卡片至少 280px，不出现第五列                 | C10 的简单结构和首版扫描密度     | W < 5×280 + 4×24 + 2×32 = 1560px |
| 复杂连接卡片至少 480px，不出现第三列                 | C11 的模型、账号、状态与操作预算 | W < 3×480 + 2×24 + 2×32 = 1552px |

三项交集为 **1416px ≤ W < 1552px**，而不是先指定某个常见屏幕尺寸。

### 推荐值与其他可行值

本轮推荐公共外框上限 **1536px，包含左右 padding**。由员工卡片首选约 350px 推导：4×350 + 3×24 + 2×32 = 1536px；扣除外围后为 1472px，恰好容纳四张 350px 员工卡，或两张 724px 复杂连接卡。

350px 的构图预算见 C09。1536px 同时落在上述交集内，且能沿用现有间距尺度；它不是因为是 8 的倍数才成立。1440px 与旧 1450px 也在可行范围内，只是在同样四列时姓名与内部信息区更紧凑。

| 外框候选 | 扣除左右 32px 后 | 员工列数/单列宽（最小 320px、gap 24px） | 简单能力列数 | 复杂连接列数 | 本轮判断                                                     |
| -------- | ---------------- | --------------------------------------- | ------------ | ------------ | ------------------------------------------------------------ |
| 1280px   | 1216px           | 3 / 389.3px                             | 4            | 2            | 无法实现四列员工目标，可作为更低密度选择                     |
| 1440px   | 1376px           | 4 / 326px                               | 4            | 2            | 满足最低预算，但姓名区域距下限较近                           |
| 1450px   | 1386px           | 4 / 328.5px                             | 4            | 2            | 可行的旧实现值，没有特别的标准地位                           |
| 1536px   | 1472px           | 4 / 350px                               | 4            | 2            | 推荐，符合首选角色与姓名预算                                 |
| 1600px   | 1536px           | 4 / 366px                               | 5            | 3            | 在现有最小预算下引入五列简单卡和三列复杂卡，超出首版密度目标 |

这里给出了“选择为什么成立”，没有证明该值是唯一最优。若真实名称、卡片信息或密度目标改变，先修改组件预算，再重新推导 W。不能只改页面 max-width 后让所有内部结构被动承受。

## 外壳、边距与最小空间

设浏览器视口宽V，侧栏占位S。桌面（V>768px）右侧外框距右边8px、上下各8px，边线各1px，查询容器可用宽A=V−S−8−2；移动端（V≤768px）S=0且A=V。资源目录、配置和文件编辑采用公共外框 F = min(A, W)，单侧外围留白 G，内容净宽 C = F−2G。对话使用下文单独的视口规则；统一空间职责不等于所有页面套同一个宽度策略。

桌面侧栏为 **240px**，替代原先 232 / 210px 的两档实现。预算为：外部左右各 16px + 收藏主链接左右各 8px + 40px 角色 + 12px 名称间距 + 约 96px 名称区 + 44px 编辑槽（36px 控件与分隔留白）。这是导航内容预算，不能因另一套组件库使用 240px 就直接照搬。

粗指针使用 44px 命中区时，允许从姓名的剩余弹性空间分配额外位置，不压缩命中区。品牌行继续使用等比 Logo；不为宽度目标改写字标。窄于 768px 时侧栏改为覆盖式抽屉、S = 0；大于768px时 S = 240px。

768px 的临界点来自侧栏 240px、单列主要内容至少约 480px、左右留白和余量的预算。它是外壳结构切换点，不能用它决定所有卡片、表单或 Tab 的内部结构。

资源目录、配置和文件编辑的外围留白根据 **右侧可用区 A** 决定：

| 可用区 A           | 单侧 G | 目的                                                                 |
| ------------------ | ------ | -------------------------------------------------------------------- |
| A < 640px          | 16px   | 确保 320px 视口仍有 288px 内容，组件可退回紧凑单列                   |
| 640px ≤ A < 1200px | 24px   | 中等工作区的标题、筛选与面板保持分组，避免视口扣除侧栏后仍误用大留白 |
| A ≥ 1200px         | 32px   | 宽工作区提供明确边界，并参与四列空间预算                             |

640px 是两张 280px 简单卡片、24px 间距与两侧 24px 留白所需 632px 向上留出余量后的密度边界；1200px 可容纳三张约 350px 员工卡片、两处 24px 间隔与两侧 32px 留白，并保留余量。两处都是空间密度过渡，边界附近允许内容宽度有小幅变化，必须在原型中核对没有列数反复或操作丢失。

外框居中于 A，不居中于整个视口；最小硬宽度为 0。工作台最低验收宽度是 320 CSS px，组件预算不能变成页面 `min-width: 320px` 再叠加 gutter。全局顶栏背景和分隔线铺满 A，其内部左右 padding 使用 G；正文页头、筛选、主体、分页和整页反馈共用 F 的起点。

全局高度沿用 `100dvh`。普通页面由主内容区滚动；对话由消息区滚动、输入保留在正常布局底部。主辅布局只给不高于可用视口的辅区使用 sticky，低高度或单列时恢复静态；不能形成无法退出的多层纵向滚动。

## 区块如何响应空间

### 网格

资源目录普通 gap 为 24px，内容净宽 C 小于 640px 时 gap 为 16px。采用自动填列，不使用跟业务内容无关的固定 `xl:grid-cols-3`。单元宽度预算分别来自 C09/C10/C11。

列数 n = max(1, floor((C + gap) / (组件最小并列预算 + gap)))。只有一个结果时，保留可容纳的列轨道，不把这一项伸展到整页；没有结果时空态占据整个结果区。卡片自身不设固定最大宽度，最大由网格轨道决定；偏好宽度与硬上限要区分。

组件实现可采用 `repeat(auto-fill, minmax(min(100%, 组件预算), 1fr))`，并对空间不足的单卡使用紧凑构图。卡片在编辑预览或弹窗中同样依据自身宽度调整，不依据浏览器宽度猜测。

### 主辅配置

辅区采用 350px，复用员工卡片首选构图。主区最低 634px 来自双列普通字段面板预算（包括为两侧边线保守预留的 2px），间隔 24px，因此并列阈值为 634 + 350 + 24 = **1008px 的区块净宽**。

达到阈值才并列；不足时先主区、后辅区，DOM 和视觉顺序一致。最大公共外框下主区为 1472−350−24 = 1098px，减去面板左右各 24px 和 2px 边线预算后有 1048px，两个字段各 512px，可容纳普通字段且不被辅栏挤压。

字段双列的查询对象是扣除面板 padding 后的字段区，阈值为 **584px = 2×280 + 24**；不能将包含 48px padding 的 632px 当作字段区净宽。面板在宿主不足常态 632px 预算时使用 16px 紧凑留白，字段仍独立按净宽判断，不能用切换留白代替字段预算。

普通字段组可以在主区内部限宽到 640px；长指令、能力装配、代码与数据不套该上限。孤立的短表单不必假造一列没有内容的辅栏，也不能把页面标题与操作移到另一条居中窄列。

### 文件编辑与查询

文件目录与编辑器在查询容器的内容宽度达到 800px 时采用 240px + minmax(0, 1fr)，该内容宽度不包含容器边线；空间不足时将目录移至顶部可折叠区。标签、错误和选择操作保留；不单纯隐藏文件目录。

典型查询行预算为搜索 320px、两个筛选各 200px、两处 gap 12px，总计 744px；实际需要额外操作时加入它的内容宽度。低于预算先换行，再在单列中使用全宽，不为三个控件强行均分。

### 断点的归属

外壳抽屉和对话页面的边距/宽度分档使用 V；资源与配置页面的 gutter 使用 A；网格、字段、主辅区、装配行和编辑区使用各自容器宽度；粗指针控件尺寸使用输入能力条件。断点的依据由其管理的空间职责决定。

这与“把所有媒体查询替换为容器查询”不同。例如 Atlassian 的全局网格使用视口断点，本项目保留外壳的视口切换；局部卡片和字段还需要适应弹窗、预览与主区内的实际空间。这是本项目的组合选择，并非声称来源要求所有断点都跟随容器。

## 对话与阅读布局

对话工作区由正文和可收起的右侧辅助栏组成。辅助栏默认展开，承载当前员工历史与能力，宽度消费 `--os-conversation-sidebar-width`。工作区净宽达到 912px 时并排；侧栏 300px 加内缩留白 24px，给正文至少约 588px；不足时辅助栏位于正文下方，按工作区高度的 38% 分配预算并独立滚动，保证输入区仍可操作。侧栏使用画布色与圆角、内缩留白区分主辅；员工身份固定在侧栏顶部，历史和能力使用分段标签切换。收起后正文使用完整工作区。正文限宽与目录安全带继续在扣除辅助栏后的消息区域内计算，不按整个工作区误算居中留白。

对话以单列阅读和输入为主，普通屏幕维持居中的适中宽度，宽屏再增加结构化内容空间。消息、输入、加载与整页反馈共用一套对话外框。资源目录和配置页面继续使用自己的组件预算，不决定对话的宽度。

设视口宽 V、扣除侧栏的可用区 A、对话上限 Wc，则外框 F = min(A, Wc)，在 A 内居中。常规 gutter 是保证内容不贴边的内层留白，外框之外还有 (A−F)/2 的居中留白；二者不能混为一谈。

| 视口 V              | 对话外框上限 Wc | 作用                                              |
| ------------------- | --------------- | ------------------------------------------------- |
| V < 1920px          | 960px           | 普通屏幕保持适中的阅读与输入区域，比原 840px 稍宽 |
| 1920px ≤ V < 2560px | 1120px          | 宽屏给表格、代码和输入组合增加空间                |
| V ≥ 2560px          | 1280px          | 超宽屏再扩展一档，保留两侧明确留白                |

内层 gutter 延续原视口规则：V ≤ 760px 为 16px，760px < V ≤ 1250px 为 24px，再宽为 32px。屏幕装不下上限时外框自然缩小，不设置整页硬最小宽度，也不靠压缩字号凑宽度。

**取值依据。** 常态正文预算沿用 C16 的 64ic，在 14px 字号下约 896px；加两侧各 32px 得到 960px 外框。它比原先约 784px 的正文净宽增加约 14%，而不是把普通屏幕的工作区全部用作消息列。宽屏每档再增加 160px，优先供表格、代码与文件使用；以八列验收表为例，平均列空间预算约从 112px 增至 132/152px，实际列宽仍按内容决定。纯文字保持行长约束。宽屏两档是温和扩展的项目设计取值，不能由此声称已证明唯一最优或行业标准。

1920/2560px 用于区分常规、宽屏和超宽屏条件，不由员工卡片列数推导；变化方向必须是屏幕变宽时上限增加，不能再出现“普通屏幕铺满、到宽屏反而收窄”。三个上限使用独立的 conversation 令牌，不与资源页的 1536px 上限绑定。

**豆包参考。** 2026-10-30 核对[豆包官方页面](https://www.doubao.com/chat/)的未登录欢迎态，1440/1920/2560px 视口的输入区均封顶 1000px，页面同时定义 800px 的对话区令牌；已加载布局样式将中心内容上限、侧栏和外侧留白分别管理。未发送消息，未验证正式消息态，因此不把这组数值说成其全部消息页断点。这里采用的是按内容角色分开限宽、居中留白的思路，普通与宽屏的具体参数仍按本项目预算确定。观察证据记录状态与限制。

消息内部按内容类型分配宽度：

| 内容                             | 空间分配                                            |
| -------------------------------- | --------------------------------------------------- |
| 输入、全局会话反馈、专业结果外框 | 共用对话外框的内容区；输入最多增长 6 行后内部滚动   |
| 助手段落、列表、引用             | 从消息起点开始按 C16 的文字测量，消息本身仍占工作区 |
| 代码、表格、文件、执行详情       | 可使用完整消息区；超过空间的二维内容内部滚动        |
| 用户气泡                         | 从右侧开始按 C18 的比例和内容测量，不把短消息铺满   |
| 空对话介绍                       | 局部最多 480px，不影响其他状态的页面外框            |

中文主界面的 `ic` 测量按中文字体；明确标注为拉丁文的内容可使用 ch，混排按所属主语言处理，不用自动猜语言来切换整页宽度。不支持 ic 的浏览器使用与当前字号对应的像素回退；字体缩放与浏览器差异仍需按验收范围核对。

普通、宽屏和超宽屏的常态净宽分别约为 896 / 1056 / 1216px（未计滚动条与窄工作区的导航避让）。64ic 的普通段落可以用满常态净宽，宽屏增加的空间供二维内容使用；不会强行把文字排成约百字一行。行长仍需真实内容阅读核验，几何测试不能证明最优。

### 导航安全带

问题导航保持原有外观：28px 宽、10px 刻度步距、细线长短与颜色、预览样式和右侧定位不变。布局统一不扩大为快捷目录的视觉改造。

右侧目录需要 R = 48px（右偏移 8px + 目录宽 28px + 内容间隔 12px）。先利用居中外框外的空白 M = max(0, (A−F)/2)，不足时才增加消息右内边距：Pright = max(G, R−M)。左侧和输入仍使用 G。普通桌面上，两侧留白已经足够容纳目录，消息和输入保持相同的内层边距；窄工作区只对消息补足避让。

计算直接落在该元素的 CSS padding 属性，百分比相对于消息视口解析；不设置随每个像素变化并向后代继承的几何变量，不使用 cqw、JS resize 状态或宽度动画。预留不随第三个问题出现而改变，避免内容突然换行。

消息滚动、历史锚点、回到最新、取消与前插分页继续复用正式滚动组件。普通样式原型只能核验空间，不能证明这些运行交互已通过。

## 实现归属

所有几何令牌与复用布局工具类维护在 `theme.css`，`spec.ts` 只登记用途。`/design-system#layout` 从浏览器计算样式读取这些值，并用正式字段组件展示容器响应；不复制一份用于展示的尺寸配置。

| 实现                                                    | 责任                                                              |
| ------------------------------------------------------- | ----------------------------------------------------------------- |
| `workspace-region` / `page-gutters`                     | 建立剩余工作区查询容器，按其净宽选择留白                          |
| `PageContainer` / `page-frame`                          | 公共上限、居中与一层页面留白；embedded 只消费宿主                 |
| `employee-grid` / `capability-grid` / `connection-grid` | 按组件预算自动填列，少量结果保留轨道                              |
| `configuration-layout` / `form-panel` / `form-grid`     | 主辅分栏、面板留白与字段重排                                      |
| `file-layout`                                           | 文件导航与编辑器的组合；目录在顶部时可折叠                        |
| `conversation-frame`                                    | 消息外框与问题导航安全带；输入和反馈使用 conversation-page-frame  |
| `conversation-workspace` / `conversation-sidebar`       | 按工作区净宽排列正文与历史/能力侧栏，分别管理滚动与空间预算       |
| `Dialog` 的 size / layout                               | small、standard、wide、workspace 与 side 角色，统一视口边界和滚动 |

媒体查询与容器查询断点使用 CSS 字面长度，与本页预算一起维护；普通自定义属性不能用于查询条件。`conversation-gutters` 保留对话的视口留白，`conversation-page-frame` 在常态保持居中限宽，宽屏再提高上限。布局宽度由 CSS 管理；ResizeObserver 只用于原有滚动/导航的高度与定位，不承担逐像素页面宽度计算。

登录保留品牌场景与既有几何控制器；头像检阅保留局部缩放视口，规范目录保留自身导航；三者的任务构图不强行改为业务列表。帮助正文使用阅读行长，标题和导航仍在公共外框。二维数据、代码和资产缩放允许局部滚动，不能用整页裁切代替响应式。

## 维护与验收

共享布局规则只在公共外框、布局样式与组件类型中实施，数值最终落到 `theme.css`；`spec.ts` 只记录名称、用途、状态和展示分组。媒体条件不能直接引用普通 CSS 自定义属性。不在页面重复 `max-w-*`、固定列数和外围 padding 组合。

每次改变角色尺度、最小卡片预算、操作数量或字段密度，重新计算列数与临界点，并更新相应样例。组件清单与规范应一起维护，新增视觉类型先补用途、预算、变体与失败状态，不必为每个新业务文件创造新类型。

早期外框研究见设计核验记录；现行对话的宽度分档以正式组件核验，不再套用原型的公共上限。验证包括实际宽度、列数、换行、主辅分栏、局部溢出，以及消息滚动、保存/发送、焦点与软键盘。至少覆盖矩阵尺寸、768px 外壳断点两侧、A 的 640/1200px 两侧、C 的 1008px 主辅阈值两侧、对话 760/1250/1920/2560px 两侧，以及长标题、错误、少量结果、空态、主题与字体缩放。

尺寸原型使用演示数据和正式资产的静态副本，不接 API、不代替正式组件测试。本次完成的检查与未覆盖范围必须按记录说明，不能将目标参数、计算结果或历史通过结果写成当前界面已通过。
