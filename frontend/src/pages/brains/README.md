# 大脑连接配置界面

管理员在大脑页面维护可被多名员工选择的模型连接。填写名称、预设、模型标识和 API Key 后保存，再到员工配置中选择。岗位指令和对话内容不进入这份连接配置。

## 模块设计

### 列表、编辑和检查各自管理状态

新建大脑位于共享页头右侧；重新加载列表进入更多菜单，只重读平台记录，不测试上游。搜索与数量复用 CollectionToolbar，桌面搜索限宽，窄屏换行。用途说明合并进标题描述，避免重复线框说明；具体连接测试保留在卡片。

`BrainsPage` 限制当前管理入口并挂载 `BrainWorkspace`；工作区挂载共享 `ModelConnections`，仅筛选 chat 连接和预设，组织列表、新增/编辑、检查和删除。检查以连接为目标分别记录进度，保存和删除也有防重复提交状态。

编辑器使用配置与凭据两类预期修订，Key 留空表示保持已有值。Key 只在当前表单中，成功后清空，响应仅说明凭据存在。冲突保留输入，由用户核对最新版本后再提交，不能读取原 Key 回填。

### 为什么保存、检查和员工装配分开

保存只确认连接配置，聊天检查只验证模型目录访问，知识库里的向量检查使用固定短文本验证实际 API；模型实际生成需在员工对话中验证。员工读取连接选项并保存引用，页面不能因为检查成功就替员工改变选择。

停用、换模型或提交 Key 影响后续使用，旧运行继续前须核对版本。仍被员工或活动运行引用时，删除由后端拒绝并在页面反馈；页面确认框不替代引用检查。

## 目录与职责

```text
brains/
├── BrainsPage.tsx                 # 提供路由入口，按当前身份限制管理页面并挂载模型连接工作区
└── BrainWorkspace.tsx             # 挂载共享模型连接工作区，限定为数字员工对话连接
```

## 与其他模块协作

[模型连接 API](../../lib/api/modelConnections.ts) 提供传输类型与请求，后端 [model_connections](../../../../backend/app/model_connections/README.md) 拥有凭据、版本及引用规则，llm 构造真实客户端。页面使用自身列表/表单状态，员工配置只消费可选连接及其摘要。

## 验证入口

[客户端测试](../../lib/api/modelConnections.test.ts)与[后端连接测试](../../../../backend/tests/test_model_connections.py)核对参数、版本和安全响应。真实生成及外部网络不能用保存或目录检查结果代替。

## 知识库向量连接

向量模型在知识库“检索设置”弹窗单独维护，不出现在大脑列表或其新建预设中。底层继续复用同一连接与凭证服务，已有向量配置保留；详见[知识库契约](../../../../docs/reference/knowledge.md)。
