## 1. 来源和快照

工作区没有可用的已提交基线，因此不声称依照某个 Git commit 做评审。使用[本轮 inventory](../proposals/platform-refactor/inventory.json)冻结复核前工程路径，567 个文件：后端 162、前端 260、文档 135、脚本 6、根目录 4。新增审查正文和本记录通过生成器新增清单进入目标树。

## 2. 实际方法

1. 从文档索引、工程约定及端内入口确认现行契约与目标方案的区别。
2. 通过 rg 建立工程清单与文本引用；提取 102 个 Python 实现/工具节点和 190 个手写 TS/TSX 节点的静态依赖。
3. 补查路由、包导出、动态加载、ORM 元数据、CLI、脚本 readFile 和静态资源入口。不能用静态图零入边判定删除。
4. 三个既有协作审查任务分别复核后端配置与技术依赖、对话/运行/CI、前端状态与工程；主任务核对结论并收敛目录，不按每条建议机械增加文件。
5. 将每项建议归为必要调整、明确保留或可选后续；统一正文、目标树和源文件映射。

检查覆盖全部路径的去向及主要职责，不声称逐行审计全部测试、图形资源和历史记录。未运行互联网研究、真实模型、远程 MCP、数据库迁移或部署。

## 3. 形成的方案修订

详细证据、来源链接和取舍见[全工程职责复核](../proposals/platform-refactor/responsibility-review.md)。

- 取消拟新增 lifecycle，状态操作集中 store；普通 progress 并入 control；旧 Run DTO 随旧入口退出；Agent 实现压平。
- 统一员工就绪与数量计算，保留配置读取未就绪员工；明确公开读取入口、调用方事务授权与上下文函数边界。
- CI 安装回专业 service，服务类改 CiDiagnosisService，专业 executor/report 拆分保留。
- 数据库设置不反向依赖 AppConfig，用量不依赖 SDK 类型；静态目录统一解析后传入交付入口。
- 配置大 Context 拆回目录/编辑生命周期，外壳仅持摘要与更新通知；编辑器注册具体放弃回调。
- 前端客户端、摘要/详情类型、URL 查询规则、导航搜索、规则编辑与品牌源稿按实际使用归位。
- 保留 Actor、权限策略、参数校验、凭证、头像、主题、UI 适配、对话公开 Hook 和实际复用入口。
- 可选样式合并、登录动画内部重命名、Workspace 整理和额外导出层未列为本轮必需项；无消费者的 Popover 仅列入 P4 计划删除。

P1 增加可分别验收的配置、导航与技术整理；Message/Run/CI 数据方案和 P2/P3 接口切换仍按原主线推进。
