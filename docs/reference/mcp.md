# MCP 服务、账号与员工装配

当前实现为 Python 模块化单体中的 HTTP 与可信 stdio MCP 接入。身份校验、凭据、目录和员工许可都由后端强制执行；前端只负责输入与展示。实现入口为 [tools](../../backend/app/mcp/README.md)、[员工装配](../../backend/app/employees/README.md)、[工具页面](../../frontend/src/pages/tools/README.md)，针对性测试见 [账号边界](../../backend/tests/test_mcp_accounts.py)和[真实子进程生命周期](../../backend/tests/test_stdio_mcp.py)。

## 支持范围与职责

HTTP 支持 Streamable HTTP、无认证、Bearer Token、自定义单个认证头及标准 OAuth；stdio 支持管理员登记的程序与结构化参数，以及按账号加密保存的环境变量。复用官方 MCPAdapter / FastMCP；HTTP 继续使用受控网络。旧 SSE、设备码、客户端凭据及反向 sampling/elicitation 不在当前范围。Skill 包与代码沙箱有独立职责，见最终实施计划。

| 对象         | 所有者与职责                                                                                           |
| ------------ | ------------------------------------------------------------------------------------------------------ |
| MCP 服务定义 | 创建者维护 HTTP 名称、功能、固定 URL 与启停；stdio 程序只允许管理员登记，不保存账号秘密                |
| 账号连接     | 连接创建者管理 Token、该账号看到的目录和别名；个人连接不对其他用户列出，明确共用的连接可以作为共享能力 |
| 员工定义     | 所有使用者共用一份；作者维护提示、Skill、工具范围及账号方式；不为使用者复制员工                        |
| 员工工具许可 | 固定连接模板、原始工具名、定义摘要、调用预算和范围；指定共用或使用者个人账号                           |
| 个人绑定     | 当前用户把本人连接关联到员工的一项个人模式许可；不修改员工流程、工具范围和其他用户连接                 |
| Run          | 按发起者冻结具体身份和许可，快照无 Token；每次动作仍检查当前账号及授权                                 |

历史没有作者的员工由管理员维护；新员工只能作者修改，其他管理员也不能修改。GitHub 普通成员可使用员工、管理本人 MCP 连接，不能修改员工或模型配置。游客继续只读。

## 页面与添加流程

能力库 `/skills` 联合列出 Skill 与两种 MCP，可按名称、说明和类型筛选，服务端统一排序、分页和统计。添加菜单统一提供 MCP 接入、Skill 创建与技能包导入；“内置工具”提供现有原生工作区登记入口。

1. 接入 MCP 时直接填写统一表单，或从服务信息右侧“快捷导入”解析客户端 `mcpServers` / 支持的 Registry 描述后回填。预览不启动程序、不安装包、不访问远端、不创建资源。变量占位符不作为密钥，支持的输入说明用于生成访问设置。
2. 在同页填写个人或明确共用及凭据；默认个人，选择匿名或按字段填写。点击“保存并测试”依次保存服务、账号并读取目录；只有服务创建者能建立共用账号，stdio 程序仍仅管理员维护。
3. 首次测试连接自动读取待确认工具；维护时点击“读取工具列表 / 检查工具更新”重试。只做协议握手和工具列表读取，不执行业务工具。
4. 核对候选、编辑可选展示名称与补充说明，再确认或应用工具列表；也可暂不更新。确认不自动装配员工。
5. 员工能力装配页选择已确认工具、账号方式、预算及范围。员工正文、Skill 与工具在主保存事务中一起提交，失败整体回滚。
6. 其他使用者从员工页或对话页进入“我的工具连接”，选择本人已确认、与员工工具定义兼容的账号。没有账号可跳转该服务详情新增 Token，读取并确认后返回绑定。

新服务在已支持的传输和认证范围内只需要配置，不需新增厂商适配器。HTTP(S) 接入不维护部署域名或私网主机白名单，支持本机、内网服务和代理 DNS；地址仍不能包含用户名、密码、查询参数或片段。传输边界见[工具契约](agent-tools.md#工具范围与网络)，操作方式见[工具部署指南](../guides/agent-tools.md)。

服务、账号连接、目录确认各自明确保存，不把远端请求放进员工数据库事务。保存服务后取消账号配置，服务仍保留；页面可稍后继续。

### 服务维护与访问设置

服务信息编辑名称、说明，以及 stdio 允许账号提供的环境变量名称；程序和启动参数继续不能原地替换。允许名称列表是宿主启动的白名单，账号可选择匿名（空子集）或使用其中的字段，不能注入未声明名称和运行时控制变量。补充字段不强迫既有匿名连接使用 Key；移除仍被连接使用的字段会拒绝。

“访问设置”保存具体身份和密钥；已有匿名连接可点击“配置密钥”切换认证，已配置的连接可修改密钥或切回匿名，不需要重新创建 MCP。stdio 使用逐字段密码输入；HTTP 支持无需认证、Bearer、自定义请求头和 OAuth 浏览器授权。修改秘密不回显原值；留空保留已有秘密，更换 stdio 凭据时须填齐该连接已选字段。身份或密钥变化会清空该连接工具目录、增加修订，重新读取确认后才能使用；不会借用其他账号。第一次配置提供“配置访问方式”，已有连接后收起为“添加另一组凭据”，用于同一服务下确实需要另一账号的情况。

新建服务拒绝相同名称（去空白、忽略大小写）或相同接入定义；HTTP 按协议/主机/端口/路径/查询，stdio 按启动程序与参数比较，不把环境凭据字段当成另一个服务。`npx/bunx` 的前置同意参数不区分新服务，包版本及业务参数仍保留。重复检查在 SQLite 写锁内完成，旧式直接创建 HTTP 连接同样复用已有目标；既有重复记录不会自动合并或删除。不同地址或参数是否指向同一业务无法通用推断。

服务与本人连接提供删除入口，前端明确确认，后端检查所有者、预期修订和引用。员工装配或个人绑定仍引用连接时拒绝删除；服务含其他用户的连接时拒绝级联删除。没有引用时删除服务及创建者自己的连接和密文凭据，不自动卸载员工、不删除历史对话。删除检查与写入在同一事务中，引用约束由员工模块提供，工具模块不维护员工关系。

员工装配页的账号与能力库管理入口在新标签页打开，避免离开未保存表单。确认目录后点击“刷新连接列表”取得可选操作；刷新只读取平台已保存目录，不重新发现远端、不替换员工草稿，也不自动增加许可。读取中或读取失败不将已有装配误报为已删除。

## Token 与身份选择

Token 与 stdio 环境变量值只写不读，使用工具主密钥加密保存；不进入服务定义、导入预览响应、浏览器持久草稿、员工提示、模型上下文、Run 或工具日志。stdio 服务只保存环境变量键清单，账号必须提供其选定字段的完整值，不能注入服务未声明的键。导入的秘密只在当前表单内存保留，选取配置后清除原 JSON，保存后清空输入。程序 stderr 不直接进入应用日志，结果与目录检查已解析凭据，避免第三方回显秘密。

- 个人模式：创建者使用自己的模板连接；其他使用者必须显式绑定属于本人的同服务连接。不会借用员工创建者的个人 Token，不会自动尝试另一个账号。
- 共用模式：必须引用明确标为共用的连接。操作消耗共用账号的资源，权限来自上游账号与平台工具许可；员工的所有使用者可通过这个账号执行所选操作。
- 没有兼容个人连接：仍能普通聊天；模型实际请求该工具时，返回“连接本人账号”的失败工具结果，不发远端请求。绑定完成后重新发送任务，不自动重放旧业务操作。
- 远端明确拒绝认证：提示检查或更换 Token；拒绝操作权限则说明检查上游权限。静态 Token 没有自动续期流程，不能把网络超时当成重新登录，也不自动进入 OAuth。
- Token 更换视为可能换了账号，清除该连接已确认目录与候选并增加凭证修订，需重新读取确认；运行中的旧身份不能继续调用。相同工具定义重新确认后，保留的具体定义许可可再次使用。

共用能力不共享对话、附件或成果。它们仍按发起用户隔离，沙箱按 Run 隔离，沿用[文件与沙箱契约](agent-tools.md)。

## OAuth 账号生命周期

OAuth 是 HTTP MCP 的可选认证方式，与本站 GitHub 登录独立。复用官方 MCP SDK 的公开 `OAuthClientProvider` / `TokenStorage` 完成元数据发现、动态客户端注册、授权码交换和 PKCE S256；没有厂商名称分支。支持服务要求预注册时填写 scopes、Client ID 和只写 Client Secret。当前不发布 CIMD，也不承诺兼容缺少标准元数据的服务。

1. 保存 OAuth 访问设置后点击“连接账号”，后端创建最长十分钟的内存授权会话；同一平台登录会话重复发起复用当前请求，单实例最多八个等待会话。
2. 浏览器整页跳转到服务方授权，回调固定为本站 `/api/tool-connections/oauth/callback`。发起页面来源必须与部署回调一致；回调匹配随机 state、连接所有者和原平台登录会话，一次消费。平台会话过期、换登录、取消、超时或服务/连接变更都不能晚到写入凭据。
3. 成功后回到工具详情，以不透明会话 ID 查询结果；code/state 不进入前端路由。自动读取的仅是待确认目录，仍须用户确认，再主动装配给员工。
4. 已连接账号重连前会使旧授权和目录失效；“断开账号”清除本地 Token 和目录，保留可复用注册资料。断开不等于撤销服务方授权，可在服务方管理页面另行撤销。

公开连接状态为 `disconnected`、`connected`、`reauth_required`，不把未完成授权显示为已配置凭据。Token、刷新 Token、客户端秘密和注册资料以版本化结构共用既有工具主密钥加密；公开配置只含 scopes 和 Client ID。凭据不进入 Run、模型上下文或浏览器存储。

后台 MCP 调用只在同连接锁内按需续期，不启动交互授权或动态注册。绝对有效期与授权服务器 token endpoint 一并持久化，重启仍可续期。正常刷新及刷新 Token 轮换只推进存储修订，不改变身份凭证修订，不使当前 Run 失效；重连、断开和明确失效会推进凭证修订。刷新缺少必要资料或返回 `invalid_grant` 时要求重连；网络故障或上游临时错误保留授权并允许后续重试。轮换保存失败后当前进程阻止该连接继续请求，不自动重放业务工具。

刷新与配置变更通过配置、凭证和存储修订共同校验，短事务内保存；网络及等待用户期间不持有数据库事务。未授权连接可用于普通聊天，实际请求该工具时提示连接本人账号，不借用其他用户身份。尚未完成的授权不跨后端重启恢复，重新点击连接即可。

OAuth 的 metadata、注册、交换、刷新可能使用不同 origin，逐目标执行相同的受控网络校验、TLS、DNS 固定与响应限额；除本机 HTTP 外要求 HTTPS，不向授权服务器转发 MCP Bearer。它不重新引入主机白名单，也不增加内网隔离。MCP 业务地址仍不能含凭据、查询或片段；OAuth 协议端点可带协议查询参数。回调访问日志去除查询串，反向代理也须禁止记录该路由的查询参数。

配置与 Notion 操作见[部署指南](../guides/agent-tools.md#oauth-与-notion-免费基础接入)。

## 目录与展示规则

每个连接单独保存候选和已确认目录。不同 Token 可能看到不同工具，所以服务卡片不能直接作为所有账号统一授权的依据。目录快照只固定平台认可的定义，不冻结远端实现。

远端目录最多 128 项，完整定义及服务说明按 UTF-8 序列化合计最多 1 MiB；网络单次响应仍受 2 MiB 上限约束。数量、体积和重名分别报错。该目录用于挑选操作，不等于全部送入同一 Run；本轮已选工具的快照限额继续独立执行。

页面称为“可用工具”：首次“读取工具列表”，之后“检查工具更新”；没有变化时提示已是最新，不生成重复确认。出现变化后展示新增、修改和移除数量，由用户“确认工具列表 / 应用工具更新”后采用；“暂不更新”仅忽略本次拉取结果，保留平台原列表，不让远端服务回滚。这是一次待审核快照，不是平台托管远端服务的版本系统。

官方握手返回的可选 `instructions` 单独保存为候选服务说明，最多 16 KiB；与目录一起确认并计入候选摘要。冻结到本轮后明确标为上游说明提供模型，不提高其指令优先级。每次调用比对服务说明和目标工具定义；说明变化也会停止受影响调用并形成候选。说明变化不改变未变工具的定义摘要，不要求管理员重新勾选所有工具。历史目录没有保存说明时，如服务返回非空说明，需要重新发现并确认一次。

| 事件                   | 处理                                                     |
| ---------------------- | -------------------------------------------------------- |
| 新增工具               | 先进入候选；确认后可供选择，默认不授权                   |
| 删除或原始改名         | 不自动迁移许可；旧操作不可调用，改名按移除加新增处理     |
| 原始定义改变           | 原摘要许可不接受新定义；提交时必须携带当前明确选定的摘要 |
| 仅修改中文展示名或说明 | 不改原始工具名、目录摘要或运行许可                       |
| 相同目录再次确认       | 清除候选，不无意义增加目录修订                           |
| 候选过期或连接改变     | 拒绝确认，重新读取；候选默认有效十分钟                   |
| 运行时发现目标定义不符 | 拒绝业务调用，保存候选供连接所有者处理，不自动发布       |

有展示名时显示“中文名（原始工具名）”；没有就显示原始名。不自动翻译，不允许编辑协议原始名称、描述或 schema。原始参数定义可展开查看；`inputSchema` 是一次业务工具调用的参数，不是账号配置表单。

别名独立修订；目录、凭证和员工保存都有预期依据检查。高级范围 JSON 只支持已有后端规则，任意提示文字不构成可执行的仓库或业务权限。

## 模块与交互

```text
backend/app/
├── mcp/
│   ├── models.py                 # 保存服务定义、账号连接与账号工具清单
│   ├── definitions.py            # 维护服务接入定义，解析支持的配置导入
│   ├── access.py                 # 检查账号与服务是否允许当前用户操作
│   ├── connections.py            # 维护账号、密文凭据、配置与凭据修订
│   ├── catalogs.py               # 读取远端工具清单，确认、忽略及标注候选
│   ├── invocation.py             # 调用已许可工具，管理每轮 MCP 客户端
│   └── adapters/http.py           # 适配官方 SDK，将认证拒绝转为平台错误
├── employees/
│   ├── access.py                 # 判断当前用户是否能编辑员工
│   ├── tool_grants.py            # 保存员工工具许可，固定账号并逐动作复核
│   └── tool_account_bindings.py  # 为员工已有许可选择当前用户的本人账号
├── execution/
│   └── snapshot.py               # 调用员工装配，按发起者固定本轮工具身份
└── infrastructure/
    └── credentials.py            # 共用凭据加解密机制；业务负责错误含义
```

前端的 `components/tools/ToolAssembly` 接受装配值与回调，不保存 Token；`pages/tools` 拥有账号与目录页面；`pages/skills/CapabilitiesPage` 是联合列表；读写集中通过 `lib/api/tools`。对话给普通成员使用精简的员工使用投影，不为开放聊天扩大员工配置读取权限。

执行路径：Conversation 接受输入 → 准备 Run 时解析账号 → Agent 决定调用工具 → AgentContext 同事务复核许可与记账 → MCPAdapter 在受控网络中复核远端定义并调用 → 保存结果 → 模型继续。整个远程 MCP 调用不启动平台沙箱；文件、命令执行依旧走原生受控通道。

## 本地、线上与迁移

Mac 和 Linux 共用代码，静态 Token 接入没有浏览器回调地址，OAuth 配置固定本站回调。两边分别配置数据库、文件目录、工具主密钥和实际网络；真实外网连通性、服务认证与上游权限需在实际部署验证。主密钥必须随数据库一起可靠备份，不能丢失后生成新密钥冒充恢复。

目录读取会区分后端 DNS 失败、链路本地等特殊地址拒绝和上游认证拒绝，即使 SDK 包装底层异常也保留平台生成的可公开说明；不返回上游原始诊断或凭证。域名与代理 DNS 无须另配主机清单，见[部署指南](../guides/agent-tools.md#3-接搜索与网页)。

正式迁移 `0007` 保留连接 ID、密文、目录和员工许可，为历史 MCP 建立服务定义，默认个人模式，原生工作区保留共用模式；旧 Run 不能绕过新的身份检查。迁移前备份数据库。降级如果新增连接出现同名，会因旧版名称唯一约束拒绝，需先处理重名或恢复备份；不静默删除账号。

`0008` 增加明确传输类型、stdio 启动定义与环境变量键、批准服务说明，保留历史 HTTP 连接和许可。存在 stdio 服务或连接时拒绝降回 `0007`，避免静默丢失身份与许可。

## 可信 stdio 运行边界

部署默认关闭 stdio。启用方式、固定依赖和限制见[部署指南](../guides/agent-tools.md#可信本机-mcp)。只有管理员可登记或修改 stdio 服务，普通成员只为已登记的服务建立本人账号。程序、参数与环境键属于固定服务定义；更换程序应建立新服务，不复用旧工具许可。环境键不能使用 PATH、HOME、PYTHONPATH、NODE_OPTIONS、LD/DYLD 加载、代理等启动控制变量，避免使用者通过凭据字段替换程序行为。远程 HTTP 仍可按原规则接入。

保存与导入不启动程序。发现目录使用短期进程；实际调用按 Run、实际连接及配置/凭据修订复用同一会话，同一 Run 后续工具保留进程状态。不同用户或 Run 不共享进程；完成、取消或应用停服均关闭。进程额度由应用全局限制，超出后有界等待，再返回容量错误，不无限排队。名额按真实打开的会话持有；登记十个服务不等于启动十个程序。

客户端使用结构化 argv，不经 shell；工作目录为独立临时目录，只继承 SDK 的最小环境与当前账号提供的声明值。SDK 处理 MCP 协议及进程组，薄启动器补齐“主程序正常退出但遗留后代”的回收；对主动脱离进程组的守护程序不提供恶意代码隔离保证。

这些程序具有后端宿主账号的权限，没有 Docker 的 CPU、内存或网络隔离；HTTP 的域名策略也不能约束第三方进程自行发出的网络请求。部署者只开放可信并固定版本的程序及工具实现，确保 Node/Bun/Python 与包已安装；首轮 `npx/bunx` 下载可超时。平台内置的脚本执行工具仍固定走 OpenSandbox，上传 Skill 不会生成宿主启动定义。但若管理员批准的 stdio 工具本身会把调用参数当代码在宿主执行，平台不能仅凭 MCP schema 阻止它；此类服务不适合向非可信使用者开放，应另行隔离。此机制不占 OpenSandbox 的容器名额，也不改变内置脚本沙箱方案。

OAuth 扩展账号认证生命周期，员工定义、目录确认和个人绑定继续使用相同模型。

## 快捷导入与连接测试

新建 MCP 只显示同一张接入表单，服务信息右侧“快捷导入”打开 JSON/文件弹窗。支持受限 `mcpServers`（含 `type` 别名）与 Registry `server.json`：Streamable HTTP、固定版本 npm stdio；后者按公开描述保存输入名称、说明、是否必填与秘密属性。当前不支持 Registry 参数模板、额外启动参数、多请求头、SSE 和 OAuth 导入描述；OAuth 需在访问设置中显式选择。不支持的导入方式明确报错或提示跳过，不静默当作接入完成。Registry 本地方式仍受部署开关和管理员登记限制。

解析仅回填草稿。客户端示例中的真实秘密只在当前表单中暂存，变量占位符保留为空；预览响应不回显秘密。多种方式先选一项，覆盖已有草稿需要明确勾选。输入说明不是实际密钥，秘密值仍只保存到个人或明确共用的账号连接；服务定义不保存秘密。

“保存并测试”依次保存定义、保存当前访问设置、建立协议连接并读取工具。它们是分开的短事务与网络操作，失败不会伪装整体回滚：服务已保存而账号失败时保留访问草稿；账号已保存而连接失败时提供修改和重试。成功后首次目录显示真实工具并等待确认，之后才能装配员工；创建服务不授予任何员工权限。读取目录成功不代表已经验证某项业务工具调用。

`0018` 为原账号增加 OAuth 状态与内部存储修订，保留旧连接 ID、静态密文、清单和员工许可。仍有 OAuth 账号时拒绝降回 `0017`，不能靠降级丢弃授权；先备份数据库及工具主密钥。
