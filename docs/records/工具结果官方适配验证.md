# 工具结果官方适配验证

日期：2026-11-10。状态：最小交接契约和隔离适配验证完成，生产未接入。对应[方案](../proposals/执行与Agent能力架构设计.md#工具结果交付小范围优化方案)与[引用交叉评审](工具内容管理与资源引用交叉评审.md)。

本文是接线前的时点记录；后续实现与真实模型结果见[改造验收](工具结果交付改造验收.md)。

## 1. 结论与证据范围

**官方 FilesystemMiddleware 可以承担新 MCP 文本结果的移存、预览，以及通过 read_file/grep 读取；平台仍需负责原始协议归档、可信来源映射和当前权限。** 隔离原型已验证这些职责可以衔接，不需要再建设一个通用结果处理服务。

本记录时点的原型运行得到 **20 项通过、1 项已确认的投影差异、0 项非预期失败**。全部使用合成数据、脚本式假模型、独立临时目录和 SQLite；真实 SDK 图、现有 ToolExecutionMiddleware、WorkspaceBackend 和 ToolResults 参与验证。业务身份和 MCP 客户端采用替身，不启动业务应用，不访问业务库或真实 MCP，不产生模型费用。约束及逐项结果见[原始报告](data/工具结果官方适配验证.json)。后续生产接线已用[正式隔离测试](../../backend/tests/test_result_delivery.py)替换临时原型，`make verify-tool-results` 现在运行正式回归，不重建本记录时点的报告。

这不是生产全链路验收，不证明真实答案质量、token/费用下降、真实网络时延或远端沙箱取消。源码指纹确认脚本执行期间所核对的应用模块未变化；没有把原型接入生产 Agent。

## 2. 适配方式和实际结果

原型使用 SDK 公开的 CompositeBackend、BackendProtocol、FilesystemMiddleware 和 SQLite Saver。官方移存目录通过 artifacts_root 定位到 `/sources/large_tool_results`；受控 Backend 将 SDK 路径登记成现有冻结文本的读取别名，底层读取继续复用原有 SnapshotBackend。只新增别名元数据，不另写一份 SDK 正文；现有原始归档格式本身未做去重或迁移。

SDK 内部登记来源别名与模型主动写文件必须区分。原型通过可信工具执行上下文关联原调用、Run 和来源绑定，写入只接受对应工具的已保存内容；模型 write_file、直接无上下文写入、来源改写均被拒绝。来源身份不从文件名反推，SDK 清洗后的文件名也不改变原始内容标识。

| 验证项 | 实际结果及边界 |
| --- | --- |
| 10,988 字符小 JSON | 完整、可解析地进入下一次模型请求，不生成移存别名；保留应用侧 artifact |
| 207,999 字符长文本 | 官方生成 1,985 字符的头尾预览；原生 read_file 可读中间段，下载文本与冻结原文一致 |
| 长 JSON 与结构化原始返回 | JSON 原文可完整恢复；上游 next_cursor 与结构化数据仍在原始归档，不与本地读取游标混用 |
| 并行两个大结果 | 原始归档和读取别名各两份，下一次模型请求参考投影约 9 KB；随后读取第二份结果，其来源关联正确 |
| 图像块与应用元数据 | 文本移存后保留非文本块，原始协议完整保存；未验证真实供应商对图片的渲染或计费 |
| read_file、grep | 复用官方读取/搜索，未递归生成新移存文件。原生 read_file 自身可按大小返回较小窗口，不能将请求的行数当作实际交付范围 |
| 平台记录与模型反馈 | 工具门包住 SDK 结果处理时，动作记录的反馈哈希与下一次模型实际收到的对应工具文本一致 |
| 来源保护 | 模型改写、无可信上下文直接写入、跨 Run 读取均被拒绝；来源撤权后 read/grep/download 均拒绝。这里的授权服务为替身，不代表生产 DAO 已验收 |
| 保存失败与取消 | 原始归档失败不发放结果；在别名生成前取消时不提供别名。原文可能已经保存，不声称同步 I/O 或远端进程立即停止 |
| 官方移存写入失败 | SDK 会保留原消息返回；原型最终容量检查拒绝超限回退，不生成虚假文件路径 |
| checkpoint 与重建 | SQLite 保存读取路径及消息；重新创建 Backend 后可读原冻结内容，不再调用业务工具。没有声称支持现有规则禁止的 MCP 执行重放 |
| 旧结果 | format_version=2 和未带 text 的旧格式均保持原字符游标与冻结投影，不重新调用业务工具 |

官方默认移存参数名为 token 阈值，但本机版本的触发采用字符数近似判断，不能将该阈值等同精确 tokenizer 计数或模型上下文窗口。未适配的现有 WorkspaceBackend 会拒绝 SDK 默认移存目录，已作负例验证；不能直接打开生产开关。

需要保留两个明确的差额：

1. 多份结果各自低于移存阈值，合计仍可能超出一次请求容量。本实验两份各 70,000 字符的结果触发最终容量拒绝；只证明单结果移存不负责整体容量。实验未装历史摘要中间件，不据此断言官方摘要组合无效，亦不证明现有 128 KiB 是模型真实窗口。
2. 公开消息转换器与 ChatOpenAI 最终请求并非字节完全一致。本次 MockTransport 捕获到：空工具调用 assistant 内容在公开投影中为 `""`，实际请求为 `null`。工具结果投影一致，两边均排除 artifact；参考视图有价值，但不能当作精确 HTTP 字节、token 或费用计量。该项明确记为 gap_confirmed，未伪装成精确容量验收通过。

## 3. 交接契约 result-handoff.v1

本节作为后续两线接入的验证基线，不是已部署 API，也不要求新增数据库表或状态机。字段形状见[四个合成样例](data/工具结果引用交接样例.json)和[样例 Schema](data/工具结果引用交接样例.schema.json)。Schema 只校验本阶段夹具，`fixture_only` 等字段不是预定产品字段。

| 内容 | 最小语义与所有者 |
| --- | --- |
| run_id、model_action_id、dispatch_status | 关联本次模型请求；prepared、dispatched、responded、failed、unknown 分开，不能把准备成功当实际响应成功。本实验 responded 来自假模型 |
| source | 原存储 content_ref、可信来源绑定、冻结表示版本、哈希与文本长度；读取仍动态核验权限，不存永久 authorized=true |
| delivered_unit | 实际提供的有界文本单元、单元标识与哈希；来源于最终请求视图，不是检索候选或读取请求参数 |
| coverage、source_ranges | full_text 仅代表此冻结文本表示完整；partial_text 不代表全文。只有可证明的范围才使用从零开始、右端不含的 Unicode 字符坐标，否则为 null |
| model_view | 原生 ToolMessage 的模型侧内容；不添加另一层强制 delivery 包装，不包含 artifact |
| application_metadata | 来源引用等仅应用侧数据，经 artifact 或已有动作结果衔接；不计入模型输入，也不自动被模型看见 |
| model_visible_reference_ids | 只登记来源适配器确实放进模型可见内容的引用句柄。样例均为空，不允许仅把句柄放在 artifact 就声称模型已取得 |
| 回答侧 text、content_blocks | 从同一 SDK 回答保留文本、内容块和 annotations；来源资格、用途、正文位置及展示由引用线处理 |

三种事实始终分开：**原内容已保存、某个单元已交付模型、回答实际使用了某个引用。** 样例中的 citation_registration 均为 not_registered：普通结果不会自动成为已验证 Citation，SDK annotation 的 URL 也不授予权限。

SDK 预览可能由头尾拼接，还可能裁短单行；read_file 请求 1,000 行也可能实际只交付较小窗口。因此本阶段对预览和原生读取只确认已提供的内容单元，精确原文范围保持未知，不解析显示行号来补造坐标。引用线可使用该单元内的已提供内容；需要未交付原文时先读取，不宣称整个原文已读。

样例为方便核对同时列出单元内容与模型视图。生产实现复用实际工具消息/动作，不要求再持久保存两份正文。若强制核验引用资格，最小交付关联需可靠保存；可失败和脱敏的诊断 wire_request 仅用于核对，不充当唯一业务事实。普通未适配结果不为此新增硬失败点。

上游结构化返回与应用 artifact 不同。原始 structured 全量保存在归档，模型收到的是明确选择的文本/内容块；本期不自动猜测、合并结构化字段的业务含义。需要将特定业务字段提供给模型时，由来源适配器明确形成模型可见单元。

当前生产 `_completed_response` 只提取 text，原生 annotation 没有进入最终成果。本次验证保留 SDK 内容块即可表达候选交接形状，但没有修改正式成果链路；该项由引用线接入。偏移单位和正文拼接由供应商/引用适配处理，不能默认是源文档坐标。

## 4. 后续删改清单

以下是实施清单，不是本阶段已修改项。工具发现代码、目录和员工装配保持不变。

| 处置 | 具体对象 | 条件与原因 |
| --- | --- | --- |
| 删除 | feedback_outcome 的无标记 24 KiB 字节切片及仅为它服务的调用参数 | 已有损坏 JSON 的确定性反例；规范化继续保留状态与多模态处理 |
| 改用官方 | 新 MCP 结果的固定 3,000 字符首预览、自建新结果字符分页主流程 | 原型已证明官方移存、预览、read_file/grep 可用；生产权限与持久关联验收后替换，不双跑两套正文处理 |
| 保留 | 原始 MCP 协议和 frozen text 归档、来源授权、Run 归属、下载与旧结果读取 | 官方只移存模型侧文本，不能代替这些业务职责；旧 reader 兼容暂不删除 |
| 最小适配 | mcp_tools 调用结果到 SDK 内容块的衔接，以及受控 Backend 的读取别名 | 先归档原始返回，再给 SDK 正确文本/内容块；不让 SDK 把外层协议包装当正文再次保存 |
| 调整时序 | ToolExecutionMiddleware 与 FilesystemMiddleware | 工具动作门需覆盖最终 SDK 反馈处理，完成记录后再交给模型；仅打开现有外层 SDK 会导致动作记录与实际反馈不一致 |
| 保留并收敛 | 一次完整模型请求的容量检查 | 剔除应用 artifact，确认真实模型窗口；公开参考投影不冒充精确 token/费用，不再增加每工具多套裁剪阈值 |
| 引用线接入 | AgentOutput/最终成果中的标准内容块和 annotations | 不把原生引用转纯文本后指望模型补回，不增加隐藏修复模型调用 |
| 独立清理 | 超时覆盖、重复限次、无效配置 | 按运行控制价值审查处理，不把本次假模型试验当成这些改造已完成 |

临时原型中的 ArchiveBeforeOffload 与 ScopedExecution 用于在不改生产的前提下验证时序。生产实现应将归档和可信上下文归回现有 MCP/工具门，不照抄成新增通用中间件层。别名持久关联优先复用现有动作结果与文件引用，本阶段的隔离 JSON 索引不预定为生产存储方案。

## 5. 接入顺序、检查与限制

1. 引用侧按本节四个样例消费来源及交付事实；共享字段由本线维护，原生注解和最终清单由引用线维护。本次未向另一聊天发送实施指令，也不代表其已经完成生产接入。
2. 后续生产改造先删除损坏反馈的切片、修正 artifact 计量；接入受控 Backend 与原 MCP 归档，验证正式权限服务、事务与取消，再替换新结果主路径。知识和已有文件继续使用原生入口。
3. 生产运行链路打通后，才做既定真实模型对照：答案/引用质量先过关，再比较完整 Run 耗时、缓存读写和折算成本。当前 Kimi Code 额度权重未知的部分保持未知。

已执行：根命令 `make verify-tool-results`；新验证脚本的 Ruff 检查与格式检查；四个夹具的 JSON Schema 校验及来源/范围一致性检查。未执行生产全套测试、真实模型、真实上游 MCP、真实沙箱或引用 UI 验收。用例中的毫秒级耗时来自假模型，仅说明验证脚本运行时间。

隔离副作用说明：实验脚本初稿曾放在 backend/experiments，触发已有开发服务的热重载。已移到根 scripts，后端日志确认重新启动完成。脚本自身不装配业务应用；本次未做业务数据全量前后比对，不把服务重载描述为生产隔离验证通过。
