# 知识库、文档与检索

知识库是组织资料，由管理员上传文件、手动后台分片、发布关键词索引和建立可选向量索引。管理入口 `/knowledge`；员工配置固定的资料范围与检索时机，运行时自动检索并给出可核对的片段引用。后台增量向量仍待实施。模块职责及实验分支见[后端知识模块](../../backend/app/knowledge/README.md)。

## 用户流程与持久化

用户创建业务知识库，进入库内选择 UTF-8 Markdown/TXT 并上传。原文件复用 files 的持久磁盘、摘要和账号配额；当前本机目录在工程外，部署位置由 FILES_DIRECTORY 配置决定，见[文件配置](../guides/backend-operations.md)。客户端不能提交服务器本机路径。

上传只校验格式、编码、大小并保存原件，不切分、不调用模型。上传成功即加入知识库，文档显示“待分片”，可下载原件，详情的document为null、chunks为空，不参与检索。演示导入同样保存为待处理原件。文件服务先保存但未成功关联的原件按暂存周期清理；已被知识文档引用的文件不会被附件清理器删除。

用户确认资料后手动提交处理批次，后台按单文件并发解析、切分与分词；计算不占写事务。每个文件的固定正文、来源块、Chunk和FTS5在同一事务发布，成功一个即可检索一个，不等整批结束。重处理前旧内容继续可用，失败保留旧内容；新关键词发布时仅清除该文件的旧向量，不混用新旧Chunk。后续向量仍通过现有独立构建入口生成，本期关键词任务不自动调用Embedding。

处理批次和文件子任务持久化，冻结原件摘要和最终规则，同文件只允许一个活动任务。服务重启后继续排队项，原执行中项标为中断并允许手动重试；局部失败不撤回其他成功文件。取消或删除使迟到任务失去提交资格；删除仅清理目标文件派生数据。生产由应用lifespan启动单文件KnowledgeWorker，使用与部署Runner锁配置相邻的进程锁；测试注入runtime.enabled=false时不启动后台扫描器，可直接驱动处理服务。

库元数据更新有修订保护；接口也支持默认切分覆盖。页面的“知识库设置”只编辑名称与用途，文档页规则弹窗只保存本页后续操作的配置，不改变库默认。默认800字符、120字符重叠。覆盖可空，合并后必须重叠小于切分长度；长度范围100～2000字符，重叠0～1000字符，短章节阈值0～2000且不能超过长度减重叠。短章节阈值默认取200与长度减重叠的较小值，0关闭合并。产品按Unicode字符计长，不称为模型token；上限也保证当前Embedding单条字节预算。新设置只影响后续任务，不自动重切旧文件；恢复默认通过清空覆盖表达。

切分先保留ATX Markdown章节与完整标题路径，按空行、换行、中文标点、空格到字符递归拆分；长度包含原文标题、空白和重叠。仅相邻且具有同一实际父标题标识、各自短于阈值的章节可合并，合计不超过长度减重叠的预算。不同顶级章节、父子导言、长章节不合并；代码围栏内的标题不作为章节。同名父标题的不同出现不能混为一组。合并片段保留所有标题、连续原文和多来源区间；该规则基于结构，不保证内容语义相近，阈值也不是承诺的最小片段长度。

文档页常显已确认规则摘要及“调整”。调整打开模态设置，编辑三项规则，并可预览首份已选文件；没有选择也可编辑规则，预览禁用。确认只更新本页配置并关闭，取消或Escape丢弃草稿；后台列表与分片操作在弹窗期间不可操作。主页面“分片并建关键词索引”直接按已确认规则执行当前选择，无额外处理确认。

预览显示总片段数、长度范围、短片段/合并数量和逐片原文及来源；每页20片段，通过offset翻页，只读原件，不生成索引、作业或外部模型调用，每账号每分钟30次。规则变化隐藏旧预览、取消过时请求并忽略迟到结果。任务冻结提交的最终规则，不受之后的配置变化影响；预览可选，不要求逐片批准。

分片提交前显示新建、复用和重新分片数量。后端核对原件摘要、有效规则、解析/分片与分词版本，以及正文、完整片段和FTS行的发布摘要；同条件且完整的结果直接标记为reused，不重新解析、分片、分词或清除已有向量。依据缺失、版本不兼容或数据损坏时重建；不同规则只重切明确选中的文档，成功发布后清除对应旧向量。旧数据没有发布摘要时继续可查，首次明确选择处理会重建并登记依据。提交标识幂等与跨请求结果复用分别生效。

当前每文件128 KiB、每库200文档/5000片段、每账号100库。原件数量在上传时检查，片段数量在逐文件发布时检查；预览和处理的切分计算也在超过单文件5000片段时提前终止，提示调整规则。文件总量另受files配额约束。当前不提供原件在线编辑、文件替换或版本历史；同名不同内容是独立文档。

## 身份与接口

管理员通过 `knowledge:manage` 管理全部组织知识库，创建人仅用于审计、创建幂等及账号配额，不构成私有读取范围。成员的 `knowledge:use` 只允许使用员工已配置的知识工具、读取本人有权查看的 Run 登记证据，不允许列库、任意文档或原件读取、检索测试和索引管理。游客保留既有 `knowledge:read` 例外：可只读全平台库、文档、片段、向量状态及处理记录，下载原件并执行关键词检索；写入、处理、取消、向量构建和向量/混合检索均拒绝。游客没有 Run 证据读取许可。上述检查在服务入口执行，不能只依赖页面隐藏按钮。

接口定义以[schemas](../../backend/app/knowledge/schemas.py)及运行 OpenAPI 为准，以下路径均以 `/api/knowledge-bases` 为前缀。

创建与上传按请求标识幂等；相同库中的相同原始字节去重，不以文件名推断覆盖。处理批次也按提交标识幂等，改变文件集合、reprocess或明确rules复用标识返回409；重试同一提交返回原批次及规则快照。失败文件重新处理使用新批次；网络未知结果重试沿用原提交标识。库更新修订过期返回409并保留表单。

错误类型、状态码遵循[统一错误规则](failures.md)：无许可为 403，不存在或 Run 不在当前读取范围为 404，大小/格式/编码/空正文/容量不符合要求为 422，分词版本不兼容为 409，上传过频为 429。网络失败不能直接判断服务端未执行，先读取或用同一标识重试。

## 来源与检索边界

文档保存固定正文和不可变摘要版本，切片包含文档 ID、版本、来源块及 `[start,end)` Unicode 码点区间。管理页通过库/文档/片段 ID 定位正文；回答引用通过 Run 与证据编号读取固定片段。不能按相似文字或列表序号猜位置。资料文本不作为系统指令执行。

BM25 使用相同 jieba 词法规则建立、查询索引；分词器、词典与 SQLite 版本摘要不兼容时拒绝混用。FTS5 排名分数越小越靠前，不是相关概率或模型置信度。FTS5 是共享业务数据库内的虚表，返回候选严格约束当前库；词频统计使用该 FTS5 表的整体语料，不承诺库间独立评分。没有召回不等于资料足以回答，也不会触发全局换库。

总览显示库名、用途、文档数和更新时间，窄屏单列。库内分为“文档”“检索设置”“检索测试”，默认显示文档。页头左侧为库名及用途，右侧上传按钮展开上传区；文件上传成功后直接进入列表。文档按名称、关键词状态、片段数和向量状态对齐，窄屏将状态合入名称；悬停、焦点与选中覆盖整行，复选框、重试与来源链接分别操作。

表头复选框负责全选／取消全选当前结果，支持半选；搜索保留范围外选择，已删除或进入处理的文档不计入有效选择。不另设全选、反选、清空选择按钮。已选数量、处理摘要与“分片并建关键词索引”始终占位，零选择时按钮禁用，不自动扩大为全库。失败/中断可逐项重试，分片记录可查看或取消；处理中的观察页面轮询，离页不停止后台任务。

上传队列由身份作用域工作台持有，通过全局非模态浮层观察；目标库和上传标识固定，SPA切页或收起继续上传，未上传的本地文件不阻止处理旧文档。失败可单项重试，确认成功显示“已上传 · 待分片”。刷新/关页可能中断传输，不承诺断点续传；取消不证明服务端没有保存。切换身份清空队列、尽力取消在途传输，迟到结果不得进入新身份。

检索测试仅提供问题、查询及命中原文与来源，不提供技术策略选择器。默认auto由服务端按当前能力选择：有ready/partial向量时混合，否则BM25；游客始终关键词检索。页面只读显示当前方式，完全没有片段时禁用并引导到文档页。检索失败明确报错，不将上游故障静默降级。

## 硅基流动向量接入

管理员在知识库“检索设置”页的“管理向量模型”弹窗管理向量模型，选择「硅基流动 · BGE-M3」后填写 Key，保存并测试真实固定短文本；使用者在索引页直接选择已启用连接、查看有效覆盖并建立或重建向量索引。大脑页面只管理数字员工的对话模型。已有向量连接继续可用，无需重新录入 Key；向量连接可在不同知识库间复用。页面明确说明此操作向硅基流动发送当前库片段，查询时发送问题。地址与模型固定，不将聊天 Key 转发到向量服务。

正式链路使用 `OpenAIEmbeddings` 发送原文，每批最多8条，单条保守限制UTF-8 8192字节（不是模型token计数）；产品片段最多2000字符、问题最多1000字符。验证返回数量、1024维、有限数值和非零范数后归一化。SDK不自动重试，HTTP超时20秒、不跟随重定向、不使用环境代理，原始上游错误不回显。

`knowledge_vector_indexes` 保存模型连接/配置修订、来源摘要、generation、Chroma collection 名与向量空间指纹；`knowledge_vector_memberships` 只保存该代有效片段及文档版本，不再保存数字数组。向量由本地持久化 Chroma 管理，使用官方 cosine HNSW 近似 Top-K，不再通过 Python 遍历全部向量。索引默认在业务数据库旁的 `knowledge-vectors/`，可用 `KNOWLEDGE_VECTOR_DIR` 覆盖；同一目录只能由一个进程使用。返回 `cosine_distance_lower_better` 距离，越小越靠前，不是回答置信度。

构建为同步有限请求，每进程仅一个构建，批次之间检查 120 秒总预算与连接修订；当前网络调用可能延至自身超时后才报告总预算耗尽。外部调用和 Chroma 构建位于 SQLite 写事务外：先在不可见的新 collection 写入已生成的向量并核对成员，再在短事务中复核资料、索引 generation 和模型/凭证修订，切换指针与成员。Chroma 不自行生成第二次 Embedding，也不下载默认模型。失败清理半成品并保留旧指针，旧代等在途读取释放后回收。进程退出不恢复未完成构建；HTTP 断线不证明发布失败，重新读取状态后再决定是否重试。

向量有效范围以当前实际 Chunk 与当前代成员关系计算，原件暂存不会使已有向量失效。删除一个文件保留其他文件向量；新文件关键词发布或重切文件后，剩余向量可形成 partial 覆盖，混合检索的 BM25 覆盖全部可用关键词内容，语义路径只覆盖有效向量。删除/重切先在业务事务移除成员，查询前用成员 ID 过滤并在返回后复核；Chroma 物理清理失败不恢复成员，启动时重新清理。页面显示有效覆盖数；构建仍整体替换所选库的可用向量，尚未实现异步增量向量任务。

模型配置变化使向量过期；换Key不重算向量，在途构建/查询按凭证修订拒绝旧结果。停用连接不可检索，被引用连接不能删除。上游失败不静默回退BM25。构建每账号每分钟3次，自动、向量与混合查询共用每分钟30次额度；构建失败保留旧索引。

混合检索生成一次问题向量，通过 Chroma 取得向量候选，再在来源/权限复核事务中取得 BM25 候选，各最多 30 条。官方 `langchain-classic` 的 `EnsembleRetriever` 以 RRF（c=60、等权、chunk_id 去重）合并；同分沿用官方输入顺序，不维护第二份公式。返回 `score=null`、`score_kind=rank_only`，页面显示融合排序第 N 项；BM25 仍返回原分数。默认返回 6 条，最多 20 条。融合不调用模型，也未新增 Reranker。

关键词路径在后端公共 `lexical_search` 内对 query 使用 jieba 精确模式、HMM=False 分词，与文档处理规则一致；向量路径把同一 query 原文交给受管 Embedding 接口。测试页传页面输入，按需 Agent 传模型生成的工具参数；两者复用同一检索核心，模型组织 query 不等于后端分词。服务就绪前核对 Chroma 发布指针并清理孤立 collection；当前 collection 缺失时移除无效索引元数据并显示需要重建，不回退旧引擎。

“检索设置”独立承载模型选择、覆盖状态、建立/更新及移除。向量操作范围是本库全部已有片段，与文档页勾选无关；按钮显示已分片文档数量，并说明其余待分片文件不参与。即使7份文件只有5份已分片，也可先处理这5份；完全没有片段才禁用。上传和分片不自动向量化，向量构建也不重复分片或关键词处理。

当前建立或更新向量仍会为所有已有片段重新编码，不提供增量向量缓存；页面明确调用范围。新增待分片文件不阻止已有向量继续使用，不引入整库降级策略。同步构建期间禁用页签切换和上传入口，并登记离开保护；检索设置与测试往返保留问题。

当前结构由 [0023 迁移](../../backend/migrations/versions/0023_knowledge_chroma.py) 替换旧 0014 向量表：直接删除旧数字数组和索引指针，保留原件、正文、片段、关键词及对话，不转换、不双写。已有库需要重新建立向量索引。公开样例、实际测试及限制见[质量验证摘要](../records/关键故障与质量验证.md)和[资料清单](../../backend/datasets/public-knowledge/README.md)。

## 员工配置与正式问答

员工的知识库范围、检索时机和每次检索片段上限是统一配置，由有员工编辑权的管理员在员工配置中维护，随“保存配置”一起生效。员工能力和对话侧只读展示，不再提供“我的知识库”或个人覆盖。最多选择10个组织知识库，`top_k` 为1—12。员工主接口通过 `knowledge={knowledge_base_ids,mode,top_k}` 读写，冲突使用员工的 `expected_revision`，字段与原子保存规则见[配置契约](configuration.md)。

`on_demand` 显示“按需检索”，模型根据当前问题决定是否查询或补读；`always` 显示“每次回答前检索”，系统在首次模型调用前先查询一次，之后模型仍可检索和补读。检索时机属于员工使用策略。资料处理和索引维护在知识库模块；查询工具只接收问题、范围或证据编号，不接收时机和算法配置。

员工配置、持久字段和新 Run 快照均不含 `strategy`，旧强制算法字段返回422。各库统一自动选择：有 ready/partial 向量时混合检索，否则使用关键词；未分片文件不参与。能力不同的库可以一起使用。真正上游故障明确失败，不伪装成无命中或静默降级。

[0027迁移](../../backend/migrations/versions/0027_automatic_employee_knowledge.py)移除旧个人算法列；[0028迁移](../../backend/migrations/versions/0028_organization_employee_resources.py)按显式接纳清单将存量知识库迁为组织资产，将选库关系和使用策略移入员工配置，并删除个人设置表和接口。迁移保留历史 Run 快照与证据、文档、原件和索引，不从历史记录恢复个人配置。执行与验收以[发布记录](../records/发布与数据迁移.md)为准，代码存在不等于目标数据库已升级。

任务接受事务捕获员工修订、知识目录、使用策略和固定库范围，将名称/用途作为资料数据注入模型上下文，实际工具定义另行注册，不改写员工原岗位指令。运行侧核对真实发起者工作授权及员工配置，不伪造知识库创建人身份，也不再将发起者等于会话拥有者作为组织资料使用前提。只允许检索本 Run 冻结的员工库范围；当前员工停用、配置修订变化或库被删除时旧任务停止。

按需检索不保证所有相关问题都调用。回答前检索通过稳定且幂等的宿主工具动作执行，长问题使用前1000个字符查询，完整问题仍送入模型；恢复复用持久结果前仍复核工作授权和来源，不重复调用向量 API。两种模式保留后续查询和补读能力。

知识提示词区分检索时机、证据使用和引用。内部具体事实、标准和流程应从组织资料取得依据；外部时效信息和实时业务数据使用已提供的相应工具。片段不足时补读，资料冲突时说明差异和适用条件；无命中、待处理和技术失败不等于不存在相关规定。资料内容作为证据，不作为系统指令。程序只校验来源身份、授权及链接配对，不证明自然语言结论得到充分支持。

连续追问只从同一对话实际纳入上下文的成功回复取得来源。knowledge核对同员工、同会话拥有者、同线程、原 Run 冻结库范围、当前已配置库范围及完整 Chunk 快照；旧个人历史还要求原 `knowledge.user_id` 与该 Run 的拥有者、发起者一致。调用方必须传可信的 `owner_user_id`、`thread_id`，不能从模型链接推断。按最近上下文、当前 Top-K、18KiB及剩余上下文预算选取，将片段、原编号和来源 Run 冻结到 `knowledge.history_evidence`，在本 Run 重新登记证据。模型收到可核对的原文，按需模式无需重复搜索同一事实；always仍执行本轮查询。

失效、超出预算或未选入上下文的旧来源不获得本轮引用资格。仅清理送模历史副本中的旧编号与链接并提示重新检索，已交付消息保持原记录。接受后撤权、删除或重切仍会阻止后续动作和发布；不能在最终答案出现旧编号时才临时跨 Run 导入来源。

`search_knowledge(query, library_ids?)` 默认查询全部本轮员工库，`library_ids` 只可收窄；`read_knowledge_source(evidence_id, offset?)` 只补读本轮登记片段，包含本轮重新核验的历史来源，单次最多2000字符。参数不能指定用户、员工身份、任意文件路径或原件。字段与工具 JSON Schema 统一来自[输入模型](../../backend/app/knowledge/schemas.py)，宿主仍执行实际参数、预算、取消、授权和动作记账检查，不套用 MCP 许可。

各库候选按名次融合，不比较不同原始分数或向量空间；合计最多 top_k 片段及约18KiB结果，分别返回空库、待处理、无命中、部分覆盖或故障状态。检索只使用已发布内容。低层查询请求及诊断结果仍可包含实际 `strategy`，不作为员工设置。

证据保存于 `knowledge_run_evidence`：记录 Run、库、文档、Chunk、正文版本和完整片段快照，不复制到普通文件下载通道。每次模型/工具动作、补读、缓存复用及发布检查员工修订、工作授权和已取得的 Chunk；即使文档 version 未变，片段重切也可使证据失效。卸载后停止当前任务，已交付历史正文仍遵循 Run 读取权限。

## 回答来源与历史阅读

新引用使用 `/knowledge/sources/{12位RunID}/{K-16位十六进制编号}`。对应 API：

| 接口                                                               | 读取范围                                                                                                                                   |
| ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `GET /api/runs/{run_id}/knowledge-evidence/{evidence_id}?offset=0` | 先核对 `knowledge:use`、`runs:read` 和该 Run 读取范围，再核对登记证据、原冻结库范围及当前文档/片段版本；返回最多2000字符，不提供全文或原件 |
| `GET /api/runs/{run_id}/knowledge-evidence`                        | 同样核对 Run 读取范围，仅返回已登记证据的有界标题、规范链接与旧链接精确映射，不列任意文档                                                  |

历史阅读不要求员工仍挂载该库；资料删除、版本或片段变化时明确失败。它与运行中工具使用当前员工配置的检查分开，成员不能借证据页进入知识管理页或读取任意文件。页面使用网站现有阅读布局，仅展示来源标题、章节、版本及片段。

模型应逐字引用结果中的 K 编号与规范链接。`finalize_answer` 只为编号和路径与已登记证据逐字配对的 Markdown 链接补回遗漏的根 `/`，然后完整验证；未知编号、未登记其他 Run 来源、错配路径、scheme、外站 host及额外 fragment均拒绝正式交付。不追加模型修复，不改写自然语言；原始动作保留，正式消息保存规范化正文，失败不发布未验证部分。

旧回答的裸库/文档链接仅通过消息所属 Run 的登记证据精确映射到新来源页，不能根据 URL 猜证据编号、切换成创建人身份或恢复个人设置。连续追问核验这些旧引用后，将送模副本改为规范链接；原始历史消息不改写。重复追问继续使用已核验的同一根来源链接。

前端通过严格站内路径解析将引用呈现为紧凑标题标签；打开卡片时读取相应 Run 证据，展示章节及最多600字符摘录，成功后提供“查看来源片段”。新标签页仍通过相同 Run 证据接口核验。完成后的 Sources 只汇总实际引用，代码示例、无效路径及仅检索未引用候选不计入。复制、存档仍使用原 Markdown。

读取资源归当前身份的 KnowledgeStore。相同证据请求共享，卡片重新打开时刷新；等待核验或失败时隐藏缓存正文，允许手动重试，关闭/卸载取消无人订阅的请求，切换身份释放缓存。旧链接没有消息 Run 上下文或匹配失败时不放行。来源目录加载不预取片段正文。

权限和历史范围回归见[员工知识测试](../../backend/tests/test_employee_knowledge.py)、[Run证据测试](../../backend/tests/test_knowledge_evidence_access.py)、[历史上下文测试](../../backend/tests/test_employee_knowledge_context.py)与[引用展示测试](../../frontend/src/components/knowledge/KnowledgeCitations.test.tsx)。真实模型及向量服务验收另见[质量记录](../records/关键故障与质量验证.md)。
