## 联网：复用 MCP，完善使用体验

网页搜索负责发现页面，内容获取负责读取指定页面；同一供应商可以兼具两者。Tavily 是现有普通 MCP 接入，不是网页读取的通用标准。

首期继续复用 MCP 的检查更新、确认目录、固定连接、员工许可与按需发现。只有确实维护稳定服务模板时，才在 mcp/presets.py 增加非秘密配置、字段说明及类别；模板不保存工具许可，不生成另一套账号或工具记录。

模型使用供应商实际返回的文本、多模态内容和结构化结果。搜索摘要、页面正文、处理失败和完整性未知应能区分；未明确产品要求前，不统一解释 results/raw_content，也不建立 agent/web_reads.py 或 mcp/tavily.py。

通用 Schema、明确参数约束、传输保护、体积和预算继续适用。若产品要提供域名范围，必须选定能可靠执行该限制的服务或明确参数映射；不能只凭 urls 等字段名猜测网页权限。相关现状见[基础工具契约](../reference/files-and-environments.md#工具范围与网络)。

验收至少使用两种不同回包结构，确认更换供应商不修改执行事务或通用结果存储。真实搜索覆盖、网页读取稳定性、费用和账号部署方式需要分别测量，不能只用离线假返回决定推荐服务。

### 4. 验收方法与退出门槛

先做隔离工程验证，再做真实模型配对对照。所有数据库、文件、checkpoint 和模型替身使用独立临时路径；不得通过开发环境配置读写真实业务目录。真实模型仍只发送已获授权的目录和合成样本，不执行远端业务操作。

样本至少覆盖：原案例形状的 50 个最近查看页面；明确完整且标注文章类型的小列表；放不进剩余请求空间的大结果；多工具并行返回；接近上下文上限或已有长历史；原文带远端业务分页；知识证据、文件读取、沙箱长输出和非文本内容。边界测试还需覆盖撤权、跨 Run、持久化失败、取消及旧结果游标，核对单一交付决定之后不存在再次切片导致的 JSON 损坏或正文丢失。大结果任务必须有需要末尾证据和需要完整明细的正例，不能靠一律提前停止获得好成绩。

隔离对照保留三组：A 为现行交付和提示；B 只换结果交付；C 在 B 上增加简短提示。三组工具发现及配置相同；受控比较使用同一份已测前缀和相同结果，按后续实际请求分别统计用量。另用独立新对话跑集成回归，使用真实工具门及保存/读取链路，不能只用临时脚本替代。集成回归不强制模型选相同工具，完整记录包括不利轨迹，不挑选样本。主案例每组至少 10 次配对，其他语义场景至少 5 次；阈值在执行前固定，调参后用未参加调参的样本复验。

| 维度         | 记录与判断                                                                                   | 拟定退出门槛                                                                                                               |
| ------------ | -------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 答案质量     | 对照事先人工确认的事实，逐条核对实际答案和工具轨迹；不能只让模型自评或匹配关键词             | 主案例应明确“本次返回 50 个页面、非全量、文章总数未知”；关键错误为零。已知完整列表应给出正确数量，正常任务完成率不低于基线 |
| 关键错误     | 把页面当文章、满页就断言更多、文本读完就断言远端无下一页、未读即声称已完整统计、虚构工具能力 | 任一次出现即不通过质量验收；性能更好不能抵消                                                                               |
| 往返         | 区分模型轮数、补读工具次数、重复业务调用及摘要调用；并行两次补读不是两轮模型                 | 主案例补读中位数为 0、模型轮数中位数不超过 3；不能用更多业务调用抵消补读减少                                               |
| 耗时         | 每次保存模型耗时之和及完整 Run 耗时；完整链路包含存储、组装和工具门，不能只报模型时间        | 主案例完整 Run 耗时中位数下降至少 20%；其他语义场景中位数不恶化超过 10%。同时报告 P90 和失败率，尾延迟异常需补样本再判断   |
| 缓存折算成本 | 按下节公式累计整个 Run，包括额外搜索、补读、摘要、失败或重试的已知调用；缺失保持未知         | 价格或额度权重确认后，主案例平均成本下降至少 10%，其他场景不得系统性增加；价格未知不能写“实际省钱通过”                     |

这些百分比是拟定的产品验收目标，不是从三次探索推断出的统计保证。真实模型结果需逐次展示原始值、中位数、均值、P90 和失败/超时，不用单个最好结果代替结论；样本不足或波动跨过门槛时继续采样，不宣布稳定达标。

对照顺序交错、串行执行，固定模型、生成参数和并发，记录价格日期及模型修订。先记录同一稳定前缀首次使用的状态，再单独比较已重复使用前缀的状态；不能手动清缓存时，以供应商实际 usage 标记缓存情况，不声称已经严格控制冷/热缓存。新增提示只改末尾相关说明，工具定义、系统段落和已有消息不做无关重排，以减少额外缓存扰动。

### 5. 缓存成本如何核算、如何交付

供应商缓存字段先归一成互不重复的普通输入 U、缓存读取 C、缓存写入 W 和输出 O。按对应模型及日期的价格计算：费用 = U × 普通输入价 + C × 缓存读取价 + W × 缓存写入价 + O × 输出价。所有价格使用相同单位；若按每百万 tokens 报价，计算总和后除以一百万。若供应商把写入费包含在输入费中，则按其规则合并，不再重复加一次。推理 tokens 已计入输出时不重复相加；缺失用量、价格或必要写入信息时保留未知。

缓存命中率只作诊断，不能单独判定成本优劣。探索中总 tokens 减少 47.9%，未命中缓存读取的输入只减少 7.8%；按缓存读价为普通输入的十分之一假设，仅输入费用下降约 21.9%。此数不含输出和可能的缓存写入费，也不是当前 Kimi Code 会员额度实扣结果。

Kimi Code 配额与公开 API 价格分开处理：有明确官方换算权重才折算会员额度；没有时保存用量，并报告不同缓存价格假设下的结果，标记为估算。若通过独立测试账号或 Key 的前后额度差验证，须排除同时使用并核对显示精度；无法隔离时不能倒推单次消耗。费用未知时只能判定质量和性能的结果，不给整体“费用验收通过”。

结果交付和官方移存已完成接线与真实对照，后续仅围绕未通过的答案质量及未知的实际费用开展独立验证，不重复安排已完成的裁剪修复与适配选型。旧结果游标继续兼容，当前规则见[运行契约](../reference/runtime.md#外部读取证据与长结果)。

### 7. 与回答引用任务的交叉边界

本节仅是本线的协调建议，未向另一聊天发送实施指令，也不代表另一任务已承诺接口或交付时间。

## SQL：业务数据源与文件分析分开

上传 CSV/JSON 的临时计算继续使用工作区与条件沙箱，不要求先建设数据源管理。企业持久数据库才需要独立连接、受限身份和可访问范围。

在数据库和岗位确定后，建议使用以下浅层落点；当前不预建空包：

```text
backend/app/
├── data_sources/
│   ├── models.py       # 数据源配置、创建审计、凭据引用和修订
│   ├── service.py      # 管理连接，在受信范围内解析数据源
│   ├── schemas.py      # 管理输入、访问范围和安全响应
│   └── sql.py          # 表结构及只读查询、服务端时限与结果上限
└── builtin_tools/
    └── sql.py          # 官方 SQL 工具的模型入口和结果转换
```

data_sources 拥有连接及查询规则；builtin_tools 只定义模型入口并绑定受控回调；agent 继续管理模型协作；execution 继续保存可靠动作。数据源凭据、任意连接串和用户身份不进入模型可填写参数。

优先复用 SQLDatabaseToolkit 的表列表、结构、查询和检查能力，接入现有官方循环，不再嵌套旧 AgentExecutor。已有 MCP 能满足岗位场景时可先使用，不重复开放两条含义相同的数据通道。

数据库必须使用真实的只读、限定表或视图身份；SQL 检查器不能授予权限。需要行列隔离时，使用数据库视图、角色或可落实的策略；只隐藏表名不等于限制查询访问。

## SQL 生命周期与验收

查询在业务写事务之外执行，定义独立时限、并发和返回量。客户端超时不等于服务端查询已结束，取消是否真正释放连接、语句和内存需要目标数据库证据。

1. 数据库身份实际拒绝写入、越表及越视图，不能仅检查提示词或 SQL 字符串。
2. 查询开始、预算、授权及结果仍经过现有动作门；撤权或连接修订变化时停止后续使用。
3. 超时与取消在服务端生效；未知结果如实保留，不因“只读”便假设所有调用都能安全重放。
4. 大结果有稳定预览、分页或交付方式，不能无限堆积模型上下文或后台内存。
5. 配置迁移保留既有历史；新存储结构附正式迁移和恢复验证，不要求重建用户数据库。

SQL 写入当前不提供通用入口。若以后出现明确业务，另行定义定向操作、权限、幂等和结果判断。

## 实施顺序与触发条件

| 阶段         | 启动条件                                 | 可交付内容                           | 退出条件                                                     |
| ------------ | ---------------------------------------- | ------------------------------------ | ------------------------------------------------------------ |
| 结果交付优化 | 小范围方案评审后，冻结对照样本和预算参数 | 有界完整交付、清晰补读语义与对照报告 | 质量无关键错误，耗时及缓存折算成本达到本节门槛；未知费用单列 |
| 联网体验     | 已选真实搜索/读取场景及候选供应商        | MCP 服务模板、配置说明、普通来源展示 | 两种服务结构可用；供应商替换不改内核；部署和费用有实测依据   |
| 结果移存接入 | 当前代码已接线且工程回归已通过           | 已并入运行契约，旧读取兼容保留       | 真实模型质量与成本验收后收敛剩余增量                         |
| SQL 数据能力 | 已明确岗位、数据库及可访问表/视图        | 受限连接、官方工具适配和查询资源控制 | 真实数据库权限、超时、取消、大结果及撤权通过                 |
| 后续专项     | 出现真实浏览器、委派或长期工作需求       | 对应的独立增量方案                   | 状态、授权、预算和交付有明确所有者，不借用无关目录代替设计   |

供应商、SQL 数据库和是否需要原生数据源管理均待场景证据决定，当前无需用户为不存在的部署选择默认值。每项实现后同步现行正文，验收进入 records，完成部分退出本文。
