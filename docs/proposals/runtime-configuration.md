## 目标与范围

调整前，应用已通过 AppConfig 聚合模块配置，但图计算步数、模型调用次数和技能读取次数仍分别硬编码在 Agent 与对话提交中。本次将三项默认值迁入 RuntimeConfig，沿用 `RUN_` 环境变量覆盖规则；配置类补充中文含义、单位及必要边界。数据库、认证、运行与模型连接继续按模块维护，由 load_config 统一装配部署配置。

## 职责与流程

1. RuntimeConfig 定义 `recursion_limit`、`max_model_calls`、`max_skill_reads`，保持当前默认行为；计数字段只接受正整数，时间字段接受有限正数。
2. ConversationCommands 在接受事务中调用员工执行配置视图，冻结这三项预算。当前快照协议从 schema 1 开始，版本常量由运行契约模块维护；未知协议不由当前执行器执行。
3. Agent 从快照读取图步数，模型和技能中间件继续读取同一快照。图步数耗尽归入已有 `agent_budget_exceeded`，保持稳定的预算失败反馈。
4. 不改数据库结构、前端接口或 CI 专业执行器的独立取证预算。修改部署配置需重启，新提交及显式重试使用新值，已接受的快照保持原值。
