# 平台后续能力的接入边界

设计状态：草案。实施状态：知识、通用工具、任务和评测未实现；P1 基础另见现行契约。更新日期：2026-10-27。

## 能力模型与实现阶段

[目标数据模型](agent-capabilities/README.md)承接现有表、读写与架构评审，已收敛每员工每技能一份参数化配置、标准内容制品、动态 MCP 目录与员工独立工具许可、知识版本/发布/作业，以及真实运行步骤。当前关系表、现状目标对照和依据在该文；原图的技能/工具部分已过时，新目标见[标准技能/MCP 设计](skills-and-mcp/README.md)。P1 已实现，标准包、通用工具授权与知识部分尚未实现。

当前基线为 0001 的十一张业务表，配置修订、参数化装配与真实运行步骤已实现，保留外部登录身份和 member 公开权限。字段见[数据字典](agent-capabilities/data.md)，运行和迁移见[契约](agent-capabilities/runtime.md)与[清单](agent-capabilities/migration.md)。独立技能发布、多实例及不可变装配历史不作为本版前置。

## 知识助手如何接入

当前实施范围与顺序以[知识库详细方案](knowledge-assistant/implementation.md#实施与验收)为准：交付上传/API、双路索引、混合召回、带引用问答及轻量真实评测；全文基线可选，正式评测平台后置。前端沿用知识、员工和对话入口；knowledge 管理资料及发布，知识问答用例统一装配检索与回答，执行宿主管理资源，轻量评测及后续 evaluations 复用同一问答用例。

继续复用现有权限、短事务、幂等、取消和运行观察机制。导入、构建和评测使用各自作业记录，共享有界资源；不为复用 Run 表伪造聊天消息，也不要求先建设独立业务任务、报告验收、工具或 SOP。

## 后续研究员如何接入

员工工作页、Task/Run/Deliverable 关系、对话与配置边界，以及等待/自动触发的分期由[员工工作页与任务执行方案](agent-workspace/README.md)维护；当前为草案，未实施。它替代研究员旧草案中 Task 必绑对话的通用集成方式，不改变知识助手的当前优先级。

以下仅说明后续扩展边界。研究员是员工配置及其装配方法，不另建包揽调度、取证、页面与存储的独立后端。

- 当前先补基础工具能力；新场景的入口、交办表单、报告及流程组织方式[后续再定](configurable-workflows.md)，不预先要求为每项工作开发专用页面，也不将配置化界面作为基础接入前置。
- 后端由任务应用操作承接交办与验收，与对话共用执行准入；执行装配准备本次依据，选定的研究方法组织核验，来源模块维护资料快照，运行驱动管理领取和取消。
- 用例分别依赖纯规则和窄出站接口；具体存储、模型与网页实现由装配根组合。纯规则不依赖 I/O，接口不按供应商定义。
- 保持同一提交的原子性、原有额度和单 Runner；不复制现有对话提交服务，也不把新研究流程全部塞进 Runner 主循环。

研究专用输入、取证、来源与报告由[研究员闭环设计](research-assistant.md)维护；共用任务数据和接口由[任务契约草案](agent-workspace/tasks.md)维护，运行演进见[执行设计](agent-workspace/runtime.md)。本页不重复定义。分层与代码所有权以[本次评审](../architecture/backend.md)及前后端说明为准。
