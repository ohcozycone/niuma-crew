# API 职责与业务入口整理

设计状态：已采纳。实施状态：已完成。更新日期：2026-10-30。

## 目标与范围

统一 HTTP 适配、业务操作、查询与装配的归属，保留当前 URL、成功响应、错误语义、持久化结构和执行生命周期。生效规则见 [API 模块](../../backend/app/api/README.md)与[后端工程手册](../engineering/backend.md)，实际结果见[验收记录](../records/api-responsibilities.md)。本轮调整职责、补齐读取模型与边界验证。

## 实施增量

| 实施前的位置或行为                             | 本轮归属与原因                                                                                                                                 |
| ---------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| routes/conversations 包中的命令服务            | 迁 conversations/service.py，业务操作拥有接受、停止、重试和反馈事务；HTTP 和 SSE 分别为 routes/conversations.py、api/conversation_streaming.py |
| tools 路由中的联合目录                         | capabilities/queries.py 维护跨 Skill/MCP 的可见范围、统一搜索排序分页及协议名；schemas.py 定义目录读取模型，API 只适配请求                     |
| tools 路由中的沙箱状态                         | 独立 sandboxes 路由；沙箱服务继续管理真实资源生命周期                                                                                          |
| 员工编辑权在路由单独事务检查                   | 有身份约束的命令显式接收 Actor；在业务写事务取得写入资格后检查编辑权、修订和资源条件                                                           |
| 路由装配删除引用检查、临时构造带默认配置的服务 | bootstrap 注入配置及必要回调，API 通过有类型的依赖取得服务，引用检查仍使用删除事务的 Session                                                   |
| 公开详情和使用摘要先构造管理 DTO               | 所属模块直接生成明确白名单读取模型；路由不解释完整配置                                                                                         |
| 部分 JSON 接口缺少响应模型                     | 补齐 JSON 读取结构和统一错误声明；文件、SSE、OAuth 和 204 按各自协议声明                                                                       |

模块先按数据、规则和生命周期所有者划界，再按实际操作选择 service、queries 或具体职责文件，不要求每个模块拥有同构文件。固定的导航计数仍保留 API 内的小型只读聚合；不增加空服务或 repository。

## 事务与失败

接受与最终发布继续使用原有同库原子操作，外部模型与工具在写事务外执行。员工拒绝、修订冲突、删除引用保护均须回滚；服务入口不能通过省略 Actor 绕过编辑规则。SSE 只观察已提交状态，断线释放连接但不取消执行。

## 验收发现的补充修复

完整回归复现 checkpoint 首次并发初始化的 SQLite WAL 切换竞争。CheckpointStore 统一读写初始化入口，在工作线程内串行完成首次建表和 WAL 设置；执行与正常存档写入继续并发，并用真实 SQLite 并发回归覆盖。
