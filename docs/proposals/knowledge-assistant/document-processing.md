# 知识库资料建设闭环

设计状态：用户已授权实施本增量。实施状态：已实施；现行规则见[知识库契约](../../reference/knowledge.md)，实际验证与限制见[验收记录](../../records/knowledge-document-processing.md)。更新：2026-10-31。

## 范围与现状

实施前上传同步发布正文、Chunk和BM25，向量摘要按整库判断。本增量已将上传改为保存受控MD/TXT原件，手动提交持久处理任务，按文件原子发布正文/Chunk/BM25；新增通用切分默认及库级覆盖、文件状态、局部重试和全局上传浮层。员工知识挂载、正式问答和AI编写助手不在本次实施范围；向量构建入口保留，兼容文件级状态，完整异步增量向量另行推进。

## 数据与执行

- 库记录配置修订及可空切分覆盖；默认800字符/120字符重叠，最终合并校验并冻结到任务。
- 文档上传后无活动正文和Chunk，状态为待处理；旧已入库文档迁移为关键词可用。
- 处理批次和文件子任务持久化，提交标识幂等。每文件只允许一个活动任务，任务固定原件摘要与规则。
- 独立、单文件并发的后台扫描器由应用lifespan持有，复用当前数据库和进程锁约束；生产不新增Redis等依赖。测试关闭后台时可直接驱动处理服务。
- 工作在事务外解析切分，提交前再次检查文件、任务标识、原件摘要；正文/Chunk/FTS同事务替换。旧产物在新发布前继续可查。
- 重启后排队项继续执行，执行中项明确标为中断、允许手动重试。失败保留原件和仍有效的旧索引；错误对外脱敏。
- 删除先取消对应任务并清理其Chunk/FTS/向量，迟到结果不得恢复文件。其他文件保持可用。
- 当前向量兼容性改为仅要求实际向量对应当前Chunk，新增待处理文件不使现有向量失效；关键词新代提交时仅清除该文件旧向量。

## 接口与页面

新增库设置PATCH（修订保护）、处理批次POST/GET及取消入口；文件响应包含处理状态、错误、关键词/向量就绪信息，未处理详情允许无正文。上传接口仍校验格式、编码与大小，但不拆分。

库内提供配置按钮与手动处理弹窗、逐文件状态和重试；处理中轮询当前库，离页不取消服务端任务。上传队列属于身份工作台，浮层在应用外壳挂载，切页/收起继续传输；整页关闭或刷新提示未完成传输，取消与未知结果明确，重试沿用提交标识。

## 验收

覆盖上传未处理不可召回、幂等、规则快照、逐文件发布、失败旧版保留、局部重试、运行中删除、重启中断/队列恢复、跨所有者隔离、迁移保留原有正文与向量，以及SPA切页/收起不终止上传、身份隔离与迟到响应。真实Embedding不属于离线接线验证；现有向量行为执行定向回归。
