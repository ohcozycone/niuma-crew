# 沙箱申请、执行环境与回收

员工需要执行脚本或更大规模文件操作时，平台可在已配置和验收的 OpenSandbox 主机申请临时环境。本模块管理环境从申请到销毁的责任；具体命令由 Agent 的沙箱适配器执行，成果另存平台文件服务。

## 模块设计

### 申请和使用为何延迟到实际需要

接受工作时先核对主机验收依据并固定地址/镜像等环境配置，`for_run` 返回属于本轮的 `RunSandbox` 句柄。句柄直到 `acquire` 才实际申请环境，避免仅聊天或导入技能就创建容器。

服务先在数据库保存含部署、运行和申请标识的资源记录，并检查容量，再向远端创建。确认成功后保存远端身份并初始化只读输入。资源与一次运行绑定，Agent 通过适配器使用同一环境进行文件和命令操作。

### 创建超时为什么仍然占有清理责任

远端可能已经创建，但响应在网络中丢失。此时不能把本地申请删除，也不能立刻再建一个。服务保留未知状态，用精确 metadata 查找原环境；销毁结果未确认时同样保留待处理责任，并由后台继续核对/回收。

这就是持久清理责任：重启后仍知道有哪些远端资源可能存在。已过期、无远端 ID 且属于当前服务的未知申请，可由维护命令核对；部署者通过 `python -m app.environments.cli` 查询待回收资源，不提供单独的 HTTP 状态入口。操作还会再次检查当前记录，避免人工核对期间状态变化后误处理。

### 临时环境如何与正式成果分开

命令/管理凭据不进入工作负载。输入 root 所有且只读，命令 UID/GID 为 1000；工作文件和输出分别使用受控路径。Agent 先将要交付的成果保存到 files，回复发布再建立附件关系，然后回收沙箱；环境不是正式历史和成果的唯一副本。

结束、取消和停服都会尝试释放句柄和远端资源。一个清理失败不应阻止无关 MCP 客户端关闭。没有有效目标主机验收依据时报告未就绪，不回退到宿主执行；SDK 重试关闭，避免未知创建被隐藏重试放大。

## 目录与职责

```text
environments/
├── profiles.py                    # 随工具管理入口维护原生工作区配置，核对版本与员工引用
├── policy.py                      # 校验工作区路径、范围及命令许可
├── models.py                      # 保存资源申请、部署/运行归属、远端身份、期限和清理次数，让重启后仍可核对未销毁环境
├── service.py                     # 检查就绪与容量，提供按运行延迟申请的句柄，记录创建/销毁及未知结果并持续回收
├── open_sandbox.py                    # 限制 SDK 传输，校验主机依据，并实际创建、按标识查找、销毁和初始化 OpenSandbox 环境
├── config.py                      # 定义服务、镜像、资源、容量及期限，使接受时配置和目标主机验收可以一致核对
├── verify.py                      # 在目标 Linux 主机验证隔离、资源、进程与网络等实际行为并生成对应部署依据
└── cli.py                         # 为部署者查询环境、资源和过期未知申请，执行有条件的人工核对
```

## 与其他模块协作

[单次执行](../execution/runtime/task.py) 准备并最终释放运行资源，[execution/runtime/workspace.py](../execution/runtime/workspace.py) 适配具体文件与命令，[files](../files/README.md) 保存持久输出，[execution](../execution/README.md) 管排队和停止。

本模块依赖数据库及 open_sandbox，活动运行查询由装配注入以保护仍在使用的环境。它管理资源生命周期，不重复建立一套工作调度。

## 部署与验证

执行上限、退出码、日志、资源及网络须分别验证，命令结果未知不视为成功。详细接入和清理核对见[部署指南](../../../docs/guides/agent-tools.md)，许可与恢复见[工具契约](../../../docs/reference/agent-tools.md)。[基础工具测试](../../tests/test_agent_foundations.py)覆盖离线 SDK/SQLite 场景；真实 runsc、磁盘、进程和网络仍需目标 Linux 主机验收。
