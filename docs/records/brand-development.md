# 品牌候选、命名迁移与验收记录

记录范围：2026-10-18 至 2026-10-22。原文中的 server 包名、原型端口和素材位置仅属于当时快照；当前应用包为 app，正式品牌见现行参考。

## 范围与命名

产品展示名为 `NiumaCrew`，副标题为「数字员工平台」，最外层目录为 `niuma-crew/`。内部目录与组件按功能和通用工程规范命名，不随品牌增加前缀。仓库名称仅用于最外层目录与产品展示。后端 Python 包使用 `server`，前后端工程包名分别使用 `backend`、`frontend`；数据库、认证、事件和存储标识按功能命名，不绑定仓库名称。

前端展示名、副标题、说明和图标地址集中在 `frontend/src/lib/brand.ts`；共享标志组件位于 `frontend/src/components/brand/`。页面、登录、帮助、调试及设计展示入口引用同一配置，文档中的产品说明同步更新。品牌配置仅承载展示信息，不控制会话和业务逻辑。

## 标志方案

当前共享品牌组件使用登录页认可的马头像与 Niuma / CREW 矢量字标，已替换早期几何 N。字形保持登录页定格状态，系统标志仅眼皮低频眨动；减少动态效果时静止。`frontend/scripts/build-brand.mjs` 从正式登录页 `logo.ts` 派生 `public/brand/wordmark.svg`，构建与开发启动自动生成，`pnpm build:brand` 可单独更新。组件不加载登录页动效模块、字体、SDK 或 React 动画库；副标题保留在可访问名称中，不再额外拼接一套系统字体字标。

浏览器图标使用独立的[马头 SVG 源稿](../../frontend/src/components/brand/mark.svg)，保留现有角色的造型与配色，以 144×144 正方形画板居中并留白，静态展示。品牌构建将源稿复制为 `public/brand/mark.svg`；不再裁切完整字标，避免将相邻 N 的竖笔带入图标。32px、192px 与 Apple Touch PNG 从该源稿导出后随仓库维护，修改源稿时同步刷新。应用入口为 SVG 图标增加版本参数，使浏览器重新获取修正后的素材。

图标验证（2026-10-22）：Chrome 已检查 16px、32px、64px 在浅深背景下的显示，无相邻字形残留；三种 PNG 的尺寸、透明背景与边缘留白检查通过。本地服务返回新 SVG，前端格式检查、生成脚本语法检查与生产构建通过。截图及尺寸记录见[图标验证](../../../niuma-crew-archive/output/reviews/browser-icon/verification.json)和[预览](../../../niuma-crew-archive/output/reviews/browser-icon/preview.png)。

夜间主题由同一矢量源派生 `wordmark-dark.svg`，只替换字母墨色；角色、字形、尺寸和眨眼保持同源。共享组件按解析后的主题选择字标，登录页的内联字标继承主题前景；不会对角色整体做颜色反转。行为与首屏规则见[主题模式](../reference/theme.md)。

## 字母联动 Logo 与独立登录页候选

设计状态：草案。实现状态：已完成（独立原型与性能打磨，最终视觉验收待定）。更新日期：2026-10-20。原型范围为登录页与品牌素材。认可的登录页已在项目中沉淀为 `/signin` 并复用正式认证，见 [Signin 页面设计](../reference/signin.md)；此节体积、性能和截图仍指独立原型，系统共享品牌组件现已复用同一矢量稿。

有效需求：保留弹跳、圆点压 i 后的字母联动和马的表情；完成后定格。登录页不能因装饰动效牺牲加载速度。整个登录窗缩小，窗内与中间区域不滚动，小屏先紧凑排版、适度等比缩放，仍放不下由整页滚动。登录完成直接切页、系统共享 Logo 的字形保持静态，仅眼皮低频活动；独立原型未制作内部页面。

构图：上半部是马与大字标，下半部左侧文案、右侧登录操作，共用连续纸色前景，通过边距、遮挡、接触阴影和受力形成整体。左上角平台小字置于角色和字标之后，马跳起经过该区域时遮挡小字，避免文字穿过角色；纸色前景仍在角色之前承担遮挡。移动端单列。桌面逻辑画布最大 820×560px，含边框 822×562px；移动端逻辑宽 360–440px、高 530px。画布整体居中，按高度缩放最低 82%，极窄屏优先适配宽度，仍无法容纳时允许整页纵向滚动。普通表单与错误提示均完整位于画布内。

文字与表单：保留原有底线输入框、字级和两栏比例，通过组内靠近、组间留白组织表单。左侧 slogan 为「牛马在岗，你先松口气」，说明为「把重复的工作交给数字员工。留点时间，做你想做的事。」；表单分为欢迎说明、账号信息、操作三个功能组。「欢迎回来」与「登录你的工作空间。」紧邻；账号标签贴近底线输入；游客文案仅在下方「以游客身份看看」入口出现，不在欢迎区混入另一条路径。Slogan 位于 Logo 下方的品牌区，避免混入表单操作与错误反馈。登录页文案和 Logo 禁用拖拽选中，输入框保留正常选择、复制与编辑。

`source/login-tokens.cjs` 仅维护候选的布局值，引用正式设计系统的间距基础值和控件圆角；不因套用规范而改变已认可的字形、配色和底线造型。构建时展开语义变量，页面不下载 token 库；`login-design-tokens.json` 供核对。正式主题不变。

错误提示出现在密码下方的固定区域，不挤动主按钮；失败通过文字和字段底线表达，并关联 `aria-describedby`，编辑后清除过期错误。提交中由请求锁和控件禁用避免重复操作，提供 `aria-busy`，不依赖布局位移。保留自动填充、长度上限和 `required` 语义；脚本就绪后统一使用页内必填提示，避免原生校验气泡与浏览器账号建议列表叠加。空用户名、空密码或两者均空会阻止登录；用户名仅空白也视为空，密码不裁剪。无效回车提交时将焦点移至提交按钮以关闭输入建议；不强制重新聚焦输入框。任何内容编辑都会清除过期反馈，包括模拟成功。游客入口不要求账号信息。脚本未就绪时仍保留原生必填校验。演示默认值为虚构账号，仅用于原型。本轮功能分组覆盖 1280×720、390×667、320×400、600×667、700×600、701×600、720×600，键盘顺序、必填、重复提交锁、错误关联、提示完整性及按钮位置实测通过，均无窗内滚动。补测桌面、390px 与 320px 下的单项空值、双空、空白用户名、点击及回车提交，未触发原生 invalid 气泡；游客空账号可用，旧反馈在编辑后清除。此前完整登录加载验证覆盖的其余尺寸见后文。未进行完整无障碍审计。

独立原型交付是纯 `login-flow.html`，不包含审阅控制、模拟工作台或框架启动代码。关键 CSS、静态矢量与表单处理内联，输入与提交处理在 SVG 解析完成之前即可绑定；静态前景与尺寸在 body 解析前确定，完整 SVG 才显示，避免 HTML 分段下载期间错位或显示半张角色脸。字段可编辑，登录与游客按钮的响应是 300ms 模拟，留在登录页展示结果，没有接入真实认证。原完整演示保留为历史 `login-review.html`，不作为本轮加载或内部页面验证对象。

动效仍使用自绘 SVG 与浏览器原生 `requestAnimationFrame`，不依赖第三方运行时、SDK、视频或远程字体。`scene.cjs` 是同一套运动模型，`runtime.cjs` 与 `login-motion-surface.js` 生成可选脚本，保留 N/i 横向固定、圆点压 i、耦合弹性链带起 u/m/a、CREW 随 a，以及马的追视和表情。正常快速连接单次播放约 4.6 秒后停止更新。输入、页面隐藏、减少动态或省流优先静态；慢连接依据已完成的导航时序选择静态，不请求动效。晚到动效不自动重播，表单永远不等待动效。

构建与投递：`source/login.cjs` 使用本项目已有的 Terser 进行构建期压缩，压缩器不会随网页下载。输出包含内容哈希的动效文件与预生成的 `.br` / `.gz`。`source/serve.cjs` 为可独立运行的本地静态服务器，仅依赖 Node 内置模块，实际返回 Brotli/gzip、`Vary: Accept-Encoding`、ETag 与 304；HTML 采用 `no-cache` 重验证，哈希脚本采用一年 `immutable` 缓存。默认 `http://127.0.0.1:8770/`。旧 Python 8769 服务不启用压缩，仅用于原始传输对照，不能混用两种体积和性能口径。

当前静态首屏约 16.4KB 原始 / 5.2KB Brotli / 6.3KB gzip；可选完整动效约 14KB 原始 / 5.7KB Brotli。精确字节数与指纹以 `login-build.json` 为准。快速连接完整资源约 10.9KB Brotli，弱网静态首屏只需一个 HTML 请求，无 SDK、字体、视频、内部页面或额外图片请求。

最近一次弱网基线（底线恢复版，本轮仅分组排版，未重跑网络耗时）：Chrome、390×667、冷缓存、每组 3 次，分别记录表单处理已安装后的首个渲染帧，以及表单和完整静态 SVG 均就绪的首个渲染帧；不把动效播放时长算作初始化。50KB/s / 300ms 下，Brotli 表单约 0.40s、完整首屏约 0.43s；20KB/s / 600ms 下约 0.83s 与 0.89s。同条件未压缩时，纯登录完整首屏约 0.63s / 1.40s，上一版约 0.98s / 2.28s。上述是受控原型实测，实际响应头与 encodedBodySize 已核对，非压缩估算。正式应用路由、真实接口、线上 TTFB、手机软键盘和低端实机尚未覆盖。

功能与效果验证：十组屏幕覆盖 1440×900、1366×768、1280×720、1024×600、844×390、768×600、390×844、390×667、320×568、320×400；正常、失败提示和游客操作均无窗内滚动与页面横向溢出。可选脚本延迟时可编辑字段并完成模拟提交；脚本失败、减少动态和省流仍可操作；输入后或晚到资源不会重播。19 个同尺寸姿态与原 60Hz 采样效果对照，最大像素平均误差约 1.13/255（非采样时刻有插值差别），静止终态一致。4 倍 DevTools CPU 降速下，277 个动画帧的间隔 P95 约 16.7ms，模型计算与 SVG 属性更新 P95 约 1.1ms，结束后 500ms 的 DOM 变更为零；不是物理低端设备的帧率承诺。Brotli/gzip/原始内容一致、ETag 304 空响应、动效重复访问零传输已验证。
