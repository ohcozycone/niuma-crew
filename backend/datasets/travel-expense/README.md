# NiumaCrew 行政管家：差旅资料与开发题

全部为虚构教学数据，状态为 **待人工审核**。面向普通员工理解差旅规则，行政或财务角色审核规则和答案。不提供真实财税或公司制度建议。

## 从这里开始

1. 打开 核心规则与样题审核稿，先看 13 条规则。金额、日期和审批要求都是本例人为设定的，确认它们清楚、自洽即可。
2. 核对 12 道样题。每题包含必要要点、错误边界、判断过程和原文摘录；链接可回到实际文件，不能只相信摘要或参考答案。
3. 有分歧时记录具体规则或题号。先修订知识与评分依据，再开始模型评测。

## 文件布局

| 文件                                 | 用途                                                               |
| ------------------------------------ | ------------------------------------------------------------------ |
| `documents/`                         | 5 篇可供助手使用的 Markdown 知识文档，包含制度、更新通知和办理流程 |
| `evaluation/REVIEW.md`               | 人工阅读入口：规则表、样题、评分方式及原文                         |
| `evaluation/rules.json`              | 结构化核心规则及原文依据，供审核使用                               |
| `evaluation/questions.jsonl`         | 12 道公开开发题，仅包含题号和问题                                  |
| `evaluation/reference_answers.jsonl` | 参考回答、必要要点、错误边界和证据，不能进入模型上下文或索引       |
| `evaluation/review-results.jsonl`    | 空白人工评分记录；没有预填模型回答或成绩                           |
| `manifest.json`                      | 知识文件清单、SHA256 和待审核状态                                  |

## 当前范围

知识包括大陆因公差旅、高铁等级、普通住宿上限及变更、逐晚计算、特别批准、材料清单、缺票处理和静态知识边界。日期统一使用 2026 年，不依赖运行当天的“现在”。金额单位为人民币，可报金额不代表实际审批通过或到账。

`review-v1` 是数据包版本；业务生效日期写在正文中，二者不能混淆。文档编号为 KB-101—KB-105。

普通员工与大陆范围是场景假设；这 12 道题不是对所有公司政策的概括，也不是独立验收集。当前未包含真实 PDF、Word、Excel 或扫描件，未实现权限或个人状态查询。不能据此宣称多格式解析、检索或生产可用性已经验证。

## 与现有项目的关系

本资料包作为行政管家首项能力的静态示例知识保留，后端不再默认加载。平台原型使用知识文档的静态快照；修改原文后需同步原型内容，并核对清单中的文件哈希和审核稿引用。

上传和知识库管理实现后再接入平台。届时仅将 `documents/` 作为回答知识；`evaluation/`、本说明及清单用于审核，不应进入回答上下文或知识索引。

旧 `make check-data` 与 `make evaluate` 命令已移除。规则、参考答案与人工评分仍为待审核状态，本包没有实际回答质量成绩。平台评测执行与数据校验将在相应功能中实现。

独立[知识 POC](../../app/knowledge/README.md)现可显式读取本包。manifest 的 sha256 定义为当前文件原始字节摘要；本轮修正了清单与格式化后文档的摘要漂移，未改变正文规则或待审核状态。开发引文覆盖不等于答案质量或未见题验收。
