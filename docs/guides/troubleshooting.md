# 问题排查

先记录出错的员工、对话或考核，以及页面提示和执行记录中的错误。区分保存失败、连接检查失败和实际执行失败，按对应步骤处理；截图和日志中隐藏密钥、授权码及业务敏感内容。

## 员工不能开始对话

1. 确认使用管理员或成员账号登录，游客只能浏览。
2. 检查员工卡片的接单状态。管理员可通过“恢复接单”启用已暂停的员工。
3. 管理员打开员工配置，选择已启用的聊天大脑并保存。普通文字对话无需先装配技能或知识库。
4. 若提示执行服务不可用，由部署者检查 `/ready` 和后端启动错误，不能只看 `/health`。

## 模型连接检查通过，对话仍失败

连接检查只查询模型目录，实际对话还会调用生成接口。根据本次执行错误核对模型标识、账号额度、服务状态和后端网络。401 或无权限先检查 Key 与预设，429 先检查额度或限流，不通过反复重试解决。

修改模型配置后再提交新请求。模型密钥只在管理入口填写，不放入对话；员工缺少更多技能不会修复模型连接故障。

## 工具已接入，员工无法使用

1. 管理员打开对应 MCP，检查组织工作连接已启用、认证有效。
2. 核对“可用工具”列表已确认；读取成功但尚未确认的候选列表不能用于新装配。
3. 在员工“能力装配”检查固定工作连接、具体操作、调用上限和范围约束，点击“保存配置”。成员无需绑定个人连接。
4. 认证或工具定义变化后，重新读取、确认目录并核对员工许可，再发起新工作。已有旧任务不会自动换用新的凭据依据。

stdio 提示未开启时，由部署者检查 `TOOL_MCP_STDIO_ENABLED`；找不到程序或目录读取超时，则检查宿主程序路径、固定包依赖和网络。实际授权与部署步骤见[工具与环境](agent-tools.md)。

## 知识文件分片失败

展开库内“分片记录”查看具体文件错误。先检查文件为有效 UTF-8 Markdown/TXT、每份不超过 128 KiB，再检查规则及服务状态。修正后单独重试失败或中断的文件。

出现 `file_content_missing` 或 `FileNotFoundError` 时，由部署者检查 `FILES_DIRECTORY` 和原件字节是否与数据库同批恢复。有文档列表或旧索引，不代表原件仍在；恢复文件需匹配数据库记录的大小和 SHA-256，不能用相似文本替代。

## 上传资料后没有检索结果或引用

1. 在知识库“文档”页确认文件已分片，存在可检索片段。仅上传成功的“待分片”文件不参与检索。
2. 在“检索测试”用材料中的具体名称或关键词查询，先确认资料本身能命中；语义检索另需在“检索设置”建立有效向量索引。
3. 管理员在员工“指令与知识 → 员工参考知识”选库，设置检索时机并点击“保存配置”。知识库创建不会自动装配给员工。
4. 在执行日志核对知识动作及其返回。按需模式由模型决定是否查询；需要先查资料时可使用“每次回答前检索”。命中、无结果和检索报错分别处理。
5. 有引用时打开来源，确认原文支持回答。引用格式正确不等于结论正确；资料已变更时重新检索。

## 向量索引构建失败或失效

管理员在知识库“检索设置”检查向量连接是否启用，测试 Key 与服务访问，再查看片段数量、索引状态和本次错误。没有片段时先分片；没有可用连接时先添加向量模型。

每次构建会重新编码全部现有片段，保持页面打开，并检查代理等待时间和上游限流。响应丢失时先“刷新连接与索引状态”，核对是否已经成功，再决定重建，避免重复编码费用。重分片或更换向量模型后，按状态提示更新索引。

## 断线、关闭页面后工作还在执行

这是已受理工作的正常情况。重新打开原对话读取进度；确需结束时点击“停止生成”。停止不会撤销已经发生的外部操作。

发送结果不明时使用“核对并重试原请求”；最后一次执行明确失败、取消或中断后，才使用“重试回答”。两者分别核对原提交和重新执行，不要把同一需求重复发送成多份工作。

## 员工说文件已生成，却无法下载

检查正式回复是否有成果文件入口，以及执行日志中是否成功保存和交付文件。模型文字中的临时路径不能直接下载；失败或停止时临时文件也可能尚未形成正式成果。

能看到文件入口但下载失败时，记录状态码与文件标识，由部署者检查当前读取权限、保留期限、磁盘字节及恢复批次。二进制或程序处理不可用时，检查员工能力页的代码执行状态；无需另外装配文件插件。

## 考核不能开始或异常结束

检查员工已接单、模型可用，题数在 1 至 400 之间。每个用户最多同时安排两个未结束的考核；达到上限时先等待或取消已有批次。

配置变化或发起会话失效会停止剩余题目，修正后重新发起。答卷格式或调用提议不符合题目要求属于“未通过”；模型执行或评分故障属于“异常”，分别检查答卷、评分依据和执行详情，不把异常当作已评分通过。

## 本地服务启动失败

查看终端中的首个错误：依赖缺失、数据库未迁移、3000 端口被占用、配置无效或已有后端持有运行锁。启动器不会自动迁移数据库、创建管理员或结束其他服务。

确认服务读取的配置和数据位置后，再处理首个错误。不要删除运行锁文件绕过已有实例；数据库、密钥或原件恢复按[配置与备份](backend-operations.md)核对。

## 代码执行显示未就绪

检查 OpenSandbox 地址、Key、固定镜像、CPU/内存配置与验收文件是否匹配。验收文件缺失或超过 24 小时都需要在实际 Linux Docker 主机重新验收；只启动服务还不能启用代码能力。

创建结果未知或容量被待回收资源占用时，先检查部署归属、实际容器及清理记录，不要直接删除数据库记录。处理步骤见[沙箱验收与回收](agent-tools.md#验收并启用代码执行)。
