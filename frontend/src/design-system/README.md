# NiumaCrew 设计系统

`/design-system` 是与产品同源的可交互目录，复用正式组件。当前版本 **2.7（2026-11-06）**。按钮的层级、状态与组合见[按钮与操作](components.md#按钮与操作)，真实样板位于 `/design-system#buttons`。工程规则见[前端工程手册](../../../docs/engineering/frontend.md)，本目录维护视觉与令牌契约；展示范围见[专项设计](../../../docs/reference/design-system.md)，当前配色验证见暖色主题验收、视觉细节统一验收和暖白卡片验收。

## 令牌来源与分层

[`theme.css`](theme.css) 是颜色、尺度、文字角色、组件组合、阴影与动效数值的唯一来源；`spec.ts` 只维护名称、用途与分组。基础值 → 语义用途 → 必要组件映射采用单向 `var()` 引用。相同颜色只在基础层登记一次；语义不同、日夜映射不同的用途仍保留独立接口。

- 基础色：`--gray-*`、`--night-*`、`--orange-*`、`--green-*`、`--amber-*`、`--red-*`、`--blue-*`；遮罩和插画单独登记。
- 语义色：`--os-surface`、`--os-text`、`--os-action` 等；用途与选择原则见[颜色规范](colors.md)。通用用途与必要组件颜色按spec.ts实际登记；头像和登录差异另外通过组件映射引用。
- 共享尺度：`--os-space-*`、`--os-text-*`、`--os-weight-*`、`--os-leading-*`、`--os-tracking-*`、`--os-radius-*`、`--os-control-*`、`--os-motion-*`。
- 文字角色：`--os-type-<角色>-size/weight/leading/tracking/color`，角色为 `page`、`section`、`title`、`label`、`description`、`body`、`caption`；`type-<角色>` 工具类应用整组规则。
- 组件组合：页头 `--os-heading-*`，资源卡片内边距 `--os-card-padding`，员工卡片 `--os-card-gap`／`--os-card-gap-sm`，收藏导航 `--os-avatar-size`／`--os-favorite-*`，功能导航 `--os-nav-*`。

`foreground` 统一缩为 `text`，背景后缀使用 `bg`；尺寸属性使用 `size`、`weight`、`leading`、`tracking`。现有消费者已迁移到短名称，不维护旧 `--os-*` 名称的长期别名。

Tailwind 的 `@theme inline` 按同名用途引用语义变量，页面与基础控件直接使用 `bg-surface`、`bg-action`、`text-text`、`text-action-text`、`text-text-muted`、`border-border` 等类。应用旧变量、旧颜色别名和 body 主题外壳已删除；全局基础规则在 `globals.css`，控件自身声明尺寸、圆角与状态。`text-body`、`text-section` 是字号类，已在 `lib/utils.ts` 注册合并分组，新增自定义字号时同步维护。

对话使用官方 shadcn/ui Base UI 的 Message、Trace、Input Group、Message Scroller、Inline Citation 与 Sources，源码按需放入 components/ui；保留交互结构，将颜色、圆角和焦点映射到已有语义令牌。shadcn 默认样式不直接覆盖全站，不新增第二套主题或运行时主题 Provider。来源与许可见[第三方说明](../../THIRD_PARTY_NOTICES.md)。

Markdown 渲染器通过官方主题变量映射与少量 `data-streamdown` 选择器适配同一组语义；不修改第三方依赖的 JS。库的颜色名称仅用于接入，应用代码仍使用项目语义类，约定见[Markdown 渲染器主题](colors.md#markdown-渲染器主题)。

## 主题与品牌

支持日间、夜间、跟随系统，默认跟随系统；控制器与偏好存储保持原约定。工作台、帮助、登录和挂载到 body 的浮层继承同一主题。完整行为见[主题模式](../../../docs/reference/theme.md)，视觉状态见[组件规范](components.md)。

日间采用暖白资源卡片、浅暖灰工作区和深灰文字，夜间采用暖炭灰表面和米白文字；以陶橙强调、灰绿成功状态搭配柔和的警告、危险与信息色。主操作保留高对比度的日间深底、夜间浅底。表单、头像背板、选区和浮层使用同源暖灰，不再保留独立的中性表单色板；详细规则见[颜色规范](colors.md)。

登录与其他页面共用 React 构建和主题状态。首屏从同一 CSS 来源内联主题样式与控制器，在 React 执行前应用偏好。品牌信息由 [`lib/brand.ts`](../lib/brand.ts) 提供，字标由 [`BrandLogo`](../components/brand/BrandLogo.tsx) 渲染；品牌构建读取同一 CSS 的日夜文字色。登录场景几何配置位于登录模块，不混入颜色数据。

## 共享表面与圆角

卡片、搜索、选择字段、导航、装配行和页面容器的归属，以及统一曲线入口、Portal 和独立造型范围，见[共享表面与圆角](surfaces.md)。普通表面与表单统一采用普通圆角，按控件 8px、面板 12px、卡片及中央弹窗 16px、桌面外框 24px 分层。设计目录保留显式曲线对比。

## 现有业务组合约定

组件外观与状态以 [components.md](components.md) 为当前规则，颜色的分类依据与用途以 `spec.ts` 为机器可读说明。展示页把使用提示放在对应示例旁，不再提供重复的“组件使用约定”折叠表格。下面保留已有业务组件的使用边界。

- 对话工作区优先保留消息空间，使用紧凑工具栏，角色展示在助手消息头部；布局与历史切换见[对话契约](../../../docs/reference/conversations.md#前端交互)。其他功能页复用 `PageHeading`，按中文标题、用途说明组织，操作与数量靠右；标题保持完整文字和紧凑尺度，规则见[标题规范](components.md#功能页统一标题)；完整文字角色和组合间距见[组件规范](components.md#文字与排版)。技能页直接衔接筛选与内容，避免重复说明横幅。
- 侧栏收藏独立滚动、低高度回退与底部账户菜单统一遵循[侧栏分区与账户入口](components.md#侧栏分区与账户入口)，`/design-system#account-navigation` 提供同源交互样板。
- 工作台顶部栏最小高度为 48px，一级页显示模块名，二级页显示可返回所属列表的真实层级；返回与员工数量摘要规则见[页面层级与列表摘要](components.md#页面层级与列表摘要)。全局搜索位于顶栏右侧、主题控件左侧，窄屏使用搜索图标；气泡问号帮助入口位于侧栏品牌行右端，在新标签页打开当前功能的 `/help/[topic]`。
- 员工背板统一使用 `--os-avatar-bg`，同一主题内不再按员工 ID 分配深浅；日间为浅暖灰，夜间为统一深灰。圆拱只承托人物，比例、底部收口和使用边界见[头像背板规范](components.md#员工卡片头像背板)。
- 游客展示复用员工卡片的 `readOnly` 模式，隐藏收藏、编辑与启停，任务体验按钮禁用；介绍与技能仍可查看。该属性只控制展示，后端独立检查权限。
- 员工统一用卡片保留头像、姓名、职责摘要、状态、技能／工具操作／知识库三类配置数量和对话入口。右上角依次展示收藏、编辑、优化／返聘三个图标按钮，悬停或键盘聚焦显示含义。收藏以实心星标表示，姓名后不重复标记；「优化它」确认后暂停接单并显示「已被优化」，可通过「返聘它」恢复在岗。配置预览隐藏操作和对话按钮。启用且配置模型的员工可对话，未配置模型显示「待配置模型」；技能为可选项。
- 当前正式头像统一渲染十三角色静态 SVG，动画制作暂缓。收藏主区域接续对话、右侧独立编辑；无框尺度、固定点击区域及触屏规则见[组件规范](components.md#员工头像导航)，接口、映射和回退见[头像组件说明](../components/avatars/README.md)。
- 颜色之外提供状态文字；保留禁用、无效输入、键盘焦点和 Portal 行为。移动端输入字号可保留 16px，避免系统聚焦缩放。
- 同一功能只保留一种展示与编辑方式。新场景优先跳转到正式页面，或直接复用现有组件及布局；不要另做快捷配置表单、档案弹窗、列表切换或聊天侧栏版本。设计样板中的配置入口进入创建页，对话入口进入正式员工列表，避免把演示 ID 当作数据库 UUID。
- 技能集合共用搜索、分类、网格和卡片内详情；查看态显示使用人数，编辑态勾选技能后由员工配置统一保存。
- 业务组件接收展示数据和操作回调；数据来源、可对话条件、保存与任务执行由调用方决定。

## 修改流程

1. 现有规范覆盖的页面直接复用；稳定且重复的组合才提取组件。
2. 新增组件类型或改变操作位置、含义、状态规则时，先说明使用场景、已有组件为何不足及拟采用的接口；按项目文档规范在已授权范围内连续完成设计与实现。
3. 修改共享组件时同步更新展示示例；检查首页和展示页的卡片、技能集合、窄屏、长文本、键盘与减少动态效果。
4. 运行 仓库根 `make lint-frontend` 和 `make build`；影响已有逻辑时运行相应测试。

ESLint 限制 Base UI 只能由 `components/ui` 引入，并阻止共享层依赖原型和展示页。更换组件库时集中适配控件属性、事件、焦点和 Portal；更换 Tailwind 仍需重写样式，不承诺零成本替换。

## 当前范围

已共享主题、基础控件、功能页标题、员工卡片与技能集合。员工配置、对话、记录页与知识库各有唯一实现；其他入口直接定位正式页面并保留返回上下文。任务运行树、评测与真实执行界面需要随功能设计确认，不在此提前规定。暂不发布 npm 包，出现多个独立应用共用的实际需求后再考虑拆包。
