# 员工收藏与目录更新

设计状态：已被[共享数据 Provider 方案](workspace-shared-data.md)取代。实施状态：局部方案曾于 2026-10-29 实现，现已由共享数据层替换；以下保留当时设计。更新日期：2026-10-30。当前规则见[员工模块](../../frontend/src/pages/agents/README.md#目录读取与收藏同步)，实际检查见[验收记录](../records/agent-directory-updates.md)。

## 目标与范围

收藏是员工的轻量状态操作。当前保存后同时更新本地员工并广播全局配置失效，使目录、计数和导航重复读取；列表将所有后台请求当作条件切换，隐藏整组卡片。改为局部响应、定向同步和保留内容的后台核对，沿用现有 PATCH、expected_revision、分页与身份权限。

## 更新与同步

1. 员工目录拥有已确认列表、按员工隔离的请求锁、收藏的临时显示值和操作错误。收藏点击立即切换星标；同一员工的收藏与启停串行，不影响其他员工、编辑或导航。失败清除临时值，保留已确认状态并在卡片提示；409、断网或服务端错误时重新读取核对，不自动重发写入。
2. PATCH 成功以服务端返回的员工及 revision 更新本地记录。普通列表维持创建时间顺序，不为收藏重取全部员工或不受影响的员工总数；导航通过独立失效信号重新读取有界收藏及计数，保持服务端排序和前 20 项规则。
3. 当前筛选不再包含该员工时，确认成功后移除卡片并调整匹配总数，再后台读取当前页补位；末页失效时回到最后有效页。启停操作沿用相同同步路径，状态在成功后确认。
4. 导航核对失败保留上次成功的收藏及计数，显示重试入口。正在请求时再次收到变更，取消旧请求并忽略旧响应。所有同步仅在当前挂载的工作台内进行，跨标签页和其他客户端的实时推送不在本次范围；手动刷新读取最新状态。

## 加载与竞争

首次读取显示加载状态；同一身份的筛选、搜索、分页、手动刷新和后台核对保留上次成功的卡片、统计与布局，使用 aria-busy 和简短更新状态表达请求。分页在请求期间暂停，搜索与筛选仍可更改，卡片按其实际员工 ID 操作。失败保留上次结果和重试，不伪装为新条件已完成。身份变化立即隔离旧数据。

读取请求取消并忽略迟到结果；请求跨越已完成的写入时丢弃该读取并重新核对，防止旧列表恢复已取消的收藏、丢失新 revision 或覆盖分页总数。写入完成时不向已卸载页面或其他身份回写状态；离开目录后仍可通知当前工作台导航核对。

## 验收

覆盖收藏和取消的即时显示、同员工重复点击、不同员工并发、失败恢复、409 核对、成功后的新 revision、导航独立同步与失败保留、收藏分页补位及末页回退、刷新期间可见内容与焦点、快速筛选的迟到响应，以及写入与读取交错和身份切换。执行前端静态检查、定向测试、生产构建及可用浏览器检查；实际结果进入 records，生效规则合入员工模块和前端架构说明。
