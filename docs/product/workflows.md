# 使用流程与执行链路

本文将页面操作与系统处理放在一起解释。先读[平台与功能说明](README.md)理解员工、技能、工具和对话；本地安装、账号初始化见[根 README](../../README.md#本地运行)，部署参数见[后端操作指南](../guides/backend-operations.md)。下面的员工与材料名称均为说明性示例，需要自行创建。

## 配置一名可以工作的员工

最小配置只需要一份可用大脑、一名启用的员工及岗位工作指令。技能、外部工具和沙箱按实际工作需要添加。

1. 管理员登录，打开「大脑配置」，填写名称、Kimi Code 预设、模型标识和对应 API Key。保存后可检查连接；检查成功仍需真实对话验证生成。
2. 打开「数字员工」，创建例如「材料整理员」的岗位，填写基本信息和工作指令，选择刚保存的大脑并启用员工。
3. 需要复用方法时，先在「能力库」创建或导入技能，再在员工能力装配中选择它；需要参数的技能在这里填写非秘密参数。
4. 需要外部操作时，先完成下文的工具接入与清单确认，再在员工配置中授予具体工具、资源范围和预算。技能选择与工具许可分开保存为员工装配的一部分。
5. 保存员工，在目录确认它满足可对话条件，再用一条直接文字输入验证。涉及文件、工具或命令时，分别验证对应动作与实际交付。

「输入不足时列出待确认项」可以写进岗位指令；「读取哪个服务、访问哪些目录」必须由后端许可限制。指令说明和实际权限共同构成工作边界。

| 页面动作       | 前端怎样处理                             | 后端怎样处理                                             | 用户得到什么                   |
| -------------- | ---------------------------------------- | -------------------------------------------------------- | ------------------------------ |
| 保存大脑       | 表单提交模型配置，API Key 不进入普通草稿 | 模型连接模块校验并加密保存，不在普通保存中请求模型       | 可供员工选择的共享连接。       |
| 保存技能       | 编辑主文与文件，或预览后确认 ZIP 导入    | 技能模块校验包，保存内容清单及不可变文件                 | 可复用的方法定义。             |
| 保存员工及装配 | 表单保留未提交输入，携带进入编辑时的修订 | 员工模块检查权限、创建者、资源引用与版本，在同一事务保存 | 已确认的员工配置及新修订。     |
| 保存冲突       | 保留本地输入，展示最新配置核对入口       | 拒绝用旧修订覆盖新配置                                   | 用户决定怎样处理差异后再提交。 |

实现入口：[前端员工编辑](../../frontend/src/pages/agents/README.md)、[员工服务](../../backend/app/employees/README.md)、[技能](../../backend/app/skills/README.md)、[模型连接](../../backend/app/model_connections/README.md)。

## 发起对话并取得结果

1. 以管理员或普通成员身份选择可对话员工。卡片「开始对话」会接续最近可见对话；需要独立话题时使用对话工具栏的新建入口。
2. 输入清楚的需求，例如「把下面这段会议纪要整理成行动项，注明负责人和待确认事项」。需要材料时上传或选择文件；只有员工获准读取的材料才能用于处理。
3. 发送后，页面先确认系统是否接受，再观察排队和执行。接受表示请求已经登记，不能理解为工作已经成功。
4. 阅读正文与过程区。过程展示实际开始的模型、技能或工具动作；某项技能已经装配，或模型声称调用了工具，都不能代替动作记录。
5. 等待明确终态。成功后读取正式回复，生成且成功关联的文件可从回复下载；失败时根据提示处理配置、权限、上游或输入问题。

| 阶段     | 系统做什么                                                                                     | 为什么需要这一步                                             |
| -------- | ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| 固定提交 | 前端为这次输入生成稳定请求标识                                                                 | 网络超时后可核对同一请求，避免无意创建两次工作。             |
| 原子接受 | 检查身份、员工就绪状态、容量和输入；同一事务保存输入、空回复记录、配置快照和待处理运行         | 不会出现只有消息、却没有对应处理记录的半成品。               |
| 排队领取 | 后台宿主领取已接受运行，启动前再次检查当前许可                                                 | HTTP 已返回后仍有明确的处理责任，排队期间撤权也能生效。      |
| 执行循环 | Agent 使用固定输入调用模型，按需读取技能、请求获准工具；每次实际动作先检查许可、预算并记录开始 | 工具说明不能绕过权限，保存失败时不会继续发起无法追踪的调用。 |
| 保存进展 | 宿主保存普通内容与真实动作；页面通过 SSE 观察已保存快照                                        | 重连能回到服务器已确认的进度，观察连接不承担执行责任。       |
| 正式交付 | 执行侧先保存成果与运行终态，对话另行接纳正文、文件关联并释放业务占用                           | 模型结束、临时文件存在和用户实际拿到成果是不同阶段。         |

同一对话当前只接受一个活动运行。后续问题沿用稳定执行线程，从成功接纳的明确存档延续消息与官方摘要；新问题单独建立运行记录、重新绑定资源与预算。无可用基点时从当前输入开始；已选定的基点失效会拒绝执行。对象关系及恢复边界见[Agent 与执行宿主](../architecture/agent-runtime.md)。

## 停止、断线与重试

| 情况                         | 用户怎样处理                         | 系统语义                                                                                                                                |
| ---------------------------- | ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| 想主动结束当前处理           | 点击当前回复的停止操作               | 排队工作可直接取消；运行中进入取消处理，停止后不接受迟到成功覆盖。外部已经发生的副作用不会因此自动撤销。                                |
| 页面关闭、网络断开           | 重新打开对话或恢复观察               | 只停止观察，后台可能继续；恢复读取不重新发送问题。                                                                                      |
| 发送超时，不知道是否接受     | 使用待确认请求的核对或原请求恢复入口 | 沿用原标识和原输入，先查已接受记录；与失败后的重新执行区分。                                                                            |
| 最后一条回复失败、取消或中断 | 查看原因；服务端允许时执行重试       | 保留原输入和旧回复过程，新增一份回复与运行；当前配置及许可重新检查。                                                                    |
| 后端重启                     | 回到对话查看恢复结果                 | 仅支持符合恢复条件的普通聊天。无可信存档、协议不支持或本轮包含禁止自动恢复的工具/沙箱配置时，明确中断；工具尚未调用也不代表本轮可恢复。 |

不要通过反复点击发送处理不明状态。前端保存待确认命令是为了核对原请求；显式重试失败回复才是一轮新的处理。实现入口为[前端对话模块](../../frontend/src/pages/conversations/README.md)和[后端对话模块](../../backend/app/conversations/README.md)。

## 接入工具并绑定使用账号

以接入一个提供外部资料读取操作的 MCP 服务为例。服务是否提供搜索、网页或其他操作，以实际发现并确认的清单为准。

1. 在能力库的添加入口登记 MCP 服务，或通过工具管理入口维护服务；填写受允许的地址与接入方式。可信本机程序另受部署开关及管理员登记限制。
2. 为服务创建自己的账号连接，填写必要 Token 或允许的环境值；秘密由后端加密保存。
3. 发现远端工具，检查操作定义和服务说明，再确认清单。仅保存账号或发现成功，不会自动授权员工。
4. 在员工能力装配中选入具体操作，设置范围、预算和个人／共用账号方式，随员工配置保存。
5. 个人账号方式下，成员为员工已有许可选择自己的相容连接。没有绑定时，系统不会借用创建者的个人账号。
6. 发起实际对话，在过程区核对操作是否执行、结果是否取得。修改账号凭据或工具定义后，旧运行不能静默切换为新的身份和依据。

这条链路分为三个所有者：`tools` 管服务、账号和工具清单；`agents` 管员工许可及使用者账号选择；运行时由宿主与工具服务共同复核后才调用。细节见[工具模块](../../backend/app/mcp/README.md)、[员工模块](../../backend/app/employees/README.md)和[MCP 契约](../reference/mcp.md)。

## 从附件到成果文件

1. 用户上传材料，文件服务先可靠保存字节，再保存元数据，返回文件标识。上传成功还没有把文件变成知识库资料。
2. 发送消息时显式选择文件，对话模块检查归属、允许使用的引用和员工读取许可，并固定该次输入清单。
3. Agent 通过获准的工作区路径读取材料。虚拟工作区与沙箱有不同的容量和执行能力，超出当前模式应先调整配置。
4. 需要产出文件时，运行资源把输出保存到文件服务，得到稳定引用；沙箱里的临时路径不能直接交给浏览器下载。
5. 执行完成时核对文件来自本次运行、属于对应用户且摘要一致；对话接纳时建立消息附件关系。下载时继续检查当前对话访问权。
6. 临时沙箱单独回收。文件清理依据保留关系处理过期暂存，不删除仍被消息、来源记录或活动运行保留的内容。

实现入口：[文件模块](../../backend/app/files/README.md)、[对话文件规则](../../backend/app/conversations/files.py)、[沙箱模块](../../backend/app/environments/README.md)。真实沙箱需要目标主机验收，不能仅凭离线测试或界面配置认定可用。

## 修改全员规章制度

管理员打开管理区域的「全员规范」，编辑并保存。所有员工自动继承，不需要挨个装配；清空并保存会取消这份全局正文。

每次提交时，系统把当时的全员规则与岗位指令组合成固定输入。已经接受的运行保留原规则，已有对话下一轮及新建重试使用提交时的当前规则。并发编辑核对版本，冲突时保留草稿。业务和实现见[规则模块](../../backend/app/employees/README.md)。

知识资料管理与上述规则维护是不同链路。个人知识库、文本与向量检索、员工知识绑定及受管引用问答已接入；SOP 和正式任务管理尚未接入。

## 管理知识资料并核对来源

1. 登录后打开知识库，创建本人资料库，再进入库详情上传不超过 128 KiB 的 UTF-8 Markdown/TXT。
2. 上传只校验并保存原件，返回待处理；全局浮层观察队列，站内切页和收起继续上传。刷新或关页可能中断未完传输，完成确认后的原件已可靠保存。
3. 确认资料后点击“处理文档”，可调整本批规则并预览片段、长度和来源，再提交后台任务；预览不建立索引，已有资料不自动重切。按文件发布固定正文/Chunk/BM25，成功一个即可查一个；失败、中断可单独重试，离开页面不停止处理。打开文档查看可用正文及来源；检索测试返回实际片段，不生成回答。
4. 点击查看来源，按库、文档和片段 ID 打开对应固定正文区间。分词规则改变时先处理索引过期提示，不能把旧依据当当前检索结果。
5. 移除文档共同删除库内索引和片段关联，原件仍按文件保留策略清理。知识库不自动绑定员工，聊天附件上传也不自动创建知识文档。

页面设计见[知识界面](../../frontend/src/pages/knowledge/README.md)，归属、入库与实验范围见[后端知识模块](../../backend/app/knowledge/README.md)。这些操作依赖匹配的数据库迁移和环境，代码接入不表示已经完成部署验收。

硅基流动向量检索：完成关键词处理后，在“检索测试 → 检索设置”选择已有向量连接并显式构建。管理员可管理「硅基流动 · BGE-M3」Key。暂存原件不影响旧向量，删除只移除对应向量；部分覆盖时页面标明数量，无向量时禁用向量/混合。当前构建仍为同步整库快照；异步增量向量仍为后续能力。员工知识使用按下文个人装配流程进入正式对话。

## 为员工装配知识并问答

1. 在知识库准备并手动处理资料；未处理文件可先保留，但不会直接进入模型。
2. 打开员工的“指令与知识”或进入对话工具栏，点击“我的知识库”，选择多个本人库。此处独立保存，只对你使用该员工生效。
3. 选择按需查询或每次先检索，默认auto有向量用混合、没有向量用BM25；Top-K为多库合计。保存冲突先载入最新，修改装配会停止仍使用旧配置的任务。
4. 在自己的对话中提问，查看执行过程的“检索知识库”“读取知识来源”及实际状态。无命中、待处理和技术失败有不同含义，不能将其中任何一种理解为已确认公司规定。
5. 点击回答或动作记录中的来源，进入对应已授权库的准确片段。来源已删或已更新时应重新检索。制度结论需要可核对证据，模型仍可能选择不调用或推理错误，按需模式不提供确定调用保证。
