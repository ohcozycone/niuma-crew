# 设计系统目录、令牌与第三方主题整理记录

记录范围：2026-10-22 的目录、令牌和 Streamdown 主题改造；部分先前建议已被后续实现替代。本次只整理文档，当前数值与用法见源码旁设计系统。

## 目标与范围

用户要求改善设计系统页面组织、缩短冗长令牌名称，并合理抽象重复色值。当前页面将色卡、排版、尺寸、组件、业务样板与维护说明混在同一长页；颜色还存在 `primary`／`action`、导航文字／正文等重复用途。

本专项整理展示目录与令牌来源，保持工作台、登录与帮助的实际日夜配色和交互。目录、状态、基础组件与登录页面的统一标准见[前端工程手册](../engineering/frontend.md)，相关实现调整不属于本专项范围。

## 目录与交互

展示页分为颜色、排版与尺度、基础组件、业务样板四类，通过 URL hash 导航；仅呈现当前分类，刷新、前进后退恢复分类。颜色内再分语义用途、基础色板与组件映射，支持名称及用途搜索、复制 CSS 变量，并显示当前主题的实际值和引用来源。

组件与业务样板继续使用正式组件。颜色分类依据常驻展示，组件说明紧邻对应示例，不再用折叠说明或页尾汇总表承载使用规则。原有账户、收藏导航等深链继续定位所属分类与示例；窄屏将侧栏转为可横向滚动的目录。

### 分类说明、瀑布流与选中态

设计状态：已采纳；实现状态：已完成；更新日期：2026-10-22。

- 颜色按职责划分：语义用途按背景、文字、操作等界面场景分组，作为页面开发的首选；基础色板按色系与明度登记具体色值，供主题引用；组件映射保留通用语义无法覆盖的组件日夜差异。分类依据、使用时机和示例直接显示在分类附近。
- 删除“令牌分层与使用”折叠块，以及基础组件页尾重复的“组件使用约定”折叠表格。导航、按钮、输入、Tabs 和浮层的使用提示放在各自样例旁。
- 语义用途按分组卡片呈现响应式瀑布流，桌面两列、窄屏单列；卡片整体保留在同一列，搜索后自然重排，不引入 JavaScript 测高或布局依赖。DOM 顺序及键盘顺序不变。
- 当前导航和已选 Tabs 在悬停时保持选中背景及前景，悬停提示只作用于未选项；保留焦点、键盘切换与滑动指示线。

本轮修改文件 ESLint、44 项设计系统与类名合并测试、完整 173 项测试、TypeScript 和生产构建通过。全量 lint 仍有同期接口迁移文件 `configuration.ts`／`configuration.test.ts` 的两处局部参数命名问题，未记为通过；未修改其业务契约。构建保留既有大分块提示。当前浏览器会话没有管理员权限，展示验证通过临时入口挂载正式组件完成，入口已清理；正式设计页权限未改变。工作台只核对侧栏状态，未验证业务接口或执行写入；未实测其他浏览器或真实移动设备。

## 令牌分层与命名

1. `design-system/theme.css` 成为唯一数值来源，基础色按灰阶、夜间灰阶、品牌、反馈和插画分类。相同颜色只登记一次。
2. 语义层保留背景、表面、文字、边界、操作、品牌和反馈；删除用途相同的重复接口，例如 `primary` 合并到 `action`、`chrome` 合并到 `canvas`，导航常态文字与图标直接引用文字语义。
3. 组件层只保存实际需要独立控制的映射，例如日间卡片边框、导航选中前景、头像背板和登录场景。通过 `var()` 引用语义或基础色，不重复存储具体颜色。某一主题同色、另一主题不同的用途不能仅因值相同而合并。
4. 保留 `--os-` 语义命名空间；`foreground` 缩为 `text`，`background` 缩为 `bg`，文字角色使用 `size`、`weight`、`leading`、`tracking`；组件名和属性避免重复上下文。全仓替换引用，不保留一套长期旧名别名。

基础值 → 语义用途 → 必要的组件映射形成单向引用；不得循环或引用未定义变量。`spec.ts` 只保存名称、用途和分组。展示页读取 CSS 计算值，构建工具从同一份 CSS 读取品牌色；登录几何配置留在登录模块。Tailwind 映射引用同一组语义变量。

## 旧命名与兼容映射清理

设计状态：已采纳；实现状态：已完成；更新日期：2026-10-22。

用户进一步要求清理项目内剩余旧 token 命名与适配层。删除 `--pv-*` 及 Tailwind 中 background／foreground／primary／secondary／accent 等仅用于兼容的颜色别名，消费者直接使用 `theme.css` 的语义令牌和工具类。保留有实际用途的 muted、surface、selected、action、text、text-muted 等名称。

删除 `.theme` 外壳、挂载代码和仅为该外壳存在的模块；根级排版、焦点和减少动态效果属于全局基础规则，控件的圆角、字号、表面、阴影与校验状态在控件自身的语义类中表达。无消费者的旧 `pv-*` 样式与空标记一并移除。

日夜数值、组件行为和业务接口保持现有契约；组件的功能变体、第三方库实际提供的位置／尺寸变量按原用途使用。本轮不更换交互库，不改登录流程。新增静态契约检查防止旧命名重新出现；核对控件计算样式与主页面，执行格式、lint、类型、测试和构建检查。

应用自身继续直接使用语义工具类。Streamdown 的第三方主题接入改用下述官方变量映射方案；自定义字号在类名合并器中登记，避免尺寸覆盖误删文字颜色。

## Markdown 官方主题接入

设计状态：已采纳；实现状态：已完成；更新日期：2026-10-23。

移除 Streamdown 2.7.0 的打包 JS 补丁及 pnpm 补丁登记，使用官方支持的主题变量与 `data-streamdown` 选择器。适配约定统一在[颜色规范](../../frontend/src/design-system/colors.md#markdown-渲染器主题)维护。

- 在现有 `theme.css` 的 Tailwind `@theme inline` 中，将库实际消费的颜色名称映射到项目 `--os-*` 语义变量，不增加另一套色值或第三方主题控制器。应用页面仍使用项目语义名称。
- 保持原先透明的代码块／表格外层和工具栏背景；仅对工具栏边框等无法由同一库变量表达的差异使用官方 `data-streamdown` 属性，不依赖打包文件名或内部 DOM 层级。
- 根元素现有 `data-theme` 与 `.dark` 驱动日夜模式；`@streamdown/code` 沿用官方默认的 GitHub 日夜高亮主题。挂到 body 的链接确认、图片和表格浮层继承根变量。
- 更新静态契约：应用源码继续禁止使用库的颜色别名，主题映射允许第三方实际使用的名称；不再要求安装包内部使用项目类名。
- 验证无补丁的可复现安装、lint、类型、测试与构建；浏览器覆盖日夜、代码高亮、表格及全屏、链接确认、图片与下载控件、悬停／焦点与窄屏。

官方依据：[样式与 CSS 变量](https://streamdown.ai/docs/styling)、[代码块日夜高亮](https://streamdown.ai/docs/code-blocks)。
