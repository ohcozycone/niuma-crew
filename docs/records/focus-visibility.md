# 焦点轮廓与滚动裁切验收

日期：2026-10-31。范围：当前前端工作区。方案见[增量设计](../proposals/focus-visibility.md)，现行规则见[焦点与裁切边界](../../frontend/src/design-system/components.md#焦点与裁切边界)。

## 原因与处理

用户截图中，KnowledgeProcessing 的内部滚动区贴着 KnowledgeChunkRules 输入框左边缘，外扩 3px 的输入焦点圈被滚动边界裁切。仅设置纵向 auto 也会让另一轴形成裁切；取消单个 overflow-hidden 不能覆盖此类问题。

本次检索覆盖前端自有 TS/TSX/CSS 中的 overflow 和蒙版使用点，排除角色原画、品牌 SVG、生成物、测试及登录动画数据；扫描时点为 36 个文件、57 处匹配（包含同一类字符串内多个声明），不是 57 个已确认故障。按交互、滚动、文本和装饰用途逐组核对。

| 类型           | 接入与处理                                                                                                      |
| -------------- | --------------------------------------------------------------------------------------------------------------- |
| 滚动表单       | 文档处理正文、工具装配侧面板、技能装配侧面板使用共享 focus-gutter                                               |
| 可交互列表     | 全局搜索、添加技能、添加工具、能力候选、技能文件目录和嵌入历史列表预留焦点空间                                  |
| 贴边交互       | TabsTrigger、菜单项、主题菜单项、收藏链接、问题刻度使用共享 focus-inset；问题刻度在焦点进入时关闭首尾淡出蒙版   |
| 富文本与动画   | BubbleContent 去掉无必要的 overflow-hidden；Trace 保留高度动画裁切，内部左右预留焦点空间                        |
| 保留的必要裁切 | 外壳视口、消息滚动、Select/菜单最大高度、技能文件卡片外框、头像和插画、标题省略、只读文本和代码滚动按原职责保留 |
| 已有足够留白   | 上传队列的列表项、页面容器及普通弹窗的外层 padding 未机械叠加第二层 gutter                                      |

focus-gutter 复用既有 8px 间距，使用负外边距抵消内边距以保持内容对齐，并设置 scroll-padding。focus-inset 同时约束 ring 和全局兜底 outline；全局规则读取局部 outline 偏移，避免组件内侧偏移被全局样式覆盖。Tab 仅过渡颜色与阴影，避免焦点轮廓从外侧动画移动到内侧。

## 浏览器验证

使用临时入口加载真实 KnowledgeChunkRules、Input、Button、PageTabs 与 Dialog；复现正式处理弹窗的固定头尾和内部滚动结构，不提交后台任务。

- 日间与夜间：首个数字输入距滚动裁切边界 8px，3px 灰色外圈完整可见；颜色、圆角和输入行为保留。
- 弹窗滚动：键盘聚焦最后一个操作后，末项底部仍留 8px，焦点轮廓未被裁掉，滚动位置随焦点移动。
- 列表滚动：用 Tab 聚焦末项，实测左右和底部均保留焦点空间。
- 首尾页签：Home/End 正常移动焦点；outline-offset 为 -2px，ring 为 inset。390px 下末项可自动滚到视口内，横向滚动继续可用。
- 390px 弹窗：数字输入为 16px 字号、左侧安全距离仍为 8px，页面无横向溢出。
- 已恢复验证前主题和默认视口，临时入口验证后删除。
