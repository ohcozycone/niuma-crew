# 设计系统

界面设计保留四项共同约束：信息层级清楚、相同操作一致、状态有明确反馈、空间由所属容器管理。具体数值来自[主题样式](../../frontend/src/design-system/theme.css)，用途登记在[规范定义](../../frontend/src/design-system/spec.ts)，示例复用正式组件。

## 视觉与交互原则

- 按背景、文字、操作和状态选择语义颜色，日夜主题使用同一含义。状态同时有文字或图标，不能只靠颜色区分。
- 页面标题、区块标题、字段和辅助说明有清晰层级，减少重复边框与装饰。
- 基础控件复用统一交互与焦点规则，业务页组合控件，不复制一套外观相同而行为不同的实现。
- 未保存、提交中、成功和失败各有明确反馈；危险操作说明对象和影响，不与普通确认混用。

## 空间与响应式

外壳拥有导航和主区域，页面拥有内容宽度及滚动，区块根据可用空间排列，组件适配自己的容器。窄屏先调整分栏与信息顺序，不靠缩小全部文字解决拥挤。

对话正文、辅助信息和编辑区分别处理滚动与固定区域。长内容、弹层、键盘焦点和裁切共同检查，不能只验证空白样板。规则见[布局与响应式](layout.md)。

## 主题与资源

主题偏好独立于登录身份，首屏与运行期使用同一控制器；页面与挂到正文根节点的浮层继承同一组令牌。品牌、头像和插画保留固有颜色，普通界面按语义映射切换。品牌源文件、生成器及许可继续由正式源码维护，不能让应用依赖归档素材。

## 查阅与修改

[颜色与主题](colors.md)用于选色，[组件与反馈](components.md)用于复用交互；文档站各查阅页提供真实示例，不加入主阅读路径。

修改时先复用已有语义与组件，确有新用途再补定义。验证日夜主题、窄屏、键盘焦点、长内容与主要状态；业务权限和保存时机按对应功能规则维护。
