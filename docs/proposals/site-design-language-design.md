## 采纳决定与范围

员工配置保留基础配置、指令与知识、能力装配三个 tab。名称与大脑同页完成最小配置，指令和资料在同一工作区，MCP、内置工具与技能共用装配列表。知识库绑定仍为规划交互，不表示正式聊天已经接入知识。

本轮提供一套完整的推荐映射，不再让不同页面分别选择。推荐标识是站内设计选择，不是 W3C、Atlassian 或 Skill/MCP 协议指定的标准。外部依据和采用边界沿用[整体计划](site-design-language.md#规范依据与采用边界)。原型允许整体切换技能标识作为对照，所有场景同步变化，不能按页面分别选择。

具体图形、普通/紧凑表达、列表密度和知识辅区已按审阅方向接入正式组件；原型内示例字段不视为新增业务要求。本文后续提及原型行为时保留原型边界，正式实现以现行规则和实施记录为准。

## 对象语义对照

对象身份由主名称、稳定类型标识和必要的来源说明共同表达。颜色不承担类型识别；不要给每个类型设一种新的主题色。图形在同一字号、描边和颜色系统中呈现，尺寸沿用现行组件预算。

| 语义键（建议）          | 主名称与推荐标识            | 明确表达什么               | 跨页使用及禁止混淆                                                                             |
| ----------------------- | --------------------------- | -------------------------- | ---------------------------------------------------------------------------------------------- |
| `agent`                 | 员工；当前角色头像          | 一份岗位配置               | 目录、收藏、配置和对话保留同一角色；`Users` 仅表示员工集合，不替代个人身份                     |
| `capability_collection` | 能力库；`Blocks`            | 技能和工具能力的集合       | 全局能力入口使用集合图形，不再用具体 Skill 的图形表示整个集合                                  |
| `skill`                 | 技能；`Puzzle`              | 可装配、复用的工作方法包   | 能力库、创建/详情、员工候选/装配、对话选择/加载保留拼图；`SKILL.md` 和包协议中继续使用真实名称 |
| `mcp_service`           | MCP；`Plug`                 | 通过 MCP 提供操作的服务    | HTTP/stdio 是次级传输属性；产品普通文案用“MCP 服务”，不把协议、账号连接与单个操作混为一个对象  |
| `builtin_tool`          | 内置工具；`Wrench`          | 平台提供的实际操作能力     | 在工具集合中与 MCP 同级区分来源，统一配置/移除位置；不使用终端图形泛指一切内置操作             |
| `tool_connection`       | 账号连接；`KeyRound`        | 访问一个服务的账号配置     | 与所属 MCP 标识组合，凭据存在/匿名访问另行说明；不取代 MCP 服务图形                            |
| `model_chat`            | 大脑；`BrainCircuit`        | 员工使用的对话模型连接     | 模型目录、员工选项和模型调用保留同一识别；“配置大脑”与真实生成不是同一步                       |
| `model_embedding`       | 向量模型；`Network`         | 将文本转换为检索向量的连接 | 只在知识检索设置等相关位置出现，不在员工大脑选择中混排                                         |
| `knowledge_base`        | 知识库；紧凑 `FolderClosed` | 一组参考资料               | 大图继续使用已认可文件夹资产；紧凑行、导航、绑定使用同一文件夹隐喻，不临时换成 Skill 的图形    |
| `document`              | 文档；`FileText`            | 库内具体文件或支持文件     | 图标只识别文件，上传/下载/阅读用动作表达；文件类型在必要时用扩展名补充                         |
| `employee_instruction`  | 工作指令；`ListChecks`      | 当前员工的职责和要求       | 与技能、规章和知识资料区分；编辑器本身已有清晰标题时不强制再加图标                             |
| `organization_rules`    | 公司规章制度；`ShieldCheck` | 自动继承的全员规则         | 与资料并列时仍明确只读继承，不能出现“解除绑定”                                                 |
| `conversation`          | 对话；`MessagesSquare`      | 持续交流及其历史           | 对话列表/导航沿用此图形，单条消息不必重复装饰；执行状态另外表达                                |

选择 `Puzzle` 的理由是可组合的方法包隐喻，同时释放书本用于阅读动作、保留文件夹用于资料。它是推荐候选；若整体改为其他图形，语义键和所有页面同时更新。用户举的闪电只是识别示例，不是必须采用的图标。

### 变体与文字规则

| 场景          | 类型表达                                  | 交互要求                                                                                       |
| ------------- | ----------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 集合导航      | 集合图标 + 主名称                         | 保持顺序与活动态，不用单一能力类型代表整个集合                                                 |
| 资源卡片      | 主身份 + 名称 + 用途；必要时附类型文字    | 对象标题进入详情；装配、编辑等动作另有明确入口                                                 |
| 装配行        | 紧凑类型图标 + 名称 + 类型文字 + 配置摘要 | 行内操作位置稳定；启停、配置、移除均有可访问名称                                               |
| 候选项        | 同一类型标识 + 名称 + 用途 + 选择控件     | “选择已有对象”与“创建新对象”分开，数量大时可筛选和搜索                                         |
| 编辑/配置面板 | 标识 + 对象名称；副标题说明当前操作       | 同一对象在定义编辑与员工装配中保留身份，但明确保存目标不同                                     |
| 对话选择      | 类型标识 + 技能名称 + 临时选择状态        | 选择使用 checkbox，不借“启用”开关暗示修改共享配置                                              |
| 执行记录      | 对象身份 + 动词 + 结果文字                | 技能加载仍显示技能图形；工具身份依可信来源映射，缺元数据时只显示通用“工具调用”，不按名称猜服务 |

产品主文案推荐“新建技能、导入技能包、保存技能”；解释或标准包相关内容可在首次出现时写“技能（Skill）”。MCP 保留专业名称并补服务、账号、操作等层级。代码/API/包文件名不做中文替换。

## 动作、关系和生效时机

| 动作                | 标识与推荐用词                                         | 实际效果与反馈                                                                                           |
| ------------------- | ------------------------------------------------------ | -------------------------------------------------------------------------------------------------------- |
| 新建对象            | `Plus` + 新建技能/新建知识库；MCP 使用“接入 MCP”       | 创建定义；进入页面不自动保存或连接远端                                                                   |
| 添加已有能力        | `Plus` + 添加能力                                      | 进入统一候选面板，按全部/工具/技能筛选，不等于新建定义                                                   |
| 查看详情/编辑定义   | 文字入口；需要强调编辑时用 `Pencil`                    | 查看完整定义或修改共享资源；不用它代替员工参数配置                                                       |
| 员工装配配置        | `Settings2` + 配置                                     | 只编辑当前员工的操作范围、装配参数或启停草稿                                                             |
| 完成面板            | `Check` + 完成，更新草稿                               | 合入员工草稿，主保存前未写入服务器；取消/Escape/关闭丢弃面板临时修改                                     |
| 保存                | `Save` + 保存配置/保存技能                             | 提交所属资源；保存按钮不使用“完成对勾”替代保存含义                                                       |
| 移除装配/解除绑定   | `Unlink` + 移除/解除绑定                               | 只解除关系；不删除能力定义、账号或知识库；恢复修改按所在草稿规则处理                                     |
| 永久删除            | `Trash2` + 删除对象                                    | 保留现有确认和后端引用保护，提示与范围相称；不把每次关系移除都做成永久删除确认                           |
| 刷新列表            | `RefreshCw` + 刷新                                     | 只重读平台数据；不扫描本机目录或发现远端工具                                                             |
| 同步技能来源        | `FolderSync` + 同步目录技能                            | 保留现有显式扫描与逐包结果，不合并到普通刷新                                                             |
| 发现/确认目录       | 明确动词 + 实际范围                                    | 发现取得候选；确认后才进入已批准目录，不扩大已有员工许可                                                 |
| 测试连接            | `Activity` + 测试连接                                  | 指明验证模型目录、向量调用或 MCP 握手；不表示真实任务全部成功                                            |
| 发送/停止/重试/重连 | `ArrowUp`/`Square`/`RotateCcw`/`RefreshCw`，配语境文字 | 分别提交工作、请求取消、创建允许的重试、恢复观察；同一图形可在不同动作中使用，但主语与可访问名称必须清晰 |

员工“优化/返聘”等品牌表达是现行员工业务用语，本轮不擅自删除。迁移时补准确效果说明“暂停接单/恢复在岗”，并在跨页状态表中与启停事实对应；普通资源仍使用明确的启用/停用文案。

| 连接          | 未配置凭据/匿名访问/待测试/测试失败/已停用   | 文字说明实际测试范围；警告或失败图形作辅助                                         | 有凭据或握手成功等于生成成功                 |

数量明确计量对象：技能数、MCP 服务数、账号连接数、装配关系数、允许操作数、知识库数、文档数分别命名。“全部 N 项能力”仅统计当前目录/装配行，不把工具操作数混入其中；员工资源摘要的工具数量遵循现有[数量契约](../reference/agent-resource-summary.md)，必要时写“工具操作 N”，不悄悄改接口含义。

## 员工页面与跨页原型

1. **基础配置**：名称与大脑放在同一字段组，常规输入/选择使用同一边界和焦点规则；小头像和分类作为资料完善；简介在下方。桌面实际卡片预览只负责展示核对；窄屏收成可展开预览，不用第二个大头像挤占首屏。
2. **指令与知识**：指令为主，知识库辅区使用同源文件夹标识；继承规章为紧凑只读入口。窄屏知识库摘要和管理入口前置；绑定、查看和解除通过面板完成。知识绑定清楚标注为规划预览。
3. **能力装配**：全部/工具/技能为同一列表的筛选，不形成新的一级流程。统一行结构和操作位置；类型、用途、账号模式/操作数或参数状态各有适当摘要。添加与配置使用同一面板规范，列表数量增长时仍能直接到达技能。
4. **能力库与详情**：同一对象在目录卡、创建/编辑、候选、员工装配中保留身份。区分“资源已启用”和“员工已装配”，定义编辑与岗位参数编辑分别保存。
5. **对话选择与执行**：选择技能是本次任务意图；技能已加载、工具调用和模型回复使用各自真实事实。原型仅模拟记录，不运行模型或发送工具请求。
6. **知识与大脑关键表达**：核对对象列表、选择器、资料行和连接摘要，保留已认可资源形象；完整上传、向量配置、OAuth/账号及所有错误链路以迁移清单和当前契约约束，不伪称原型已实现全部功能。

原型的能力行数、分页和示例参数是检验布局的设计数据；不新增后端容量、参数规范或权限。图形与标签由一份类型映射生成，候选标识改变后所有页面同步，不使用逐页 CSS 或 DOM 补丁形成表面一致。

拟议的 `CapabilityIdentity.tsx` 在实施时归并为 `components/common/ResourceIcon.tsx`，只维护纯对象映射和渲染，不承担领域加载、权限或保存。知识库等非能力资源仍由各自业务所有者呈现。

### 路由与旧入口迁移建议

建议先保留现有 `identity` 与 `capabilities` URL 值，显示名更新为“基础配置”和“能力装配”；`instructions` 继续可达新的“指令与知识”。这样无需为重命名标签破坏已有链接。模型缺失、模型进度项和相关校验应准确指向 `identity`，不能延续当前错误的 `instructions` 目标。

若组件内拆分为三个私有区块，`AgentConfiguration` 继续持有草稿、revision、校验、保存和离页保护，各区块只编辑同一草稿。能力筛选状态不得卸载并丢弃已经提交到父表单的选择；错误发生在不可见类型时先定位对应 tab/筛选和字段。
