# 知识库、文档来源与检索界面

知识页面让已登录用户按业务建立本人知识库，上传 UTF-8 Markdown/TXT，查看固定正文和切片，再用问题检索当前库并核对命中来源。管理员通过独立的[全员规范](../organization-rules/README.md)维护共同指令，规则与资料分别处理。

## 模块设计

### 路由怎样表达阅读层级

`KnowledgePage` 先检查知识使用能力，再按库 ID 和文档 ID 选择总览、创建、库详情或文档页。库详情内的文档和检索页签、问题及命中片段写在 URL 中，可刷新、返回和直接定位。未登录入口引导登录，不继续读取本人资源。

`KnowledgeLibraries` 展示和创建本人库；`KnowledgeLibrary` 组织文档列表、上传/移除及库内检索入口；`KnowledgeDocumentPage` 读取指定文档固定正文、全部片段和原件下载。通过库与文档的稳定 ID 导航，不把页内数组顺序当作来源身份。

### 优先看库和文档，操作按需展开

总览采用资源卡片网格，按可用内容宽度自动排多列，窄屏单列。KnowledgeLibraries 只传入 library，完整 KnowledgeCard 复用员工卡片同源的 Card、CardContent 和 CardFooter，统一表面、内容留白与底栏。所有库使用同一通用知识图标，当前接入生成图片 `public/knowledge/library-folder-clean.png` 作视觉试用；生成来源见前端 `knowledge-assets.json`。图片以48px方形留位、透明底等比显示，装饰性空alt不进入链接名称。用户已认可2号文件夹造型，按要求移除了拟人眼睛，保留纸张与回形针。标题和用途最多各两行，完整名称仍作为整卡链接的可访问名称并保留 title；底栏显示文档数与更新时间，空库单独提示。切片数与重复的可检索状态不占总览空间。完整名称和用途可在库内阅读；名称/用途搜索保持 URL 查询状态。

总览的新建、库内的添加文档与阅读页的返回/下载均通过 PageHeading.actions 放在标题说明右侧；搜索与结果摘要通过 CollectionToolbar 贴近集合，重新加载列表进入页头 PageActionsMenu。总览不再设置资料/制度页签；库内文档/检索继续复用 PageTabs。

库内页默认显示文档与文件级处理状态，添加区提供选择文件及上传入口。上传只暂存原件；队列属于工作台，通过Layout中的非模态浮层查看。SPA切页、切页签与收起添加区/浮层继续传输；刷新或关页对未完成传输提示风险，切换身份取消并清空旧队列，失败重试沿用原标识。页面订阅生命周期不持有上传请求。

用户检查后点击“处理文档”，可选择部分文件或默认处理全部待处理项；弹窗展示本次字符规则与重新处理的影响，可临时调整长度/重叠/短章节阈值，选择文件分页预览；改规则或换文件即隐藏旧预览，关闭后取消读取。预览不写索引，提交沿用同一规则，临时值不写库设置。正文独立滚动，标题和提交入口固定。提交后后台继续，列表轮询阶段与覆盖，成功文件立即可检索。失败或中断项有单独重试按钮，记录可查看最近批次或取消未完成项。关键词可用与处理失败可以同时存在，表示重处理失败但旧结果保留。

“知识库设置”弹窗维护名称、用途与可空切分覆盖，合并默认后校验。元数据和规则带修订保存；规则修改不自动重切旧资料。名称/用途有静态编写指引，AI编写助手未接入。检索测试继续保持问题、方式和命中为主体，向量配置保留原按钮弹窗。

### 页面为何经 KnowledgeStore 读写

每个身份的 WorkspaceData 提供 KnowledgeStore，Resource 按库/文档/问题缓存和订阅。创建、上传和移除使用明确请求标识或库提交锁，成功使知识相关查询重新核对；页面只处理输入、进度和导航，不另存一份完整资料库。

上传前后都明确支持格式和上限，失败保留输入并允许处理原因。异步读取显示 loading/error/重试，移除只在确认和提交成功后返回库，不把前端先删卡片当作后端已完成。

### 检索结果如何回到原文

`KnowledgeSearch` 把问题存入 URL，通过库内检索资源取得命中，展示原文、排名、定位和诊断分数。查看来源跳到带片段 ID 的文档页，文档页从已返回片段中核对目标，显示对应固定正文字符区间；不存在的目标明确报错，不猜一个相近段落。

旧前端内置正文已移除；差旅教学资料通过明确的样例导入操作迁移到普通知识库，技术样例同样走后端入库服务。原件由 files 保存在配置的持久目录，数据库保存文档、来源和切片，页面没有单独的差旅硬编码展示。

BM25 分数与向量 cosine 距离均越小越靠前，不代表回答置信度；混合结果只显示融合排名，不虚构 RRF 数值。页面不直接连接向量库；库内检索测试本身也不能证明某次员工对话实际使用了知识。原件下载继续走当前用户的后端授权。

### 员工如何使用本人的资料

[EmployeeKnowledge](../../components/knowledge/EmployeeKnowledge.tsx)是知识模块提供的独立个人装配界面，复用于员工指令侧栏、成员可访问的员工只读页及对话工具栏。它通过KnowledgeStore读取本人库目录和已处理/向量覆盖，允许装配多个库、选择按需或每次先检索、召回方式及所有库合计的片段上限。设置按当前用户与员工隔离，个人入口显示自己的库数，不混入共享员工卡片的计数。

弹窗独立保存修订，不修改AgentPatch、岗位草稿或原System Prompt；新员工先保存。无库时提供管理入口，未处理资料可先挂载但明确尚不可检索；自动模式在无可用向量时使用关键词，显式向量模式不可用会提示并保留原选择。脏表单、保存中离开、修订冲突和身份切换都有独立处理，修改装配会使使用旧快照的任务停止。

实际问答通过后端捕获的个人范围检索，来源链接使用平台返回的库、文档和Chunk标识。对话正文与执行过程只将严格匹配的站内知识路径渲染为链接，入口复核权限和片段是否仍存在；链接可打开不等于回答语义已得到充分支持。

### 资料与全员规范各自生效

[OrganizationRulesPage](../organization-rules/OrganizationRulesPage.tsx) 保持独立加载、草稿、修订冲突和保存保护，拥有规则权限才显示。规则通过对话接受进入固定指令；个人知识资料需明确装配后才以目录和受管检索能力提供给员工，上传或共用导航不会自动授予对话读取能力。

## 目录与职责

```text
knowledge/
├── KnowledgePage.tsx              # 按身份、库/文档路由和权限选择知识总览、创建、详情，兼容旧规则链接
├── KnowledgeLibraries.tsx         # 展示本人知识库列表，创建带请求标识的新库，并复用加载/失败反馈
├── KnowledgeCard.tsx              # 复用共享卡片表面、内容与底栏，显示通用知识图标和摘要并导航到真实知识库
├── KnowledgeLibrary.tsx           # 组织单库文档列表、文本上传/移除、统计及检索切换，连接共享知识数据操作
├── KnowledgeProcessing.tsx        # 装配临时规则、目标文件预览及持久任务提交，处理分页、失效与读取取消
├── KnowledgeChunkRules.tsx        # 共用三项字符规则控件和合并校验，区分阈值与最小片段长度
├── KnowledgeSettings.tsx          # 通过修订保护维护库名称、用途与字符切分覆盖，不隐式重建索引
├── KnowledgeVectors.tsx           # 通过检索设置弹窗管理向量连接和索引，展示实际覆盖与失败状态
├── KnowledgeDocumentPage.tsx      # 显示固定正文、所有切片及指定命中来源，提供授权原件下载和移除反馈
├── KnowledgeSearch.tsx            # 按 URL 问题检索当前库，展示真实片段、排名和诊断，并定位到文档来源
```

## 与其他模块协作

[KnowledgeStore](../../state/knowledge/knowledgeStore.ts) 管读取与写操作，[knowledge API](../../lib/api/knowledge.ts) 管协议，[后端 knowledge](../../../../backend/app/knowledge/README.md) 管所有者、固定来源及词法索引，files 保管原件。

[UploadQueue](../../state/knowledge/uploadQueue.ts)独立持有上传写入和取消，[全局浮层](../../components/knowledge/KnowledgeUploadPanel.tsx)只订阅和操作队列；不随文档页卸载取消。后台处理存活由服务器负责，浮层不管理作业执行。

规则仍调用 organization_rules，页面不导入后端实验或设计样板作为正式资料。个人装配的候选、修订及读写经过KnowledgeStore，实际模型工具执行由后端会话与运行模块负责；知识页保留独立的关键词、向量和混合检索测试入口。

## 维护与验证入口

路由、列表、文档和检索组件都保留加载/空值/失败状态及明确来源标识。当前实现范围以本模块和[后端知识说明](../../../../backend/app/knowledge/README.md)为准；资料是否已进入员工上下文不能由知识页存在推断。原件、固定正文和切片变更须同步协议、URL 与来源定位。

## 向量索引配置

检索方式、问题与结果为页面主体，`KnowledgeVectors.tsx` 通过“检索设置”按钮打开弹窗，从共享 KnowledgeStore 读取启用的向量连接，明确资料发送目的地，提供建立/重建/移除、就绪/过期/停用及错误重试。检索方式写入 URL，查询缓存区分模式；页面不直连第三方模型。管理员在弹窗中通过共享 `ModelConnections` 管理向量模型及 Key，大脑页只维护对话模型。索引未就绪时禁用向量/混合方式，BM25 保留。没有管理权限的成员只看到共享连接的 ID、名称和模型，不取得 Key。
