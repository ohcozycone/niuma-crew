## 1. 目标与实施边界

工具连接持有访问外部服务所需的凭证，员工工具许可决定谁能用这个连接做什么，Run 固定本次使用的连接与范围，宿主执行逐次检查。AppConfig 保留平台启动和加密主密钥配置，移除日常执行对 CI_GITHUB_TOKEN 与 CI_GITHUB_TOKEN_FILE 的依赖。GitHub 登录 OAuth 仍属于平台认证配置，不与工具凭证合并。

首个可实施增量只开放现有 GitHub 只读 CI 预设和 Bearer 认证，允许管理员创建多条连接，并为不同员工选择连接与仓库。采用已经规划的 tool_connections、agent_tool_grants 和 agent_skills.tool_bindings，不新建 CI 专用连接表或每员工一份 token。

该增量可以先于标准技能包、完整通用 MCP 和 CI 统一循环完成；它不证明任意 MCP 地址、其他认证、个人 OAuth、GitHub App、写入操作或租户隔离已经实现。当前只有平台管理员管理资源，member/guest 的权限不扩大。创建者字段用于审计，不充当租户或个人所有权隔离。

## 2. 对象归属与授权边界

| 对象                     | 拥有什么                                                          | 不负责什么                                                 |
| ------------------------ | ----------------------------------------------------------------- | ---------------------------------------------------------- |
| 工具连接                 | 远端及传输、认证类型、加密凭证、已审核目录、配置/凭证/目录修订    | 不因创建或测试就授予员工权限                               |
| 连接凭证                 | 以密文保存在对应连接中，由工具模块在获准请求前解析                | 不进入员工、技能正文、普通参数、Run 快照、步骤、日志或响应 |
| 员工工具许可             | 员工与连接的唯一关系、明确操作/契约摘要、受信范围策略、启停及修订 | 不保存 token，不把技能文本或任务参数当授权                 |
| 技能配置                 | 方法启停、默认目标和对已有许可的工具映射                          | 不因装配 CI 方法就自动获得仓库权限                         |
| 本轮工具许可快照         | 本次选择的连接、许可修订、工具摘要和固定任务范围                  | 不复制秘密，也不使撤销后的权限继续有效                     |
| AppConfig 与共享加密基础 | 数据库、会话、运行器及部署主密钥                                  | 不选择某员工的 GitHub 账号，也不保存业务访问 token         |

首批沿用字段字典中 encrypted_credentials 归连接所有的方案，不另建独立凭证库表。只有确实需要跨连接复用同一秘密或单独委托凭证管理时，再设计独立凭证实体；不提前以 credential_id 制造一套空管理层。

连接的三个修订分别管理：配置变化、秘密写入/清除、目录批准/撤销。更新须带预期修订，冲突返回 409；即使写入相同 token，也按一次明确的凭证更新递增 credential_revision。轮换不能使旧 Run 自动使用新身份。

### 管理权限与使用权限

沿用接口目标的 tool_connections:read/create/update/delete/test 与 tools:approve，并明确增加 tool_connections:use、agents:assign_tools。首批在管理员映射中显式注册；未知角色、member、guest 不自动得到权限。

- 创建/更新/轮换凭证只允许管理者，读取接口只返回 has_credentials、修订、引用和当前基线的安全测试结果，既不返回明文也不返回密文。
- 员工许可保存须同时检查员工修改能力、agents:assign_tools、连接可见及可用范围。保存员工、许可与映射在同一事务，秘密更新独立提交。
- 发起工作须有 runs:create、tool_connections:use、对话资源访问权及员工许可。resources:all 不绕过员工工具许可或本轮范围。
- 连接测试和目录发现是独立的受限管理操作，只允许握手与目录读取，不提供任意 tools/call 调试接口，也不顺带授予员工权限。

首批共享连接由当前平台管理员管理。未来若支持团队或个人连接，须补资源归属、Actor 上下文、列表/单条查询与执行隔离，再迁移已有连接；本次不以 created_by_user_id 代替这些条件。

## 3. 凭证保存、加密与外部请求

1. 管理页面以只写字段提交 token，沿用身份、Origin、JSON、体积和权限检查；秘密字段不进入浏览器草稿、URL 或客户端持久缓存，提交成功后清空输入。
2. 将现有 [CredentialVault（已迁位）](../../../backend/app/infrastructure/credentials.py) 的窄加解密能力抽到拟议的 infrastructure/credentials.py，模型连接和工具连接分别注入同一部署密钥，不调用模型连接业务服务来解密工具凭证。异常由调用模块转换为各自稳定错误码。
3. 本次保留 MODEL_CONNECTIONS_KEY_FILE / MODEL_CONNECTIONS_ENCRYPTION_KEY 及对应 AppConfig 字段作为历史兼容命名，说明它们是共享部署主密钥；通用命名调整另行处理。不得通过更名生成新密钥或隐式重加密旧记录。
4. 密钥初始化策略须同时考虑模型与工具两类密文：任一类已有密文时，缺少或错误主密钥均拒绝新增，不能只检查 model_connections 是否为空后生成替代密钥。准备与加密不占长数据库事务，提交时再复核基线。数据库和主密钥分别备份。
5. 首批 public_config 选择受信 GitHub Actions 只读预设，目标及必要只读头由宿主控制；不开放任意地址、任意鉴权头、重定向、环境代理或工具返回 URL 的自动访问。Bearer 由工具模块注入，不能被模型或请求参数覆盖。
6. PATCH 省略凭证表示保留，空串/null 拒绝；显式 clear_credentials 必须与连接停用一起提交，递增对应修订并使连接未就绪。普通保存不访问远端。

管理界面区分“已保存凭证”“协议/认证测试结果”“目录已审核”“员工已获准”“本次调用成功”。测试记录绑定 config_revision、credential_revision 及测试时间，配置或凭证更新后过期，不作为永久可用凭据。没有可靠的上游身份返回时，不猜测 token 所属账号或全部可访问仓库。

## 4. 员工许可、默认目标与工具选择

### 4.1 仓库范围必须由受信代码执行

首批每员工每连接一份许可，仓库限制使用已登记的 github_ci_repository 策略。当前迁移保留单仓库限制；跨多个仓库的同连接许可后续再扩展策略，不把空对象或通配符理解为全部仓库。

| 操作         | 固定操作限制                                     | 资源检查                                                                  |
| ------------ | ------------------------------------------------ | ------------------------------------------------------------------------- |
| actions_get  | method=get_workflow_run                          | owner/repo 固定为许可和任务交集；resource_id 为本次 GitHub 运行编号       |
| actions_list | method=list_workflow_jobs，沿用既有分页/数量限制 | 同一仓库和运行；不能换成其他 method 或枚举其他运行                        |
| get_job_logs | 沿用现有尾部窗口和次数预算                       | job_id 必须来自本连接、本仓库、本次 run_id/attempt 已核验的失败作业白名单 |

工具名授权不够：actions_get/actions_list 的其他 method 仍拒绝。上游 token 权限、发起身份、员工许可、任务目标和平台预算共同限制实际调用；上游权限不足会失败，不能由平台扩大。上游只读注解或只读请求头不能代替这些检查。

Job 只在确认运行归属、attempt 和 head_sha 后进入本次白名单。不同连接即使返回相同数字 job_id，也不能互相使用。领域检查继续由 CI 组件提供，工具网关在实际调用前强制执行范围策略；不能让其他调用入口绕过它。

### 4.2 显式映射连接，不自动选择账号

技能参数 parameters.repository 是默认任务目标；agent_tool_grants.scope_policy 是安全边界。修改参数不会增加仓库权限，越出许可时拒绝执行。用户提供的运行链接始终重新规范化、检查，不因来自前端就可信。

agent_skills.tool_bindings 使用既定的需求键映射：读取运行、枚举作业、读取日志分别映射到 connection_id/tool_name，均须引用同员工的许可。当前 CI 三项操作必须落在同一连接，避免同一调查中跨账号或跨服务混用证据。多个连接可满足条件时须在员工配置中明确选择，运行时不取第一条、不取最近测试成功者。

新建工具许可独立于技能。解除 CI 方法不会自动删除独立许可，界面须显示仍保留的授权；撤销许可使依赖它的方法未就绪。当前先行阶段仍只有 CI 专用入口消费工具，普通聊天不因此获得通用 MCP 权限。

**旧授权不得因迁移扩大**：legacy_ci 迁入许可保留受信的执行上下文限制，scope_policy 标明仅供现有 CI 执行配置使用；宿主检查当前入口、CI 方法和原仓库，模型不能自行声明该上下文。它不会在后续通用循环上线时自动变成可供任意任务使用的许可。放宽该限制需显式复核并记录新许可修订；grant_origin 只保留来源审计，不单独充当授权开关。

## 5. 运行时流程与撤权语义

### 5.1 接受与快照

ConversationCommands 的接受事务检查身份、幂等、容量、员工/方法、映射及许可，捕获连接配置、凭证、目录修订和操作摘要；不在该事务解密秘密、读取 token 文件或调用 MCP。连接未启用、无凭证、映射缺失、范围冲突或目录未审核分别返回可处理原因。

在升级后的 Run 快照中增加明确的 tool_capabilities，不复用现有 connection_id：现有字段表示模型连接。每项保存 tool_connection_id、grant_id/revision、连接三类修订、操作/descriptor_hash、受信 scope_policy 与本轮仓库/运行目标。仅保存 ID、修订和非秘密摘要，不保存 token、密文或新的 token_fingerprint。

快照 schema 在实施时按实际基线升级，不预占版本号。幂等重放沿用原快照；显式重试创建新 Run，重新采用当前映射与许可，不执行旧授权。

### 5.2 调用与会话

1. Runner/协调器复核发起会话、员工、CI 方法及本轮许可，取得 tools 模块提供的受控调用入口。
2. 工具模块复核本轮固定的连接、凭证和目录修订，解密一次并在本 Run 的有界 MCP 会话中持有秘密；CI service 不接收明文 token，也不再接收整个 AppConfig。
3. 第一次握手/发现和每次工具调用前检查本地许可及修订；按总体方案重新发现远端目录并匹配获准摘要。无法验证或工具契约变化时停止受影响调用，不透明接受新目录。目录批准变更使旧 Run 停止并显式重试，未变更摘要的员工许可可供新 Run 复用。
4. 请求参数经过受信范围策略和 CI 对象归属检查后，才进入真实 tools/call。模型逻辑请求与底层 MCP 调用关联记录，不重复计数。
5. 执行中 watcher 继续复核授权；响应返回后、报告交付前再次检查。最终成功事务同时复核取消及本地连接/许可修订，避免在独立授权检查和最终提交之间漏过已提交的撤销。复用同一数据库 Session 的检查入口，不在提交事务访问远端。

每个 Run 的网络会话和鉴权头独立，不能按工具名或全局环境变量缓存身份。已捕获连接的 token 换新后，旧会话只用于尽力结束，后续请求被修订检查拒绝；不将新 token 塞入旧会话继续工作。

本地授权检查与外部请求之间仍有竞态，平台不能撤回已发出的请求。撤权后不发后续请求，不将迟到结果覆盖取消或发布为成功；数据删除/完整远端撤权也不能仅靠清除本地 token 承诺完成。

### 5.3 失败与记录

连接停用、凭证轮换/清除、许可撤销/修改、受影响目录变化或映射解除，均令旧 Run 后续调用失败。保留现有用户取消、服务重启 interrupted、预算和失败重试规则。密钥不可用、上游鉴权失败、目录失配、资源越界分别使用工具模块稳定错误码；CI 仅将其映射为可展示诊断失败，不吞掉授权错误继续调用。

RunStep 增加 tool_connection_id，safe_details 只保存连接名称快照、许可/连接修订、操作及范围摘要。历史读接口继续检查对话范围，连接读取能力不自动允许查看历史日志；历史读取也不依赖连接仍存在。模型草稿和思考的既有 CI 发布限制不变，报告/证据/反馈沿用原领域契约。

## 6. 接口与前端增量

完整 API 名称沿用[接口目标](../agent-capabilities/runtime.md#接口目标与切换)，首批实现连接 CRUD、test、discover、catalog/approve 和员工 tool_grants/tool_bindings 保存。仅 GitHub 只读预设与 Bearer 可创建，未实现类型明确拒绝；保存不等于测试或批准。

员工 PATCH 省略 tool_grants 保持现值，[] 撤销该集合，null 拒绝；修改某个许可时须携带其预期 revision，修改员工映射同时携带员工预期 revision。所有集合项先整体验证再提交，出错回滚，不保留半套映射。连接更新核对预期配置/凭证修订；批准目录核对候选基线及预期目录修订。

前端在已有 /skills 的“工具连接”Tab 管理连接；员工配置分别展示方法、工具许可和工具映射，常用表单填写仓库而非 JSON。游客/member 继续不读秘密、内部目录和授权详情。模型与工具凭证不进入编辑草稿；其他非秘密字段仍沿用草稿及冲突保护。

当前 /api/ci-diagnosis/capability 的全局 github_configured 无法代表某员工就绪，随前后端同批切换退出。员工详情返回按实际方法、映射、许可、目录与凭证配置计算的 CI 就绪摘要及缺项原因；目录/连接是否测试过另列，不从一个 bool 推断可执行。来源报告与反馈接口保留。

连接被许可或活跃 Run 引用时拒绝删除；停用可立即阻止后续使用，删除须先解除许可并排空/结束活跃引用。已结束步骤外键可 SET NULL，非秘密来源快照保留。引用检查包括活跃 Run 的 JSON 快照，不能声称仅外键已覆盖所有引用。

## 8. 迁入、切换与回退

该增量属于 P2 中可先交付的 CI 连接化子阶段，不要求同步完成标准包或统一循环，不替代 S2/S3 的完整验收。

1. **基线与准备**：停止接受并排空或明确中断活跃 Run，备份实际数据库和原主密钥；按当前 Alembic head 建结构，不沿用旧文档中的表数推算。只读 dry-run 列出原合法仓库、技能/关系启停、孤立配置和参数冲突，不输出 token 或指纹。
2. **显式迁入**：由本机受保护维护命令读取原环境 token 或 0600 文件，沿用原优先级和路径解析。命令不接收命令行明文 token，不借 AppConfig 在启动时自动迁移。网络发现/检查和加密准备在写事务外，保存时复核准备基线。
3. **一次确定的目标连接**：操作员显式指定目标连接标识，重复执行核对既有记录与修订后幂等跳过，不按名称或 token 哈希静默覆盖，不复制给每个员工。第一次保存为停用连接；实际发现并批准原三项操作和 method 上限后才可启用，其他发现工具不自动批准。
4. **转换原配置**：对原合法 CI 关联迁入相同仓库范围及受限执行上下文，grant_origin=legacy_ci；未知旧授权人保留 NULL，本次迁入操作者另记迁入结果。停用关联不自动启用，缺仓库/技能/凭证不补造可用许可，列出待处理项。将旧 ci_repository 转为已有技能参数 repository，已有不同值或参数规范不兼容时停止该项供核对，不覆盖用户数据。
5. **原子配置与范围核对**：许可、映射、技能参数和相关修订同事务提交；对每位员工比较旧可访问仓库、method、日志范围和预算。多个映射指向不同账号时拒绝。未处理项保持不可执行，不能回退全局 token 继续服务。
6. **同批切换**：部署新前后端、就绪接口和升级后的快照。新执行只读连接/许可/参数，旧 ci_repository 不再作为可写来源，旧快照只读。运行时不尝试旧环境变量兜底；残留变量只按名称报告弃用诊断，不保存其值或据此判断可用。缺连接时 CI 返回未就绪，普通聊天继续可用；运维切换完成后移除旧部署变量。
7. **退出旧结构**：真实 CI、撤权、轮换及恢复验证通过，核对孤立值处理后，在后续正式迁移删除旧列和旧配置入口。旧历史报告、消息、来源与反馈不改写，不补造新许可。

旧字段仅在受控切换期间只读保留，新旧实现不同时接收配置写入，不长期双写。迁入结果只记录对象 ID、范围、基线修订及成功/缺项，不能包含凭证明文、密文或可用于恢复秘密的数据。维护命令的重复执行不等于凭证轮换，实际替换仍须走显式凭证更新。

尚无新写入时可按演练恢复备份及旧应用；一旦出现多连接、新许可或轮换，就不能无损压回单个全局 token。回退须先停写、导出新增配置及历史，恢复一致的数据库/密钥/应用版本，并核对上游权限后重开；不能重用备份中已经撤销的旧凭证恢复访问，也不承诺自动降级无损。

## 9. 验收与取舍

| 场景                                       | 必须观察到的结果                                                   |
| ------------------------------------------ | ------------------------------------------------------------------ |
| 两员工共享方法但使用不同连接               | 账号、仓库和 job 证据不串用；复制方法不复制秘密或许可              |
| 管理员发起超员工范围任务                   | 即使 resources:all 也被员工许可及任务范围拒绝                      |
| 同工具的其他 method、越仓库或伪造 job      | 调用前拒绝；无越权外部请求，无伪造成功步骤                         |
| 凭证轮换、连接停用、许可撤销、解绑         | queued 和 running 的旧 Run 均不能继续后续调用；不透明换新凭证      |
| 撤销与最终交付竞争                         | 已提交的取消或授权变化阻止迟到成功，保留已取得证据但不发布报告     |
| 上游新增工具或契约变化                     | 不自动授权；摘要失配或无法校验时停止待复核                         |
| 任一凭证存储已有密文且主密钥丢失           | 不生成替代密钥，模型和工具密文均受保护                             |
| 列表、详情、错误、日志、草稿、Run/Step/SSE | 无 token、密文、鉴权头；公开读取和历史证据不扩权                   |
| 迁入重复、参数冲突、缺配置、部分失败       | 幂等可核对、不覆盖新凭证、不扩大授权、不恢复旧兜底                 |
| 当前 CI 全链路回归                         | attempt、SHA、日志窗口、引用、覆盖、预算、取消、历史和反馈保证保留 |
| 第二个非 GitHub MCP、个人/团队隔离         | 本次未覆盖，不宣称已经实现，按后续阶段单独验收                     |

首批接受仍由 CI 专用循环消费工具许可，代价是暂时保留专业入口；收益是先移除全局业务凭证与错误授权归属，同时保留现有证据保证。S3 接统一 Agent 循环时复用相同连接、许可和受信策略，删除专用循环，不另造一套连接表。

当前设计没有必须由用户补充才能继续的业务参数。真实部署迁入前须核对实际密钥、凭证可读性、远端目录及原员工范围；本次未读取这些秘密或运行外部验证。
