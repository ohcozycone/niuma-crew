## 目标与当前差异

对外只提供 useConversation 和 useMessage。改造前 useConversationSession 同时持有会话与消息数据，停止和重试隐式选择最新执行；消息组件经 props 取得数据。新结构以当前会话页的 Provider 创建唯一实例，两个公开 Hook 共享提交后的快照和网络生命周期。

## 职责与读取

useConversation 提供元信息、可见消息 ID 顺序、历史读取和定位、交互 phase、发送、重连及待确认提交恢复。useMessage(messageId) 提供指定消息的正文、执行 status、步骤、用量、执行错误、消息操作状态，以及绑定该消息的停止和重试。

useMessage 只按传入的消息 ID 读取。useConversation 提供 lastMessageId 定位会话末条消息，没有消息时为 null，不随历史阅读窗口改变；输入区通过 useMessage(lastMessageId) 读取执行状态和操作资格。ID 为必填参数，可显式传 null；null 或未加载 ID 返回空消息且不请求。

Provider 只在当前会话页挂载，按身份与会话隔离，内部协调器复用已有 history/SSE、幂等、取消和恢复逻辑。Context 传递稳定实例引用，useSyncExternalStore 读取提交后快照；消息组件按 ID 读取，正文片段不改变消息 ID 列表或未变化消息的快照引用。历史窗口与最新窗口保持连续性边界，读取消息的索引覆盖两者已加载数据，不拼接有空洞的消息列表。

## 操作与故障边界

停止仅针对指定消息的活跃 Run；重试仅针对最后一次失败、取消或中断的助手消息，仍创建新的 Run 和助手消息。命令执行时重新核对目标，过期回调不能改为操作另一条消息。消息操作状态和错误独立于 Run 的执行状态与错误。

尚未确认接受的提交没有确定消息 ID，其同键重发和停止意图属于会话；挂载与重连只核对，不重发。连接故障不覆盖提交故障或消息操作故障。卸载消息组件不关闭 SSE，卸载会话作用域释放观察与读取，不取消后台工作。

## 验收

验证多个消息消费者共享一次加载和一条订阅、按消息 ID 隔离读取与操作、未加载/null ID 不请求、历史定位后可读取、片段只更新对应消息、过期按钮拒绝、操作错误隔离、未知提交同键恢复、StrictMode 与切换身份/会话清理。同步现行契约与模块说明，实际结果进入 records。
