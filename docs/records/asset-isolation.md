## 工程目录整理

- 现有 `output/` 的 87 个文件（1,972,411 字节）包含验收截图、基线与当前对照、检查结果和复现材料，完整迁入同级 `niuma-crew-archive/output/`，逐项校验 SHA-256 后移除主工程副本。现有归档无同名冲突；迁移清单与本轮检查放在归档 `migration/project-organization/`。历史证据内容保留原样，文档链接按新位置维护。

## 范围与依据

用户要求将当前未使用文件移至独立工程目录，头像只保留静态 SVG。经代码、构建入口、包清单与锁文件扫描，正式头像已使用十三角色本地 SVG；前后端运行和构建不读取 `artwork/` 或 `output/`。迁移前，主工程仍保存动画源包、原图、拆件、候选、独立原型与历史验证证据，`node_modules/.pnpm` 还残留未在锁文件声明的旧头像包和 Rive 缓存。

独立目录采用同级 `niuma-crew-archive/`，保留原目录结构。迁移是本地归档，不发布、不新建 Git 仓库，也不修改已有独立 `niuma-avatars` 工程。

## 迁移与恢复

1. 迁移前记录逐文件路径、字节数和 SHA-256；符号链接记录目标。正式 SVG 和现用包清单另留基线。
2. 按清单移动目录，保留独立目录中的完整制作资料。主工程仅维护前端实际使用的 SVG、目录和组件，母版与许可均在独立工程维护。
3. 移除主 Makefile 的头像制作命令；应用构建命令保持现有入口。历史 Markdown 的本地链接按新位置调整，历史脚本和证据 JSON 不批量改写。
4. 独立目录保存 `migration-manifest.json`、迁移前 Markdown 快照和制作 Makefile。恢复时按清单迁回所需目录；前端现用 SVG 须先比对哈希，避免覆盖后续修改。改动过的文档可从快照取回。

归档保留历史工程上下文，不承诺所有旧脚本迁移后直接运行。部分脚本依赖旧绝对路径、额外制作环境或主工程源码；依赖缓存是快照，不作为可独立安装的锁文件。
