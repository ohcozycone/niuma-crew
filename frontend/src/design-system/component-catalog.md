# 组件分类与空间规范

更新日期：2026-11-01。本文为正式组件的类型与空间规范，已接入页面布局；实际检查见布局验收及访问异常验收。品牌、颜色、头像原画和业务流程继续沿用现有规则。

先从本目录选择组件类型，再由[布局规范](layout.md)组合页面。当前源码逐文件归属见[组件清单](component-inventory.md)，已实现的颜色、文字角色、形状和交互细则分别由[颜色](colors.md)、[现行组件规范](components.md)、[共享表面](surfaces.md)维护，不另造一套。

## 规范如何阅读

- “最小宽度”默认表示并列布局的空间预算，**不是给组件加不可收缩的 CSS min-width**。在 320px 视口，组件必须能够进入单列和紧凑结构。
- “建议宽度”是基于当前头像、文字、控件和操作的设计预算，不是用户研究结论；“最大宽度”可以是宿主分配的 100%，不要求每个组件都有像素上限。
- 组件管理自己的 padding、内部 gap、内容优先级和状态；父容器管理组件之间的 gap、列数和外围留白。Card 表面不隐含业务 padding，嵌入场景不套第二个页面容器。
- 全部尺寸为 CSS 像素，外框使用 border-box。间距角色的唯一目标表在[空间尺度](layout.md#空间尺度与留白)，避免同一数字散落在各页面。
- 缩略信息允许省略，但完整内容必须能在详情或有键盘、触屏等价能力的入口中读取；不能把桌面 `title` 悬停提示当成唯一完整信息来源。

## 操作与字段

| 类型                      | 目标尺寸、留白与间距                                                                                                      | 缩放、长内容与状态                                                                                                 | 设计原因                                                                     |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------- |
| C01 普通按钮              | 沿用 32 / 36 / 40px 的紧凑、默认、主要控件高度；左右 12 / 16 / 24px；图标与文字 gap 8px，行内 6px、xs 4px；按钮组 gap 8px | 宽度按内容，默认不拉伸；窄屏任务栏允许换行或逐项全宽，保持 DOM 顺序。加载复用图标槽并保留动作名称，不改变操作顺序  | 保留既有控件尺度；宽度表达标签，不让短操作在大屏随表单变长                   |
| C01 纯图标按钮            | 图标通常 16px，默认命中区 36px；24px 仅用于空间确实受限的桌面内联操作                                                     | 粗指针命中区至少 44×44px，视觉图标可不变；不得让相邻热区重叠。必须有可访问名称；必要含义同时提供可见文字或 Tooltip | 图形大小与操作命中区分离；44px 是本项目触屏目标，不冒称 WCAG AA 的统一强制值 |
| C02 短字段                | 已知长度用约 8–20ch 的输入宽度，上限 100% 宿主；以值的字符类型选择 ch 或 ic                                               | 数量、短别名等不铺满整页；放大和窄屏自动收缩                                                                       | 字段宽度提示预期内容长度，采用 GOV.UK 的内容驱动方法                         |
| C02 普通字段              | 并列预算每列至少 280px；建议字段组内容上限 640px，字段 w-full；控件左右 padding 12px                                      | 标签在上，标签到控件 8px，控件到说明/错误 4px，字段组间 24px。姓名等允许完整编辑；显示态与输入态的省略规则不同     | 一列可处理常见名称与连接名；将标签、输入和反馈形成稳定整体                   |
| C02 长标识/地址           | URL、模型 ID、路径、命令、密钥和协议文本允许使用整个主编辑区，不套 640px 的普通字段上限                                   | 输入可按原生方式内部滚动；只读值允许断行或显式复制。不是所有长值都强制 break-all                                   | 避免短字段和技术长字段被同一宽度模板误伤                                     |
| C02 多行文本              | 普通说明至少 3 行、建议 6 行，正文行高 24px；长编辑器见 C17                                                               | 随内容增长到 12 行后内部滚动；保留手动拉伸或等价扩展；不以固定高度裁掉文字                                         | 按“行”表达写作空间，避免每个页面独立指定奇数高度                             |
| C03 Select                | 与普通 Input 同高；字段选择器铺满字段，工具栏选择器按内容并预留箭头；左右 12px、内部 gap 8px                              | 选项过长可换行或在触发器内截断，选项列表可完整读取；浮层约束见 C23                                                 | 同行输入和选择控件具有相同的操作基线                                         |
| C03 Switch/checkbox/radio | 视觉大小沿用组件；选择行 gap 8px、行间 12px；文字与控件整体组成命中区                                                     | 选择行至少 32px 高，粗指针至少 44px；选项多时自然换行，不能只放大 Switch 图形而忽略命中区                          | 维持紧凑视觉，同时满足操作尺寸和标签关联                                     |

原生文件输入、checkbox/radio 可以保留原生语义；不为了枚举完整而预建未使用的组件。placeholder 不代替标签，错误通过 aria-describedby 关联，业务请求锁与权限仍由业务所有者负责。

## 导航与查询

| 类型              | 目标空间规则                                                                                               | 空间不足时                                                                                              | 设计原因                                                 |
| ----------------- | ---------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| C04 搜索与筛选行  | 搜索预算 240px、建议 320px、通常不超过 400px；筛选器预算 160px、建议 200px；控件间 12px，工具栏与结果 24px | 容器放不下时换到下一行；最后进入单列，搜索可全宽。数量摘要与查询同行或在下一行右对齐，不能挤掉主要输入  | 搜索优先于筛选，不让三项选择器均分空间后挤窄关键词输入   |
| C05 主导航        | 导航行默认至少 44px 高，左右 padding 12px，图标与文字 gap 12px；数量固定在尾部                             | 标签区域 min-w-0；窄屏导航整体进入抽屉。侧栏空间预算见布局正文                                          | 保留完整的导航命中区与图标位置，不以压缩文字代替结构变化 |
| C05 收藏行        | 头像 40px，头像到姓名 12px；主链接横向 padding 8px；编辑操作及分隔区独立预留                               | 姓名省略，完整名称在可达详情中读取；编辑操作可见性沿用现行键盘和触屏契约                                | 延续角色识别与双入口边界，hover 不改变宽度               |
| C05 账户与主题    | 账户至少 48px 行高；主题图形按现行品牌规范、外部命中区按 C01                                               | 不以缩小控件处理低高度，侧栏在低窗口整体可滚动；菜单由 Portal 定位                                      | 账户必须始终可达；主题图形不成为第二套控件尺寸体系       |
| C05 面包屑        | 紧凑文字角色，项间 8px；只给文本分配可收缩空间，返回入口不压成 0                                           | 对话员工名与问题分别省略；操作换行，不把路由层级隐藏掉                                                  | 位置信息优先于顶栏次级操作，保持真实导航关系             |
| C06 功能页头      | 标题、说明间距 8px；文字与操作区 gap 24px；页头到主体 24px；操作组 gap 8px                                 | 依据“标题至少 320px + 操作实际宽度 + 24px”判断并列，放不下就换行；不对所有标题写死同一个视口断点        | 使用内容预算，能处理长标题或多一个操作的页面             |
| C06 区块头/工具栏 | 区块标题与辅助信息 gap 12px，标题到内容 16px；外壳顶栏最小高度 48px，横向 padding 与布局对应               | 顶栏需要两行时自然增长；不强制内容垂直居中到固定高度                                                    | 区块与整页层级明确，对话仍用紧凑工具栏                   |
| C07 Tabs          | 下划线类型的标签 gap 24px、内边距 0；普通分段类型继续使用组件内边距；交互行至少 36px                       | 标签不能完整放下时在 Tab 列表自身横向滚动，并将活动项带入视野；右侧摘要另起一行，不把一组 Tabs 拆成多行 | 单行顺序与箭头键操作一致，指示线不跨行                   |
| C07 分页          | 摘要与页码/按钮组 gap 16px，按钮间 8px；与列表相隔 24px                                                    | 先将摘要移到单独一行，再将按钮分组换行；不可因无 wrap 造成 320px 页面溢出                               | 保留数量、当前位置和翻页能力，避免只适配空数据           |

## 卡片与配置

| 类型              | 最小并列预算 / 建议尺寸 / 最大尺寸                                              | 内部留白与结构                                                                                                       | 适配与原因                                                                                                                                            |
| ----------------- | ------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| C08 基础表面      | min-w-0，最大为宿主分配宽度；不设置隐式高度                                     | raised 供独立资源，outline 供配置分区，muted 供附属说明，empty 供明确占位；形状和阴影沿用现行规范                    | 同一表面不代表相同内容布局；不在每个分区再套多层 raised 卡片                                                                                          |
| C09 员工卡片      | 并列下限 320px，首选约 350px，最大跟随网格单元；不设会溢出小屏的硬下限          | 常态 padding 16px；头像 104×112px，头像到文字 12px；文字右侧保留 8px；身份后说明 12px，底栏分隔后 12px；简介显示两行 | 卡片自身小于 320px 时使用紧凑头像 88×96px、padding 16px、头像间距 8px，不能只在整个视口小于 600px 时才紧凑                                            |
| C10 能力目录卡    | 并列下限 280px，首选 320–360px，最大为网格单元                                  | padding 20px，小容器 16px；名称、两行说明、底栏间 12px；底栏允许换行；目录网格 gap 24px                              | 比员工卡片少一个大角色构图，可以更早出现多列；内置名称和协议标识均允许换行                                                                            |
| C10 技能选择卡    | 与能力目录共享空间下限，选择集合 gap 16px                                       | 标题、说明、选择态和展开详情保持同一表面；详情自然增长；同排卡片只对齐摘要区，不硬锁全部高度                         | 装配任务比目录更紧凑；展开内容不能被等高裁切                                                                                                          |
| C11 复杂连接卡    | 并列下限 480px，常规为一至两列，最大为网格单元                                  | padding 24px，小容器 16px；标题到状态 8px，状态/模型/账号组间 16px，操作 gap 8px                                     | 名称、模型、凭据、连接反馈均需要独立阅读空间，不能与简单能力卡一律四列                                                                                |
| C12 配置面板      | 并列字段内容下限 280px/列；常态双列面板预算 634px 外框                          | padding 24px，窄面板 16px；字段列 gap 24px、字段行 gap 24px；区块间 32px；文本说明到字段 16px                        | 2×280 + 24 + 2×24 = 632px，另为两侧边线保守预留 2px，得到 634px。字段区扣除 padding 后达到 584px（2×280+24）才排两列；紧凑 padding 下也按实际净宽判断 |
| C12 规则/单列配置 | 普通字段或阅读区按 C02/C16 限制，长编辑器可伸展；面板外框不再各自相对浏览器居中 | 描述和反馈与对应字段组同宽；继承说明属于主区内的附属内容，不另做浮动侧栏                                             | 页面位置稳定，具体内容按功能分配宽度，避免整页被短表单收窄                                                                                            |

员工沿用320px并列下限、约350px的首选宽度，为底栏资源数量和对话操作保留空间。104px角色与12px间隔让姓名区更充裕，卡片标题使用16px；长姓名仍可省略并通过详情读取。紧凑头像由卡片自身的320px容器阈值触发，不按视口直接缩放。

## 列表与数据

| 类型         | 尺寸与间距                                                                                                | 适配                                                                                          | 设计原因                                                         |
| ------------ | --------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| C13 内容行   | 一行摘要最小行高 48px，标题+说明为至少 64px；纵向 padding 12px、横向 16px；图标/头像到文字 12px           | 主信息 min-w-0；日期、状态、尾部操作独立。行内容宽小于 480px 时元信息与操作下移，不隐藏信息   | 列表按行阅读，不用资源卡片 padding 和等高规则代替                |
| C13 键值说明 | 单列时标签在上、值在下，gap 4px、记录间 16px；有足够空间时可用标签 120px + gap 16px + 值区                | 长路径和结构化值可断行/复制；窄屏退回标签在上                                                 | 说明型数据无需表格外框，但需要稳定的对应关系                     |
| C13 状态徽标 | 非交互状态按内容宽度，左右 padding 8px、图标间 4px，文字使用 caption；整体高度由文字和上下各 4px 留白决定 | 状态文字保持可读；一组徽标可换行；可点击筛选标签必须额外遵循 C01 命中区，不能沿用静态徽标尺寸 | 区分“状态说明”和“可操作筛选”，不为静态标签机械设置按钮大小       |
| C14 装配行   | 外侧 padding 16px、内部 gap 12px；名称区预算 160px，配置/启用/移除是独立操作组                            | 内容宽不足 480px 时操作组完整移到下一行；组内再按空间换行，粗指针保持 C01/C03 尺寸            | 不让长技能名挤掉移除或开关，也不将多个操作嵌进整行点击           |
| C15 数据表   | 表格占可用内容区；单元格横向 padding 12px、纵向 12px；数字靠右、文字靠左，表头与内容对应                  | 在表格自己的容器横向滚动，表格区域可由键盘聚焦；单元格文字可重排；保留标题与列头语义          | 表格是 WCAG 重排的二维内容例外之一，但不能把整页横向溢出算成例外 |

表格和列表按信息关系选择：用户需要横向比较相同属性时用表格，只需识别对象和执行操作时用内容行或卡片。禁止为统一外观把所有记录改为卡片，也不为当前仅存在的 Markdown 表格预建未使用的 Table 组件。

| 类型             | 目标空间                                                                                       | 行为与设计原因                                                                                                                  |
| ---------------- | ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| C16 独立长文     | 中文阅读列建议上界 48ic，拉丁文建议上界 75ch，均不超过宿主；正文沿用项目字体角色，长文行高 1.8 | ic 近似一个中文全角字形，ch 基于数字 0 的字形，不能混称“字数”。帮助/文章以持续阅读为主，限制行长；实际浏览器字体需验证          |
| C16 对话内文字   | 段落、列表和引用的首版上界 64ic，拉丁文 90ch；保持消息起点一致，代码与表格不受该限制           | 这是为工作对话保留扫描与上下文的项目取舍，比独立文章更宽；不将长文字行长误作整个对话宽度，不宣称这些上界是行业结论或 AAA 达标值 |
| C17 代码与协议块 | 占可用内容宽度，代码保留缩进，内部横向滚动；块内 padding 16px                                  | 技术数据比普通段落更需要横向空间；不强制所有代码折行造成结构难读                                                                |
| C17 文件编辑区   | 文件导航 240px，编辑区最低预算 560px，外框至少 800px 才并列；分隔线不额外增加 gap              | 560px 预算覆盖约 64 个 13px 等宽字符、编辑留白和行号；窄于阈值目录移到顶部可折叠区域，文件选择与正文仍可键盘访问                |
| C17 大段编辑器   | 默认至少 12 行、建议 16 行、最长 24 行后内部滚动；允许扩展或原生拉伸                           | 指令、JSON、代码各自保持语法含义；按编辑任务定义高度，不照搬短说明字段的 3 行高度                                               |

长文与对话行长是**待正式内容复核的项目设计参数**。WCAG 1.4.8 的 AAA 条款要求存在调整文字呈现的机制，包含 80 字符、CJK 40 字形等条件，不等于要求所有产品默认按该行长显示。独立文章与工作对话的预算不能被当成规范背书；来源与采用范围见[外部参考](layout.md#参考依据与采用边界)。

## 结构与维护

C26 包括 `PageContainer`、`PageToolbar` 插槽、Tabs 结构、Collapsible 和组合层。外框/主辅/阅读/编辑/浮层的组合只采用[页面模式](layout.md#页面模式与路由归属)，不为了某个 URL 新建一种页面宽度。Collapsible 不自带卡片和页面留白，触发器与主体由所属内容类型决定。

Provider、权限边界、路由包装、懒加载头像等不算新的视觉类型：它们的加载、失败和拒绝显示继承宿主模式。`ConversationProvider` 不负责页面宽度，`AuthBoundary` 不负责为内容选择窄列。

交互类型需要核对默认、hover、focus、pressed/selected、disabled、loading 和 error；有集合的类型额外覆盖 empty。静态文本和装饰不机械添加这些状态。不可因规范列出了 loading 就在基础组件内创建第二份请求状态。

每次新增或实质修改组件，维护其类型、消费者、宽度预算、窄屏变化、命中区、状态和示例。可稳定判断的接入规则在迁移时纳入现有检查；本轮没有声称仅靠文档就完成了代码约束或可访问性认证。
