## 后续实测：工具定义展开触发本地输入上限

2026-11-11，迁移分支启动后，用户新建对话的执行 `100000000179` 在首轮模型及 `search_tools` 成功后失败。只读核对数据库、已保存请求和工具结果，确认第二轮尚未发给上游，失败来自本地 `RUN_CONTEXT_BYTES` 默认 131,072 字节检查，不是模型已拒绝请求或历史过长。与迁移前快照对比，输入计量、模型门和工具发现算法相同；原验收没有覆盖这组真实 MCP 定义的展开体积。

此次发现的 5 个 Notion 工具经 SDK 转换后合计 126,333 字节，其中 `notion-query-data-sources` 的 Schema 从原始 28,557 字节展开为包含工具说明的 112,996 字节定义。使用保存的首轮请求、回复、发现结果和当前 SDK 重建第二轮投影，16 项实际可见工具及消息、系统说明合计 154,495 字节。同一投影在 131,072 字节配置下被拦截，在 262,144 字节配置下可进入假模型处理；未调用真实模型或 MCP，未改写原 Run、存档、参数 Schema 或资源数据。

当前迁移 worktree 的私有 `.env` 已设置 `RUN_CONTEXT_BYTES=262144` 并重载。该部署覆盖值依据此次输入体积及 [Kimi 官方配置示例](https://www.kimi.com/code/docs/en/kimi-code-cli/configuration/config-files)核对；官方示例的 `max_context_size` 单位为 token，不能与本地字节值等同，也不代表本账号已通过真实上游验收。全局默认值仍为 128 KiB。新提交及重试采用新值，原失败记录保持原冻结预算。

修正公开提示，明确上下文包含工具定义，并提示缩小工具范围或核对配置，避免把新对话误作通用解决办法。环境示例及运行契约补充字节预算、Schema 引用展开和摘要的适用边界。[新增回归](../../backend/tests/test_tool_discovery.py)用合成共享引用 Schema 验证原始定义小于 32 KiB、展开后介于 128—256 KiB，同一 SDK 链路在两档冻结预算下分别停止与成功接纳。定向回归 195 项通过；静态、类型及最终文档检查另按本次变更执行。这里的通过只证明本地拦截问题得到处理，真实模型任务效果仍由后续实测确认。
