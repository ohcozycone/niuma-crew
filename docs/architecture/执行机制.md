# 智能体执行

平台复用框架的模型与工具循环，维护业务所需的输入依据、操作许可、执行记录和成果。理解这条分工，才能判断哪些控制有必要，哪些是在重复实现框架能力。

## 模型与工具循环

执行从当前输入、岗位要求、方法和可见工具开始。模型生成回复或提出工具调用；工具结果回到上下文，模型再决定继续调用还是结束。工具可以并行，具体循环由官方智能体框架组织。

当前入口使用 LangChain 的智能体构建接口，结合 LangGraph 检查点及 DeepAgents 中间件。平台在[框架适配](../../backend/app/agent/engine.py)中连接模型、技能、工具与检查点，不自行重建一套通用循环。

## 装配与上下文

受理时捕获员工和资源的配置依据，运行时准备客户端、受限工具与执行环境。岗位和全员规范构成固定指令，技能按需读取，工具按需发现，知识检索结果作为资料参与回答。凭据不进入配置快照。

普通续聊从明确的检查点基点读取消息与摘要，新输入开始新的一次执行。知识引用还需重新核验。历史正文、工具反馈和检索资料各有用途，不能把曾经出现的内容一概当作当前事实。

## 状态为什么分开

| 对象             | 保存什么                                   | 边界                                     |
| ---------------- | ------------------------------------------ | ---------------------------------------- |
| 对话与消息       | 交办关系、用户输入和正式回复               | 供业务历史阅读，不直接暴露框架内部消息   |
| 执行记录         | 一次尝试的输入依据、动作、用量、成果和终态 | 重试新建记录，执行成功不等于业务验收通过 |
| 框架线程与检查点 | 消息状态、摘要和执行位置                   | 不是正式回复存储，也不等于跨对话长期记忆 |

例如，考核取得答卷后还要评分；对话保存成果后还要形成正式回复。具体公开状态见[执行规则](../reference/runtime.md)。

## 必要控制与实现代价

装配先收敛能力，执行时检查让该范围真正生效。模型和工具动作共享预算及授权依据，动作结果持久保存，单次执行协调资源收尾。当前同进程后台处理承担这些责任，不是一个分布式调度平台。

恢复资格取决于可信检查点、动作及资源条件；不能从任意位置重放有外部影响的操作。取消、断线、失败和成果保存也需要分别处理。每增加一项包装或限制，都应核对框架已有能力，并验证它解决的具体缺口、维护成本及对任务质量的影响。

内部协调见[执行实现](../../backend/app/execution/README.md)。跨对话记忆、持久等待和长期任务仍在建设。
