# 员工考核

员工考核组织一批固定考题，让选定员工逐题提交答卷，再按题库规则评分。当前支持 BFCL v4 `simple_python` 400 题的专项适配，原始题目、可接受答案及许可位于 [data](data/manifest.json)。此前 `/tmp/niuma-bfcl-audit` 的两道自建题只用于接线验证，不属于这套正式题库。

## 使用与结果含义

从员工管理页进入员工考核，选择抽样题数并提交。服务固定员工配置和题库依据，建立批次与题目快照；后台逐题提交独立 Run，原始答卷落盘后单独评分。关闭页面不取消考核，返回页面继续读取；取消操作保留记录，运行异常与答题未通过分别统计。每题独立线程，不继承聊天历史或上一题记忆。

首版采用专项配置：保留岗位指令、组织规则和模型，关闭实际工具、技能及个人知识装配，只收集函数调用提议。它不证明真实工具能执行或员工能完成原岗位任务，也不直接对标 BFCL 官方榜单。英语原题不自动翻译。更换配置后应重新考核，不能覆盖旧成绩。

## 职责和调用

```text
evaluations/
├── models.py         # 保存批次、逐题快照、Run关联及评分
├── schemas.py        # 校验员工、题数、题库及幂等提交标识
├── benchmark.py      # 校验固定题库，生成不含答案的输入，解析JSON答卷并评分
├── bfcl_checker.py   # 由固定官方源提取Python规则，不执行被测函数
├── service.py        # 管权限、创建、取消、版本核对、逐题推进和报告投影
├── worker.py         # 独立扫描持久化考核记录，跨页面和进程重启继续推进
└── data/             # 原题、可接受答案、上游评分源、摘要及Apache-2.0许可
```

应用装配在 `bootstrap` 创建服务与扫描器，HTTP 适配位于 [evaluations.py](../api/routes/evaluations.py)。评测调用 `RunService.submit(tools_enabled=False)`，复用 RunWorker/RunTask；执行层不导入本模块，不包含 BFCL 分支。没有 Conversation、Message 或通用 Run HTTP 接口的依赖。

创建请求与参数摘要按用户唯一；重发返回同一批次，改参数复用标识返回冲突。题目受理和 Run 关联同事务提交；重启看已有 Run，不重复调用模型。单批逐题执行，容量不足等待。每题提交前重新捕获专项配置摘要，与批次创建时核对；发生变更或授权失效时明确停止剩余题目。

每名用户最多安排两个未结束批次。批次接口仅展示本人的记录，管理员也不通过该入口越权读取他人的答卷。原始配置快照不进入公开响应，标准答案只在完成评分的题目详情中返回，不进入模型输入。已有考核记录的员工不能删除，应停用。

评分和取消各在短事务内提交。Run 成功但答卷错误时，Run 仍成功，考题未通过。执行异常不计为答错，通过率分母是已评分题数；计划数、完成数和异常数另外展示。当前不提供重评分或批次删除，派生评分器版本不匹配时报告评分异常。

取消与完成按数据库提交顺序判定：取消时Run已经完成，先接纳答卷并评分；Run仍活动则请求取消，之后保存其最终答卷但不再判为答对或答错。并发创建和扫描使用相同写事务与唯一约束，避免重复批次及重复提交。

## 验证与维护

迁移 [0022](../../migrations/versions/0022_employee_evaluations.py) 只新增两张表，不重建原有记录；不支持有损降级。评分器生成入口及来源见 BFCL资源说明。

[隔离测试](../../tests/test_evaluations.py) 覆盖400题与官方规则的一致性、格式/类型/额外参数、独立SDK执行、错误答卷与Run状态分离、取消、重启去重、配置改变及访问隔离。生产模型和外部工具的效果需要实际考核验证，离线测试不证明员工成绩。

评分器的固定正确与九种错误答卷控制位于 tests/support/evaluation_controls.py；test_evaluation_wire.py 通过本地 HTTP 替身检查 SDK 编码、员工指令、答卷及异常。它们不调用真实模型，也不代表任何员工成绩。

## 考题执行证据

报告里的每道已受理考题可进入执行详情。先核对本人批次与 EvaluationCase，再复用 execution 查询；不创建对话，不重跑或重评考题。见[契约](../../../docs/reference/execution-evidence.md)。
