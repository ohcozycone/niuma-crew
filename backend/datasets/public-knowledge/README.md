# 公开知识库验收资料

这些通用公开手册只作为加载、存储和检索接线的冒烟资料，不能证明模型依赖私有知识回答。业务事实测试改用[虚构企业资料](../fictional-enterprise-zh/README.md)，其题目和答案独立保存。

这三组中文资料供真实知识库上传、切分、关键词/向量/混合检索及 Agent 工具链路验证。正文来自公开项目，按原许可使用；不包含私人业务资料，也不包含生成的参考答案。2026-11-05 获取，固定提交、原始地址、许可、整理后和原件 SHA-256 见 [manifest.json](manifest.json)。

## 内容和来源

每组目录中的 TXT 文件是可直接上传的 UTF-8 正文，保留 Markdown 标题用于章节切分。对应 `originals/` 保存取得的原始 Markdown 字节，使用 TXT 扩展名将外部资料和工程自身文档区分，外部相对链接不作为仓库链接检查。`LICENSE.txt` 保存原项目许可。

上传正文仅去掉网站 front matter、HTML 注释、Hugo 短代码及 FastAPI 外部代码包含指令；正文不翻译、不由模型补写。未下载网站图片、外部示例源码或课程数据集，涉及它们的练习不保证独立可执行。每份上传文本加入项目、固定来源、许可链接及整理说明；MIT 资料还附原许可全文。原作者、项目和翻译贡献者的权利沿用原许可，来源链接可继续核对完整文档。

来源项目：[FastAPI](https://github.com/fastapi/fastapi)、[Kubernetes website](https://github.com/kubernetes/website)、[Microsoft ML for Beginners](https://github.com/microsoft/ML-For-Beginners)。这些是固定版本的验收输入，不能当作始终更新的产品使用指南。

## 录入与验收

1. 为当前用户分别创建上表三个知识库，仅上传各目录顶层的三份正文 TXT；不要上传 `originals`、`questions.json` 或本说明。
2. 通过普通处理入口生成正文、片段与关键词索引。分词规则继续使用产品的 jieba 实现。
3. 在“检索测试 → 检索设置”选择真实 Embedding 连接，再为每库建立 Chroma 向量索引；文档会发送给该连接的供应商，目录和许可不会自行选择模型。
4. 使用 [questions.json](questions.json) 分别运行关键词、向量和混合检索，检查前六条中是否包含目标文档，并人工核对命中片段是否支持问题。这个文件只有问题与目标文档，不得进入索引。
5. 给同一员工挂载多个库，在按需模式下观察模型实际生成的 `search_knowledge.query`、搜索范围、来源引用和补读。模型是否调用工具、query 是否合适，与同 query 的检索命中分开判断。

问题集只是九道冒烟题，目标文档命中不等于回答正确，也不是独立相关性基准。合成向量只验证存储与接线；真实语义质量须用实际 Embedding 单独记录。Agent 能否自主选择工具和正确引用还须单独验证，不能从页面搜索成功推断。

本机录入和实际覆盖见 [08 验收记录](../../../../niuma-crew-archive/docs/history/2026-11-08-文档精简/docs/records/知识向量存储与公开资料验收.md)。
