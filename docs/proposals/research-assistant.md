## 集成设计的归属

本文保留研究专用输入、取证、来源和报告要求。通用工作页、Task/Run/成果/验收、权限、迁移与执行演进改由[员工工作页与任务执行方案](agent-workspace/README.md)及其配套设计维护，均为草案、尚未实施。研究任务未来作为一个 task_type 接入，不因此提前成为当前主线。

## 目标与验收对象

平台先自用、再验证商业化。当前首项建设为[项目知识助手](knowledge-assistant/README.md)；本文保留后续研发研究员的拟议范围，不作为当前开发顺序。研究员拟承担的工作是：**围绕一个具体技术或产品问题，核实已有调研的关键主张，结合明确提供的项目情况，交付可复核的采用建议。**

工作价值假设是减少反复查原文、识别口径错误和重新解释项目背景的时间；该假设尚未通过实际任务验证。首版验证工作是否有用，不以员工数量、模型调用量或报告长度衡量价值。

验收分两层：事实核验看引文是否支持主张、条件与版本是否匹配；采用建议看前提、取舍和待做实验是否清楚。程序通过只说明格式、来源定位与覆盖检查通过；最终正确性与是否采用由用户决定。

## 首版范围

| 项目     | 首版包括                                                                             | 延后                                                                   |
| -------- | ------------------------------------------------------------------------------------ | ---------------------------------------------------------------------- |
| 交办     | 一个问题、待核验稿或 1–8 条主张、项目背景、预期决策；单用户主动触发                  | 多人协作、定时任务、跨聊天自动归纳                                     |
| 资料     | 用户指定的最多 5 个公开 HTTPS HTML/Markdown/纯文本 URL，以及粘贴的原文或项目文档摘录 | 自主全网发现来源、登录网页、浏览器渲染、PDF/Office、内网和本机路径读取 |
| 来源要求 | 关键事实优先原始公告、论文或官方文档；二手资料标注来源层级                           | 将“官方来源”直接当成事实正确或产品成熟的证明                           |
| 核验     | 逐项核对数字、日期、版本、条件、来源支持与项目适用前提；证据不足可交付待定           | 无依据的信任分、自动作出最终业务决定                                   |
| 交付     | 一份结构化决策简报，包含来源定位、覆盖说明、失败来源、建议和未知项                   | 外部发布、Notion 同步、代码修改                                        |
| 验收     | 接受／要求修订、具体原因、复核耗时；修订创建新 run 与交付版本                        | 自动学习并改写技能、自动发布、完整评测平台                             |

首版保留“指定 URL 获取原文”，使研究员能承担真实取证工作。粘贴资料是读取失败时的显式替代输入，也是第一阶段开发的起点；不能用用户提供的摘要冒充已读原文。更广的搜索在真实试用表明资料发现是主要耗时后加入。

数值是首版工程默认值，不是模型能力声明：资料正文与项目摘录合计最多 64 KiB UTF-8；交办正文最多 8 KiB；每来源原始响应解压后最多 2 MiB；最多 3 次重定向。超过限制明确要求缩小范围，不静默截断。正文规模不适用时返回资料限制错误，不伪装采集成功。

研究 run 的总时限拟为 480 秒、最多 4 次模型请求、一次最多 5 个 URL；共用现有 run 并发与队列额度。阶段上下文仍受现有 128 KiB 字节上限约束，并单独核对模型上下文与输出限制。普通聊天继续使用现有默认值。实现时以模型实测调整，不能通过降低资料限制隐藏失败。

## 端到端流程

| 阶段        | 用户动作与看到的内容                                                 | 后端动作                                                                 | 保存与失败处理                                                     |
| ----------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------ |
| 1. 交办     | 从研究员点“交办研究”，填写问题、待核验内容、资料 URL／摘录、项目背景 | 校验必填、范围和额度；保存草稿；用户主动提交后冻结本次输入、配置和方法   | 草稿可继续编辑；已提交输入不可覆盖；重复提交返回同一 run           |
| 2. 获取资料 | 逐项看到已读取、失败或用户提供摘录；失败可补原文                     | URL 只读采集，规范化正文，生成来源快照与段落位置                         | 记录原始／最终 URL、获取时间、处理版本和哈希；失败不是“无相关事实” |
| 3. 确定主张 | 查看本次实际核验的 1–8 条原子主张                                    | 用户已给清单时保留原意；给稿件时用一次模型调用拆分；保留稿中原位置       | 不增加用户未要求的调查范围；混合判断拆成事实和推断                 |
| 4. 核验     | 每条显示主张、结论、引文和条件；展示的是核验结果摘要                 | 一次批量核验调用，随后程序检查引用是否真实存在、是否覆盖每条主张         | 引文不存在或结构错误可修复一次；仍不合格则本次失败，保留诊断       |
| 5. 交付     | 先看建议摘要，再展开主张表、来源和未知项                             | 一次综合调用，生成结构化报告；建议引用已核验事实，不能引入未取证的新事实 | 验证通过后原子保存不可变交付、run succeeded 和任务 awaiting_review |
| 6. 验收     | 接受或要求修订，填写问题类别和复核耗时                               | 对最新交付记录人工决定；修订需再次主动提交，产生新 run                   | 旧交付、旧反馈不被覆盖；接受不自动修改技能或准许扩大权限           |

最多四次模型请求包括：可选主张拆分、批量核验、报告综合，以及共享的一次结构修复机会。修复只处理结构或无效引用，不自动扩大搜索范围；所有请求计入预算与用量；run 汇总本次各请求的已知 token 用量，供应商未提供的部分标为未知，不把缺失计作零。需要更多证据时交付“资料不足”，或由用户补充后再提交。

已读取到足够资料时，某一来源失败不必使整个任务失败，但报告必须列出缺失与受影响主张；所有来源都不可用且没有有效摘录时终止为 `no_usable_sources`。信息不足可以形成有效交付，不等于技术失败；格式失效或伪造来源不能作为正常交付。

### 交办结构与提交类型

`input` 包含 `question`、`draft_text` 或 `claims`、`project_context`、`sources`。`question` 必填；`draft_text` 与显式主张清单二选一，主张清单为 1–8 条，常用规模预计 3–8 条；稿件拆分超过八条时要求缩小范围。`sources` 每项为 `{kind: url, url, title?}` 或 `{kind: pasted, text, title, origin_url?}`。项目背景只作为用户提供的项目信息，未经读取代码不能写成当前实现事实；没有项目背景时只能给条件化建议。

研究输入由 `research_verification_v1` 任务类型的专用 schema 校验；执行、重试和修订命令沿用[共用任务契约](agent-workspace/tasks.md#32-执行命令)。输入与修订意见进入任务 Run 的不可变依据，不为执行额外创建聊天消息。URL 重试重新取证并形成新来源，旧来源保持可读。

### 交付结构

一份交付至少包含：

1. **问题与建议**：回答本次问题；区分建议与已确认事实。
2. **主张核验表**：`claim_id`、原主张及原位置、`supported / partial / contradicted / insufficient`、核验说明、日期／适用范围、引用。
3. **项目适用性**：输入的项目事实、建议采用／小实验／暂缓、原因、必要前提和验证办法。
4. **资料覆盖与未知项**：成功与失败来源、核验范围、尚未确认的问题。

每条引用指向本次来源快照的段落标识，并保留精确摘录。程序校验该段落归属当前 run 的资料集、摘录确实位于正文中。核验结论是否得到摘录支持仍需模型判断与人工抽查。来源内容变化后，旧报告继续打开当时的快照，而非悄悄展示新网页。

材料发布时间、生效时间与平台获取时间分别记录；未明示的发布时间为未知。页面较旧不自动判为过期；只有取得替代或失效证据时才说明已被取代。不同来源冲突应并列说明，不按来源数量投票。

示例报告题目：“当前阶段是否需要引入混合检索？”输入应包含当前资料量、已观察到的失败及候选方案；没有失败数据时，可以交付建议实验，不能声称方案已提升本项目质量。

## 领域关系与状态

员工承接任务，任务包含多次运行，每次运行关联来源快照、步骤与交付；验收绑定具体交付。Task 不要求专用 Conversation，来源对话仅用于显式交办的追溯。状态、版本与原子性以[共用任务契约](agent-workspace/tasks.md)为准，不在本页重复一套状态机。

研究执行只使用本次问题、方法、资料及明确选择的前次成果/修订要求；不自动把整段聊天历史当作证据。研究模型中间输入不进入普通对话，进度来自宿主步骤，正式报告由 Deliverable 保存。资料不足和相互冲突可以成为明确披露限制的交付，但技术通过不表示结论已被接受。

## 模块与最小扩展点

代码分层补充见[前端](../architecture/frontend.md)、[后端](../architecture/backend.md)及[分层评审](../architecture/backend.md)。研究员是平台公共执行基础的首个工作方法：任务模块拥有交办与验收，runtime 的应用职责包含执行装配及方法协调，运行驱动负责领取与生命周期，具体网络与存储由适配器提供。下列首版模块是渐进实现位置，不把 research 视为决定整个平台结构的独立领域，也不把 runtime 整体等同于基础设施。

1. 注册 `research_verification_v1` 任务类型，声明输入、方法要求、执行策略和交付检查；按员工实际就绪条件提供交办选项。不增加员工唯一 execution_profile，也不按“研发研究员”名称路由；普通聊天不自动升级为研究任务。
2. 研究任务选定一个已装配的 `method_skill_id`。提交时保存员工系统指令、方法技能文本、ID、更新时间与内容哈希；技能修改只影响之后的提交。初期不增加全局技能版本中心。
3. `tasks` 负责交办、验收与跨对象原子提交；抽取现有提交逻辑中真正共用的授权、配额和 run 创建协作，保留同一事务。不能从 TaskService 调用带提交的旧 HTTP 路由，也不能为研究任务复制另一套容量计数。
4. `runtime` 根据冻结的执行配置分派普通聊天或研究流程，共用进程锁、扫描器、运行句柄、授权复查与取消。研究方法实现位于 `research`；提供小范围的受控调用接口即可，不先建设通用 Agent 插件框架。
5. `sources` 负责网络边界、正文与定位；`runs` 记录阶段；`tasks` 保存交付与验收。`research` 组合这些接口并维护核验 schema，不反向拥有生命周期或登录会话。
6. `llm` 增加经验证的结构化结果适配；模型不支持强制 schema 时使用 JSON 输出加本地校验，失败有明确结果，不能把供应商功能假设为可用。

普通对话继续使用现有提交协议；任务 Run 通过 TaskService 接受，按 origin_kind 与 XOR 约束建立独立来源。来源对话不能通过发送/重试接口改变任务。Run 来源、读取和消息列的正式迁移遵循[共用任务契约](agent-workspace/tasks.md)，不能只放宽空值而省略归属约束。

## 拟议数据契约

Task、Run、Deliverable、Review 的字段和约束沿用[任务数据增量](agent-workspace/tasks.md#4-数据增量与强制约束)。研究专用增量是不可变 source_snapshots，字段如下；D 为数据库强制，A 为应用校验，全部尚未实施。

| 字段                                                       | 类型            | 可空    | 默认            | 含义与约束                                                       |
| ---------------------------------------------------------- | --------------- | ------- | --------------- | ---------------------------------------------------------------- |
| `source_snapshots.id / run_id`                             | UUID TEXT       | 否      | 应用 UUID / 无  | D：PK / FK runs；来源只能归属一次 run                            |
| `source_snapshots.source_key`                              | TEXT            | 否      | 无              | D：同 run 内唯一；A：与本次输入资料对应                          |
| `source_snapshots.kind`                                    | TEXT            | 否      | 无              | D：`url / pasted`                                                |
| `source_snapshots.original_url / final_url`                | TEXT            | 是      | NULL            | URL 资料填写；粘贴资料可给来源说明但不冒充已获取 URL             |
| `source_snapshots.title / supplied_by`                     | TEXT            | 否      | 无              | 可读标题／`fetched / user`；A：与 kind 一致                      |
| `source_snapshots.status`                                  | TEXT            | 否      | 无              | D：`ready / failed`；失败保留记录                                |
| `source_snapshots.text / content_hash / extractor_version` | TEXT            | 是      | NULL            | ready 时 A：均非空；不可变规范化正文、SHA-256、处理版本          |
| `source_snapshots.paragraphs`                              | JSON            | 是      | NULL            | ready 时 A：段落 ID 与正文 Unicode 码点起止位置；不得跨 run 引用 |
| `source_snapshots.observed_at / published_at`              | UTC TEXT / TEXT | 否 / 是 | 当前时间 / NULL | 获取或接收时间；页面明确的发布描述单独保留，不推断成日期         |
| `source_snapshots.error_code`                              | TEXT            | 是      | NULL            | failed 时为白名单错误；不保存上游敏感错误全文                    |

来源另有 created_at，按 run 索引，删除采用 RESTRICT，ready 正文不得覆盖。读取来源须通过所属 Task 的 owner 检查，不能因管理员 resources:all 读取他人任务或只凭 snapshot UUID 返回正文。

研究阶段复用现有 run_steps.kind/safe_details/result_ref 表达阶段及证据引用，不再另定义与当前 Step 不一致的 stage/result 列。任务快照采用[共用任务快照协议](agent-workspace/tasks.md#42-runs-的-w2-增量)，额外记录方法、研究流程与报告 schema 版本、来源输入和预算；实际正文只能在取得资料后保存为快照，不能声称提交时已经获取。

## 拟议接口契约

任务创建、草稿、提交、验收、结果读取、Run 与 SSE 复用[共用接口](agent-workspace/tasks.md#52-拟议接口)，不维护另一套研究专用 Task CRUD。研究任务额外需要 `GET /api/tasks/{id}/sources/{source_id}`：要求 tasks:read 且为 owner，成功返回 200；无权或来源不属于该任务均为 404，失败来源返回状态与安全原因，不返回伪造正文。

研究任务的输入由 task_type 校验，显式方法选择必须属于获准装配；来源段落与报告引用均绑定当前 Run。请求重放、修订冲突、版本验收与来源判别响应沿用共用任务契约。接口、任务页及研究执行当前均未实施。

## 前端交互

- 研究员从员工工作页提供就绪的“核实调研结论”任务选项，配置仍有独立入口；普通问答不自动产生正式核验交付。
- 新增 `/tasks` 和 `/tasks/{id}`。任务页沿用当前布局和设计系统，顺序为交办草稿、执行进度、交付及来源、验收；不新增独立门户。
- 草稿提供问题、待核验稿／主张、来源与项目背景，避免把方法版本、模型预算等技术字段放入常用交办流程。保存草稿显式发请求，离开未保存页面沿用 dirty 提示。
- 页面加载从任务详情恢复；执行中禁止改动本次输入，保留停止按钮。读取失败可重取；提交失败保留草稿；网络重发沿用同一个 client_request_id。
- 单来源失败显示原因及补原文入口；输入超限指出具体来源。补充资料在本次结束后保存为草稿，再主动提交；首版不做运行中暂停等待用户输入。
- 验收针对具体交付显示“接受／要求修订”；原因区分事实错误、来源不支持、条件遗漏、建议不可用、表达偏好与其他，避免把所有修改统计成错误率。可选填写复核分钟数，转换为秒保存。
- 通过的自动检查显示为“引用定位／结构检查通过”；任务只有人工接受后显示“已接受”。资料不足、相互冲突和待验证建议保持可见。

## 权限、资料与执行边界

资料是待核验内容，不是指令来源。网页中的提示、脚本、下载建议或工具命令不会获得执行权限；源码片段只作为文本。研究员没有 Shell、文件写入或外部发布权限，不能读 `.env`、浏览器登录态或凭据库。

URL 首版只接受 HTTPS 的公开地址与 443 端口，不接受 userinfo、file/data 等协议；逐跳校验域名与解析 IP，拒绝回环、私网、链路本地、云元数据及 IPv4/IPv6 映射绕过。实际连接必须绑定已验证的解析结果，不能仅预检 DNS 后让客户端重新解析。关闭环境代理、Cookie 和自动重定向；受控重定向最多三跳，不把平台凭据或登录 Cookie 传给来源。限制响应大小、正文类型、解压后字节和总时限；实现时通过受控 transport 与假网络测试验收，而不是只测试字符串黑名单。

用户粘贴的项目资料会进入已配置的模型服务；交办页应说明这一数据流，用户选定内容后提交。首版不自动扫描仓库、不建立本地执行器，也不把“资料在本地”描述成“内容不会发送模型”。来源正文仅在具备权限的任务 owner 范围可读，渲染不执行外部 HTML／脚本。

研究运行沿用登录会话复查；每阶段前复查员工启用与方法仍在员工装配中，运行中停用或授权失效停止后续调用。流程与方法文本使用提交快照，凭据按现有连接版本规则解析；已取得的非秘密结果可保留。修改配置不静默切换正在执行的模型或方法。

取消传播至网页请求、模型调用与阶段调度。不能保证撤回已经产生的模型费用；取消后的迟到结果不得生成成功交付。持久化失败遵循现有停止调用、503 与恢复规则。重启把未完成 run 和活跃步骤标记 interrupted，并将任务转 needs_attention；不自动续跑或重发；新 run 显式重新获取资料，保留前次快照。

## 开发顺序与阶段验收

| 顺序 | 可交付增量           | 依赖与新增能力                                                                                       | 阶段完成条件                                                                                |
| ---- | -------------------- | ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| 1    | 资料包驱动的最小闭环 | 复用共用 Task/Run/成果/验收；增加粘贴来源快照与研究输入/方法；不新增聊天消息依赖，先保持单次模型生成 | 在页面交办，产生可定位引用的报告，接受或要求修订，刷新后都保留；重复提交不重复执行          |
| 2    | 核验过程可检查       | 将单次生成拆为有界研究流程；结构化模型适配、阶段记录、引用／覆盖校验、预算、取消传播                 | 每条主张有状态和来源；伪造引用无法交付；失败／取消／重启不被标成成功；不复制 Runner         |
| 3    | 指定 URL 自动取证    | 受限网页读取、正文提取、不可变来源快照、网络边界与来源错误展示                                       | 输入真实公开 URL 即可核验；页面变更不改旧交付；失败和超限可通过补摘录解决；网络拒绝场景通过 |
| 4    | 五次真实任务试用     | 报告阅读与反馈体验、用量及复核耗时；已知错误回归案例与新任务分开                                     | 完成真实使用记录，估算准备＋复核＋维护成本；用户愿意再次使用，再决定搜索或持久项目知识需求  |

第 1 阶段是垂直切片，不先完成全部通用基础再做页面；第 3 阶段完成才覆盖本设计首版的“指定 URL 获取资料”。阶段 1 的单次输出必须标明其核验流程尚未拆分，不能提前宣传为完整自动核验。阶段 4 的继续投入条件与收益是实测结果，不是先验承诺。

本轮只交付设计，不新增业务代码、数据库迁移或演示研究结果。实际开发时随阶段更新本文件的实现状态与验证记录。

## 兼容与迁移

本轮没有可执行迁移。工作入口及共用 Task/Run/成果/验收先按[分阶段方案](agent-workspace/README.md)建设，研究用例再增加来源与方法适配，不再增加员工唯一执行配置或 Task 专用对话。旧聊天不回填业务任务；Run 来源和可空列按共用契约迁移，所有新外键与跨主体拒绝场景须验证。

先停止接收提交、做 SQLite 一致性备份，再升级 schema 与后端，随后前端。回退必须先停止研究执行并导出新增业务数据；不能直接删表后声称无损回退。历史普通聊天继续可读，研究任务不降格成已经验收的普通回答。

## 待验证选择

- 指定来源的核验是否已足够省时，还是资料发现才是主要成本；五次任务后决定搜索优先级。
- 用户更常提供完整主张还是长稿；据此调整拆分交互与每次范围。
- 64 KiB 正文与最多五来源是否适合实际资料；超限频率应记录，再决定片段选择或检索。
- 当前模型的结构化输出能力与费用；需实测，不以框架支持代替供应商可用性。
