# 员工知识库装配与问答

日期：2026-11-01。设计状态：完成独立评审并采纳下列修订的实施定稿；实施状态：已实施并完成限定范围验收。用户授权本轮连续完成方案、sub评审、实施及真实页面验收，无须再次确认。原初稿与评审意见的落实见[设计评审](../../records/employee-knowledge-design-review.md)、[最终代码复核](../../records/employee-knowledge-final-review.md)及[实际验收记录](../../records/employee-knowledge.md)。现行规则见[知识契约](../../reference/knowledge.md#员工个人装配与正式问答)。

## 目标和模块边界

知识库模块独立拥有装配设置、授权库范围、检索策略、多库结果、来源证据和权限复核；员工模块只提供员工标识及展示集成，运行适配器只消费普通快照与注入回调，不导入知识数据库。复用已建设的原件/逐文件就绪/BM25/向量服务，不改变上传和处理流程。

员工为共享岗位，而现有库为本人私有资料。因此挂载采用“当前用户使用该员工时的个人设置”：一个员工挂多个本人库，其他用户使用同一员工不会得到这些资料。装配不改变库的所有权，不建立团队共享。UI在已有员工配置及对话工作台提供知识库装配入口；未保存员工提示先保存，所有者和普通使用者均可维护自己的装配。公共投影不暴露私人库名、描述或数量。

## 初稿契约

- knowledge所属表保存(user_id, agent_id)唯一设置、revision、mode（on_demand/always）、strategy（auto/bm25/vector/hybrid）、top_k（1—12）及选库关联，最多10库。修改使用expected_revision，原子替换并复核当前库所有权及员工可访问性。
- knowledge命名空间提供GET/PUT /employee-bindings/{agent_id}；返回本人库目录、装配及已处理/待处理能力。原件未处理不向模型提供全文。
- 提交消息时在同一事务捕获库名称、用途、装配修订、模式、召回规则；运行时自动增加目录和使用规则，不修改员工原始System Prompt。目录为数据而非指令，工具schema真实注册，参数不允许模型传user_id/agent_id或扩大授权范围。
- 统一search_knowledge(query, optional library_ids)与read_knowledge_source(evidence_id, offset)；前者默认检索所有本轮挂载库，后者仅补读本轮实际命中过的来源，限长度。工具通过现有宿主预算、取消、动作记账及权限门，不走未登记旁路。
- auto对每库使用有效混合或BM25，纯BM25无模型依赖；explicit vector/hybrid不可用时明确错误，不静默降级。多库不同空间按名次RRF融合、全局Top-K及总证据字节预算，不能直接比较原始分数。
- on_demand由模型结合岗位、目录、问题与工具定义选择；always在首次模型调用前执行同一受管检索，再把证据放入本轮上下文，平台保证已检索而不靠提示词承诺。检索结果区分空库/待处理/无命中/故障/部分覆盖。
- 每次检索、补读、恢复缓存及最终发布复核当前装配、身份与文档版本。撤销挂载使在途或checkpoint旧授权失效；资料重处理不混用旧引用，删除原件不得通过旧evidence_id补读。
- 证据固定正文、版本和片段ID，存入现有运行来源持久通道以支持恢复；模型获得稳定证据编号与当前授权的原文链接。制度结论提示引用证据、依据不足时说明缺失；不添加第二个隐藏模型修复回答。最终对模型生成的知识引用校验登记、Run归属与权限。

## 验收矩阵

无挂载不装配工具；同员工不同用户隔离；多库命中；仅原件不给全文；无向量auto降级BM25；部分就绪照常检索；explicit模式故障明确；全局Top-K和输入限制；空命中；知识描述提示注入；卸载/删除/重处理阻止旧结果；当前Run来源补读；拒绝伪造引用；always路径确实检索；动作预算、取消及checkpoint恢复。离线使用真正LangChain工具循环与可控模型验证调用链；页面使用隔离数据完整操作，并在已有配置允许时做有界真实模型烟测，区分接线与效果证据。

## 评审后完整实施契约

### 私有资料和共享员工

个人装配接口位于knowledge命名空间，仅要求knowledge:use和runs:create，不要求员工编辑权。员工必须存在，停用员工不允许新建运行。库只选本人库，最多10库。设置和关联在knowledge模块维护，revision为个人设置修订，expected_revision=0仅表示尚未建立。共享员工卡片保留现有公共数量语义，个人入口显示自己的库数；不把私人库名塞入员工的共享字段。

管理员既有resources:all允许访问他人会话，但不能把自己的个人知识装入他人拥有的对话：接受时若有知识装配，发起者必须等于对话拥有者，guard再复核。历史中已经交付的正文沿用现有会话访问规则，不宣称管理员不能查看它。

### 知识模块的对外接口

EmployeeKnowledgeService由KnowledgeService持有，get/replace管理个人设置，capture在接受事务捕获目录，assert_current在宿主提供的事务复核，authorize返回专用知识工具的只读恢复及调用预算，call在事务外执行查询并登记证据，finalize_answer完成有限的来源路径规范化并调用verify_answer检查最终知识引用。应用bootstrap注入该服务到会话准备和授权；agent_runtime只接收RuntimeResources的knowledge_call/knowledge_finalize回调。

HTTP GET/PUT /api/knowledge-bases/employee-bindings/{agent_id}；PUT字段为expected_revision、knowledge_base_ids、mode、strategy、top_k，响应含revision、所选ID、同样配置字段及本人库能力目录。源文件/Chunk管理API保持独立。新增knowledge_employee_settings、knowledge_employee_libraries、knowledge_run_evidence，迁移0017；原库、向量和员工数据不重写。

### 运行、检索和来源

快照knowledge包含user_id、agent_id、revision、所选库名称/范围、mode、strategy、top_k；有挂载时加入两个kind=knowledge的专用binding（search_knowledge、read_knowledge_source）。运行时目录通过JSON编码并明确是数据，提示只在问题涉及所列内部事实时查资料；公开时效问题使用匹配的Web工具，不能将内部原文转发给Web。检索原文明确是不可信资料，不能覆盖岗位、用户目标和平台授权。空库目录可以提示待处理，但不提供未处理全文。

search参数query长度1—1000、可选library_ids仅收窄已挂库；read参数evidence_id、offset限界，不能指定任意文档或文件。每库候选受限，跨库以RRF合并，最终最多top_k和约18KiB证据正文预算，每次查询最多登记12片段。auto只在向量未就绪/停用时使用BM25，不把真实上游故障默认为关键词；explicit模式不兼容明确返回失败。状态字段区分待处理、空命中、部分向量和技术失败。

证据ID为Run范围稳定编号，登记原始Chunk快照、库/文档/版本及原文链接。补读限于当前Run已登记来源的固定证据片段，不是任意全文读取；offset分页最多2000字符，保留SourceSpan可继续前往原文页。每次guard检查设置修订、库所有者和已取得证据的当前Chunk仍存在且版本/正文匹配；仅比较文档version不足以发现规则重切，必须核对Chunk身份。缓存命中和最终发布也执行同一复核。旧快照没有knowledge则按原路径运行，装配变化要求新发任务，不将权限扩展到旧checkpoint。

所有知识调用进入hooks.begin_tool/guard_tool/complete_tool，RunAction持久记录结果及来源，不能让StructuredTool绕过宿主门。always使用固定幂等action_key在首次模型调用前预检索，恢复时经权限和证据复核才复用缓存，将结果加入本轮输入上下文；on_demand仅注册工具由模型选择。不添加第二个隐藏模型调用、回答润色或模型修复循环。

模型使用结果提供的来源链接引用。输出验证只证明引用对应本轮登记证据、来源仍获授权及链接路径准确，不能证明模型结论在语义上被充分支持。未知知识证据ID、任意拼接知识链接及引用未重新登记的其他Run证据拒绝成功交付；无命中可如实说明依据不足，不强迫捏造引用。历史引用只有经过下述重新核验与本轮登记才可沿用。来源登记、补读、模型决策和最终回答分别验收。

### 页面和实施顺序

knowledge独立组件同时挂在员工指令侧栏、普通成员可访问的员工只读页及对话工具栏。个人弹窗独立保存，阻止Portal表单提交冒泡；加载前不能保存，失败保留输入，409提供载入最新，关闭脏弹窗和保存中离页使用现有保护。向量不可用不改写所选策略，显示能力状态和影响。装配修改会使正在使用旧装配的任务停止，页面提前说明。

Markdown及动作来源只开放严格匹配的站内 /knowledge/{UUID}/documents/{UUID}?chunk={固定片段ID} 链接，不允许任意相对URL或javascript协议。打开后仍由后端和页面复核当前库所有权，资料删除时明确不可用。

实施按knowledge持久/检索服务、运行快照与宿主工具、独立前端装配和引用、联调验收四部分推进；各部分定向测试后运行全套前端与相关后端、迁移检查、构建和真实页面流程。实际调用模型时仅发送合成测试资料，并记录用量/失败边界，不读取或回显密钥。

### 来源路径遗漏斜杠的兼容增量

2026-11-01现场Run因模型将`/knowledge/...`输出为`knowledge/...`而整体失败。新增确定性的正文完成回调：仅当Markdown链接的K编号属于本Run，且目标补一个开头`/`后逐字等于该编号登记来源时补回斜杠，然后继续完整权限和引用校验。编号与路径错配、其他Run、外站host、sandbox协议、额外参数或fragment均不规范化、不放行。模型动作保留原始文本，正式消息保存完成后的正文；SDK和发布事务共用此入口，发布事务仍独立复核。此增量没有第二次模型调用，也不改写自然语言内容。验收覆盖原始失败格式、幂等、错配、撤权、绕过SDK的发布入口及实际页面。

### 连续追问的历史证据重新核验

2026-11-01另一现场Run直接沿用上一成功回答的来源，而当前Run证据为空。历史成功消息已送给模型，来源许可却没有对应衔接，导致合理追问被拒绝。

接受事务只从本对话实际纳入上下文的成功回复获得来源Run及正文；knowledge进一步核对本人、同员工、来源Run成功、当前挂载库和完整Chunk快照，且只接受历史正文中编号与地址完全配对的引用。按最近上下文优先、全局Top-K、18KiB和剩余上下文预算选取，再把证据及原始来源Run登记到本Run，保留编号供追问使用。模型同时获得重新核验后的原文片段、编号及来源，不只看上一轮模型摘要。不得按模型输出的任意旧编号全库查询或在发布时临时扩大授权。

未通过核验、已删除/重切/卸载、超出预算的历史来源，从送模副本移除编号和链接资格，并提示重新检索；历史消息本体不改写。新Run仍能使用正常知识工具查新问题；没有历史证据的首次问答无额外处理。读取、恢复、每次动作与最终发布继续校验本Run登记快照。按需模式可直接沿用重新核验的资料；always仍执行本轮搜索。历史核验记录为独立knowledge动作，显示已核对来源，不伪装为新检索，不调用Embedding或额外模型。无表结构变更，不自动改写历史失败结果。

验收覆盖成功首问后的连续两次追问、补读、只有同库但不同会话的来源拒绝、来源Run失败/其他用户/员工拒绝、删除/重切/卸载、预算裁剪、冻结后失效、恢复及最终发布；用隔离页面实际发送首问与追问并打开引用。现场失败输出只在本地临时副本重放，不对真实业务资料增加模型调用。

### 正文引用角标

本段的裸上标外观已被下述官方Base UI组合取代，准确识别和编号规则保留。

前端将通过严格站内路径检查的知识来源链接显示为上标`[1]`、`[2]`，按每份回答中实际Markdown链接的首次出现顺序编号，同一精确片段地址重复引用沿用编号。内部K证据ID及原链接继续保存在正文数据中，页面展示不修改存档、复制文本或后端来源校验。代码示例、普通外链及非法相对路径不参与编号。角标保持可点击、键盘焦点和可访问名称，流式追加及最终完成沿用相同编号规则。使用现有Markdown插件入口，不增加依赖或模型调用。

### 官方Base UI引用模式替换

本增量已实施，生效规则见[知识契约](../../reference/knowledge.md#员工个人装配与正式问答)，本轮实际验证见[验收记录](../../records/employee-knowledge.md#官方base-ui-inline-citation与sources)。

用户在查看官方演示后授权以[Inline Citation](https://ui.shadcn.com/docs/ai-elements/base/inline-citation)和[Sources](https://ui.shadcn.com/docs/ai-elements/base/sources)替换上面的裸上标展示，连续实施及页面验收。保留Markdown解析后的准确引用识别、原始K编号、链接校验及现有模型链路。

- 按官方Base UI Hover Card/Preview Card + Button组合呈现浅色圆角引用标签，标签显示实际来源标题的简称；悬停、键盘焦点或点击可预览。卡片展示完整文档标题、章节定位、最多600字符命中片段及明确的“查看原文”链接；点击预览不直接跳离回答。
- Sources按官方Trace/TraceCollapsible组合置于正文末尾，按解析出的实际引用地址去重，首次出现顺序与正文一致。不会把仅检索返回但未引用的候选计入“引用了N个来源”。普通网页链接仍为普通链接，本增量只处理知识来源。
- 标题从已保存动作来源取得；缺少标题时使用“知识来源N”，不展示内部ID。预览打开时通过knowledge的独立只读接口加载指定库/文档/片段，复用当前用户知识库归属检查并限制返回长度，不读取全文、不调用模型或Embedding。删除、重切、无权限、网络错误分别有明确提示和重试，不能用旧缓存冒充当前核验结果。
- 预览读取进入现有身份作用域KnowledgeStore，共享同地址请求，关闭订阅取消在途读取，身份变化释放缓存；每次重新打开卡片重新核对，不在页面批量预取原文。Sources打开只显示引用目录，原文片段仍按需读取。
- 基础组件沿用官方结构和MIT说明，映射现有日夜令牌、Portal、碰撞避让及焦点；移动端可点击展开，面板限制在视口内，Escape/外部点击可关闭。兼容已有成功回答，无迁移或重生成。

验收覆盖实际Markdown去重、代码样例排除、无引用隐藏Sources、流式追加、当前身份预览、跨库/文档/片段拒绝及删除；页面用现有合成历史检查标签、卡片、Sources、原文跳转、键盘和390px夜间。完成后用户直接在3000页面review。
