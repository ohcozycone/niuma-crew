# 执行详情与调用证据

员工主页的对话记录、全局对话记录及考核报告中的已受理考题，通过大型「执行日志」弹窗查看证据，保留原列表、筛选和报告。对话内的执行过程继续用 Trace 时间线原地展示必要步骤与状态。弹窗用已有 Run、RunAction 及业务关联组织执行路径，不建立 Trace、Span、事件账本或另一套状态机。

弹窗标题栏只显示标题与关闭按钮，下方用全宽分隔线界定独立滚动正文，不展示说明描述。正文滚动轨道与弹窗边缘、内容分别保留留白并预留稳定槽位。对话、执行与提问编号分别映射 conversation_id、response_id/run_id 与 input_message_id，使用中文标签、可选取的等宽数字，员工及模型配置独立排列。

## 模块边界与关联

| 模块 / 文件                                              | 负责什么                                                                        | 不承担什么                                   |
| -------------------------------------------------------- | ------------------------------------------------------------------------------- | -------------------------------------------- |
| execution/models.py、store.py                            | RunAction 的私有请求/响应文件引用；证据登记与动作引用同事务；保留原工具恢复载荷 | 不解释对话或考核归属，不新增调度器           |
| execution/runtime/model_calls.py、tool_calls.py、task.py | 在原调用路径采集、标记捕获阶段，记录工具申请与平台改写后的参数                  | 不改变提示词、工具授权、预算、评分和接纳规则 |
| llm/factory.py                                           | 请求作用域的观察回调，捕获实际 HTTP JSON 请求体                                 | 不查业务库，不保存请求头、连接地址和认证凭证 |
| files/service.py、storage.py                             | 先原子写文件，再在调用方事务登记；校验大小及 SHA-256；单独计量 evidence         | 不判断谁可以查看某次执行                     |
| execution/queries.py                                     | 读取已有执行和动作、按引用取证据，提供分页投影及下载                            | 不读 SDK checkpoint，不补造历史输入          |

| infrastructure/observability.py                          | 原 logging 的有界 JSONL 文件输出与按 Run 查询                                   | 不建立业务表，不把所有第三方日志复制落库     |
| components/execution/ExecutionLogDialog.tsx              | 大型弹窗内组织概况、执行路径和动作证据；窄屏上下排列，关闭取消读取              | 不执行或重跑考题，不修改业务结果             |
| ExecutionTracePage.tsx                                   | 将历史 trace URL 转到历史列表或考核报告并打开日志弹窗                           | 不再承载独立日志详情页                       |

## 诊断结构与定位

先看原问题、执行与交付状态、耗时、输入／输出／总 Token、缓存命中及调用数量，再选择动作。接口独立查询全 Run 的失败步骤，返回 failures（total 与按序前 20 项），默认优先选择与 Run 错误码一致的失败步骤；否则选择已记录失败步骤，再回退当前页首项。指定 action_id 时尊重该选择。失败不受动作分页限制，选中不在当前页的步骤会单独显示定位入口。普通调用数量超过一页时标为当前动作页，失败总数单独显示。

错误定位区明确展示步骤序号、名称、action_key 和错误码；错误事件按 action_key 关联，展示事件时间、异常类型、事件记录的源码位置，以及实际保留的异常调用位置。事件有 action_key 但步骤尚未载入时说明步骤未载入；没有动作关联时标为执行级事件。回复保存错误单独指明为交付阶段。只有 Run 错误而无动作或事件时明确无法定位，不推断为模型或工具调用错误。

左侧按实际顺序展示路径，工具通过 parent_action_id 缩进表达所属调用，失败节点直接显示错误码。右侧按实际证据决定栏目，不套固定四栏：模型提供模型请求与完整响应，默认响应；工具提供调用参数与返回结果；知识、技能及校验等动作直接展示自身记录。仅有一项内容时直接展示，不画 Tab；空的分类字段、空数组等不单独撑起记录。完整响应默认展示已采集结构，思考文字及 JSON 内的思考字段默认折叠。未采集、受限、不可读分别说明，不用空栏目承载提示。取消通用「动作元数据」附栏。

错误区直接对照失败模型调用的请求输出上限、实际输出、思考用量及占比、非思考输出差值、步骤耗时及总 Token 占整轮的比例。只有错误码为 output_limit_exceeded 且实际输出达到已采集请求上限时，显示预算耗尽判断；没有上限或用量时保留未知。思考包含在输出中，差值不等于有效正文长度。来源及计算口径可展开核对；摘要触发时的上下文用量及依据尚未采集，页面不据此判定摘要是否必要。

各阶段消耗表与当前动作页一致，显示每一步的耗时、输入／输出／思考／总 Token；可以选择步骤查看证据。占比以整轮已报告总量和原始时间计算，展示时间舍入不反推百分比。工具等非模型步骤的 Token 显示「—」，模型未报告显示「未报告」；不按 0 补全，不重复累计父子耗时。失败投影仍独立于分页。

运行事件每次执行只有一个可折叠入口，有事件才显示；它用于核对程序时序、异常类型与源码位置。与错误有关的事件在错误定位区就近展示，不再作为每个动作的固定技术日志 Tab。多次调用或高用量仍只是排查线索，不自动判为浪费。

结构化对象及完整 JSON 字符串由只读 JsonInspector（@uiw/react-json-view）展示，支持层级折叠、复制和主题映射；不完整的 JSON 保留文本预览。完整提示词按消息角色折叠，保留消息顺序、tool_call_id、完整文件下载、缺失和受限状态。思考只展示实际采集内容，折叠不移除响应字段，完整 JSON 复制和下载保留原始已采集证据。

工具响应中的 content 若为完整 JSON 字符串，解析为独立的只读结构；知识检索 hits 按原顺序展示命中列表，含文档标题、来源位置、可折叠正文、偏移及来源标识，正文复用安全 Markdown。首项展开，其余折叠；知识库状态可展开核对。没有命中时明确显示空结果，非知识工具显示 JSON 树或原文。解析不覆盖原始返回，原始 JSON、复制及完整文件下载继续保留；不自动将噪声条目判为根因。

Conversation ID 定位整段对话，输入 Message ID 定位问题，Run ID 定位一次执行尝试，且对话的 response_id 与 Run ID 相同；重试产生新的 Run。SDK thread_id 是内部续接标识，不作为前端日志检索入口。历史列表支持主题关键词及完整 Conversation ID／Run ID；合法的 12 位数字按 ID 精确匹配，不混入标题包含该串数字的其他记录。返回 matched_response_id 时日志入口精确打开命中的旧尝试。搜索不扩大所有者或员工范围。历史 trace URL 仅负责打开相应宿主弹窗。

关联主线为：`Conversation → ConversationRun → Run → RunAction → StoredFile`；考核为 `EvaluationBatch → EvaluationCase → Run`，后半段完全复用。并行工具按原 parent_action_id 关联模型轮；只读恢复产生新尝试时，证据写入对应动作尝试。拒绝的工具申请记录 failed、executed=false，不扣调用预算、不执行工具；模型响应同时保留其工具申请。完全未提供给 SDK 的工具名仍可从模型响应和 Run 错误定位，不能伪称存在一次工具执行。

## 采集内容与含义

1. **wire_request**：实际发送的 JSON，包含 system/messages/tools 与模型参数。每轮单独保存，所以第二轮能看到上一轮工具反馈。它是经凭证字段脱敏后的请求证据。
2. **sdk_response**：SDK 合并并解析后的响应，包含正文、工具申请、可用的供应商思考字段、响应元数据及用量；不是原始网络 SSE 字节流。
3. **model_error**：调用没有得到完整响应时，记录已分类的错误码，不保存上游异常正文。取消/进程被杀前未完整采集的响应可能缺失，动作状态与已有过程文字仍保留。
4. **tool_request**：模型申请的参数、授权状态，以及平台实际传给工具处理链的参数。包括技能读取对 offset/limit 的改写；SDK 内部后续注入的对象和默认值不伪造为已观察值。
5. **tool_response**：实际反馈给模型的内容、状态、附加数据和来源。外部工具的大原始结果继续使用既有 source 文件，页面提供下载入口；历史结果可复用原 result_payload，但明确标成恢复记录。
6. **思考内容**：只展示供应商实际返回的可见字段或标准 reasoning 块，默认折叠，未提供时不建立空展示区；摘要截断沿用原预算，不承诺模型内部完整思维。

证据文档包含 `schema_version=1`、`capture_stage`、脱敏规则版本和 `payload`。已知密码、API Key、Cookie、Authorization、令牌等结构化字段及 Bearer 字符串被遮盖，也处理嵌套 JSON 字符串；这不是对任意自然语言秘密的自动识别。实际执行输入不会被脱敏函数修改。

## 数据保存与故障边界

- 数据库只增加 RunAction 的 nullable `request_file_id`、`response_file_id`，均引用现有 StoredFile；StoredFile 的 purpose 增加 `evidence`，没有新增表。
- 证据正文在现有文件目录保存，字节先写入并完成同步，再把文件登记和动作引用一起提交。事务失败产生的未持有字节由原 FileCleanup 清理；已被动作持有的证据保留，不当作临时孤立文件清理。
- evidence 不进入普通附件、source 列表、模型文件选择或 SDK 工作区。普通上传/产物配额与证据配额分开。
- 每文件沿用 `FILES_MAX_FILE_BYTES`；证据每 Run 默认 64 MiB、每所有者默认 512 MiB，分别由 `FILES_MAX_EVIDENCE_RUN_BYTES`、`FILES_MAX_EVIDENCE_OWNER_BYTES` 配置。达到上限后本次证据可能缺失，不影响原对话和考核执行。
- **证据属于诊断扩展**：采集失败保留安全诊断事件，不替换动作结果或阻断外部调用；原动作事实、工具恢复数据及成果事务失败的处理不变。页面明确区分未采集、不可读、无权限和预览截断。不能把「未采集」解释为「没有发送」。
- 开启运行器时，核心执行日志写到 runner.lock 同目录下的 `logs/execution.jsonl`，每文件 5 MiB，保留 3 个轮转文件。只保存时间、级别、日志来源、Run、动作键、事件、错误码及安全的异常类型/源码位置，不复制消息正文、异常字符串或任意日志参数。目录/日志写入故障不阻断业务。最多有界读取四个文件、返回最近 200 条匹配事件；未开始采集的旧运行、进程硬退出和已轮转事件可能没有日志。

## 查询接口与权限

| 接口                                                                                | 用途                      |
| ----------------------------------------------------------------------------------- | ------------------------- |
| `GET /api/conversations/{id}/responses/{response_id}/trace`                         | 指定回复的执行详情        |
| `GET /api/conversations/{id}/trace`                                                 | 该对话最近一次执行        |
| `GET /api/evaluations/{batch_id}/cases/{case_id}/trace`                             | 本人考题的执行详情        |
| 对应指定回复/考题路径后接 `/trace/actions/{action_id}/evidence/{request或response}` | 下载该动作的完整证据 JSON |

详情接受 offset、limit（1—100）、action_id。返回 run、configuration 概要、actions 分页、failures（全 Run 失败总数及前 20 项）、selected 动作详情、can_inspect_inputs 和 logs；对话还返回原问题、交付保存状态与同题最近 20 次执行尝试。列表不携带其他动作的完整证据文件。单个证据最多内联预览 256 KiB，更大文件显示截断并提供完整下载。响应均为 `Cache-Control: no-store`。

模型动作增加 metrics 数值投影：usage（输入、输出、总量及 reasoning_tokens）、usage_source、output_limit 和 output_limit_field。用量优先提取已保存响应，缺失时回退动作已记录用量；输出上限仅从实际请求的 max_completion_tokens 或 max_tokens 提取。仅有诊断权限时读取证据，受限或截断证据不补造数值；普通身份继续只使用已有公开动作用量。仅投影当前页、失败步骤和显式所选步骤，同一次查询复用证据读取，不新增采集或数据迁移。

所有读取先要求 runs:read；对话还要求 conversations:read 并核对归属和回复关联；考核只读当前用户的批次，核对考题和 Run。完整模型输入、工具载荷和技术日志额外要求 agents:read 与 organization_rules:read，当前对应管理员。普通成员只得到已有公开动作信息，下载再次授权。客户端不能提交任意 file_id 越过业务关联。

前端按身份和资源隔离数据；切换动作取消前一次请求；活动执行每 2.5 秒串行刷新，终态停止。对话执行成功与回复保存成功分开展示；考核评分继续在原报告里查看，进入详情不创建对话、不重跑考题。

## 使用与验收

1. 登录管理员，进入员工主页的对话记录或全局对话记录，点「执行日志」打开弹窗。可以按完整 Conversation ID 或 Run ID 定位。对话内的步骤与思考仍原地展开。
2. 老记录应显示动作与已有结果；实际请求显示「未采集」。历史内容不会从 checkpoint 重建成证据。
3. 新发一条消息，进入对应模型动作的「请求输入」，核对当时的员工指令、全员规则、历史和参考资料。调用参数与工具定义可以展开，完整 JSON 可以下载。
4. 选择工具动作，核对申请参数、授权及结果；再选下一轮模型动作，确认请求中有对应 tool_call_id 的工具反馈。关闭弹窗回到原列表及筛选。
5. 在已有考核报告展开一题，点「查看执行详情」打开同源弹窗，核对该题请求与答卷；关闭后仍是原报告。查看日志不产生模型调用。
6. 用普通成员验证完整输入不可见、证据不能下载；跨用户或拼接其他动作 ID 应被拒绝。模型未返回思考时不能出现补写的思考文字。
