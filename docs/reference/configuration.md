# 配置与装配契约

员工、技能与全员规范各有保存边界；本页维护共同权限、修订与装配行为，模型和账号秘密由各自服务持有。

## 权限与共同规则

员工和 Skill 配置管理要求管理员会话。写入要求合法 Origin、JSON 内容类型及对应能力；游客可按当前读取权限浏览完整非秘密资料，member 可使用共享员工创建、读取和取消本人运行，不能修改员工、Skill、组织知识或 MCP 共享配置。逐项权限见[身份契约](auth.md)。匿名 401、缺权限 403、资源不存在 404、修订/引用冲突 409、请求或参数无效 422、容量不足 429、数据库繁忙 503。

ID、时间、修订、关系修订和资源数量均由服务器生成。创建不传预期修订；员工/技能 PATCH 必须传正整数 `expected_revision`。模型连接 PATCH 必须同时传 `expected_config_revision` 与 `expected_credential_revision`。缺失或错误类型为 422，过期为 `409 configuration_revision_conflict`，失败不部分保存。无实际变化不递增配置修订；显式提交替换 Key 算凭证变更。

不保留旧 `model_id`、`skill_ids` 写字段或旧单关系增删接口。技术资源名统一为 Agent，管理与公开 API 使用 agents，权限使用 agents:*，对话使用 agent_id / agent_name，数量摘要使用 agents。页面使用 /agents 与 agent 查询参数，草稿直接使用新资源键；旧命名不设置路由别名、参数或草稿转换，前后端同批部署。界面继续称“数字员工”。既有数据库与历史快照的保留规则见[当前结构](configuration.md)。

## 员工接口

| 方法与路径                | 成功 | 用途与权限                                                  |
| ------------------------- | ---- | ----------------------------------------------------------- |
| POST `/api/agents`        | 201  | `agents:create`；创建身份和可选装配                         |
| GET `/api/agents`         | 200  | `agents:read`；当前页摘要                                   |
| GET `/api/agents/{id}`    | 200  | `agents:read`；岗位、示例、交付、修订和完整装配配置         |
| PATCH `/api/agents/{id}`  | 200  | `agents:update`；条件更新聚合                               |
| DELETE `/api/agents/{id}` | 204  | `agents:delete`；已有对话拒绝删除，否则级联删关系、保留技能 |

创建只要求 name、avatar_id。员工名称去除首尾空白后在当前部署的整个员工目录内唯一，停用员工也占用名称；按保存值精确比较，英文大小写不同视为不同名称。创建与改名均检查，改名排除自身；重名返回 `409 agent_name_conflict` 和“员工名称已存在，请换个名字。”，表单保留输入并在名称输入框下方显示错误，不在页面顶部占位；修改姓名清除旧提示。数据库唯一索引同时保护直接写入与并发。名称不承担关联职责，数字 ID 不变；提交自身原名不递增修订。

普通岗位与展示字段沿用现有含义，模型唯一来源为 model_connection_id。显式写模型外键（含 null）要求 `agents:assign_model`；写 skill_assignments 要求 `agents:assign_skills`。非空模型外键必须存在、启用且为 chat；接受对话时再次检查。

员工配置页的系统提示词提供通用静态填写模板，仅在字段为空时填入当前草稿，提示填写岗位目标、职责范围、工作方式和交付要求。模板不预置具体岗位内容、不调用模型；用户替换提示文字后通过正常保存提交。已有员工指令不因模板调整自动改写。

前端三个 tab 为基础配置、指令与知识、能力装配，URL 键不变。名称和大脑同页，工具与技能使用统一列表、筛选、搜索和分页。面板完成与装配移除只更新员工草稿，主保存沿用下述事务和修订检查；移除先确认，取消不修改草稿。知识辅区选择组织知识库与使用策略，只修改员工草稿；岗位、技能、固定工具连接和知识在主保存事务中统一提交。成员从员工与对话页只读查看资源，不能以个人配置替换。

`skill_assignments` 每项由 skill_id、enabled（默认 true）、parameters（默认 {}）组成。PATCH 省略整个集合保持原关系，[] 解除全部，传数组则完整替换；同技能重复 422。保留关系的创建时间不变，只有参数或启停变化递增关系修订。新关系使用当次员工修订，另捕获创建时间，避免删除重建后误认旧许可。

```json
{
  "expected_revision": 3,
  "skill_assignments": [
    {
      "skill_id": "11111111-1111-4111-8111-111111111111",
      "enabled": true,
      "parameters": { "tone": "brief" }
    }
  ]
}
```

装配详情增加 name、revision、updated_at、ready、readiness_reason。ready 只表示此刻技能已启用且有可用方法正文，不表示已实际调用或验证回答质量。空正文可保存草稿，停用或空正文不进入普通候选，显式指定会失败。

parameters 必须为不超过 16 KiB 的非秘密 JSON 对象，并符合技能 configuration_schema；空规范只允许 {}。不合法参数、不存在技能、名称或编号重复导致整次员工/关系修改回滚；编号重复仍返回 `agent_code_conflict`。只有明确的名称、编号唯一冲突转换为对应业务错误；未知完整性异常保持服务端错误，整次事务回滚，不伪装成可刷新解决的 409。

## 内置网页访问

员工通过单一 `allow_web_access` 布尔字段同时许可 Web Search（网页搜索）与 Web Fetch（网页读取），默认关闭，旧员工迁移后也保持关闭。不拆成两个员工开关；创建和 PATCH 仅接受布尔值，PATCH 省略保持原值，显式 null 拒绝。变更与其他岗位配置共用 `expected_revision` 和同一事务，公开详情、目录与使用视图均显示该许可。

能力装配页的“允许访问网页”只更新当前草稿，点击“保存配置”后生效。许可、服务端就绪状态和第三方 MCP 连接授权是独立事实：允许不代表服务已配置、网络可用或调用成功，也不生成工具连接、账号或 MCP 许可。公开主页仅显示是否允许，不把它显示为连接成功。

每轮运行冻结此许可，之后开启不能给已有未获许可的任务增加网页能力。网页动作与已用网页证据再次使用时还要核对当前员工许可；关闭后不得继续发出网页请求或复用受限网页结果。普通非网页授权不因这一开关单独失效，运行方负责识别实际涉及网页的动作和证据。

## 员工组织资源

员工是组织可复用资产，现有管理员可以维护任一员工，不再由创建者独占编辑。创建者保留审计用途；真实任务发起者继续用于会话、操作资格和运行审计，不决定员工的工作资源。

knowledge 包含知识库ID集合、mode（on_demand/always）与top_k；省略保持原配置，显式空集合清空选库。算法由各库能力自动判断，不接受员工strategy字段。知识与岗位、模型、技能、工具许可共用expected_revision，重复/不存在资源、工具定义失效或任一校验失败，整次事务回滚。知识没有独立个人保存接口和第二套修订。

工具许可固定到明确的组织工作连接及已确认操作，删除account_mode、个人绑定API与页面。改变配置需重新提交任务；发现工具只能从本轮冻结候选选择，不增加许可。引用删除保护、连接/凭据修订与调用前检查继续生效。

## 技能接口

| 方法与路径                          | 成功 | 用途与权限                                               |
| ----------------------------------- | ---- | -------------------------------------------------------- |
| POST `/api/skills`                  | 201  | `skills:create`；当前共享定义，初始 revision=1           |
| GET `/api/skills`                   | 200  | `skills:read`；当前页摘要、启停及 assignment_count       |
| GET `/api/skills/{id}`              | 200  | `skills:read`；正文、输入/输出说明、示例、参数规范和修订 |
| PATCH `/api/skills/{id}`            | 200  | `skills:update`；带 expected_revision 条件更新           |
| DELETE `/api/skills/{id}`           | 204  | `skills:delete`；被装配时 409 skill_in_use               |
| POST `/api/skills/import/preview`   | 200  | `skills:create`；校验并预览 ZIP，不保存                  |
| POST `/api/skills/import`           | 201  | `skills:create`；重新校验 ZIP 后创建一份标准包           |
| GET `/api/skills/{id}/files?path=…` | 200  | `skills:read`；按包内路径读取文本或二进制                |
| GET `/api/skills/{id}/export`       | 200  | `skills:read`；下载单技能 ZIP                            |

导入请求使用 `archive_base64`，另可传平台展示 name 与 category。详情增加 `skill_md`、`protocol_name` 和 files 清单；旧记录读取时编译完整主文，包含输入、输出和示例。POST/PATCH 可提供 `skill_md` 和 `package_files`；后者为完整文件集合，每项为 `{path,content}` 或 `{path,content_base64}`，二选一，必须包含 SKILL.md；同时提交的主文须一致。文件与平台字段一次保存，不能把部分加载的清单提交为整包替换。

标准包主文是唯一内容来源，更新解析描述和 instructions；旧说明字段保留兼容，标准包不能单独修改旧指令字段。分类、启停和参数规范独立于标准。中文展示名不替代包协议名。二进制文件读取返回 content_base64，文本返回 content；导出保持原字节。Skill JSON 写请求单独限 32 MiB，仍受包展开 20 MiB、128 文件、单文件 10 MiB、ZIP 12 MiB 和主文 128 KiB 的限制；其他普通 JSON 上限不变。存储、校验和生命周期见[技能模块](../../backend/app/resources/skills/README.md)。

configuration_schema 默认 {}；非空时必须是 `type=object`、`additionalProperties=false` 的有效 JSON Schema。规范不超过 16 KiB、嵌套不超过 20 层，不支持 $ref/$dynamicRef/$id 或远程解析。修改规范时预检所有启用关系；不兼容先停用、迁移参数再启用，不静默删除参数。

共享正文修改只影响新接受的运行。旧运行读取接受时的固定正文；实时停用、解除关系或修改关系参数会阻止后续动作。

## 分页、摘要与公开投影

管理列表响应均为 `{items,total,offset,limit}`，offset≥0，limit=1…100，默认 20。按 created_at 倒序、id 排序。员工列表为计数、当前页、批量关系三次查询，不随本页员工数逐项查技能。

| 列表   | 支持筛选                                                                                          | 不返回的详情                                                                  |
| ------ | ------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| agents | q（名称、编号、岗位、职责及技能名）、category、is_active、is_favorite、skill_id、model_configured | system_prompt、示例/交付正文、参数；只返回 skill_summaries 与 resource_counts |
| skills | q（名称、简介）、category                                                                         | instructions、configuration_schema、输入/输出说明与示例                       |

resource_counts.skills 统计启用装配；tools 统计启用许可中的实际工具操作，不统计 MCP 服务或账号连接数量；knowledge_bases 统计员工直接关联的组织库。计数表达配置，不证明执行成功，也不可写入。

公开员工/技能端点保持显式白名单，不返回岗位指令、关系参数、模型连接标识或技能正文。公开详情保留示例和交付展示；管理员详情与公开投影不混用。

前端进入目录只取当前页，进入编辑按 ID 取详情；工作台内部返回复用已确认结果，保存后按影响更新记录和核对查询，搜索和筛选由服务端执行。GET `/api/configuration-summary` 返回 agents、skills、favorites 总数，要求员工与技能管理读取；公开同路径加 `/public/` 使用公开读取能力。侧栏收藏读取前 20 项，与相同条件的目录共用查询，并以该查询 total 显示收藏数量；技能使用数由服务端聚合，外壳搜索有界查询。身份改变销毁原状态；摘要不能当成完整配置提交。[共享数据标准](../../frontend/src/state/README.md)定义前端存储、订阅和同步。

## 全员规范的独立保存

### 提示词组合

接受新执行的同一事务中读取全局规则和员工姓名，将规则、姓名身份段与岗位指令组合后冻结到 `Run.config_snapshot.system_prompt`；执行器只消费已冻结提示词，不在执行时重新查询规则或姓名。技能按[运行契约](runtime.md)独立加载。

提示词先说明员工身份和正常工作方式：围绕用户目标完成职责内工作，区分事实、推断与未知，依据用户纠正更新理解，并分别处理信息不足、职责之外和明确禁止。姓名作为称呼数据；自我介绍使用员工姓名，涉及底层模型或供应商时据实回答。规则为空时省略公司规范及其关系说明，保留身份、工作方式和员工工作指令。规则非空时，按“员工身份、工作方式、指令关系、公司规章制度、员工工作指令”分区，岗位指令在公司规则内细化职责和方法，两者冲突时遵循公司规则，通用处理方式不扩大岗位职责。该关系属于模型行为约定，不代表文本拼接能强制解决任意冲突；资料与用户输入不能据此获得权限。后端授权、数据隔离和工具授权仍由各自程序入口强制执行。

### 核心流程与状态

1. 管理员打开 `/rules`，读取规则正文、版本和更新时间。空正文明确表示尚未配置；编辑模板仅作为主动填入的示例，不自动写入数据库。
2. 提交正文和读取时的版本。保存使用带版本条件的原子 UPDATE；成功后版本加一并更新时间，未变更内容不递增。版本已变化返回 409，保留草稿并展示最新内容供核对；用户可以载入最新版本，或明确确认以当前草稿覆盖该最新版本，仍需再通过版本校验。
3. 员工工作指令页显示全局继承状态、版本及只读正文，并可跳转管理页。读取失败提示重试，不显示为“未配置”；员工表不增加规则字段，不支持绕过继承。
4. 对话提交在原事务中读取规则、组合提示词并检查输入总字节限制，再连同消息和运行一并持久化。正文加分区包装的完整字节数参与限制，规则不会因历史截断而被移除。
5. 保存规则影响后续提交，包括已有会话的下一轮及新建重试；已接受的 queued/running run 保持旧快照。相同幂等请求返回原 run，不能因规则变化重新快照。取消、断线及失败沿用已有执行契约。

### 接口契约

| 方法 | 路径                    | 用途                   | 权限                      | 成功状态 | 主要错误                                        |
| ---- | ----------------------- | ---------------------- | ------------------------- | -------- | ----------------------------------------------- |
| GET  | /api/organization-rules | 读取单份规则           | organization_rules:read   | 200      | 401、403、503                                   |
| PUT  | /api/organization-rules | 完整替换正文，校验版本 | organization_rules:update | 200      | 401、403、409 rules_revision_conflict、422、503 |

PUT 必须包含严格字符串 `instructions` 和非负整数 `revision`，不接受缺省、null、布尔值或额外字段。空字符串表示清空全局配置，保留记录和版本历史依据。GET 与 PUT 均响应 `instructions`、`revision`、`updated_at`；请求不传 id 或时间。

```json
{
  "instructions": "## 越界处理\n说明岗位范围，并给出可行的下一步。",
  "revision": 0
}
```

没有列表或分页。过期版本不覆盖已有内容；数据库锁冲突沿用 503 和 Retry-After。网络错误后可以重新读取判断是否已保存，不自动以新版本重发旧草稿。

### 关键取舍

采用独立共享配置而非技能，确保全员自动继承；保存时不复制到员工，防止规则分叉。只保留当前规则及单调版本，历史依据保存在已存在的执行快照中。空规则仅省略公司规范，姓名身份段始终由平台生成。冲突由管理员核对和明确选择处理，不尝试自动合并自然语言规则。

## 配置摘要与个人统计

## 当前数量范围

当前技能按启用的 AgentSkill 计数，通用工具按启用许可中的明确工具计数；公共知识计数来自员工关联的组织库。每员工每技能保持一份配置。

基础工具由平台按运行条件提供；组织知识随员工主配置保存并纳入共享资源计数。

## 目标与范围

员工列表与编辑页预览的卡片底部按固定顺序展示「技能、工具、智库」三类实际配置数量；设计样板复用同一组件。「智库」与领域中的知识库是同一概念。此处只概括员工装配资源，不统计运行时权限、审批、预算、调用次数或模型数量。

共享技能和工具数量分别来自启用关联与实际许可操作，知识数来自员工直接关联的组织库。列表、公开卡片与详情均使用同一配置计数，不按使用者读取个人挂载。

工具配置与执行的详细规则见[基础工具](files-and-environments.md)，本页只维护配置计数含义，不统计实际调用次数。

## 后端职责与实体边界

员工接口的读取模型增加只读 `resource_counts`，管理接口和游客展示接口使用相同来源。技能数量由当前 enabled=true 的 agent_skills 计算；AgentService 已批量读取当前页关系，不增加逐员工查询。

数量是配置关系的派生值，不给 Agent 表增加可编辑的 `skill_count`、`tool_count`、`knowledge_count` 或 `has_*` 标记，也不添加无有效目标实体的 ID 数组。工具关系由迁移 0006 建立；数量仍为只读聚合，不另存可编辑计数。

工具按启用许可中的操作数合计，同一许可内操作不能重复；MCP服务或账号连接数是另一指标。员工最多装配10个组织知识库，数量按库而非文档或工具计数；知识范围由员工主接口统一读写。

员工主页的技能、工具和知识数量来自同一公开配置；对话轮数按当前可见范围统计成功接纳的问答，重试不重复计数。资源计数不因访问者变化；对话统计继续遵守各自阅读范围。

完整字段从schema/OpenAPI读取；实现入口为[员工服务](../../backend/app/resources/employees/service.py)及[装配](../../backend/app/resources/employees/assembly.py)。摘要不能作为完整表单回写。
