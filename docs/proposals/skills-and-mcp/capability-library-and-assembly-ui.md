## 2. 能力库布局

保留“能力库”名称，统一统计“项能力”。MCP 服务、Skill 和未来插件并非同一协议对象，类型标识继续保留，但不占独立的整行。

### 2.1 页头与工具栏

```text
能力库
管理可复用的技能与 MCP 服务，按需装配给员工。

[ 搜索名称或功能…                 ] [ 全部类型 ▾ ]   共 N 项   [刷新] [添加 ▾]
```

1. 标题区只保留标题与说明。搜索承担主要宽度，类型选择固定适中宽度，数量为次要文字，右端为刷新与添加。
2. 搜索和筛选继续使用服务端查询、分页及总数。无筛选显示“共 N 项能力”；有条件显示“找到 N 项能力”。当前接口仅返回查询后的总数，不虚构未筛选总数。
3. “刷新能力列表”只重读平台列表；不连接远端、不发现目录、不改变员工授权。图标按钮必须有 Tooltip 和可访问名称。
4. 窄屏搜索占满一行，筛选与右侧操作在下一行换行；不缩窄输入到不可用，也不横向溢出。
5. 无创建权限时不展示添加项。没有任何可用项时不保留空菜单。

添加菜单建议如下，按能力类型命名，避免把所有对象统称为 Skill：

| 菜单项            | 当前支持 | 目的地或行为                                                     |
| ----------------- | -------- | ---------------------------------------------------------------- |
| 添加 MCP 服务     | 是       | MCP 创建页；页内标题为“接入 MCP”                                 |
| 创建 Skill        | 是       | 当前 Skill 编辑页                                                |
| 导入 Skill 技能包 | 否       | 完成标准包解析、文件管理和校验后再显示；当前不提供可点击的假入口 |

“创建 Skill”和“导入 Skill 技能包”应同时保留：前者支持平台内编写，后者接收已有多文件包。上传文件只是导入的一步，故菜单用“导入”比“上传”更准确。

“管理内置工具”放在工具栏附近的次要文字入口，独立于添加菜单：它管理现有平台能力，不表示新增一种外部服务。首次改版保持当前联合列表的数据范围；把内置能力也纳入卡片、筛选与统计属于后续接口投影增量。

### 2.2 卡片

```text
Tavily
搜索公开网页并提取页面正文，供员工查询和整理资料。

[类型图标] MCP · 已启用                         查看配置 →
```

- 移除顶部类型/状态行，以名称作为第一个信息层级。摘要最多两行，保留两行等高区域，使底栏对齐。
- 底栏左侧显示统一的类型图标、文字和状态；MCP 可用 `Plug`，Skill 可用 `BookOpen`。类型不能仅靠图形或颜色区分。
- 底栏右侧使用紧凑的次级链接式操作“查看配置”；保留足够点击区域及焦点样式，不做占整行的大按钮。
- 能力卡片展示的是共享定义。不要在这里用一个统一的绿色“可用”状态代替每个账号、员工和使用者的实际就绪状态。
- 沿用现有表面、边界、圆角、文字及间距令牌；减少纵向分组，不通过缩小正文字号压缩卡片。
- 桌面保留两到三列，窄屏一列；名称、长英文和无说明状态均需验证。

## 3. MCP 创建与配置导入

### 3.1 页面结构

```text
能力库 › 接入 MCP                         ← 共享顶栏面包屑

接入 MCP                                      [取消] [保存服务]
登记服务后，配置账号并确认工具目录，再装配给员工。

[手动填写] [导入配置]
当前输入方式的内容
```

面包屑当前项为“接入 MCP”，父级“能力库”可点击。正文不再重复放“返回能力库”。取消与保存放在 `PageHeading.actions`，与员工编辑保持一致；窄屏由现有页头规则换到标题下方。按钮通过表单关联提交，不复制一套保存逻辑。

“保存服务”与后续“保存账号”“确认目录”保持各自清晰的提交边界。页头保存不暗示已经完成联网验证或全员装配。

### 3.2 两种输入方式，一份结果

JSON 中的 `url` 与表单里的 MCP 地址是同一份数据。MCP 协议不要求重复填写；`mcpServers` 是常见客户端配置组织方式，不是账号安装表单的统一协议。

1. 手动填写：名称、功能说明、服务地址；支持范围在地址下用简短说明呈现。
2. 导入配置：粘贴 JSON 或选择 JSON 文件，二者共用同一原始输入；检查后列出候选服务，明确选择一项。
3. 选择后进入同一接入表单，带入地址和名称等可编辑字段；原始 JSON 编辑区收起，不继续出现两个都可修改的地址来源。
4. 若导入包含 Token，只在当前表单内存保留。保存账号后清空，不进入 URL、浏览器持久化、预览响应、日志或模型上下文。
5. 切换输入方式遇到未采用的修改时明确提示保留或丢弃；普通空表单切换不弹确认。JSON 有错或不支持时保留输入，给出具体字段与支持范围，不创建半份服务。

服务定义不保存账号秘密。导入账号信息可以带入后续账号步骤，但不因导入顺便建立共用连接。保存服务后离开，服务保留为已登记状态，之后可继续配置账号。

### 3.3 完整接入与装配流程

1. 能力库 → 添加 MCP 服务 → 手动填写或导入 → 保存服务。
2. 服务详情 → 添加账号 → 选择个人或明确共用 → 配置认证及 Token → 保存账号。
3. 该账号下检查连接与目录更新 → 编辑展示别名 → 确认目录。仍按原始工具名调用，别名展示为“中文名（原始工具名）”。
4. 员工编辑 → 能力装配 → 添加能力 → 选择 MCP 和已确认账号 → 选择允许的操作与账号模式 → 保存员工配置。
5. 对话中使用：共用模式走明确共用账号；个人模式解析实际使用者的本人绑定。缺少绑定时只拦住相关工具调用，不借用创建者个人 Token。

目录发现、别名与更新确认只在能力库的账号详情维护。员工页的刷新读取已保存目录，远端新增操作不会自动进入员工许可。

### 3.4 MCP 详情页也使用明确的编辑与保存

创建与编辑共用页头组合：面包屑提供上级导航，正文取消重复返回；标题右侧放取消与保存。详情中存在服务信息、不同账号及工具目录，不把它们伪装成一个可以全部回滚的表单。

- 每次编辑有明确范围，例如“服务信息”或“工作账号的目录展示设置”。页头保存处理当前范围的草稿，取消丢弃该草稿；切换编辑范围时处理未保存修改。
- 保存服务、建立账号、更换 Token、读取候选、确认目录仍保留各自提交语义；联网检查与目录确认是明确动作。取消本地表单不能撤销已经保存的 Token 或已经确认的目录。
- 将当前目录底部的“保存展示名称与说明”收敛到该编辑区域的右侧操作区；如果目标是整个详情页一次保存多个账号，须新增聚合事务，不能只用多个请求加一个通用“保存成功”掩盖部分失败。

### 3.5 工具名称与补充说明的紧凑编辑

当前每个工具都展开原文、单行名称输入和等宽多行说明，形成大量空白。建议默认使用目录摘要行，点击“编辑展示”才展开当前工具。

```text
网页搜索（tavily_search）                   已确认    [编辑展示]
搜索公开网页并返回摘要与来源链接。                    [查看原文]

展开编辑：
展示名称（可选）
[网页搜索                         ]
补充说明（可选）
[给管理者看的说明，最多显示三行编辑区域                         ]
原始参数定义 ▸
```

名称和说明纵向排列，名称输入限制适宜阅读宽度，说明使用全宽短文本区域；不再让单行 Input 和多行 Textarea 占两个等宽列。原始长英文描述默认折叠，不与用户编辑的说明争夺层级。候选目录仍明确显示新增、移除和定义变化。

目前别名和补充说明只供人查看，模型实际收到的仍是上游描述。页面文案需表达清楚；若后续要增加“给模型的使用指引”，应作为独立扩展设计，不能静默改变已有展示说明的含义。更完整的标准包与执行可靠性分析见[接入增量](skill-package-and-runtime-integration.md)。

## 4. stdio / npx 的接入边界

本节旧容器执行建议已由[最终实施计划](execution-plan.md)取代。`npx`、`bunx` 是启动器，stdio 仍然连接 MCP Server；通信标准不自带安全隔离。

本轮采用部署者显式启用的可信子进程通道：管理员登记程序及结构化参数，使用者只配置账号秘密；官方 SDK 负责双向通信与进程组关闭。目录发现临时启动，实际使用按 Run/账号复用并在结束关闭，不与 OpenSandbox 的脚本容器混用。它拥有宿主服务账号权限，不接受普通用户提交任意可执行命令；需要运行不可信 MCP 时应另行增加隔离后端。

## 5. 内置工具入口

“平台工作区”目前登记的是平台原生能力，包括文件读写、查找以及环境支持时的代码执行。它不是另一份附件存储，也不是一个远程 MCP 服务。

建议入口改为“内置工具”，详情用“文件与代码”解释业务作用；详情分别显示文本工作区和沙箱执行的实际能力。虚拟文本工作区不伪装成能执行脚本，沙箱未就绪也不显示为可运行。

这组能力仍需员工主动装配，仍受读写范围与预算限制。共享的是工具定义；每个使用者的附件、对话与每轮任务的临时环境不会因此共享。上传文件保存与按需送入沙箱的规则继续遵循现行文件契约。

## 6. 员工基本信息与大脑选择

将现有 `AgentModelConnectionField` 从“工作指令”移到“基本信息”，位于头像区域右侧。头像组和大脑组分列，姓名、岗位、简介在下方；窄屏先头像后大脑。大脑影响员工是否可对话，属于基础配置，与系统提示的编辑分开更容易找到。

```text
[员工头像]  头像与更换入口       装配大脑
                                [选择模型连接               ▾]
                                Key 已配置 · N 位员工使用
                                去配置大脑 ↗          [刷新]

员工姓名                         岗位分类
[输入框]                         [选择框]
员工简介
[输入框]
```

- 模型选择继续用带边框的 Select；不把模型详情全部搬到员工页。
- “去配置大脑”是真实导航链接，常态带下划线，打开新标签页，保留当前员工草稿；外链图形与可访问说明表达“新标签页”。
- “刷新大脑列表”用低权重图标按钮与 Tooltip；加载、失败、空列表和当前大脑停用均有明确反馈，不清空原来的选择。
- “选择头像”“取消”等次级操作使用描边按钮；“保存配置”保留主要按钮。不要把所有动作一律做成同样重量的方框。
- 搬动组件不改变字段、权限与员工原子保存；尚未选择大脑仍可保存草稿，不能对话的提示沿用当前规则。

## 7. 员工能力装配

### 7.1 默认只看已装配摘要

```text
能力装配                        已装配 N 项能力              [添加能力]
[搜索已装配能力…] [全部类型 ▾]

Tavily       MCP    共用账号 · 已选 2 项操作       [启用] [配置] [移除]
代码审查     Skill  已配置参数                    [启用] [配置] [移除]
文件与代码   内置   允许文件读写                  [启用] [配置] [移除]
```

1. 首屏呈现已装配项，不平铺能力库中的全部工具。未装配的能力放在“添加能力”选择面板中，支持搜索与类型筛选。
2. MCP 展示一条账号装配摘要，内部操作折叠到配置面板。相同服务的多个账号可按服务分组，但必须保留独立账号子项及许可，不能合并身份。
3. 统计按能力与操作分开：一份 MCP 有十个工具，仍是一项能力装配、十项操作；多个账号装配需显式展示账号数量。现有 Tab 只统计 Skill，需修正为覆盖实际装配对象的摘要。
4. 空态直接提供“添加能力”；加载或失败不把已有装配误报为删除。已有工具被移除或定义变化时保留问题项，明确要求重新确认或移除。

### 7.2 配置面板

桌面打开右侧配置面板，窄屏使用占满可用宽度的 Dialog。复用现有 `Dialog` 的焦点与键盘行为，不增加一套独立弹层框架。只打开一个面板，避免抽屉内再嵌套抽屉。

| 对象     | 显示内容                                                                    | 不在这里进行                                             |
| -------- | --------------------------------------------------------------------------- | -------------------------------------------------------- |
| MCP      | 服务、模板账号、个人/共用模式、已确认操作搜索与开关、预算；高级范围默认收起 | 发现远端目录、编辑原始工具名、放大共用范围或输入新 Token |
| Skill    | 说明、当前声明的参数规范及参数输入；无参数规范时不伪造专用字段              | 从正文猜出“报告语言”“审查重点”等表单，自动获得执行权限   |
| 内置工具 | 已实现的文件/执行操作、读写范围、预算及环境状态                             | 让上传者自行选择绕过沙箱或扩大宿主访问                   |

账号缺失或目录未确认时，可在新标签页进入同一能力库详情准备账号，返回后刷新平台目录。不是在每个员工里重新做一套账号管理页。

面板“完成”只更新员工草稿，页面“保存配置”才将员工、Skill、工具一起持久化。面板“取消”丢弃本次面板修改；关闭有修改的面板需明确处理。页面统一显示“有未保存修改”，避免用户把局部完成误认为已保存。

其他使用者的“我的工具连接”只绑定本人账号，不获得员工编辑权限；这条个人绑定流程与作者的能力装配面板保持职责分离。

## 8. 设计系统补充与组件复用

实施时将下列生效模式写入[组件规范](../../../frontend/src/design-system/components.md)并增加同源展示样板；当前先作为拟议规范，不把尚未实现的侧栏样式写成已有能力。

| 模式         | 视觉与行为要求                                                 | 复用入口                                                                  |
| ------------ | -------------------------------------------------------------- | ------------------------------------------------------------------------- |
| 能力库工具栏 | 输入、筛选、数量与操作对齐；窄屏分行；刷新有名称与反馈         | `Input`、`Select`、`Button`、`Tooltip`                                    |
| 添加菜单     | 一个主要触发器；图标加文字；键盘移动、Esc 关闭、关闭后焦点返回 | `DropdownMenu`                                                            |
| 紧凑能力卡片 | 名称、两行摘要、底栏；类型图标加文字；只读启停状态与配置链接   | 当前表面/文字/间距/圆角令牌                                               |
| 页面标题操作 | 标题左、取消与保存右；窄屏按共享页头规则换行                   | `PageHeading`、`PageBreadcrumb`                                           |
| 轻量导航链接 | 真实 anchor，常态下划线，可见焦点；新标签有说明                | 当前链接或 `Button` 的 link 变体；变体默认仅 hover 下划线时补齐本场景样式 |
| 配置面板     | 标题、主体滚动、底部取消与完成；焦点约束；窄屏满宽             | `Dialog` 的共享适配                                                       |
| 装配摘要行   | 名称、类型、账号与操作数、状态、操作；问题不靠颜色单独传达     | 业务装配组件；有复用需要再抽公共模式                                      |

按钮使用现有 `control.small/default/large` 及主题令牌。主操作用实心，次级动作描边，导航用链接，紧凑工具动作使用 ghost 图标。所有图标均有文字或可访问名称；日夜主题不依赖单独的硬编码颜色。

## 10. 验收与失败处理

1. 真实平台页面和设计样板共用组件；覆盖日夜主题、桌面及 320/390px 窄屏、长名称、空摘要、筛选空态、接口失败与重试。
2. 导入与手填最终只有一个有效 URL；多服务 JSON 选择明确；错误不创建资源；Token 不进入持久化草稿，保存与离开后按规则清除。
3. 新增服务与确认目录后，现有员工许可不变。装配只选已确认目录，新增工具默认未授权；别名不覆盖原始名。
4. 多个服务、多账号和几十项操作时，主页面仍只展示装配摘要；账号身份、目录摘要和权限没有在分组中合并。
5. 面板完成、取消、Esc/关闭与页面保存有一致草稿语义；保存失败保留草稿，主事务失败不产生半份装配。
6. 大脑管理新标签跳转保留员工输入；回来刷新不会替换当前选择。停用、缺 Key、未加载与网络失败的提示准确。
7. Tab、菜单、面板与图标操作可用键盘完成，焦点可见并能返回触发器；链接与操作按钮使用正确语义。
8. 前端改动运行对应静态检查、定向交互测试和生产构建；实际视觉结果进入 records。stdio 和包导入另有隔离执行、并发、资源清理、迁移及拒绝路径验收，不能以 UI 测试代替。
