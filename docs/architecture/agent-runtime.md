# Agent 与运行管理的协作

员工是配置；运行中的 Agent 是使用这份配置创建的 SDK 程序。平台的执行管理负责工作能否继续、如何取消和记账，SDK 负责模型与工具往返。两者位于 execution 子系统内部，代码边界通过普通协议与回调建立。

| 组件                                      | 决定什么                                       | 产物                                       |
| ----------------------------------------- | ---------------------------------------------- | ------------------------------------------ |
| conversations                             | 谁与谁交流，如何保存和展示正式回复             | Message、对话占用和成果接纳                |
| execution 的 Service、Worker、Task、Store | 一次工作是否被接受、能否执行、如何收尾         | Run、动作、持久预算和可靠成果              |
| execution/snapshot、prompts               | 本轮采用什么冻结配置和平台指令                 | 普通配置快照和平台指令                     |
| execution/runtime                         | 后台怎样推进、绑定资源并驱动模型与工具形成输出 | 单次执行状态、SDK 状态、进展和 AgentOutput |

业务消息、模型上下文与 checkpoint 分别管理。业务历史服务于应用；稳定 Thread 承载连续交流，多次 Run 各自记账；checkpoint 是线程某一步的状态与执行位置。下一轮从成功接纳的明确基点开始，原 Run 恢复则读取属于原 Run 的最新点。

模型和工具开始前必须通过 AgentContext 申请动作，平台在同一事务核对许可和预占预算。SDK 工具消息只在 runtime 解释，知识、MCP 和文件的实际权限留在所属平台服务。streaming 将 SDK 片段转成普通内容，workspace 将获准文件组织成受控视图，二者都不直接驱动前端。

循环使用官方 create_agent、SQLite Saver 与摘要中间件。摘要会产生受管模型调用；实际 token 取标准返回字段，未知用量不补零。完成时读回存档，要求本 Run 的完成标记、没有待执行节点和合法输出，然后才交给运行管理保存成果。对话接纳在之后独立进行。

详细目录、具体协作方法、恢复资格与限制分别见[执行子系统](../../backend/app/execution/README.md)、[运行契约](../reference/runtime.md)和[部署操作](../guides/backend-operations.md)。
