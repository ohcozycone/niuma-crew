# 工程评审后的可靠性与验证增量

设计状态：已采纳。实施状态：已完成；[实际验收](../records/engineering-review-reliability.md)。更新：2026-11-02。

## 目标与范围

依据当前源码及离线故障复现，恢复可运行的工程验证基线，保证应用收尾不因单个资源关闭失败而跳过其他资源，并补齐执行准备的类型和模块边界。现行入口为[后端手册](../engineering/backend.md)、[HTTP 错误契约](../../backend/app/api/README.md#应用错误分类与-http-转换)及[共享表面](../../frontend/src/design-system/surfaces.md)。

本轮保留同库事务、发布与存储的委托、会话唯一 Controller 和已有公开投影；不按文件行数或名称数量删除实验入口、拆分模块或合并权限投影。

## 实施顺序与契约增量

1. 现有工程先建立 Git 基线；修复失效历史证据链接，保留证据缺失说明。HTTP 故障测试改为验证安全 500、回滚和关联 ID；服务层未知故障仍原样传播。Tab 守卫允许外部布局，继续拒绝内部视觉覆盖。
2. 应用生命周期按依赖顺序注册清理；创建或启动中途失败、任一关闭异常时，仍尝试其余已创建资源的清理。知识 worker 的锁也必须在任务异常后释放。
3. 执行准备明确必需依赖及输入输出类型，纳入 mypy；快照构造受类型检查，保留存储快照的运行时校验。已登记业务错误的子类沿最近 MRO 分类映射，未知 ServiceError 保持服务器错误。
4. 扩展现有表驱动边界守卫，覆盖模型适配和 API 到装配层的限制；同步当前架构、共享入口与历史调查的适用范围。
5. 按真实复用与规则所有权复核跨模块查询、实验代码及命名。仅在能说明具体收益时实施拆分；本轮不强制统一成引用检查回调。

## 验收与交付

定向测试覆盖故障响应与回滚、启动部分失败、多个关闭异常、worker 失败释放锁、错误子类映射、边界守卫及 Tab 布局/视觉区分；最后执行 make check。测试使用临时数据库和假上游，真实模型、远程 MCP、沙箱及容量不在本轮验收范围。实际结果进入 records，生效规则回写现行正文。
