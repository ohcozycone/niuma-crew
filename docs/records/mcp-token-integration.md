## Tavily 实际接入排障（2026-10-28）

用户报告已保存 Tavily 配置但无法使用和装配。只读检查确认账号已启用且有加密凭证，候选与已确认工具均为空。通过正式页面复现读取失败；本机 DNS 将 `mcp.tavily.com` 解析到私网地址，默认网络策略在发送凭证前拒绝。SDK 包装传输异常后，页面原先只能显示笼统的连接失败。服务地址末尾的 `/` 符合官方示例，不是已确认故障原因。

先对同一域名进行无凭证 TLS/HTTP 验证，确认受控路径可达且返回 401；再使用已有密文凭证做 MCP 握手和只读目录发现，成功返回 `tavily_search`、`tavily_extract`、`tavily_crawl`、`tavily_map`、`tavily_research`，没有执行搜索或提交用户资料。仅本机开发环境的 `.env` 显式允许此域名的私网映射，项目默认值不变；无活动 Run 时触发开发后端重载。

修复让平台生成的网络拒绝和 DNS 错误穿过 SDK 包装后保留可公开说明，不回显上游诊断或凭证。员工装配增加“刷新连接列表”，管理目录在新标签页打开；刷新不覆盖员工草稿，加载中/失败不误报原有装配已删除。

实际验证：

- 正式 3000/8000 平台使用已有 Tavily 账号完成真实协议发现和目录确认，员工创建页显示全部 5 个可选工具。没有替用户勾选操作、创建员工或保存未完成的员工草稿。
- 后端账号与基础工具定向测试 27 项通过，包含 SDK 屏蔽传输异常、DNS 失败、凭证未发送，以及精确私网配置下仍拒绝云元数据地址。
- 前端装配/工具页 6 项通过，覆盖目录刷新后保留草稿、读取中/失败不显示错误移除入口。ESLint、TypeScript、Prettier、后端 Ruff/mypy、文档检查和 Vite 生产编译通过。

本次未执行真实 Tavily 业务搜索、员工模型完整对话或腾讯云部署验收。目录成功证明该账号当前可连接并列出工具，不证明全部操作的额度和权限。OAuth、stdio 和独立沙箱池仍不在实施范围。

## Tavily 模型调用与旧会话验证（2026-10-28）

后续用户截图显示：员工装配后，普通对话仍回答没有联网工具。核对该 Run 确认快照包含 5 个 Tavily 工具，账号无需补配；实际只有一次模型调用、零工具调用。同一旧会话还包含装配前“没有搜索引擎”的历史答复。未修改员工配置前，用相同网页问题开启独立验收对话，真实模型成功执行一次 `tavily_extract` 后回答，说明运行通道可用；历史影响是与该现象相符的原因判断，不将其表述为已观察到的模型内部机制。

运行提示补充由当前快照生成的操作名/调用名清单，要求按当前工具定义判断能力，在外部任务中使用匹配工具，不沿用历史“无工具”说法。保持函数定义、账号和逐动作宿主授权不变，不扫描回复关键词强制重试，也不删除历史。

验证结果：

- 在原会话再次发送同一公共网页读取请求，完成“模型第 1 轮 → `tavily_extract` 成功 → 模型第 2 轮”，总计 3 项动作，网页内容已返回并生成总结。独立新会话也完成相同链路。未运行搜索、爬站或研究工具。
- 新增回归通过真实 ChatOpenAI HTTP 序列化与流式响应，保留旧“没有联网”历史，确认请求含当前函数名、参数 schema、工具状态指引，再完成工具和下一轮模型调用；上游仅为测试替身，不使用真实 Token。
- 基础工具、能力循环、MCP 账号和 Runtime 边界共 54 项测试通过；Ruff 格式/规则与 mypy 通过。仅改后端运行提示与测试，没有前端或表结构变更。

两次真实网页提取验证了当前账号与该目标页面，不证明所有 Tavily 操作、额度或其他用户账号均可用；腾讯云部署仍未验证。

## 提取后错误进入 Skill 读取的修复（2026-10-28）

用户截图显示 `tavily_extract` 已完成，第二轮模型后却以 `skill_not_allowed` 失败。读取该失败 Run 的存档确认：本轮有 5 个 MCP 工具、没有 Skill 和原生文件许可；提取成功后，第二轮模型请求 `read_file` 读取本轮保存的 `/sources/.../page-1.txt`。平台当时无条件附带 Skill 文件读取工具，又在工具结果中提供了来源文件路径；没有普通文件绑定时统一误报技能错误。

修复让 SDK 文件工具与本轮实际可执行能力保持一致，空工具集合不再回退到 `read_file`。普通来源读取拒绝与未获准 Skill 读取分开分类。MCP 结果只有在已授权 `read_file` 覆盖 `/sources` 时才向模型提供文件读取路径；无该权限时保留有界预览和来源元数据，用户下载资料不受影响。没有给已有员工新增文件权限，没有修改 Skill/MCP 目录或 Token。

验证：基础工具、能力循环、账号和 Runtime 边界以及新增来源读取测试共 58 项通过；包含 MCP-only 不暴露 reader、Skill reader 不能读取来源、显式 `/sources` 原生许可可成功分段读取且不产生 Skill 激活，以及普通文件/Skill 失败分类。Ruff 和 mypy 通过。真实本机验收对话完成网页末段提取：两轮模型、一次 `tavily_extract`，正常返回，无 Skill 错误。该真实验证使用公共文档页面，不证明所有网页或模型输出均可正确处理。

另补查普通对话 29 项与持久化/重启恢复 17 项，均通过。恢复测试首次因执行沙盒不允许绑定本机端口而未能启动；在允许临时回环监听、仍使用隔离数据库和假模型的环境中重跑通过，没有改动正在运行的开发服务。
