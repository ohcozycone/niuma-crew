# 能力评估

评估需要回答具体问题：共享员工能否完成指定工作，改动是否改善结果，为此增加或减少了多少成本。模型答题、检索命中和完整任务的合格率不能混为一个分数。

## 当前专项考核

当前考核使用 BFCL Python 单调用题库，固定题目、答案和评分依据，逐题通过正式执行入口取得答卷再评分。它保留岗位指令、全员规范和模型，但关闭真实工具、技能和员工知识装配。

因此，当前报告反映这一专项配置的表现，不能直接证明员工完成实际岗位工作的能力，也不能当作官方榜单成绩。原始答卷、执行错误与评分失败分别保留，规则见[考核说明](../reference/employee-evaluations.md)。

## 知识检索评估

已有独立实验可以比较候选与实际上下文中的引用区间覆盖，并保留逐题结果。输入与限制见[知识实现](../../backend/app/knowledge/README.md)和[公开资料集](../../backend/datasets/public-knowledge/README.md)。

后续按阶段补齐指标和数据，不能仅凭回答流畅判断检索有效：

| 阶段       | 评估问题                     | 拟补充的依据                         |
| ---------- | ---------------------------- | ------------------------------------ |
| 召回       | 应有证据是否进入候选         | 标准片段、召回率与不同查询类型       |
| 排序与筛选 | 有用证据是否靠前并进入上下文 | 排名指标、噪声、重复与上下文预算     |
| 回答       | 结论是否得到证据支持         | 正确性、引用支持程度、无答案时的表现 |
| 整体任务   | 结果能否满足交办要求         | 成果标准、人工修正和失败原因         |

完整指标、标注工具和自动回归仍在建设。标准答案与证据需要独立审核，开发调参数据和最终测试数据分开使用。

## 最小装配实验（建设中）

对同一岗位和任务，比较最小能力、增加无关工具、全部注入与按需加载等组合。固定模型、任务集和资料版本，记录重复运行结果，避免把一次成功当作稳定收益。

同时观察任务合格率、工具误用、模型及工具调用次数、实际用量、耗时和人工修正。首轮注入减少只是中间指标；发现与补读增加的成本也应计入。模型回答的事实错误与工具选择错误分别归因。

## 岗位评估与改进回归（建设中）

从真实工作中整理代表性案例，明确输入条件、成果要求和允许操作。比较员工版本、技能、模型或检索策略的变化，保留失败样例，改动后重跑相关任务。

评估结果用于决定保留、调整还是删除能力。人工评分、规则评分和模型辅助评分需要说明各自覆盖范围；没有依据的综合分数不用于证明岗位合格。
