## 1. 决策与交付目标

2026-11-08：文件与代码已改为 Agent 底层能力，不再做系统插件装配，详见[实施记录](../records/Agent基础文件与沙箱.md)。本文其余方法包、搜索适配、预算和评测继续作为待评审增量。

平台维护少量官方基础能力，对默认工具、方法、结果表达与真实任务质量负责。底层优先复用现有 MCP、标准 Skill 和执行环境；外部业务系统继续插件化。官方维护与插件实现可以同时成立。

首版交付后应能完成三类可验收工作：

1. 用户提出公开资料查证问题，员工能搜索、读取证据并引用回答；资料不足或服务失败时准确说明。
2. 用户上传受支持的文本、CSV 或 JSON，员工能读取、整理并交付真正可下载的文件。
3. 目标环境已验收时，员工能在沙箱计算、处理数据并交付可核对结果；没有验收时明确不提供执行能力。

保留当前模块化单体和 LangChain/Deep Agents 循环。不引入第二个 Agent 循环、默认监督 Agent、通用工作流引擎、新插件执行协议或统一能力数据库。首版不建设完整浏览器、长期记忆、定时任务、OAuth 或第二家搜索供应商。

“完整方案”指上述首版从配置到验收、升级和回退都有明确路径，不表示一次实现所有数字员工功能。

## 3. 能力包是维护与装配单位

### 3.1 首版能力清单

| 官方配方                          | 工具与资源                                           | 方法与交付要求                                       | 首版状态目标             |
| --------------------------------- | ---------------------------------------------------- | ---------------------------------------------------- | ------------------------ |
| `information-research@1` 信息获取 | Tavily 搜索、提取；结果续读及来源保存                | 找到合适来源、读相关证据、处理冲突、支持结论的引用   | 必须完成                 |
| `file-work@1` 文件与成果          | 现有文件工具；输入、来源、工作区、输出目录的明确范围 | 先检查格式与内容，按任务整理；交付文件已保存且可下载 | 文本、CSV、JSON 必须完成 |
| `data-compute@1` 计算执行         | 同一原生沙箱连接上的文件工具与 execute               | 核对输入、执行、检查退出码与数值、保存成果           | 有真实目标环境验收才开放 |

首版信息配方只推荐搜索和读取，不默认加入 crawl、map、research。管理员仍可为具体员工配置这些高级工具。文件配方使用虚拟或沙箱工作区，计算配方要求沙箱；两者合并时复用一份原生连接，不能违反“一员工最多启用一份原生工作区连接”。

### 3.2 不增加另一套权限和包管理状态

配方以受信仓库清单发布，包含稳定键、版本、说明、官方 Skill 内容摘要、所需工具角色、允许的适配配置和推荐范围。它不包含账号、Token、任意 Python 导入路径或可以执行的流程 DSL。

“应用配方”只产生员工草稿中的 Skill 关系与工具许可，最终仍由员工主保存提交。首版不新增 `Capability`、`AgentPackageAssignment` 等业务实体：

1. 运行权限只来自现有 AgentSkill、AgentToolGrant 与个人绑定。
2. 页面根据实际已装配方法摘要、工具适配配置和范围，派生“匹配官方组合 / 自定义组合 / 待补齐”。配方卡片不是另一份必须同步的授权事实。
3. 用户删改其中一个组件后，显示实际状态，不自动补回、不自动删除其他组件；多个配方共用的 Skill 或原生连接去重。
4. 官方标识依据受信清单与完整内容摘要比对，不能由上传包自行声明 `official: true` 获得。
5. 历史官方版本保留清单。Run 固定实际 Skill 和适配配置摘要；配方名称只用于解释、诊断和评测。

官方 Skill 继续采用 SKILL.md 与支持文件，通过既有 Skill 发布流程进入共享库。首次发布或更新由管理员主动执行；不在启动时扫描用户目录、安装依赖或覆盖同名内容。同名不同内容报冲突，提供保留自定义或另行处理的选择。

## 4. 模块所有权与调用路径

| 位置               | 新增职责                                               | 保持的边界                         |
| ------------------ | ------------------------------------------------------ | ---------------------------------- |
| agents             | 官方配方定义、装配预览与校验、适配配置随许可保存及捕获 | 不保存秘密、不执行外部请求         |
| skills             | 随产品发布的方法、支持文件、主动发布与内容摘要识别     | Skill 不授予工具权限               |
| tools              | 官方工具适配配置、参数转换、供应商结果/错误归一、脱敏  | 不选择业务结论、不发布对话         |
| capability_catalog | 官方配方及就绪原因的只读查询投影                       | 不增加写入、远端目录读取或执行入口 |
| conversations      | 接受时组合并冻结身份、版本与资源；发布正文和成果       | 不解释 Tavily 字段                 |
| execution          | 持久预算、软收束依据、拒绝新动作、取消及硬截止         | 不识别搜索供应商或用户题目         |
| agent_runtime      | SDK 工具视图、方法加载、统一结果保存/呈现、收束请求    | 不绕过宿主记账或直接访问业务数据库 |
| files / sandboxes  | 既有文件和临时执行资源；按环境验收开放计算             | 不增加宿主 Shell 回退              |

一次信息调用的顺序：

1. 接受请求时捕获员工许可、实际账号、原始目录摘要、适配配置版本和 Skill 依据。
2. 运行层只向模型展示选定的官方搜索/读取接口，保留底层绑定与调用名映射。
3. 受信适配配置把模型参数转换为原始工具参数，并应用服务端强制范围；宿主对最终实际参数检查许可、范围和预算并登记一次动作。传输层使用同一份参数，不能在获准后换成另一个请求。
4. tools 再核对当前账号与原始定义，调用现有 MCP 客户端；供应商结果经脱敏和统一解释后返回。
5. 运行层通过注入资源接口保存原始响应与逐页文本，只把有界的有效内容和续读引用送给模型。
6. 模型继续或回答；发布仍核对授权并原子提交正文、文件关联和终态。

每次真实上游调用只有一个动作与预算入口。适配配置不在内部偷偷串行调用多次搜索或提取；重试、备用路径也不得隐藏在一个“成功工具”下面。

## 5. 信息获取的具体契约

### 5.1 显式选择官方工具适配配置

在 AgentToolGrant 增加可空的 `tool_profile_id`，首个受信值为 `web-info.tavily.v1`。它表示如何呈现和适配这份已批准许可，不是额外权限。原有许可缺省为 null，行为保持兼容，不根据名称猜测后静默启用新逻辑。

兼容不包括保留已确认的错误：现有 Tavily 特判涉及的业务错误和来源表达先迁入纯适配函数修复，旧调用名与参数仍保留；未知 MCP 响应不凭正文关键词猜供应商或成功状态。启用新模型接口则必须显式选择 profile。

首个配置限定一个经审核的 Tavily 服务连接，同时选中原始 search、extract 操作；实际 inputSchema 必须通过适配兼容检查。不兼容时显示待处理原因，不放宽原始摘要校验，也不自动换账号。个人账号仍需同服务、同定义的相容绑定。

模型侧首版接口：

| 接口               | 参数                                     | 实际行为                                                                      |
| ------------------ | ---------------------------------------- | ----------------------------------------------------------------------------- |
| `web_search`       | query；count 缺省 5、最大 5              | 映射一次 tavily_search；遵守已有域名范围，关闭可选自动答案/全文，返回发现结果 |
| `web_read`         | urls，最多 3 个                          | 映射一次 tavily_extract；首版不传 query 过滤参数，读取后再定位证据            |
| `read_tool_result` | result_id；可选 source_id；offset、limit | 仅续读本 Run 已保存结果或其中某页正文，不再请求上游                           |

保留原始 `tool_name`、inputSchema 和 descriptor_hash 作为批准与授权依据；另存模型视图及转换依据，不覆盖原始目录。转换前校验模型参数，转换后复用宿主对原始 schema、scope 的校验。调用审计同时保留模型接口与原始操作的非秘密标识。

同一 Run 首版只选择一条官方搜索/读取路由，配方预览发现冲突时要求选择。已由官方接口覆盖的原始 search/extract 不再重复暴露；其他自定义工具按原许可保留。工具视图裁剪不删除员工许可，也不扩大账号范围。

### 5.2 统一结果的最小含义

沿用 ToolOutcome，在普通数据中增加版本化的 normalized 结果。只规定信息工具需要的字段，不为全部外部工具强制新协议。

| 字段               | 含义                                                                |
| ------------------ | ------------------------------------------------------------------- |
| kind               | search 或 page_read                                                 |
| result_state       | ok、empty、partial、error                                           |
| items / pages      | 搜索条目或逐页结果；每页分别有状态、URL、标题和文本依据             |
| source_id          | 此结果内稳定的页面标识；不是任意宿主路径或任意文件 ID               |
| text_scope         | snippet、passages、page_text、unknown；表达供应商实际返回的文本范围 |
| provider_truncated | true、false 或 unknown；不凭字段缺失宣称全文完整                    |
| error              | 已确认错误代码、可公开说明、可否重试及已知 retry_after              |
| provenance         | 请求 URL、已知最终 URL、取得时间、原始响应引用和工具版本依据        |

`page_text` 表示取得该页的文本投影，不保证网页全部交互内容、附件或子页面。平台预览是否截断另由 preview_end、next_offset 表达；工具结果读完不等于原网页完整。

ToolOutcome.status 与 RunAction.status 保留现有状态集合：无可用数据的业务错误记 failed；部分页面成功时动作可 succeeded，但 safe_details.result_state 必须为 partial，页面展示实际部分失败。empty 是成功执行的空发现，不能当作匹配证据。业务错误代码由 ToolOutcome 传递到动作，不再全部压成 tool_upstream_failed。

### 5.3 保存、预览与续读

1. 保存经脱敏的原始响应，保存逐页文本与来源元数据；复用 files 的来源生命周期和配额。
2. 搜索结果先展示标题、URL 与有界摘要；逐页读取先展示每页状态和正文片段。避免把长 JSON 元数据放在正文证据之前，避免同一内容在 content 与 structured 中重复进入上下文。
3. 复用现有模型输出字节上限；各页公平分配预览预算，不让第一页占满。精确保存展示区间及被省略区间。
4. `read_tool_result` 增加可选 source_id。未提供时继续兼容原始结果分页；提供时读取此结果已保存的指定页文本，以实际返回的 next_offset 续读。
5. source_id 必须属于当前 result_id、当前 Run 和原始工具绑定。即使没有 `/sources` 文件许可也可以沿原结果许可续读，但不披露不可读文件路径；撤权后不能继续读取。
6. 不要求模型读完整份 JSON 才认定取得网页证据。网页核验改为识别成功取得且已展示/读取的文本区间；关键证据是否充分由方法和任务评测判断，不假装用通用正则证明答案正确。

### 5.4 错误和降级

| 情况                   | 首版行为                                                   |
| ---------------------- | ---------------------------------------------------------- |
| 已知限流/配额不足      | 业务错误，不显示调用成功；返回已知等待建议                 |
| 认证失败               | 提示管理员维护员工固定工作连接的凭据                       |
| 服务超时或连接失败     | 区分错误类别；模型可以交付已取得的部分证据或说明未完成     |
| 部分 URL 失败          | 返回逐页状态，保留成功页；不能用一个总成功掩盖失败页       |
| 上游只有片段或发生截断 | 明确范围，不补造全文；可以读取其他获准页面                 |
| 结果过大或保存失败     | 不把未可靠保存的数据作为可交付证据；按现有存储故障路径停止 |
| 定义不兼容/工具被撤权  | 停止该调用，维护者核对；不自动退回原始工具绕过适配检查     |

首版默认不自动重试，也不自动换供应商。错误说明给出下一步，方法禁止无变化地反复重试同一失败请求；总次数仍有宿主上限。只有实际验证出可用性缺口后，才在另一个增量中设计有记账的重试或备用供应商。

### 5.5 官方方法

关键语义随工具视图提供简短说明；完整方法作为 `information-research` Skill 按需读取。用户显式选择时沿用已有 pin，不为普通聊天全局预加载，也不引入自然语言任务分类器。

方法覆盖：明确问题及版本时点；技术定义优先核对现行官方说明；区分发现摘要与页面证据；只在冲突、过时或缺证据时继续取证；足够回答即交付；未知项如实限定。软件分类问题可提供 CLI、Skill、原生插件、自定义工具和 MCP 的概念参考，但不能硬编码 OpenSpec 的结论。

不规定每题必须搜索三次、引用三个网站或走完固定六步。简单事实、深度研究和网页操作有不同完成条件。工具安全与保存约束落实在代码，不能只写进 Skill。

## 6. 为最终回答预留预算

### 6.1 硬限内收束，不追加隐藏模型轮

保留宿主持久上限、SDK 上限与总时限，新增 final_response_reserve=1，以及有界的 response_reserve_seconds，首轮灰度候选为 30 秒。预留时间不是保证模型一定在该时间内回答。

RuntimeControl 增加只读预算投影，返回持久计数计算出的剩余模型/工具次数及实际截止时间；它不授予动作、不重置时限。软收束依据由宿主给出，SDK 适配负责组织最后一次请求。无需为此新增 Run 状态或业务表，不能只用进程内计数判断恢复后的剩余预算。

1. `start_model` 原子取得真实轮次。最后一个可用模型动作发出请求前，运行层将工具列表清空并加入短收束说明，只允许根据已有证据回答或说明缺口。
2. 工具预算用尽或到达软截止时，停止发起新工具，转向已有预算内的最终回答。硬截止、撤权和取消优先，不因需要总结而延长执行。
3. 工具已成批请求时，未获准开始的调用返回明确的“本次未执行”结果并满足 SDK 的 tool_call_id 对应关系；不伪造上游失败，不扣除未发生的网络动作。已获准开始的操作仍受各自时限和硬截止控制。
4. 单次上游等待不应跨过软截止；通过注入的剩余时间限制实际调用时限。原始配置时限仍为上限，不能因重试重新获得完整时限。
5. 最终模型动作也必须授权、计数、保存真实用量。若模型仍返回工具调用，不执行、不额外修复，按明确错误收束。
6. 模型或网络最终仍失败时，发布现有失败状态和准确的失败说明；不把最后的思考、计划或半句工具前言当成完成答案。

只把明确的预算收束转换为“未执行”工具结果；取消、撤权、数据库错误和不明外部操作结果继续沿现有停止路径处理，不能被统一 catch 后继续聊天。被软收束拒绝的调用 ID 和原因进入非秘密步骤详情，不登记成已经执行的上游动作。测试捕获模型最终实际收到的工具列表，防止后续 SDK 中间件重新加入工具。

可以为预算/超时失败提供基于已保存状态的固定提示，但不得生成未核验的业务结论。取消及授权失效不发布来源内容或新成果；存储不可用时沿用现有待修复路径，不承诺一定能写入提示。

### 6.2 默认值与完成含义

首版先保持生产默认值，通过评测比较：旧行为 8 轮、新行为 8 轮、新行为候选 16 轮；第一轮总时限统一 180 秒、工具上限统一 32。若 16 轮候选仍主要因硬时限失败，再单独验证 300 秒，避免把两种预算变化混在一起。这些只是待验证参数，不直接把实验的 24 轮/600 秒搬进生产。

SDK 能正常返回、Run succeeded、原任务完整完成是不同指标。诚实说明无法查证可以完成一次答复，但评测仍把未完成的用户目标计为任务未通过；不靠“所有运行都有文字”提高成功率。首版不增加业务 Task 状态机或强制结构化模型自评。

## 7. 文件与计算的交付范围

### 7.1 文件包

复用当前输入选择、四类目录范围和上传下载，不增加宿主文件系统访问。官方 `file-work` 方法包含：确认文件类型、编码/列结构，读取必要内容，明确转换规则，写入输出，重新读取或以程序检查，最后关联可下载成果。

首版验收 UTF-8 文本、CSV、JSON；覆盖中文、引号/换行、空值、坏行、空文件和超限输入。验收夹具对 CSV/JSON 采用确定性解析，不仅检查文件名；运行时没有计算包则通过现有读取工具核对文本，不伪称已经执行程序验证。涉及数值汇总或大文件时要求计算包；虚拟工作区不能执行时如实说明，不让模型假算后交付。

文本模式不适合的大文件继续遵守现有限制。输入原件只读，中间文件进入 workspace，最终文件进入 outputs；成果由 files 保存、conversations 发布。输出未持久保存、哈希不匹配或下载未授权时，不报告已交付。

### 7.2 计算包

复用 OpenSandbox、固定镜像依据、Run 独占环境、现有执行配额与回收。由部署管理员完成目标 Linux 主机当前验收；账号配置、网络可达或 SDK 安装不能替代环境验收。

官方方法与脚本在沙箱执行，支持文件保持只读，文件操作和代码使用同一工作副本。检查退出码、输出存在及结果不变量，例如汇总金额与已知样本一致、过滤后行数正确。非零退出码不能仅凭存在一个输出文件当作成功。

新增文档处理依赖属于沙箱镜像，不安装到后端宿主，不让上传 Skill 自动安装。首版不依赖 Word/Excel 渲染服务；DOCX/XLSX 作为下一版，需另验打开、结构、公式/样式及必要渲染，不把任意扩展名文件当作合格办公成果。

## 8. 最小数据、接口与兼容增量

### 8.1 数据与快照

| 位置                   | 变更                                                                                            |
| ---------------------- | ----------------------------------------------------------------------------------------------- |
| AgentToolGrant         | 新增可空 tool_profile_id；仅接受受信目录中支持的值；变化递增 grant revision，并随员工主事务保存 |
| GrantInput / GrantRead | 增加同名可空字段；已有客户端未提供时按兼容更新规则处理，不能无意清除已保存适配配置              |
| Run 快照               | 新协议 v4，固定适配配置标识/版本/摘要、模型视图与原始绑定、官方方法摘要及收束配置               |
| ToolOutcome            | 添加可选业务 error_code，normalized 放普通 data；不要求全部通用 MCP 改成信息结果格式            |
| 来源/动作 details      | 保存 result_state、文本范围、续读区间和已知错误；保持当前 RunAction/Run 状态集合                |

首版仅上述必要字段迁移，不创建配方关联表。迁移默认 null，数据库拒绝非空但只有空白的 profile；应用和运行准备拒绝不支持的值。既有员工、绑定、目录和历史不自动改变。个人账号可用性继续由当前使用者解析，不能冻结他人的密钥。

旧客户端更新同一连接的 grant 未提供 tool_profile_id 时保留原值；显式 null 才清除；新建时未提供为 null。即使保留原值，工具集合或范围与 profile 不相容也必须拒绝保存，不能让旧客户端绕过校验。前端类型、草稿、AgentStore 与工具读写均需保留该字段往返。

v2/v3 快照继续使用原兼容解释；v4 严格检查新增依据，不能把未知适配配置当原始 MCP 继续执行。保留已发行适配配置的实现或明确中断不支持的运行。配置变化不影响已接受输入，运行时仍核对当前撤权与修订。

### 8.2 拟新增管理接口

以下为本方案接口目标，当前尚不存在：

| 接口                                   | 作用与写入                                                                 |
| -------------------------------------- | -------------------------------------------------------------------------- |
| GET /api/foundation-presets            | 返回官方配方与公开要求；不发远端请求，不返回秘密或其他人的连接             |
| POST /api/foundation-presets/preview   | 管理员预览当前员工或新员工草稿的合并结果、差异和缺口；只读，不授予权限     |
| POST /api/skills/bundled/{key}/publish | 管理员主动发布指定摘要的随包 Skill，复用现有包校验、修订和存储；冲突不覆盖 |

应用配方最终仍走现有员工 POST/PATCH；不增加第二条保存装配的写路径。预览和正式保存共用纯校验逻辑，但正式保存必须重新核对当前所有者、账号、目录及修订，不能信任前端预览结果。

预览已有员工必须有编辑权并携带 expected_revision；新员工按创建权校验。缺依赖或不兼容参数为 422，修订/内容冲突为 409，越权为 403，沿用现有 HTTP 转换规则。

### 8.3 连接归属与更新规则

首版沿用组织员工和固定工作连接，不引入另一套账号所有权。管理员统一维护连接并在员工主保存中明确操作许可；普通使用者通过员工委托，不取得凭据管理权。配方不自行替换账号、不添加工具许可，仍须完成现有配置与授权检查。

同一连接当前一份 grant 包含全部选定工具与范围；新配方与已有配置合并若要扩大 scope、改账号方式或替换工作区连接，必须展示差异并由维护者在正常保存中明确采用，不能静默取并集。

升级官方 Skill 会沿用现有共享 Skill 更新语义：影响未来运行，已接受运行字节不变。更新前列出受影响员工；有自定义内容冲突时保留原内容。工具适配升级使用新 profile ID，不静默改变旧 ID 的含义；采用新版通过员工修订保存。

与旧工具配置不相容的方法升级使用新的标准 Skill 名称/记录，由新配方引用，不能原位更新旧方法后让旧 profile 继续假装匹配。仅兼容的内容修订可更新原共享 Skill；回退共享内容同样列出受影响员工。

## 9. 产品使用流程

### 9.1 部署与员工装配

1. 管理员在现有能力库看到官方基础配方及要求，主动发布随包方法。
2. 通过现有 MCP 流程配置主搜索连接、确认目录；协议检查与真正业务搜索测试分开展示，后者使用明确有界查询并记录真实结果。
3. 员工装配页提供“添加基础能力”入口，先选择信息获取、文件或计算，再选择有权使用的连接，预览实际工具、范围和账号方式。
4. 应用只更新草稿；与岗位指令、大脑、其他方法及工具一起保存。失败保持整份草稿与原修订。
5. 普通成员直接使用员工；固定连接失效时提示管理员维护，不要求寻找搜索插件或编辑提示。

既有员工不自动装配。新员工显示推荐组合，维护者保存时确认实际范围；不是所有员工强制联网或执行代码。

### 9.2 就绪状态

不把所有原因压成一个“可用”：分别展示未配置、工作连接未就绪、待确认目录、定义不兼容、环境未验收、已配置、最近业务测试结果。最近测试记录包含时间，只证明该时点；不承诺下一次服务必然可用。

就绪状态作为读取投影，不在列表查询中连远端、不为每个员工启动容器。运行失败沿用步骤与错误展示；部分页面失败、来源范围和预算收束原因显示真实状态。界面日常文案使用“搜索资料、读取网页、处理文件”等工作语言，profile/schema 只在高级详情出现。

### 11.1 可直接进入开发的首批任务

1. **T01 固定基线**：导出非秘密的源码摘要、模型配置标识、员工方法摘要、工具定义/账号修订和预算，保留基线代码；实际结果写独立临时目录，不改原对话。
2. **T02 建立最小故障集**：从已取得的脱敏上游样本整理正常搜索、429、部分页面失败、长页正文和畸形响应；先写外部输入与预期行为，避免按新适配实现反推 fixture。
3. **T03 建立隔离评测入口**：实现 fixture 模式，使用真实 SDK 循环、假模型/假上游和新测试数据库；另设显式 live 模式及限额。默认不连接外部服务，不生成或改写真实用户会话来绕过准入。
4. **T04 修复结果语义**：提取纯 Tavily 结果函数；业务错误进入动作；原始结果、逐页文本和范围分别保存；现有读取测试及新增 fixture 通过。
5. **T05 实现预算收束**：先覆盖最后一轮、工具预算耗尽、批量部分未执行、软截止和硬截止，再覆盖重启计数、取消、撤权及存储失败；使用真实 SDK 假模型捕获最后实际请求。
6. **T06 运行 A/B 首轮**：先跑冻结资料和故障集，再按明确额度做小批真实样本；保留错误答案和无答案，确认测量链路后补足样本，不直接执行完整付费矩阵。

D0 拟新增统一命令 `make eval-foundations`，缺省只运行 fixture；live 必须显式指定模式、样本/重复次数、max_runs、max_total_tokens 与输出目录。缺必需限额直接拒绝启动。该命令当前不存在，随实验入口和 Makefile 一起实施。

编码后的常规检查复用现有 `make lint-backend`、`make test-backend`、`make lint-frontend`、`make test-frontend` 和 `make check-docs`；按单元先执行受影响的定向测试，涉及迁移/授权/发布时再执行对应完整回归。界面变更还需实际窄屏、键盘与可访问性核验，不能仅靠快照测试。

## 12. 评测与发布门槛

### 12.1 样本与对照

| 集合       | 最小首轮规模             | 目的                                                                     |

| 信息任务   | 20 题，每个候选重复 3 次 | 项目/协议分类、现行官方说明、冲突资料、长页中间/末尾证据、应当承认未知   |

| 计算任务   | 6 题，每个候选重复 3 次  | 汇总、过滤、转换及失败脚本；只在实际验收环境计为计算通过                 |

题目保存输入、允许来源、2–5 个关键判分点、预期交付与允许的不确定性。冻结资料与实时联网分开报告：前者测试证据使用，后者测试真实服务与时效；冻结回放不能代替实时链路。

首个模型使用当前配置的 kimi-for-coding，模型连接先做有界检查；首轮不同时更换模型和供应商。对照 A 为当前行为，B 为结果/方法/收束改造但仍 8 轮，C 为同样改造加 16 轮候选；三组先统一 180 秒。逐项报告变化，避免把扩大预算的收益全部归给适配设计。保留可重复运行的基线实现或隔离代码副本，不能仅用旧报告替代 A；实时测试按题交错执行各组，另保存冻结资料回放。

批量脚本必须有 max_runs、max_total_tokens、单 Run 时限和停止机制；实测花费有明确总额度才启动。首版串行评测，启动新 Run 前检查累计记账，达到阈值停止余下样本并记录未跑范围。供应商事后才报告 token，因此该阈值不是精确的跨请求硬限，最多一个在途 Run 的额外消耗受单 Run 预算约束。未报告用量保留 unknown 并暂停批量任务，不填零后继续；不为了跑满矩阵无界调用付费服务。

### 12.2 初始建议门槛

以下是本方案提出的首版验收目标，尚未有通过结果；D0 后可以有依据地修订并留痕：

1. 权限、取消、保存、业务错误状态与来源分页的确定性用例全部通过；测试集中不允许越权、伪造已调用或失败成果被当成功下载。
2. 信息任务核心正确率至少 90%（60 份答案中至少 54 份），正常可用条件下技术性中断不超过 5%。工具失败与资料不足样本单独评分诚实处理，不将“写出失败说明”算作原题回答正确。
3. 已引用关键结论的证据支持率至少 95%；引用可达、相关和支持结论分别检查。首轮由人工按判分点核验，模型评审只作辅助。
4. 文件与计算集合中的结构、已知数值和成果归属检查全部通过；环境未验收记未覆盖，不填通过。
5. 共同正确题目的 P90 token 与时延暂以不超过基线 1.2 倍作为回归线；同时报告全量开销和每个正确交付的总成本，不能删除失败样本或只挑最好一次。

准确率提高但超过成本回归线时，必须列出取舍并调整预算/默认范围后再决定发布，不能自动认定通过。20 题×3 次是工程诊断起点，不是统计充分性证明。

### 12.3 必须记录的指标

逐 Run 记录配方/Skill/profile/模型版本依据、资料模式、最终正文、关键判分、实际模型动作数、真实上游调用数、本地读取数、失败/取消次数、总时延、输入/缓存输入/输出 token 及未知用量。推理 token 若已包含输出不得重复求和，不同供应商 token 不直接当金额比较。

步骤分析使用可观察的调用、结果、耗时与最终文本，不把模型自述思考当成正确性证明。离线报告至少列出中位数、P90、通过比例和全部失败原因。

## 13. 上线、回退与文档闭环

1. **部署前**：备份业务库、Skill 来源与不可变字节；执行正式迁移，旧 grant 的 profile 为 null。发布已验证代码和随包方法，不自动改员工或启动真实评测。
2. **小范围采用**：选一名现有测试员工，通过预览明确采用官方信息配置与方法。使用明确测试账号和有限额的真实请求，不把测试答案写入原诊断对话。
3. **参数冻结**：D5 选定工具组与预算，记录依据；部署默认只对新接受的 Run 生效，活动 Run 不改快照。
4. **推广**：为适用员工逐个展示差异并正常保存；新员工提供推荐。文件/计算根据验收矩阵独立开放。
5. **功能回退**：停止新采用、恢复已保存的员工配置/官方方法版本；先排空或中断 v4 活动 Run。工具适配不可用时明确未就绪，不自动绕过成原始工具。
6. **二进制/数据库降级**：旧程序不认识非空 profile，可能把许可解释为原始 MCP，因此降级前必须显式处理所有非空 profile、排空新协议 Run，再执行有拒绝条件的降级迁移。不能仅隐藏 UI 或删除列后宣称安全兼容。

官方方法升级必须保留旧内容依据；正在运行的 Skill 修改沿用当前快照与撤权规则。外部工具 Run 仍不在重启后自动重放，不能因为官方适配称其只读就改变恢复政策。

验收后更新工具/MCP/运行/员工配置契约、产品使用流程、模块 README 和部署指南；实际命令、版本、真实输出及未覆盖项进入 records。新方案不改写历史设计和过去验收结果。

## 15. 方案交付与实施起点

本轮完成设计与现有源码/契约核对，尚未执行迁移、模型调用、沙箱验收或业务改造。实际编码从 D0 的隔离基线和 D1 的确定性结果/收束用例开始；首先确认能复现、能判断正确，再改变生产默认组合。
