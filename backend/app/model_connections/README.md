# 共享模型连接与凭据

前端称为「大脑」的对象，是一份可被多名员工复用的模型连接。管理员维护名称、预设、模型标识与 API Key，员工引用连接；岗位指令和对话上下文由其他模块决定。

## 模块设计

### 配置与秘密为什么集中在连接

连接表保存非秘密配置和加密凭据，多名员工只保存连接标识。这样凭据更新与引用保护集中管理；代价是共享连接修改影响所有后续使用者，不能把它当作某位员工的私有字段。

`presets.py` 限定服务地址和协议，目前正式预设为 Kimi Code、智谱 GLM、DeepSeek 聊天及硅基流动 BGE-M3 向量。智谱采用标准 API 地址与 Key，不能使用 Coding Plan Key。普通保存验证并保存配置，不调用上游；聊天连接检查是独立动作，只验证模型目录访问；向量连接检查实际调用 embeddings。将保存与检查分开，使短暂网络故障不阻止管理员编辑，也避免把「保存成功」理解成「生成成功」。

### 一次模型请求如何取得正确参数

接受工作时记录连接 ID、配置版本和凭据版本。执行准备及后续模型请求前，服务按预期版本检查启用状态并解析秘密，生成不可变的 `LLMConfig` 交给模型客户端。配置版本表示模型/设置，凭据版本表示访问身份。

若排队期间有人换模型、停用或提交新 Key，旧请求不能记录旧依据却使用新身份，版本检查会拒绝继续；用户可重新发起。已经解析并开始的外部调用使用该次参数，配置修改不代表撤销已经发出的请求。

### 保存与删除怎样保护共享引用

更新同时核对两类预期版本；真实配置变化才推进配置版本，提交 Key 推进凭据版本。连接仍被员工或活跃运行引用时拒绝删除，检查在同一短事务内完成。已结束运行保留非秘密来源快照，但快照没有 Key，不承诺日后复现模型结果。

加解密机制由共同凭据组件提供，本模块将其故障解释成模型凭据错误。已有密文而主密钥缺失或不匹配时不得生成替代密钥；新增 Key 也先检查既有记录是否能解密，降低密钥分裂风险。数据库和密钥分别备份，完整密钥轮换尚未实现。

## 目录与职责

```text
model_connections/
├── presets.py                     # 声明允许的模型服务地址、协议和默认模型，防止浏览器随意指定请求目的地
├── models.py                      # 保存共享连接、启停、配置/凭据版本和密文，使员工引用稳定且秘密不复制
├── schemas.py                     # 定义创建、带双版本更新、检查和安全响应，只返回凭据存在标志及引用信息
└── service.py                     # 组织连接维护、引用保护、版本检查、秘密解析和主动连接测试，生成明确模型参数
```

## 与其他模块协作

[employees](../employees/README.md) 保存员工选择，[conversations](../conversations/README.md) 固定本轮版本并请求解析，[llm](../llm/README.md) 只用解析后的参数构建客户端。[共同凭据组件](../infrastructure/README.md) 提供加解密，本模块负责业务故障含义。

本模块读取员工和运行表进行删除保护，因此存在同库数据依赖；移除对话服务调用不等于完全独立。已获准运行的内部解析不要求普通成员拥有模型管理权，用户管理入口仍显式授权。

## 当前协议与验证入口

当前正式创建支持 Kimi Code、智谱 GLM、DeepSeek 聊天和硅基流动 BGE-M3 向量连接；能力由预设决定，员工只能装配聊天连接。向量测试调用固定短文本，索引引用阻止连接删除。供应商接入需同时检查预设、输入结构和协议适配，不能只在前端加选项。仅识别连接名称的明确唯一冲突为重复，其余未知完整性错误保持原意。

凭据配置及备份见[后端操作](../../../docs/guides/backend-operations.md#模型知识工具与沙箱)，对外规则见[模型连接契约](../../../docs/reference/model-connections.md)。[连接测试](../../tests/test_model_connections.py)覆盖安全响应、引用、版本和密钥失效，真实生成须通过实际对话另验。
