# 技能与工具服务联合检索

能力库让用户用同一组搜索、类型和分页条件查找技能与 MCP 服务。本模块负责生成这份可见清单，例如搜索「整理」后返回匹配的方法和已登记服务；发现条目后仍进入各自的维护与员工授权流程。

## 模块设计

### 为什么在数据库中先合并再分页

`queries.list_capabilities` 先检查查看能力和参数，将技能与 MCP 服务投影为 ID、名称、说明、类型、启用和创建时间等共同概要，再联合为一份查询。根据身份及搜索条件过滤：游客只列技能，普通身份按当前允许范围取得条目。

在统一结果上计算总数并按创建时间/ID 排序后分页，避免先从两类各取一页再拼接造成总数、排序和页边界错误。当前页确定后，才批量补齐这一页技能的协议名称，不为全部匹配内容加载主文或支持文件。

### 统一的是读取结果

Skill 正文、包和版本继续由 skills 维护，MCP 定义、账号及工具清单由 tools 维护，岗位选择和许可由 agents 维护。统一检索项只包含发现所需概要；本模块不连接远端 MCP，也不把「查到了」变成「可调用」。这种查询可供不同入口复用，而不强造一套共同维护/执行模型。

## 目录与职责

```text
capability_catalog/
├── queries.py                     # 联合查询已保存的技能和 MCP 服务，先应用可见范围与条件，再统一计数排序分页，补齐当前页概要
└── schemas.py                     # 定义技能/服务共用的检索条目字段，让页面可按类型继续导航而不泄露完整配置或秘密
```

## 与其他模块协作

API 的 capabilities 路由只解析条件和响应；本模块使用 auth、数据库及 skills/tools 的约定概要字段。员工装配和实际执行回到所属模块。包名为 capability_catalog，对外路径仍为 `/api/capabilities`，内部目录改名不改变协议。
