# Agent 基础文件与沙箱实施记录

日期：2026-11-08。应用改造和本机数据迁移已完成；真实 OpenSandbox 主机验收尚未完成。当前行为以[文件与执行环境](../reference/files-and-environments.md)为准，部署步骤在[接入指南](../guides/agent-tools.md)。

## 这次改变了什么

文件读写与代码执行不再是可装配插件。启用工具的 Agent 直接取得 Deep Agents 官方文件工具；沙箱配置和验收匹配时，同一组工具增加 `execute`。Skill 继续提供方法，MCP 继续连接外部服务，二者仍由员工显式装配。

工具名称、描述和参数来自锁定版本的 `FilesystemMiddleware`，虚拟文件使用 `StateBackend`。真实文件操作复用官方目录列出的社区 OpenSandbox 适配器，平台只补本轮路径、运行身份、资源上限、成果保存和环境释放。没有另外定义一套插件格式或手写文件工具 Schema。

按官方 [sandbox-as-tool](https://docs.langchain.com/oss/python/deepagents/sandboxes#sandbox-as-tool-pattern) 接入，Agent 和模型凭据留在应用侧，沙箱承接工具执行。本平台选择每 Run 独占并最终销毁，减少环境保活与跨轮恢复状态；这是当前短任务的取舍，不宣称是官方的默认线程复用策略。

## 一次工作的完整链路

以“读取销售 CSV，按部门汇总并交付结果”为例：

1. 用户上传并在本轮选择材料。文件服务保存原始字节，受理固定文件 ID、摘要、所有者和输入路径。
2. `execution/snapshot.py` 固定本轮环境及官方工具定义。沙箱未就绪时使用虚拟文本状态，不提供 `execute`；环境就绪时固定沙箱配置，运行中不换文件后端。
3. `agent/engine.py` 装配官方文件中间件，模型按工具描述选择读取、编写文件或执行程序。工作区与外部工具动作继续经过授权、原子预算和持久动作记录。
4. `WorkspaceBackend` 延迟取得本轮唯一沙箱。输入只读；程序、临时文件和结果分别在 `/workspace`、`/outputs`。执行前把已激活技能和本轮来源的原始字节同步为只读文件，模型阅读的长行投影不参与程序计算。
5. `execute` 以 UID/GID 1000 在 `/workspace` 运行镜像中已有的程序，限制命令时间和日志。退出码与真实输出反馈模型，不能把未知结果当成功。平台没有宿主 Shell 回退。
6. 成功结束前停止工作负载、检查并收集输出，再保存到平台文件服务。执行成果可靠保存后，对话接纳关联正式回复；浏览器下载检查对话权限，不暴露沙箱地址。
7. 所有退出路径尝试销毁环境。未知创建或回收失败保留资源记录、占用与清理责任，后台继续核对，TTL 提供补偿。正式文件不依赖环境继续存在。

仅文字回答不会创建容器。沙箱模式中的真实工作区操作会按需创建环境，不要求必须先调用 `execute`；文件与命令始终使用同一份远端文件。下一轮保留正式消息和成果引用，不继承临时目录。

## 文件和生命周期的所有者

| 位置                                                                           | 职责                                                                   |
| ------------------------------------------------------------------------------ | ---------------------------------------------------------------------- |
| [agent/filesystem.py](../../backend/app/runtime/tools/workspace.py)            | 取得官方工具定义并配置文件中间件，不创建插件或远端环境                 |
| [agent/workspace.py](../../backend/app/runtime/tools/workspace.py)             | 将文件工具路由到虚拟状态、冻结只读资料或本轮唯一沙箱，收集待保存输出   |

| [execution/store.py](../../backend/app/runtime/execution/store.py)                     | 原子授权、预算与动作记录；虚拟文件首次修改前标记不可自动恢复           |
| [environments/service.py](../../backend/app/resources/environments/service.py)           | 就绪检查、延迟申请、容量、未知状态和持续回收；拒绝排队后变化的环境配置 |
| [environments/open_sandbox.py](../../backend/app/resources/environments/open_sandbox.py) | 管理 OpenSandbox，约束身份、命令、真实路径、只读投递和输出收集         |
| [files](../../backend/app/resources/files/README.md)                                     | 持久字节、文件元数据、完整性与保留；正式消息关联仍由对话接纳负责       |

## 迁移与恢复

正式迁移 `0026` 停用所有旧 `native` 连接及相应员工许可，保留 ID、定义和历史引用；受影响员工增加修订，使旧页面草稿不能重新提交退役装配。能力库只展示 Skill/MCP，员工页面以只读文字显示基础文件能力与代码执行状态。

快照更新为版本 7，旧活动工作不能按新权限重放。虚拟只读和普通聊天仍按可信存档恢复；首次修改前在动作事务中禁用自动恢复，防止动作完成记录和框架文件状态分别落盘后重复修改或丢失状态。沙箱和外部工具同样不自动重放。

本机应用库已从 `0025` 升级到 `0026`。升级前活动工作为 0，通过 SQLite backup 保存一致性副本；升级后用户、员工、技能、MCP、连接、许可、对话、消息、Run 和文件记录数量均未变化，两条旧原生连接已停用，外键与完整性检查通过。备份位于 `/var/folders/wc/tk20rszj07q93k81dfj4h8380000gn/T/niuma-before-workspace-0026-z54mmd68/`，该临时位置不替代日常持久备份。

## 验证范围

离线测试覆盖无装配文件交付、官方参数定义、禁用工具时不提供文件、只读与越界拒绝、虚拟写入恢复边界、单后端文件与命令、来源原始字节、按需创建、配置变化拒绝、关闭后不再申请、成功后收集与销毁、未知创建补偿，以及已有取消和持久化故障场景。迁移覆盖离线 SQL、旧连接及许可 ID 保留、修订、重复升级和外键。

实际检查结果：后端全量 1130 项通过；随后补上清理失败仍关闭本地连接的修复，相关 38 项定向用例通过。前端全量 97 个文件、714 项通过，随后说明文字调整的员工装配用例和构建也通过。Ruff、格式检查、49 个源文件的类型检查与受影响前端 ESLint 通过；文档本地链接检查无错误，站点内容同步和 11 项内容测试通过。

本环境使用现有 `.venv` 中的工具执行后端检查，避免 uv 缓存权限及联网构建依赖干扰；需要本机临时端口的协议用例在允许回环服务的环境运行。上述用例不请求真实模型或真实沙箱。

真实页面已核对：能力库只保留现有 Skill/MCP，员工页显示文件能力无需装配，代码执行显示未配置或未通过验收。未改变业务员工配置或发起真实模型任务。

当前机器 Docker 服务未运行，后端没有 OpenSandbox 地址、密钥、镜像或验收文件。真实 Linux 容器中的 runsc、网络、磁盘与内存限制、程序执行及远端回收尚未验证，不能据此记录为“沙箱已就绪”。初始化命令仍保留，显式生成并持久保存配套密钥；不会在应用启动时自动启用未验收环境。
