## 需求与范围

依据用户最新截图：白色只保留几乎不可察觉的暖倾向，登录页同时调整；色值采用连续、低彩度的中性阶，点缀色与语义状态色有明确用途。森林绿、奶油白、燕麦、鼠尾草的大面积 UI 色调不再适用。初始配色整理保持既有布局、字号、字重、间距、控件、圆角、字标和动画时序；角色插画本体颜色保留，作为局部点缀。

## 规范版本与维护入口

配色基线为规范 1.0，日期 2026-10-20；当前设计系统版本与后续排版规则见[设计系统入口](../../frontend/src/design-system/README.md)。数值由 `theme.css` 维护，`spec.ts` 提供版本、语义色分组及组件规则。1.3 将当前菜单调整为 Logo 嘴部品牌橙，1.5 将选中前景统一为卡片白色；导航状态颜色、选中字重与常态／当前态图标描边统一纳入 token，由同一 CSS 供管理员、游客与样板复用。[组件规范](../../frontend/src/design-system/components.md)集中定义视觉与状态；[设计系统入口](../../frontend/src/design-system/README.md)说明维护与业务组合边界。日夜模式现按完整语义映射接入，行为与首屏契约见[主题模式](../reference/theme.md)；本页保留日间视觉基线。

配色规范 1.0 的整理与验证已完成，当时产品配色、布局、字号与间距保持既定值；后续 1.1 的文字角色与共享页头调整在端内组件规范维护，不沿用本页旧验证作为新排版的依据。规范版本与具体视觉验收分别管理。

## 色卡与语义

`theme.css` 的基础色是唯一颜色来源；业务组件与登录页使用 CSS 语义变量，必要的组件映射通过 `var()` 引用同一色卡。未定义用途的基础色不进入业务界面。配色以连续明度、极低彩度、明确语义和可读性对比约束。

| 角色               | 规则                                                                                                                                                       |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 主表面             | `surface` = `#fdfdfb`，接近白、RGB 通道差仅 2；不使用明显奶油黄或纯 `#ffffff` 大底                                                                         |
| 统一工作底         | `canvas` / `chrome` = `#f8f8f6`；顶栏、侧栏与内容区连成一个连续底面                                                                                        |
| 次级与选中         | 普通控件仍用中性浅灰；侧栏菜单使用专属 `nav-active` 品牌橙 `#ec8a76`，配成对的 `nav-active-text`；常态、悬停与数量颜色归入导航语义组，不加重色边条         |
| 菜单图标           | 常态使用中性灰 `text-muted`，选中继承与文字、数量相同的卡片白色前景；17px 图形常态 1.75px、选中 2.25px 描边，选中文字与数量 600 字重；管理员与游客共用样式 |
| 正文与辅助字       | 墨黑与中性灰，辅助字保持可读，不以极淡字色制造层次                                                                                                         |
| 主操作、链接与焦点 | 墨黑体系，两页共用；反白字使用主表面色；不另设品牌绿按钮                                                                                                   |
| 登录页             | 外底、品牌场景、表单纸面对应三个中性明度；标题、slogan 首行、输入和游客入口中性化；「你先松口气。」保留原陶土橙 `#bc7863`，取消残留固定绿字                |
| 点缀               | 铜橙用于收藏与品牌小点；登录 slogan 第二行使用原陶土橙 `#bc7863`，属于明确的品牌强调；菜单选中使用来自 Logo 的品牌橙，插画固有色保留，不扩散成页面底色     |
| 状态               | 成功绿、警告琥珀、错误红、信息蓝仅在相应反馈出现，同时保留文字或图标，不做通用装饰底                                                                       |
| 头像底             | 统一浅暖灰圆拱背板，使用 `portrait.background`；比例与底部收口见[组件规范](../../frontend/src/design-system/components.md#员工卡片头像背板)                |
| 阴影与边界         | 中性阴影和浅灰细线建立表面层次，不新增颜色光晕；阴影几何和透明度保持                                                                                       |

色阶按亮度组织，中性白阶的 RGB 差值保持很小。UI 大面积只使用中性系；状态与小点缀是明确例外。`/design-system` 同步显示当前基础色族、语义映射与使用限制，旧森林绿／纸白方案的说明不再作为规范。

## 演示与验证

后续演示使用真实前端页面，截图仅用于内部检查。3100 为生产构建，8772 为同一前端的只读展示数据审阅代理；所有 API 写入被拦截，不转发 Cookie 或 Authorization。可对比 `/`、`/signin` 与 `/design-system`。不代表真实认证、数据库保存与模型调用经过测试。

本轮验证结果：

- 生产构建、TypeScript、77 项回归测试、本轮 ESLint 与格式检查通过。
- 十一种实际组件视图无浏览器报错，八组受保护页面的布局与字级基线不变。
- 十五组文字、按钮、状态、选中和输入边界对比度检查通过；全部 UI、头像浅阶与登录颜色来自注册色卡。
- 原生页面核对主表面 `#fdfdfb`、主操作 `#252523`，工作台输入与弹层同色；登录必填反馈正常，390px 工作台和登录页均无横向溢出。
- 规范页六组色卡可展开，旧森林绿文案已撤除。角色原画颜色保留，矢量字标墨色跟随全站文字令牌。
- 登录页 HTML 24,136 字节，Brotli 7,100 字节，gzip 8,491 字节；动画资源名称与 14,530 字节体积不变，没有新的字体、SDK 或图片请求。此次明确改变登录 HTML，不能套用旧字节指纹结论。阴影只改中性墨色，几何与透明度不变。

证据：`../niuma-crew-archive/output/theme/light/neutral-reference-verification.json`、`token-verification.json`、`theme-scheme-verification.json` 及内部 QA 截图。当前网页演示仍为只读展示数据，视觉认可待用户审阅。全仓库既有动画制作脚本 lint 问题未在本轮处理。

## 设计规范 1.0 整理验证

- `spec.ts` 的七个语义组完整覆盖 31 个颜色 token，编译约束与测试防止遗漏分组；基础色色值继续由 `palette` 单独维护。
- `brand-text` 统一登录 slogan 与规范页的品牌强调色；`icon` 组统一导航尺寸、描边与 CSS 单位，管理员、游客及样板使用同一规则。
- 真实 `/design-system` 提供八类组件规则、菜单切换样板及已有控件与反馈；菜单背景、图标色、尺寸和描边已逐项与工作台匹配。390px 视图无页面横向溢出。
- 生产构建、TypeScript、95 项测试与本轮文件 ESLint / 格式检查通过；十一种实际组件视图无页面报错，八组产品布局指标与原始基线一致。
- 全仓库 lint 未通过，结构化结果中的问题均位于未修改的 `animations/` 制作脚本与第三方 Rive 文件；生产规范代码不在失败清单。相关文件有其他任务并行维护，本轮未修改这些工具。

规范页证据为 `../niuma-crew-archive/output/theme/light/spec-v1-verification.json`，静态检查摘要为 `spec-v1-static-checks.json`。网页演示仍为只读展示数据，未执行真实后端写入或模型调用。
