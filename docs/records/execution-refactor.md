# 执行重设计第一阶段验收

日期：2026-10-26。适用快照：当前工作区，仓库尚无可引用提交。范围为已授权的执行所有权、稳定消息与结果、跨模块事务、前端消费、迁移和检查；Task、Plan、Goal、通用 MCP 与真实模型服务不在本次验收范围。

## 实际改动

- 原 runs/runtime 统一为 execution，SDK 适配位于其内部；配置捕获和当前方法授权回到员工/技能视图。
- 增加 Message、ConversationRun、RunResult，Run 去除对话输入输出字段；RunAction 区分逻辑调用与实际尝试并关联工具请求来源。
- RunCommands 原子接受输入，PublishRun 原子发布结果、消息、终态及活动位置；execution 不导入对话/HTTP/CI 实现，不使用 Session.info 传递存档依赖。
- SDK 按 Run 隔离；产品历史不打开 checkpoint。缺失或损坏的恢复状态明确中断，未知远端结果和用量保持未知。
- 前端消费 actions、稳定 result 和 published 状态；消息 Hook 的 executionActions 与用户操作 actions 分开。
- 迁移 0004 对旧存档做预检，保留正文、输入、动作、历史身份和反馈；缺失资料回滚，旧协议活动尝试明确中断。新模型已有数据时拒绝有损降级。
- mypy 增量覆盖执行边界并纳入 lint-backend；自动测试强制 execution 的导入方向。

## 覆盖的关键场景

原子接受与重复提交、失败重试保留原输入、取消和完成竞争、发布器中途失败完整回滚、重复发布不重复消息、工具请求与实际动作关联、未知调用用量、SDK 存档丢失后的历史读取、旧库正文搬迁及失败预检、空库升级/降级/再升级、完整图恢复时只补结果、强制终止后的身份/预算/超时复核。

## 操作与限制

本次只在隔离测试库执行迁移，未访问或升级开发业务库，未删除用户数据。部署已有数据库前停止服务并保留业务库、对应 checkpoint 文件及主密钥，在线执行 make db-upgrade，再执行 make db-check；细则见[维护指南](../guides/backend-operations.md#数据库迁移)。

现有部署仍为单机 SQLite 与单 Runner，未验证多进程扩容、真实上游可用性、并发性能或模型内容正确性。CI 专用循环、仓库配置和专业预算仍存在，统一标准技能及 MCP 属于下一阶段。类型检查仅覆盖已列出的执行边界，不代表全部后端代码已严格检查。
