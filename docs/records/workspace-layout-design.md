## 原型方法

[layout-study.html](../../frontend/src/design-system/layout-study.html) 是独立几何原型，读取现有 theme.css，使用演示内容和正式 designer-bull.svg 的嵌入副本，不发起业务 API 请求、不保存偏好。它不引入项目运行期的第二套主题或业务组件。

通过已有 Vite 服务的源码 HTML 地址在本机浏览器打开。每个 iframe 保持标注的真实 CSS 视口宽度，父页只对展示做缩放。原型在 iframe 加载和尺寸更新后读取计算样式，将结果显示在“实际布局数据”中，再由浏览器工具读取这些可见 DOM 数据。

每个矩阵视口同时包含七种结构：员工、简单能力、复杂连接、主辅配置、文件编辑、对话宽内容，以及列表/反馈/任务容器。检查 frame、gutter、内容宽、网格列数与卡宽、主辅/字段/文件分栏、段落宽、导航命中区和文档横向溢出。宽表格和代码保留局部滚动。

使用 18 档视口：320、390、767、768、769、879、880、881、1024、1280、1295、1296、1297、1439、1440、1441、1920、2560px，覆盖外壳、外围留白和主辅阈值两侧。五种外框候选产生 90 组尺寸数据，另外检查 18 组“夜间 + 粗指针预算 + 原型 200% 字级”的组合状态。原型字级放大不等于浏览器真实缩放。

## 实测结果

下表为推荐外框下的日间默认几何，取主要尺寸；全部列宽使用浏览器计算值，不以设计公式冒充实测。

| ---- | ---- | -------- | -------- | -------------------------- | ---- | -------------- |
| 320  | 320  | 288      | 16       | 1 / 1 / 1                  | 堆叠 | 254            |
| 390  | 390  | 358      | 16       | 1 / 1 / 1                  | 堆叠 | 324            |
| 768  | 528  | 496      | 16       | 1 / 1 / 1                  | 堆叠 | 446            |
| 1024 | 784  | 736      | 24       | 2 / 2 / 1                  | 堆叠 | 331            |
| 1280 | 1040 | 992      | 24       | 2 / 3 / 2                  | 堆叠 | 459            |
| 1440 | 1200 | 1136     | 32       | 3 / 3 / 2                  | 并列 | 344            |
| 1920 | 1536 | 1472     | 32       | 4 / 4 / 2                  | 并列 | 512            |
| 2560 | 1536 | 1472     | 32       | 4 / 4 / 2                  | 并列 | 512            |

- 1295 / 1296 / 1297px 的内容区为 1007 / 1008 / 1009px，主辅从堆叠切为并列；并列首点的两个字段各为 280px。已把面板边线计入预算，未将 632px 的无边线内容预算误作完整面板外框。
- 879 / 880 / 881px 的单侧留白从 16px 切为 24px，内容宽从 607px 到 592px 再到 593px；简单卡片维持两列，没有阈值两侧反复切列。
- 1439 / 1440 / 1441px 的留白从 24px 切为 32px，三种卡片列数及主辅结构保持稳定。
- 最大推荐外框下，员工和简单能力卡实际各 350px，复杂连接卡各 724px。五种候选的实际列数和卡宽与设计比较表一致；1600px 外框出现五列简单卡和三列复杂连接卡，确认它改变了既定密度。
- 日间默认和组合状态各视口均未出现文档级横向溢出；320px 时示例表格保留 960px 数据宽并在局部视口滚动，不推动整个页面横向溢出。
- 桌面导航命中区实测为 28×24px，组合状态为 44×44px；宽屏已有空白足够时正文不再额外缩进避让。原型修正了在错误的嵌套容器中读取单位导致安全带始终占位的问题。
- 默认宽屏普通中文段落实测为 896px，表格可用区约 1470px；并未把整个 Markdown/报告限制到段落宽度。

正式字体和不同语言可能改变行长观感；不把无溢出解释为内容一定最易读。原型中的宽卡片、较少列数和局部文字测量有意呈现取舍，未隐藏 1280px 员工目录由当前三列变为目标两列的影响。

## 检查与产物

原型内联脚本通过 `node --check`。Impeccable 的 layout 范围机械扫描已执行，返回空发现；它无法证明跨页面一致性、语义或用户体验，浏览器数据和人工观察承担这些核对。

临时原始数据保存在 `/tmp/niuma-layout-design/`，含默认、组合状态、五种候选和最终默认复核。截图保存在本任务的可视化输出目录。文字结论、主要数据和可复现原型均在本仓库，不依赖临时路径才能理解。

复用现有后端环境执行 `make check-docs` 通过：233 个 Markdown 文件、2473 条本地链接、错误为 0；13 个本轮修改/新增文件的定向 Prettier 检查通过。没有因文档和独立 HTML 原型而运行全量业务测试或声称生产构建通过。

浏览器日志曾出现 `MutationObserver.observe` 参数不是 Node 的错误；本原型自有脚本只使用 ResizeObserver，当前尚未确定错误来源，不据此宣称控制台无错误。可见布局数据和尺寸切换继续工作，日志问题与正式组件接入均未在本轮视为已验收。
