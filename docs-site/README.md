# 牛马文档站

独立的 Fumadocs + Next.js 静态文档应用。正文在仓库 Markdown 中维护，站点负责把它们组织成适合阅读、搜索和继续查阅的页面。原文与生效状态遵循[项目文档规范](../docs/documentation.md)。

## 文档怎样组织

正文和根 README 使用同一套主题名称，站点分为三个阅读入口：

| 入口     | 内容                                     |
| -------- | ---------------------------------------- |
| 平台介绍 | 平台定位、组织资产、员工设计             |
| 技术解析 | 开发参考、架构设计、运行机制、检索与评估 |
| 使用指南 | 员工配置、资料、对话、考核、部署与排错   |

首页先呈现资产沉淀和最小能力装配，再提供架构与技术解析。建设中方向放在对应主题说明问题与状态，不用空白文章占据导航。主标题与导航使用中文，必要代码名称在正文对应说明。

架构与对话页复用现有图源，知识检索流程沿用相同字体、日夜语义配色和线型。图源在 `docs/architecture/diagram/` 维护，不在站点生成第二份。

## 启动与检查

需要 Node.js 22.12+ 和 pnpm 11，设计交互示例还使用前端依赖，`make setup-docs` 会一并安装，在仓库根目录执行：

```bash
make setup-docs
make dev-docs
```

开发地址为 `http://127.0.0.1:3001`，端口已占用时明确失败。平台默认在 3000 端口；文档站不依赖平台服务、数据库或模型。

首页“了解平台介绍”旁提供“进入平台”，顶部与侧栏不重复放置。地址按以下规则选择：

1. 设置了 `NEXT_PUBLIC_PLATFORM_URL` 时，使用构建时指定的平台地址；适用于独立域名、不同应用路径或自定义本机端口。修改后重新构建。
2. 通过本机回环地址访问时，指向相同主机的 3000 端口，开发服务与静态预览一致。
3. 线上未单独配置时，指向同域根路径 `/`，适用于平台与文档同域交付。

一级分类使用大图标，当前分类以实心图标底色和加重文字标识。二级分类使用小图标与标题，文章向内缩进，保持展开。开发参考只保留一个“开发入门”入口。

```bash
make check-docs-site   # 内容、类型、定向测试、格式及静态构建
make build-docs        # 生成 docs-site/out 静态产物
make preview-docs     # 在 3001 端口预览静态产物
```

开发服务监听现行文档、模块 Markdown、引用图片、品牌资源和设计令牌变化并重新同步；正式组件、样板及样式变化同时重新构建设计示例。同步先完整读取并校验原文，再优先发布资源、逐文件原子更新变化的正文；未变化文件保持不动，原文校验失败保留上一次可用内容。修改发布清单或站点配置后重启开发命令。`make preview-docs` 需要先完成构建，与开发服务共用端口，运行前先结束另一项服务。

## 内容与发布

[发布清单](scripts/content.mjs)维护主页面的网址、标题、说明、来源章节和侧栏主题。`group` 指定当前分类内的阅读分组，生成索引将它交给导航组件；首页入口与主导航保持相同的主题分类。正文仍在原始 Markdown 维护，提取指定章节时保留子节并规范标题层级；不存在的来源或标题会中断同步。

原文链接按以下方式处理：

1. 已发布 Markdown 映射到对应站点正文；进一步阅读的现行文档进入资料页，不加入主导航。
2. 图片和明确允许的附件复制为静态资源；源码、`LICENSE` 许可文件、方案和记录进入只读原文页。历史材料保留状态提示，不进入全文搜索；清单明确选入“规划与讨论”的当前草案单独发布，并保留状态说明。
3. 仓库外归档标明出处，不复制宿主机文件；禁止通过相对路径或符号链接越过仓库边界，不发布真实环境文件与凭据。
4. 正文不展示“查看原文”入口，平台介绍页直接呈现内容；技术章节中的必要源码引用仍可进入只读原文页。

`.generated/` 中的编译输入、索引和主题令牌，以及 `public/repository/`、`public/brand/` 均由同步脚本产生并忽略提交。不要直接编辑这些目录。热更新时保留旧编译模块可能仍引用的资源；如需清理未引用的历史生成资源，先停止文档服务，删除生成目录后再重新启动。Markdown 原文、品牌和配色分别来自现行文档、[品牌资源](../frontend/src/lib/brand.ts)及[设计令牌](../frontend/src/design-system/theme.css)。

站点采用 Fumadocs 的 Base UI 官方模板及文档布局，使用 Next.js 官方 Webpack 编译路径，使用默认多语言分词与浏览器静态搜索。搜索客户端读取 `/api/search.json` 静态索引，避免无扩展名地址被托管服务补为目录。Next.js 使用静态导出，不运行生产 Node 服务；部署时保留 `out/` 的目录结构和每页 `index.html`，缺失地址返回 `404.html`，不配置单页应用回退。

## 界面示例

设计原则直接在开发入门中顺序介绍，颜色、布局和组件细节再进入查阅页。原有设计系统网址保留。发布项的 `navigation: false` 表示不加入主目录，正文仍可访问与搜索；合并后的重复入口使用 `search: false` 退出搜索，旧网址继续可用。

示例复用前端真实组件。构建入口为 [`frontend/design-examples.html`](../frontend/design-examples.html)，由[示例构建脚本](scripts/build-design-examples.mjs)生成到 `public/design-examples/`，故障插画生成到 `public/failures/`。主题随文档入口，资源不依赖平台服务或登录，也不人工编辑。

嵌入内容隔离平台样式与路由上下文，页面跳转沿用 `NEXT_PUBLIC_PLATFORM_URL`。旧平台设计入口通过 `VITE_DOCS_URL` 指定文档根地址；独立域名部署修改后需要重建前端。

## 工程职责

```text
docs-site/
├── scripts/           # 维护发布清单、同步原文、启动监听与定向测试
├── src/
│   ├── app/           # 首页、正文、原文、搜索和 Markdown 路由
│   ├── components/    # 主题、搜索及 Markdown 渲染适配
│   └── lib/           # 加载内容、配置导航与站点信息
├── next.config.mjs    # 配置静态导出、目录路径与图片
└── package.json       # 管理独立依赖及构建命令
```

技术解析先读开发入门，再读架构设计、运行机制和检索与评估。技术栈、目录结构、环境设置与设计原则在入门页连续阅读；正文链接只补充更具体的规则、操作或实现，页尾不再自动推荐相邻文章。

新增文章先确定读者和问题，再在发布清单登记原文及分组。功能是否可用由产品、契约和代码说明，站点导航不授予新的能力。
