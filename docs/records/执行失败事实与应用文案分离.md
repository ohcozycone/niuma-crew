# 执行失败事实与应用文案分离

状态：已实施并通过离线验收。更新：2026-11-08。

## 验证与结论

用户提出的归属更合理：Agent 与 Execution 负责失败含义和执行处理，应用负责公开说明。重构前 Runner 用 `ERROR_MESSAGES` 判断错误码是否合法，执行校验也直接构造中文提示；文案修改可能影响执行分类。工具步骤还把不同失败统一写成 `tool_upstream_failed`。这两处职责混合已在本轮解除。

## 本轮实施

1. 定义不带展示文案的失败基类与技术分类；Agent、Execution 分别定义自身错误码及类型，取消异常别名。执行终态只使用技术事实，不引用文案表。
2. 将公开文案移到应用层 `app/common/public_errors.py`。HTTP 和对话读取分别在输出时选择说明，考核沿用自己的应用展示。执行侧的业务错误保留具体异常类型和 code，省略文案；响应格式及既有中文提示尽量保持兼容。
3. 步骤继续使用现有 RunAction 的类型、动作键、状态和错误码定位，不重复建立错误台账或修改数据库。工具参数错误、平台错误及结果未知分别保留对应错误码；原始上游异常不作为公开说明。
4. 注释沿用后端手册：中文、简短、说明非显然原因；保留并发、事务和恢复约束，不重加职责口号。提示词、工具反馈及测试样本与注释分别维护。

应用展示可以变化；错误码、执行终态及外部副作用是否确定不由展示层决定。本轮不建设多语言框架，不增加自动重试，不改历史数据或快照版本。

## 验收

- 移除或修改公开文案不改变错误分类与 Run 终态。
- Agent 和 Execution 不导入公开文案模块，异常不携带用户提示。
- 参数错误、缺账号、上游失败、结果未知及持久化故障可区分；步骤事实与缓存复用一致。
- HTTP 状态、公开错误格式、旧历史读取及未知故障脱敏保持有效。
- 运行受影响测试、完整后端回归、静态类型与文档检查；实际结果记录于质量记录。

## 文件归属与兼容

| 文件                                                                   | 实际职责                                                           |
| ---------------------------------------------------------------------- | ------------------------------------------------------------------ |
| [app/common/errors.py](../../backend/app/common/errors.py)                           | 共用机器错误基类、技术类型及可信错误码提取；业务异常可省略公开文案 |
| [agent/errors.py](../../backend/app/runtime/agent/errors.py)                   | 引擎失败定义与 RuntimeFailure                                      |
| [execution/errors.py](../../backend/app/runtime/execution/errors.py)           | 执行失败定义、ExecutionFailure、持久化故障及终态处理               |
| [public_errors.py](../../backend/app/common/public_errors.py)                 | 应用默认公开文案，核心不得导入                                     |
| [api/errors.py](../../backend/app/api/errors.py)                       | 按异常类型确定 HTTP 状态，在输出时补充公开说明                     |
| [conversations/queries.py](../../backend/app/applications/conversations/queries.py) | 对话场景的公开说明及部分输出提示                                   |
| [execution/queries.py](../../backend/app/runtime/execution/queries.py)         | 读取既有 Run/动作事实，附加可确定的技术分类                        |

响应原有 code、message 保留；对话 error.kind、诊断 run/动作的 error_kind 为新增可空字段。历史未登记码原样保留，类型返回 null，不回填未知阶段或真实根因。模型超时与整轮超时分别用 upstream_timeout、run_timeout；命令非零退出用 command_failed。启动进程锁竞争上报 execution_host_locked 与 conflict 类型，运维测试不再匹配中文文字。

注释继续使用[后端标准](../engineering/backend.md#注释与说明语言)：沿用已精简的自有中文说明，保留事务、取消和资源顺序原因。第三方生成源码、历史迁移、提示词和工具反馈不机械处理。注释阶段的 AST 与接口结构核对结果不能替代本轮错误语义的回归。

环境为 macOS、Python 3.12.13、当前锁定依赖和临时 SQLite；模型与远端工具使用确定性替身，进程恢复测试使用本机 HTTP 端口。

删除默认文案目录或替换其中一条提示后，真实 Runner 的错误码与终态不变；应用读取分别得到兜底或替换后的说明。伪造上游 `.code` 不会冒充平台取消；模型服务超时与总时限可区分。持久化故障在成果校验和工具受理阶段均原样传播，不登记为业务拒绝或授权拒绝。

本轮未部署、未修改数据库或历史数据，未验证真实模型、远程 MCP 和目标 Linux 沙箱。技术类型不是自动重试承诺；未知结果仍保留原执行限制。当前规范见[失败契约](../reference/failures.md#执行失败事实与应用文案)。
