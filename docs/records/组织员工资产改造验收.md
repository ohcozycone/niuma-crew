## 2. MCP 固定工作连接

员工许可固定到明确的组织连接及批准操作。删除个人绑定服务、DTO、路由和页面，以及 account_mode/account_scope；不保留组织与个人两套解析方式。创建者只记审计。

保留服务与连接分离、凭据加密、目录确认、定义哈希、范围限制、引用保护和调用前复核。OAuth 继续绑定授权发起管理员会话；其他管理员接手维护不会自行替换凭据。成员可以委托员工，不能管理或替换工作连接。规则见[MCP契约](../reference/mcp.md)。

## 3. 知识作为组织资料，引用仍有边界

保留资料、原文、分片、关键词、向量和内容版本；不因本轮归属变化重新切分或向量化。员工与知识库直接关联，替换个人设置及中间设置ID。管理员管理资料，成员通过员工的冻结范围检索。

删除伪造用户身份的运行适配。来源接口先校验Run阅读资格，再从该Run证据派生片段和版本，不接受任意库读取范围；通用文件权限没有扩大。既有游客知识只读规则保留。历史个人证据依旧按原冻结归属检查，不自动提升权限。规则见[知识契约](../reference/knowledge.md)。

## 4. 内置能力与按需发现

builtin_tools独立组织文件、知识、结果读取与发现入口，使用窄宿主接口；MCP真实接入仍归mcp，执行记账归execution。删除知识模块的重复工具定义，通用工具门不再解释各业务的artifact或退出码。

本次采用应用侧FTS5/BM25目录搜索，没有使用供应商原生ProviderToolSearchMiddleware。目录在请求受理时冻结，运行准备时构建内存索引；首请求提供常驻内置能力和发现入口，MCP完整定义在搜索后按需提供。简短来源入口按服务名、连接名和候选数量机械生成，索引使用原始工具名、描述和参数，不要求逐工具人工写摘要。没有全量回退或额外联网搜索服务。

每次模型请求保存实际可见集合；调用检查其父模型动作，猜名及同批先搜索后越权调用不能执行。并行发现合并后统一校验上下文，结果可靠保存后才提交图状态，新Run清空发现集合。过程列表展示发现耗时与数量。规则见[运行契约](../reference/runtime.md#工具发现与实际可见范围)。

## 5. 配置到运行、迁移与最终检查

1. 管理员接入组织连接、确认目录并维护知识资料。
2. 在员工主保存中确定岗位、模型、技能、固定连接及操作、知识范围与策略，整体检查并推进修订。
3. 委托时校验真实发起者，捕获员工配置与资源依据；凭据不进入快照。
4. 运行准备创建工具目录，按条件提供常驻内置能力；模型发现获批候选后，下一请求加载完整定义。
5. 每次模型及工具动作复核当前授权和预算，可靠保存结果后反馈；成员的会话、对话、取消和审计保留真实身份。
6. 新一轮按当前配置重新捕获；旧个人资源线程不加载进新图，页面历史保留。旧执行成果及证据不被迁移重写。
