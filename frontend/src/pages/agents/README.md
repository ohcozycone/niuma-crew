# 员工目录、配置与展示

用户在员工目录寻找岗位并进入员工管理页，管理员在配置页编辑身份、工作指令、大脑及能力。目录、侧栏、编辑预览都围绕同一份员工资料，但展示摘要与可保存的完整配置分开读取。

## 模块设计

### 员工管理页与考核

员工头像、姓名、卡片主操作和收藏导航进入 `/agents/:id/home`，原配置页 `/agents/:id` 保留。主页用圆拱头像、姓名简介及五个页签组织内容，简介下方以陶橙资源图标和紧凑横排展示「N 技能」「N 知识库」「N 轮对话」，窄屏整项换行。技能数取公开投影；知识库数订阅当前身份的 KnowledgeStore；完成对话轮数通过独立只读聚合读取，按当前可见范围统计成功接纳的问答，不统计重试次数。游客或缺少权限时不请求私有统计，加载、失败及零值分别展示，失败可独立重试；范围见[资源摘要](../../../../docs/reference/agent-resource-summary.md#员工个人页统计)。

默认对话记录，考核可发起、取消及读报告；任务、定时和长期记忆只显示建设中。历史列表复用 [共享对话历史](../../components/conversations/ConversationHistory.tsx)，提供服务端主题／Conversation ID／Run ID 搜索、最近回复状态筛选与四列表格；最近活动和创建日期同格展示，保留执行日志／去对话，不显示轮次。日志与考题证据复用大型 ExecutionLogDialog，关闭返回原宿主。聊天侧栏保留紧凑列表。员工页不创建会话作用域或展开聊天正文。

`EmployeeHomePage.tsx` 持有当前员工身份、URL栏目和权限展示；`EmployeeEvaluations.tsx` 持有本人考核列表、发起表单及逐题报告，按批次状态观察进度。API契约、评分范围和版本依据见[员工考核](../../../../docs/reference/employee-evaluations.md)。身份或员工改变时重建局部作用域，取消旧读取，不混用其他人的报告。

个人页的技能与知识统计可作为配置快捷入口：在已有配置查看权限下，分别进入当前员工编辑页的「能力装配」与「指令与知识」标签，使用原有 `tab` 参数并携带个人页的完整返回来源。零值可进入添加，知识读取失败仍可单独重试；具体权限和路径见[个人页统计契约](../../../../docs/reference/agent-resource-summary.md#员工个人页统计)。

### 目录怎样从 URL 变成卡片

页面 Hook 将关键词、分类、状态、收藏和分页组织成查询。AgentStore 保存按 ID 的员工摘要和查询成员顺序，目录只按 ID 渲染，每张卡片订阅自己的记录；侧栏收藏使用同一数据来源。因此一次收藏确认能同时更新两处，不需要分别广播「目录变化」和「导航变化」。

刷新和切换条件保留上次成功内容，显示正在更新或失败，避免列表和导航整体消失。较旧修订或已取消读取不能覆盖新保存记录，当前条件总数与全体数量分别读取。

搜索与岗位分类并排位于工具栏左侧，右侧统一显示顶部分页，列表底部不再重复分页。每页 20 位，页码与左右箭头更新 URL 的 offset 并保留其余条件；关键词、分类、状态及技能筛选变化会重置第一页。页数来自服务端当前条件的 total，长页数以首尾、当前页和省略号压缩；窄容器保留当前页和左右箭头。零结果时显示第一页且两侧禁用，加载期间暂停翻页，失效末页沿用自动回到最后有效页的逻辑。

### 配置表单怎样保存完整装配

`useAgentEditor` 按 ID 读取完整员工配置并提供保存操作，`AgentConfiguration` 管理输入草稿、校验和预期修订。技能面板、大脑选择和工具装配都先改变同一表单草稿，面板「完成」不等于已保存到服务器。

表单使用基础配置、指令与知识、能力装配三个 tab，原 URL 键保持不变。保存按钮常驻，无改动时禁用；共享指令、技能与工具仍由同一主保存提交。基础配置将圆形头像与名称式大脑选择入口并排，名称和分类成组，简介独立占据主区；点击整张头像打开选择器，14px细线相机图标仅作更换提示，24px半透明圆底在日间为灰底白图标、夜间为偏白底深色图标，复用action/action-text，无描边或阴影。宽屏右侧直接展示完整员工卡片，不另设预览标题、更新说明或分隔线，窄屏按需打开；大脑读取失败、凭证问题、刷新及管理入口继续保留。指令与知识由 AgentInstructions 组织：暖白编辑器为主区，模板只填入空指令；字数和生效说明放在下方。右侧分别展示本人知识库名称及独立保存入口、自动继承的公司规章制度，窄屏排在编辑器之后。个人知识不随员工共享配置保存。能力装配由 AgentCapabilityAssembly 组合工具和技能 Hook，以同一列表提供类型筛选、搜索和分页，避免工具变多后技能入口被推远。类型身份与动作规则见[设计语言](../../design-system/resource-language.md)。

三个页签的操作统一放在页头右侧。已有员工未修改时保存按钮显示勾选图标与“已保存”并禁用；草稿与基准不同时显示保存图标与“保存配置”并启用，恢复原值后回到已保存；请求中显示“保存中…”。状态在按钮内表达，下方不重复说明；无变更的隐式表单提交也不写入。新建员工没有删除入口，保留保存配置以支持必填校验。返回沿用离页保护，保存中及过期草稿待处理时禁用操作；删除继续经过独立确认。窄屏沿用共享页头换行，不设置底部操作条。外框与主辅尺寸见[布局规范](../../design-system/layout.md#员工编辑工作区)。

主保存将岗位字段、技能关系及工具许可交给共享数据操作，后端一次事务确认。成功用完整返回结果更新表单基准并清草稿，再返回目录；失败保留输入，版本冲突须核对最新配置。摘要缺少指令等字段，不能直接当完整表单回写。

系统提示词为空时可“填入通用模板”，按岗位目标、职责范围、工作方式和交付要求填写；方括号是待替换的编写提示，不预置行政等具体岗位内容。模板只写入当前草稿，不调用模型，也不覆盖已有指令。AI编写助手作为后续需求储备，当前未接入。

### 个人知识范围为何独立保存

“我的知识库”复用[EmployeeKnowledge](../../components/knowledge/EmployeeKnowledge.tsx)，为当前用户使用这位员工时选择最多10个本人库、检索时机、方式和合计召回上限。它是个人设置，不进入Agent草稿、岗位System Prompt或“保存配置”；弹窗具有自己的修订、保存和离页保护。新员工先保存再装配，已有员工可以从指令侧栏进入；成员和非创建者从员工只读页也可进入，不需要员工编辑权。其他用户使用同一岗位不会获得这些个人资料。

个人入口的数量来自当前用户的知识装配，员工卡片的共享资源数量不混入私人库数量。加载前不能保存，冲突保留输入并提供显式载入最新；取消脏弹窗需要确认，提交中不能关闭。保存影响新任务，使用旧装配的在途任务会停止，需重新发送。知识候选、能力状态、读取取消及身份切换隔离由KnowledgeStore负责，不由员工模块维护另一份知识事实。

### 显示组件与业务操作怎样分工

`agentPresentation` 将记录转成卡片展示契约，`AgentCard` 同时用于目录、编辑预览和样板。预览不传操作回调即可只读；视觉映射不决定后端权限。可对话状态来自员工启用及模型配置，不以技能数量充当就绪条件。

员工卡片收藏常显，编辑和暂停／恢复接单收进「更多操作」，暂停先确认并保留配置与历史，装配移除确认只修改当前草稿；永久删除有独立确认且后端继续保护历史引用。全员规则只读继承，显示不复制进员工草稿；工具账号的本人选择也不改共享岗位定义。

## 目录与职责

```text
agents/
├── AgentsPage.tsx                 # 装配员工目录和编辑路由，连接身份、共享数据与进入/返回导航
├── useAgentDirectory.ts           # 将 URL 筛选和分页连接到共享目录查询，组织统计、收藏及状态操作
├── AgentDirectory.tsx             # 组合查询工具栏与分页槽位，按 ID 渲染卡片并保留已确认结果
├── AgentDirectoryPagination.tsx   # 将服务端总数与 URL offset 连接到页码及箭头
├── useAgentEditor.ts              # 按 ID 读取完整配置，组合保存/删除操作、版本和编辑来源
├── AgentConfiguration.tsx         # 管理岗位表单、草稿、校验及完整能力选择，统一提交并登记未保存状态
├── AgentCapabilityAssembly.tsx    # 工具和技能的混合列表、筛选、搜索、分页与统一添加入口
├── AgentModelConnectionField.tsx  # 读取可选大脑及当前选择，反馈连接异常，刷新选项时保留员工输入
├── AgentSkillAssembly.tsx         # 展示和选择已装配技能，分页查候选，维护同一员工草稿中的关系集合
├── AgentDeletionDialog.tsx        # 要求明确确认永久删除，控制提交/关闭和失败反馈，成功后由页面清理并导航
├── AgentCard.tsx                  # 呈现姓名、岗位、状态和资源摘要，按回调提供收藏、配置或对话操作
├── agentPresentation.ts           # 把员工与关系数据映射为统一卡片显示结构，供目录与预览共用
├── agentCardStyles.ts             # 集中定义员工卡片的布局与状态样式，避免不同使用处漂移
├── types.ts                       # 声明本模块的展示和编辑结构，区分摘要、完整输入及操作回调
└── index.ts                       # 导出本模块明确复用的入口，页面私有实现保持就近归属
```

## 与其他模块协作

共享读写经过 [AgentStore](../../state/agents/agentStore.ts) 及 [WorkspaceData](../../state/README.md)，HTTP 与结构映射由 [agents API](../../lib/api/agents.ts) 提供。技能、模型及工具提供候选资源，工具装配复用 [ToolAssembly](../../components/tools/ToolAssembly.tsx)。

后端 [employees](../../../../backend/app/employees/README.md) 拥有岗位与装配规则，[conversations](../../../../backend/app/conversations/README.md) 接受实际工作。路由/外壳负责导航和离页保护，本模块不自行运行模型或在每张卡片维护第二份服务端事实。

## 目录读取与收藏同步

首次读取使用页面加载状态；同一身份下切换筛选、搜索、翻页或刷新，保留上次成功的卡片、统计、标题、Tabs 与搜索框。列表通过 `aria-busy` 和「正在更新」标识后台请求，完成后替换结果；请求期间只暂停分页，卡片按实际员工 ID 交互。失败保留上次结果，提示更新失败并允许重试。取消旧请求并忽略迟到响应；身份或读取权限变化立即隔离旧数据。全部员工徽标独立读取 `configuration-summary`，不随筛选、分页或收藏写入重复读取；右侧使用列表响应的 `total` 表示当前条件的匹配总数，可对话数量限定为本页。总数首次读取失败显示未知数量；后台失败保留上次已确认总数与重试入口。

收藏点击立即切换当前卡片星标，用按员工隔离的临时值覆盖显示，不覆盖已确认记录。该员工的收藏与启停请求串行，其他卡片、编辑和导航继续可用；目录状态操作不登记全局编辑保存锁。PATCH 成功采用服务端员工和 revision，普通列表保持创建时间顺序；失败撤销临时值并在卡片提示，409、网络断开或服务端错误还会重新读取核对，不自动重发写入。启停在服务端确认后更新展示。

成功写入更新 AgentStore 中唯一的员工摘要。普通目录与侧栏读取同一记录；“已收藏”目录的第一页与侧栏共享同一查询和 total，不再单独广播导航或配置版本。筛选中的成员不再匹配时，确认成功后移除、调整可确定的总数，再后台补位；末页失效时回到最后有效页。跨越写入的读取取消并重新核对，较旧 revision 不覆盖新记录。

409、断网或服务端错误改为按员工 GET 核对；若核对仍失败，卡片保留待确认状态并提供“重新核对”，只重试读取，该员工解锁前不再重复提交。侧栏核对失败保留上次收藏及计数，手动刷新目录也核对侧栏。同步范围为当前工作台；跨标签页和其他客户端的更新在重新读取时可见。共享存储、订阅、缓存和后续接入标准见[共享数据模块](../../state/README.md)。

页面入口为 `AgentsPage.tsx`，页面 Hook 负责 URL、详情读取和表单操作组合，员工摘要及写入由 AgentStore 统一持有。技能选择复用 SkillStore 的分页资源，搜索技能不会重新读取员工完整详情。配置标签由 URL 表达，表单草稿按身份和资源隔离；编辑器向共享编辑保护登记脏状态及丢弃回调，Layout 处理离页确认。

## 员工永久删除确认

编辑页用独立删除对话框说明实际影响：删除岗位及其装配关系，共享技能、大脑和其他员工继续保留。已有对话历史时后端拒绝删除并提示停用。

用户完整输入「确认删除」后才可提交。取消、Escape 或遮罩关闭会清空输入并恢复焦点；提交中锁定操作和关闭，失败保留弹窗及错误，成功清理员工草稿、解除脏状态并返回目录。文字确认用于防误操作，实际权限及引用保护由后端执行。

## 配置与验证入口

保存的字段和原子性见[配置契约](../../../../docs/reference/agent-configuration/api.md)，全员继承见[规则契约](../../../../docs/reference/organization-rules.md)。目录/编辑相关测试就近维护，重点核对共享同步、草稿、冲突和装配；图示描述正式实现，不使用设计样板作为运行数据。

### 装配目录与配置面板

已装配能力使用统一集合边界与 AssemblyItem 行，名称、用途、类型、启停、配置及移除分层，保留类型筛选、搜索与分页。添加能力为侧栏目录；技能可连续加入并显示已装配及本次反馈，完成选择只关闭目录，仍需主保存。工具先进入操作配置，明确已选操作数、账号方式、调用上限及高级范围约束，完成后才更新草稿；取消／关闭不改变已有装配。不可用候选显示停用或目录未确认原因，技能读取失败可重试。

工具高级 JSON 与调用上限保持联动，修改上限不会覆盖已填写的其他高级字段；无效 JSON 保留原输入，调用上限在面板内校验 1—32 整数。配置错误位于面板滚动主体内，不挤掉底部完成／取消操作。实际验收见员工编辑与历史列表验收。
