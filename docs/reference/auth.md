# 管理员登录与游客访问契约

本文维护当前已实现行为。实现与测试入口见正文；未来能力仅作为限制或链接，不构成已实现承诺。

## 目标与范围

已确定的产品需求：超级管理员可管理平台内容；未登录访问者可选择“随便看看”，浏览相同员工和展示信息；游客不能创建、修改、删除平台数据。GitHub 登录开放普通用户自动注册；本地密码只面向管理员，邀请注册仍未实现。

本阶段交付管理员登录、退出、登录态保持、游客会话、员工与技能的游客浏览、后端权限保护及前端权限交互。管理员初始化和会话撤销通过本机管理命令完成，不增加账号管理页面。

Kimi Code 模型连接已在[大脑配置设计](model-connections.md)单独实现；管理员真实模型对话和消息/run 持久化见[对话设计](conversations.md)。真实 Agent 执行已接入；邀请注册、角色管理界面和多租户尚未接入。本阶段不创建任务、体验额度、邀请、角色关联或工作空间表。游客仅有只读展示权限。

## 当前认证边界

受保护 API 从服务端 Cookie 解析身份并检查权限；游客使用独立字段白名单，不读取完整配置。前端先加载身份，再按能力选择接口，身份变化时清理私人状态。开发代理双向转发 Cookie，并保留 Origin。员工与技能保留创建者归属，用户 ID 与员工 ID 是不同实体。

## 模块职责与依赖

以下模块均已创建并接入。

| 模块                                                           | 职责                                                           | 边界                                                         |
| -------------------------------------------------------------- | -------------------------------------------------------------- | ------------------------------------------------------------ |
| `backend/app/auth/service.py`                                  | 用户、密码哈希、会话创建与解析、过期和撤销、管理员命令         | 不导入员工、技能、任务模块；不代替业务前置条件检查           |
| `backend/app/auth/actor.py`、`backend/app/auth/permissions.py` | 当前可信主体、权限编码、固定角色映射和权限检查                 | 不读取 Cookie、不导入 FastAPI、不查询业务表                  |
| `backend/app/api/`                                             | 解析认证传输、校验请求来源、注入 Actor、将错误转换成 HTTP 响应 | 每个受保护入口执行授权；不通过客户端传入的角色或用户 ID 授权 |
| 现有 `employees/`、`skills/`                                   | 业务规则与数据库查询，定义公开展示投影                         | 不承担密码或会话处理；展示 DTO 明确允许的字段                |
| `frontend/src/components/auth/`                                | 登录页、身份加载、会话失效和退出交互                           | 能力列表只用于交互，不代替后端授权                           |
| 现有前端代理和 API 客户端                                      | 同源转发、类型映射和统一错误处理                               | 不签发第二套 token，不自行信任角色 Cookie                    |

Actor 至少包含 `kind`、`user_id`（游客为空）、`session_id`、可信角色编码。认证解析用户当前启用状态和角色，再形成 Actor。auth.permissions 通过统一入口回答 `require_permission(actor, "agents:update")`，角色映射集中在后端一处维护。

HTTP 授权必须发生在业务服务调用之前。本阶段服务是后端内部接口；后续增加队列、Agent 或其他执行入口时，也必须在调用业务能力前进行同等授权，不能绕过检查直接复用 CRUD 服务。数据归属规则出现时，由业务提供资源事实，授权层返回判定或范围，业务查询层落实范围；当前不提前实现通用范围引擎。

## 用户与会话数据

新增两张表，沿用项目 UUID 文本和 UTC 时间类型。除指定的应用默认值外，必填字段均由受信任的后端流程提供。密码和原始会话 token 不写入日志。

### users

| 字段            | SQLite 类型 | 可空 | 默认值           | 含义与约束                                                                                            |
| --------------- | ----------- | ---- | ---------------- | ----------------------------------------------------------------------------------------------------- |
| `id`            | TEXT        | 否   | 应用生成 UUID v4 | 稳定主键，不随用户名修改                                                                              |
| `username`      | TEXT        | 否   | 无               | 管理员登录名独立唯一，规范化为小写；普通用户保存 GitHub 账户名，稳定关联依据外部 ID，允许与管理员同名 |
| `password_hash` | TEXT        | 是   | 无               | 管理员必填 Argon2id 哈希；GitHub 普通用户为空，不接受本地密码登录                                     |
| `role`          | TEXT        | 否   | 无               | `admin` 或 `member`，创建流程显式指定；GitHub 用户不会自动成为管理员                                  |
| `is_active`     | BOOLEAN     | 否   | true             | 是否允许登录与继续使用会话                                                                            |
| `created_at`    | TEXT        | 否   | 当前 UTC         | 创建时间                                                                                              |
| `updated_at`    | TEXT        | 否   | 当前 UTC         | 账号修改时间                                                                                          |

数据库维护主键、管理员登录名独立唯一、非空、布尔值与角色／凭证 CHECK 约束；应用维护管理员登录名格式和密码规则。密码不 trim、不自动截断，创建和重置密码接受 8～20 个字符；本机创建和重置均使用隐藏输入并再次确认。登录继续按原密码校验，保留最多 128 个字符的输入兼容，避免此前设置的长密码失效。

不提供 HTTP 用户删除或本地密码注册。管理员初始化命令只在不存在管理员时创建初始管理员，普通用户先注册不会阻断初始化；重复执行不能覆盖账号或重置密码。本机维护命令按管理员登录名查找，不影响同名 GitHub 用户；修改密码和停用账号在同一事务撤销该管理员全部会话。不提供通过启动配置反复覆盖密码的路径。GitHub 注册、外部关联与用户表新约束见增量设计。

### auth_sessions

| 字段           | SQLite 类型 | 可空 | 默认值           | 含义与约束                                                                                        |
| -------------- | ----------- | ---- | ---------------- | ------------------------------------------------------------------------------------------------- |
| `id`           | TEXT        | 否   | 应用生成 UUID v4 | 会话记录主键，与浏览器持有的秘密 token 不同                                                       |
| `token_hash`   | TEXT        | 否   | 无               | 随机 token 的 SHA-256 十六进制摘要，唯一；原始 token 使用密码学安全随机数生成，至少 32 字节随机性 |
| `kind`         | TEXT        | 否   | 无               | `user` 或 `guest`                                                                                 |
| `user_id`      | TEXT        | 是   | 无               | 外键 `users.id`；用户会话必填，游客会话必须为空；删除用户时级联删除会话                           |
| `created_at`   | TEXT        | 否   | 当前 UTC         | 创建时间                                                                                          |
| `last_seen_at` | TEXT        | 否   | 当前 UTC         | 最近一次记录的有效访问时间，更新可节流                                                            |
| `expires_at`   | TEXT        | 否   | 无               | 绝对到期时间，持续访问不能越过此时间                                                              |
| `revoked_at`   | TEXT        | 是   | NULL             | 撤销时间；非空即不可用                                                                            |

数据库维护 `token_hash` 唯一索引、`user_id` 索引、`expires_at` 清理索引、类型与用户外键组合 CHECK，以及到期时间晚于创建时间的约束。应用统一使用带时区的时间；先检查过期再更新访问时间，不能复活过期会话。

会话只保存身份关联，不保存一份权限快照。每次解析查询用户启用状态与当前角色；以后引入角色缓存时需另行设计失效机制。

会话查询沿用短事务；访问时间最多每 5 分钟更新一次，防止每次 GET 都造成 SQLite 写入。闲置到期允许最多 5 分钟的提前失效误差，不能延长绝对期限。定期清理到期或已撤销会话通过维护命令进行，不依赖清理动作才让会话失效。

## 登录与会话流程

### 会话策略

以下是首版可配置的实施默认值，不是用户指定的固定业务要求：用户会话闲置 24 小时失效、绝对期限 7 天；游客会话固定 7 天，到期后可重新选择“随便看看”。不增加“记住我”开关，浏览器 Cookie 持久化到绝对期限。后续游客体验不得把会话存续直接当作永久的人级次数限制。

FastAPI 是唯一会话签发和校验方，SQLite 为会话存储。通过 `Set-Cookie` 写入 `app_session`：`HttpOnly`、`SameSite=Lax`、`Path=/`，不设置 `Domain`。生产启用 `Secure` 且仅允许 HTTPS；本机 HTTP 开发可以显式关闭 Secure。Cookie 的 Max-Age 与服务端绝对期限匹配，服务端检查仍是最终依据。

### 管理员登录

1. 浏览器向同源登录接口提交 JSON 用户名和密码，不接受角色、用户 ID 或权限参数。
2. 后端校验请求来源和登录限速，再检查凭证及账号状态；不存在账号、密码错误或停用统一返回相同的登录失败信息，未知用户名执行等价的密码哈希校验路径。
3. 密码校验放在数据库写事务之外；签发前重新检查账号状态及已校验的密码哈希是否仍然有效，避免与停用、改密竞争。写入新会话，并撤销请求携带的旧会话，提交成功后才发送 Cookie。
4. 前端重新获取身份并加载管理数据；成功前不提前显示管理员界面。失败保留用户名，不回显密码，不清除仍有效的游客会话。

游客升级为管理员必须换发 token，不能复用原游客会话。其他设备的会话不因普通登录自动撤销；管理员可通过维护命令撤销全部会话。

### 浏览与退出

“随便看看”调用游客入口创建会话，不创建 users 记录。已有有效游客会话时返回同一身份，不刷新绝对期限；已有管理员会话时保持管理员身份，必须先退出才能切换游客，避免后台误降级。

身份接口返回当前用户基本信息和能力列表，不返回密码哈希、原始 token 或内部会话记录 ID。退出撤销当前会话并清除 Cookie；对已过期、无效或缺失会话同样返回 204。退出不是只删除浏览器本地信息。

所有身份相关响应及受保护数据响应使用 `Cache-Control: no-store`。身份失效后不自动创建游客或重试原来的写操作；用户明确选择重新登录或浏览。

## 请求来源、代理与登录防护

- 所有 POST、PATCH、PUT、DELETE（包括登录、游客创建和退出）必须具有精确匹配允许列表的 `Origin`。缺失、`null` 或不匹配均返回 403；比较规范化的 scheme、host、port，不使用后缀匹配或通配域。
- 除流式文件上传外，写入口仅接受 `application/json`，空操作提交 `{}`；不允许 GET 修改业务数据。文件上传同样检查 Origin 和身份，另由文件接口限制字节大小。结合 Origin 检查与 SameSite Cookie 实施 CSRF 防护，本阶段不另发 CSRF token。命令行请求 HTTP API 同样必须显式发送受信任 Origin 和认证 Cookie；现有本机账号维护命令直接访问服务，属于受信运维入口。
- 开发代理只向 BACKEND_URL 指定的后端发送请求，保留原始 Origin 和会话 Cookie；缺失或非法 Origin 不替换为合法来源。生产同源请求直接到 FastAPI，由后端路由、权限和 BrowserSecurityMiddleware 执行边界，不再维护第二份 Next 白名单。
- 逐条转发后端 `Set-Cookie`，不能用逗号合并或丢失清除指令；保留状态码、错误码、Retry-After 和 no-store。代理失败返回 502，不能包装成 401 或自动重放写请求。
- 本机初始来源允许 `http://127.0.0.1:3000` 与 `http://localhost:3000`，两者 Cookie 独立，不混用。正式部署显式配置站点 HTTPS Origin，不将开发来源带入生产。后端可直连时也执行完整认证与来源检查。
- 登录尝试限速按来源地址与规范化用户名分别处理，游客会话创建按来源地址限速；不因攻击者尝试而永久锁定用户。首版单进程可用有界、带过期的内存计数器，建议初值为每来源每分钟 20 次登录尝试、每用户名 15 分钟 10 次登录尝试、每来源每分钟 20 次游客创建，超限返回 429 和 Retry-After。未知用户名使用同样规则。
- 生产入口同时限制请求体大小和请求速率。当前应用不读取转发地址头，提供的 Uvicorn 启动命令关闭代理头信任；Vite 开发代理也移除这些头。经过开发代理时，应用按其连接地址计数，该代理下访客共享来源额度。生产网关需另加真实客户端限速；未来可信来源转发需要单独配置，不能直接透传客户端自报地址。身份与密码不可写入访问日志。

内存限速不是多实例共享限速，重启会清空计数；首版部署限定单应用进程，扩容时先换成共享限速存储或在统一网关执行。此限制不影响 SQLite 中持久会话的有效性。

## 权限与展示数据

### 固定权限映射

权限编码集中定义，面向用户的业务入口接收 Actor 并检查所需权限，HTTP 路由负责取得身份；未知角色或权限默认拒绝。模块间受信配置读取可以共用调用方 Session，不额外要求配置管理权限，但实际执行仍复核发起者和当前许可。`admin` 是平台超级管理员角色，不使用字符串前缀或任意权限通配符自动授予新能力。

| 身份          | 公开展示     | 管理配置与模型连接         | 对话执行与工具账号                       |
| ------------- | ------------ | -------------------------- | ---------------------------------------- |
| 管理员        | 允许         | 允许，仍检查具体操作与引用 | 允许，仍受准入、容量、配置与资源范围约束 |
| GitHub member | 允许         | 拒绝                       | 允许本人对话和运行、管理本人 MCP 连接    |
| 游客会话      | 允许         | 拒绝                       | 拒绝                                     |
| 无有效会话    | 拒绝业务读取 | 拒绝                       | 拒绝                                     |

具体能力名称与角色集合以[授权实现](../../backend/app/auth/permissions.py)为代码事实，对外访问边界由本契约维护。管理员拥有 resources:all 不表示未来已经具备租户或私有知识权限模型。

员工 POST/PATCH 包含 skill_assignments 时还检查 agents:assign_skills；包含 model_connection_id 时检查 agents:assign_model。当前不接受 skill_ids 写字段，也没有旧的单关系增删接口。后续新增用户入口应调用同一业务操作，避免绕过装配、模型授权和资源归属检查。

登录、游客创建无登录前置，但执行来源、校验与限速；退出和本人身份属于会话生命周期。普通用户可使用共享员工创建本人对话和运行，并管理本人 MCP Token；游客仍无执行权限。登录不自动提供个人模型或免费额度。账号与作者边界见 [MCP 契约](mcp.md)。

### 公开展示投影

`public` 表示字段适合展示，仍要求已有游客或用户会话；无会话直接调用返回 401。管理员和游客浏览同一批员工与技能，包括停用员工，查询前使用相同的筛选和分页规则；本阶段没有员工私有归属或发布状态。

| 资源 | 展示模型入口                                          | 保护边界                                                                                    |
| ---- | ----------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| 员工 | [PublicAgent](../../backend/app/employees/schemas.py) | 只给展示资料、启用技能 ID、只读资源摘要及模型配置标记；不暴露指令、关系参数、连接 ID 或凭证 |
| 技能 | [PublicSkill](../../backend/app/skills/schemas.py)    | 只给用途与展示资料、引用计数；不暴露内部指令、参数规范及修订管理字段                        |

字段名称、类型与默认由各显式 DTO 和 OpenAPI 维护，完整分页与读取语义见[配置 API](agent-configuration/api.md)，本页不重复另一份字段清单。

`model_configured` 仅表示员工已绑定模型连接，不能表示连接验证通过或已接通真实执行。游客是否能交办由能力与执行状态单独决定，不能由此字段推导。`is_favorite` 仍是当前平台共享展示状态，不是游客自己的收藏。

公开返回模型采用显式字段声明，不继承完整管理 DTO 后仅排除少数字段。新增管理字段不会自动对外公开。前端分别使用展示数据和可编辑配置类型，不能为缺失的提示词、模型名称等编造值后再用于保存。

未来真实任务加入公开标识和归属检查后才能展示。当前演示记录没有后端公开任务接口，也不能跨管理员和游客复用内存缓存。

## HTTP 契约

接口延续 `/api` 前缀、snake_case JSON 和现有错误包络。开发代理按 /api 前缀转发，权限继续由后端执行；代理范围以 vite.config.ts 为准。

| 方法 | 路径                      | 访问要求                                    | 成功                            | 主要失败                                           |
| ---- | ------------------------- | ------------------------------------------- | ------------------------------- | -------------------------------------------------- |
| POST | `/api/auth/login`         | 来源检查与限速；JSON `username`、`password` | 200 身份响应及 Cookie           | 401 凭证无效、403 来源无效、422 输入无效、429 限速 |
| POST | `/api/auth/guest`         | 来源检查与限速；JSON `{}`                   | 200 身份响应，必要时签发 Cookie | 403、429                                           |
| GET  | `/api/auth/me`            | 有效会话                                    | 200 身份响应                    | 401 会话缺失或失效                                 |
| POST | `/api/auth/logout`        | 来源检查；JSON `{}`                         | 204，并清除 Cookie              | 403 来源无效                                       |
| GET  | `/api/public/agents`      | `agents:read_public`                        | 200 分页展示列表                | 401、403、422                                      |
| GET  | `/api/public/agents/{id}` | `agents:read_public`                        | 200 展示详情                    | 401、403、404、422                                 |
| GET  | `/api/public/skills`      | `skills:read_public`                        | 200 分页展示列表                | 401、403、422                                      |
| GET  | `/api/public/skills/{id}` | `skills:read_public`                        | 200 展示详情                    | 401、403、404、422                                 |

公开列表沿用对应现有列表的分页、筛选和排序语义，包括员工的技能筛选；总数来自同样范围。装配展示使用当前员工公开 DTO 与技能摘要，字段以[现行配置接口](agent-configuration/api.md)和 schema 为准；不返回内部参数或工作指令。有效身份下使用不存在的资源 UUID 返回 404。

现有管理接口的方法、路径和成功响应不变，新增身份与上述权限要求。角色检查先于资源读取，游客请求管理资源返回 403，不通过存在与否的差别泄露管理信息。非法媒体类型返回 415；数据库繁忙和后端不可达沿用 503、502 的既有语义。

管理员身份响应示例（ID 为虚构值，能力列表仅节选）：

```json
{
  "actor": {
    "kind": "user",
    "user": {
      "id": "c50c36ae-2f66-4a80-9054-0f953d61d820",
      "username": "admin"
    }
  },
  "permissions": ["agents:read", "agents:update"],
  "expires_at": "2026-10-24T00:00:00.000000Z"
}
```

游客响应为 `actor.kind = guest`、`actor.user = null`，permissions 包含完整的游客权限列表；expires_at 为绝对期限，闲置或撤销可使其提前失效。前端不依赖角色字段控制按钮，也不把权限列表存为长期可信缓存。

| 状态码与 code                 | 含义与前端动作                                               |
| ----------------------------- | ------------------------------------------------------------ |
| 401 `invalid_credentials`     | 登录失败，停留登录页，统一提示用户名或密码错误               |
| 401 `authentication_required` | 缺失、到期、撤销或账号失效；清空身份及业务缓存，返回登录入口 |
| 403 `permission_denied`       | 有效身份缺少权限；保留会话，提示无权操作并刷新能力           |
| 403 `invalid_origin`          | 请求来源校验失败；不当作退出登录，不自动重试                 |
| 429 `rate_limited`            | 展示稍后重试和 Retry-After，禁止自动密集重试                 |

仍使用 `{"detail":{"code":"...","message":"..."}}`；Pydantic 422 校验错误沿用现有数组格式。登录凭证、角色、会话状态不通过错误详情泄露。网络失败不能清除一个可能仍有效的会话。

## 前端页面与状态

正式入口现为 `/signin`，提供用户名、密码、登录和游客入口；旧 `/login` 重定向并保留经过校验的站内返回路径。认可的品牌构图、轻量原生入口和主题边界见 [Signin 页面设计](signin.md)。首次进入工作台先请求 `/api/auth/me`，加载期间不请求管理配置或闪现管理按钮。无会话进入登录页；有效身份按权限加载管理或展示 API。静态帮助和头像素材不包含受保护数据，可以公开；`/design-system` 与头像调试页面采用管理员页面访问检查，不能成为游客进入编辑流程的入口。

| 场景                             | 页面行为                                                                                                 |
| -------------------------------- | -------------------------------------------------------------------------------------------------------- |
| 管理员                           | 保留员工和技能管理入口，显示用户名与退出                                                                 |
| 游客                             | 显示“游客浏览”和登录入口；可搜索、筛选、看描述与技能介绍；隐藏新增、编辑、删除、收藏切换、启停和装配操作 |
| 游客访问 `/?agent={id}` 编辑深链 | 明确提示无权编辑并提供返回员工列表；不挂载编辑表单、不发管理请求                                         |
| 游客交办或任务深链               | 提示“体验功能尚未开放”，不创建演示或真实任务，不消耗未来额度                                             |
| 当前任务记录页                   | 管理员查看真实对话；游客不开放真实记录，不伪造共享历史                                                   |
| 管理员真实对话                   | 使用真实模型与持久化历史，按独立对话权限保护；身份切换后清空客户端数据                                   |
| 会话失效                         | 关闭编辑和敏感详情，清空配置与会话状态；提示未保存内容未提交，不自动重放写操作                           |
| 后端不可达                       | 显示网络错误与手动重试；不能当作匿名身份或回退到演示数据                                                 |

登录和退出成功后重新挂载身份边界及工作台，取消旧身份正在进行的读取、断开旧身份对话订阅，并丢弃已发出的旧请求的迟到结果，避免身份切换时旧数据回填。未保存草稿不写入 localStorage，不跨身份恢复；主动退出有未保存内容时沿用现有离开确认。

身份边界首次挂载时请求 `/api/auth/me`，将身份和权限保留在当前工作台的共享内存状态中。登录成功继续整页跳转到功能页面，由该页面加载身份；整页刷新或重新进入身份边界时重新请求。工作台内的功能切换、普通操作和窗口重新聚焦复用已加载身份，不额外检查，也不通过定时轮询刷新。

业务 API 返回 401 时清空身份与业务状态并返回登录页；403 `permission_denied` 触发权限重新确认；读取失败保留手动重试入口。使用 BroadcastChannel 传递退出或身份变化事件以清理同源其他标签页，不在消息中传 token 或业务数据。服务端过期、撤销或权限变化可能在下一次业务请求时才反映到当前页面，后端始终独立验证会话与权限。

登录后返回地址只接受站内明确允许的路径和查询参数，拒绝外部地址与 `//` 开头路径；没有合法返回目标时回到 `/`。页面门禁只改善交互，API 权限检查不能省略。

## 配置与部署迁移

初始迁移创建用户、会话与外部身份表，不插入默认账号或明文密码。新部署执行 `make db-upgrade` 后使用 `make admin-create` 创建管理员。配置来源、Cookie 与代理设置见[后端操作](../guides/backend-operations.md)。

## 关键取舍与后续扩展

- 使用服务端随机会话，撤销与账号禁用可在下一次校验生效；代价是每次请求需要查询会话和账号。当前 SQLite 规模下优先保持简单。
- 角色映射固定在代码中，业务依赖权限编码；以后将权限解析换成 RBAC 查询，不改变员工及技能标识。新角色在明确需求后才引入。
- 公共展示字段显式列举，避免管理 DTO 扩展时无意公开内部配置；代价是维护独立展示类型及页面映射。
- 游客会话只是浏览器身份，清除 Cookie 或更换浏览器可以获得新会话。后续一次体验需要独立额度、原子扣减和防滥用设计，不能声称当前会话可以识别同一个自然人。
- 企业 SSO 以后作为认证适配接入，并关联平台用户；业务授权继续由本平台处理。多租户仍需另行迁移数据归属，本阶段不预埋没有用途的 group 字段。
