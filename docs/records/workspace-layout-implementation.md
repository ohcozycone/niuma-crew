# 工作台布局实施验收

日期：2026-10-30。范围：[现行布局规范](../../frontend/src/design-system/layout.md)及[组件分类](../../frontend/src/design-system/component-catalog.md)的正式接入。早期[尺寸研究](workspace-layout-design.md)保留为设计证据；本记录检查实际路由和组件，不将原型结果当作生产验收。

本记录的首轮实现与 512 组检查保留为当时快照；它们没有测量窗口缩放性能，也未代表用户认可快捷目录改样式。当前生效规则见文末[对话宽度语义纠正](#对话宽度语义纠正与豆包核对)。首轮与第一次反馈中的页面宽度策略不能作为当前规范。

## 首轮实施结果

共享外壳使用同一导航占位和工作区查询容器，工作台页面由公共外框管理最大宽度、居中与留白。员工、能力、复杂连接的网格各自消费组件预算；主辅、字段和文件编辑依据局部可用空间重排。独立帮助、规范目录、头像检阅与登录场景按各自任务组合基础规则。

对话移除散落在滚动组件、输入和反馈中的私有窄外框；消息正文单独限制行长，表格、代码和专业内容保留宽空间。问题导航的真实目标改为桌面 28×24px、粗指针 44×44px，滚动步距从计算样式读取，并保留历史锚点与定位流程。

浮层使用 small / standard / wide / side 角色，统一视口边界、关闭命中区、滚动和操作顺序；基础按钮、选择行与输入按粗指针能力增大命中区。分页、内容行、装配操作和 Tabs 保留窄屏访问路径，知识资料的分类在窄屏下移，取消原先隐藏分类的做法。

规范页新增 `/design-system#layout`，读取正式计算值并展示相同字段组件在不同宿主宽度中的响应。源码清单更新为 98 个 TSX 文件，仍归入 26 种视觉类型，不把文件数称为组件数。

## 检查方式与证据

浏览器：本机 Codex 内置 Chromium。使用正式 Vite 源码、正式路由、真实业务组件和项目 SVG 资产，验证入口仅提供合成的只读 API 响应；未知请求和所有写请求均在浏览器验收环境内拒绝，不连接真实模型或修改业务数据。

真实开发站点当时无法连接后端，故数据验证采用上述隔离环境。它能检查正式组件的构图、样式、DOM 和本地交互，不能据此宣称真实数据库保存、权限后端或模型调用端到端通过。

[全站尺寸结果](../../output/reviews/workspace-layout/production-matrix.json)覆盖 28 个页面分支 × 7 档视口，共 196 组；视口为 320、390、768、1024、1440、1920、2560px，高度 900px。覆盖员工目录与创建/编辑三个页签、能力目录与新建/导入/编辑、连接、知识资料与规则、对话记录和真实消息列表、帮助、头像、五类设计系统目录、开发样板、登录及 404。每组检查文档宽度、可见溢出、计算网格、页面框、相关请求与运行错误，最终 196 组均未出现整页横向溢出或运行错误。

原生文档纵向滚动条会占用实际内容宽度；代码、表格、头像放大视口等明确的局部滚动不按整页溢出计。最大工作台外框在宽屏维持同一上限；普通配置与消息滚动区的原生滚动条会产生数像素可用宽度差异，不隐瞒为完全相等。

[最终汇总](../../output/reviews/workspace-layout/validation.json)共 **512 组**，包含：

- 日间正常页面 196 组；夜间、字号令牌 200% 与触屏命中预算组合 196 组。
- 配置区和对话区各 18 组临界宽度，包含 767/768/769、879/880/881、1295/1296/1297、1439/1440/1441px。
- 7 个主要页面 × 3 档宽度 × 空态/错误/加载/无权限，共 84 组，视口高度 480px。

最终各组均无整页横向溢出或页面运行错误。压力检查模拟的是字号令牌与目标几何，不宣称执行了完整浏览器缩放或真实触屏输入。

配置临界点验收发现并修正了字段查询对象错误：包含 padding 的 632px 不能当作字段区净宽；改为 584px 后，在 1296px 视口处实测为 634px 主区、350px 辅区，两个字段各 280px。夜间压力检查还修正了按钮组无法换行、Select 长值挤出箭头和对话工具栏禁止收缩三处共用问题。

手动检查了 320px 下头像弹窗（288px 宽）、工具配置侧面板（320px 全宽）、取消后不提交装配修改、导航抽屉、长路径文件选择和折叠、问题跳转与消息焦点、历史弹窗（288px 宽）及 Escape 焦点返回。九行输入使输入宿主比默认增长 96px，达到六行编辑上限；未发送消息。

验收期间同一工作区另有 CI 移除重构，本轮保留该改动，并在移除后的前端重新执行全站矩阵和测试。当前源码与测试数以本记录最后一轮为准。

验收脚本副本保存在[隔离入口](../../output/reviews/workspace-layout/harness/index.html)；需通过 Vite 运行，HTML 文件直接打开不代表正式路由运行。

宽屏实测示例：[配置页截图](../../output/reviews/workspace-layout/configuration-desktop.png)与[计算尺寸](../../output/reviews/workspace-layout/configuration-desktop.json)。1920px 视口的外框为 1536px，主区 1098px、预览 350px、字段各 512px；正文工作区净宽 1472px。截图使用隔离数据。

## 反馈后修正与复验

本节是第一次纠正的历史快照。其中“1920px 以下铺满”的理解随后被用户明确纠正；目录恢复和变量继承的性能定位继续保留，但尺寸与测量不能代替下节的现行验证。

同日根据用户反馈修正：仅对话采用视口分级，760px 及以下保留 16px 留白、至 1250px 为 24px、之后为 32px；1920px 以下外框铺满工作区，1920px 起才启用 1536px 上限。消息、输入、加载、权限与错误反馈共用同一对话外框。员工目录和配置页面保留首轮布局，不将对话策略推广为全站统一限宽。

右侧快捷目录恢复原有 28px 宽与 10px 步距，细线、颜色、位置和预览继续沿用；撤销首轮未经授权的 24/44px 纵向目标改造与相关规范。对话正文继续预留固定导航空间，宽屏利用已有外框空白，不按问题数量改变宽度。外壳的 Tailwind 严格小于断点由 767px 修正为 768px，与原设计的抽屉边界一致。

缩放卡顿确认与 CSS 注册长度变量的继承有关：旧 `--os-frame-outside` 随 cqw 逐像素变化并继承到整棵消息树，即使宽屏的实际内容已限宽，仍重复计算后代样式。正式实现移除该变量及注册属性，改用媒体查询分配导航留白；没有引入 JS 页面宽度计算或全局 resize 状态。

[性能对照](../../output/reviews/layout-correction/performance.json)使用本机内置 Chromium、独立生产构建、40 轮/80 条合成消息；分别在 1920–2560px 和 1200–2400px 间改变真实 iframe 视口，每组 180 帧，统计剔除前 10 个样本。对照只重建旧 CSS 公式，导航均使用恢复后的同一几何。结果如下：

| 实现                            | 强制样式/布局耗时中位数 | 帧间隔 P95 |
| ------------------------------- | ----------------------- | ---------- |
| 旧公式与可继承变量，1920–2560px | 19.0ms                  | 34.8ms     |
| 仅禁止变量继承，1920–2560px     | 1.3ms                   | 14.0ms     |
| 最终媒体查询实现，1920–2560px   | 0.6ms                   | 13.9ms     |
| 旧公式与可继承变量，1200–2400px | 15.5ms                  | 41.2ms     |
| 最终媒体查询实现，1200–2400px   | 2.7ms                   | 41.6ms     |

这是定位与修复宽屏缩放开销的局部对照，不等同于全站性能评分；跨越流式宽度、字号与行长临界点时，长会话仍有正文重新换行和表格布局的峰值：1200–2400px 压力场景的 P95 没有下降，不能称为全区间无掉帧。此次消除了布局变量造成的持续后代重算；未引入可能改变历史锚点的消息虚拟化，也未用局部对照宣称所有设备、浏览器或原生窗口拖动场景都达到固定帧率。

正式组件使用隔离只读 API 验证，未写入业务数据：

- [对话断点](../../output/reviews/layout-correction/conversation-breakpoints.json)：17 档宽度，覆盖 320–2560px、760/761、767/768/769、1250/1251、1919/1920/1921；检查实际边距、最大宽度、输入框和快捷目录。
- [关键页面回归](../../output/reviews/layout-correction/key-pages.json)：员工目录、配置与对话各 7 档宽度，共 21 组。
- [短屏状态](../../output/reviews/layout-correction/states-short.json)：对话 320/768/1920px × 空态/错误/加载/无权限，共 12 组，高度 480px。

本轮 50 组布局记录均无整页横向溢出或运行错误；对话断点、关键页面与短屏状态已在独立生产构建中复验。真实 1440×900 与 1920×900 浏览器视口另外检查了快捷目录点击定位及 Home 键焦点；均正常。截图：[常规屏幕](../../output/reviews/layout-correction/conversation-1440.png)、[宽屏](../../output/reviews/layout-correction/conversation-1920.png)，宽屏消息与输入外框均为 1536px，消息滚动条造成居中起点有 2.5px 差异。

ESLint、TypeScript、定向 Prettier 与生产构建通过；构建保留依赖分块大于 500kB 的提示。当前前端回归为 58 个文件、409 项测试；删除的一项仅针对已撤回的 44px 刻度方案，其余刻度稳定、滚轮累积、触摸、键盘与分页测试按原 10px 几何回归。Impeccable 布局扫描结果为空。`UV_CACHE_DIR=/tmp/niuma-layout-uv-cache make check-docs` 通过（242 个文件，0 错误）；临时缓存用于避开沙箱外默认 uv 缓存目录。

[源码摘要与验证入口](../../output/reviews/layout-correction/source-sha256.json)固定本次检查范围；[验收脚本副本](../../output/reviews/layout-correction/harness/geometry/index.html)保留方法，需在原前端根目录和 Vite 环境中运行。Safari / Firefox、真实触屏和软键盘仍未实测；本轮未执行真实消息发送或后端保存。

## 对话宽度语义纠正与豆包核对

用户再次澄清：普通屏幕沿用此前适中的居中对话宽度，允许稍宽；屏幕变宽后才适当放大。第一次修正将普通屏幕铺满工作区，仍未符合要求，已撤回。现行规则是普通 960px，1920px 起 1120px，2560px 起 1280px，空间不足时收缩，媒体断点只增加上限。资源目录、配置和右侧快捷目录保持既有策略。

常态 960px 来自既有 64ic × 14px 的约 896px 正文预算，再加两侧各 32px；相对原 840px 外框与约 784px 正文净宽增加约 14%。宽屏每档增加 160px，供表格、代码和输入使用，文字行长保持独立。它是内容预算与温和扩展的项目取值，不假称用户研究结论、豆包参数或行业标准。详细规则只在[现行布局规范](../../frontend/src/design-system/layout.md#对话与阅读布局)维护。

参考[豆包官方页面](https://www.doubao.com/chat/)的可访问未登录欢迎态，1440/1920/2560px 下输入区域均封顶 1000px；页面还定义了 800px 的对话区令牌。已加载布局样式区分中心内容上限与两侧区域。这里采用其“内容角色与外侧留白分开管理”的结构思路；未发送消息，未验证实际消息态，所以没有把欢迎态尺寸推定为全部对话的宽屏规则。[观察记录](../../output/reviews/chat-width-system/doubao-observations.json)包含状态、计算尺寸及官方样式资源地址。

导航避让现在直接由消息容器的 CSS padding 计算，优先利用居中外框之外的空白；不足时才补右内边距。没有恢复被确认会导致持续后代重算的 cqw 注册变量，没有引入 JS resize 计算。右侧目录仍为 28px 宽、10px 步距。

本轮使用独立生产构建和合成的只读 API 验收，未知请求与写请求拒绝，未提交真实消息或修改业务数据。

- [对话断点](../../output/reviews/chat-width-system/conversation-breakpoints.json)：25 档宽度，覆盖 320–3440px 及 760、768、1250、1920、2560px 两侧；检查上限、消息与输入宽度、正文行长、快捷目录及溢出。
- [页面回归](../../output/reviews/chat-width-system/key-pages.json)：员工目录、员工配置和对话，各 7 档宽度，共 21 组；资源与配置布局保持原规则。
- [短屏状态](../../output/reviews/chat-width-system/states-short.json)：对话 320/768/1920px × 空态/错误/加载/无权限，共 12 组，高度 480px。

合计 58 组布局记录均无整页横向溢出或运行错误。另在真实浏览器视口下检查：[1440px](../../output/reviews/chat-width-system/conversation-1440.png) 的消息与输入均宽 960px、正文 896px，工作区两侧到内容各约 150px；[1920px](../../output/reviews/chat-width-system/conversation-1920.png) 为 1120px 外框，[2560px](../../output/reviews/chat-width-system/conversation-2560.png) 为 1280px 外框，正文均保持 896px。消息滚动条仍造成外框起点约 2.5px 差异。点击目录定位首问后焦点为 u1，Home 键保留目录焦点；未改变目录样式或发送消息。

[缩放复测](../../output/reviews/chat-width-system/performance.json)使用 40 轮/80 条合成消息，每档 180 次真实 iframe 宽度更新，统计剔除前 10 次。1920–2560px 与 1200–2400px 两档的样式/布局耗时中位数均为 0.6ms；帧间隔 P95 分别为 20.8ms 与 34.7ms。跨较窄宽度时仍有文字换行和表格重排峰值，不能宣称全程固定帧率；本轮没有恢复逐像素继承变量或增加消息虚拟化。

58 个测试文件、409 项测试通过；ESLint、TypeScript、定向 Prettier、独立生产构建及布局机械扫描通过。构建保留既有依赖分块大于 500kB 的提示。主题令牌契约在本轮检查中发现两个局部辅助变量缺少根默认值，已补为现有尺度的引用并保留局部覆盖，没有放宽测试。
