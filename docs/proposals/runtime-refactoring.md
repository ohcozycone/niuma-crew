## 目标与已完成增量

将后台调度、一次执行和 SDK 适配分开；复用 LangChain 工具循环、流式消息、中间件及用量状态。普通聊天支持边生成边显示，技能读取及激活分别记账，模型实际提供的思考文字可以展开查看。

已实现错误分类一致、部分回答保存、统一终态、后台异常监督和就绪检查。当前基线保存分轮文字、思考及步骤版本；执行快照版本和生效规则集中维护于现行运行契约，不在本方案重复定义。

## 文件结构

```text
backend/app/runtime/
├── contracts.py    # 执行输入、结果、内容和可用状态
├── runner.py       # 后台队列、并发与监督
├── execution.py    # 单次执行的准备、看护和结束
├── agent_loop.py   # LangChain Agent 装配与流式执行
├── progress.py     # 分轮文字与思考内容合并
├── middleware.py   # 模型检查、记账及整个中间件栈装配
├── skills.py       # 技能快照、目录、加载激活及当前许可
├── hooks.py        # 授权与记录入口
├── errors.py       # 稳定失败及终态规则
├── config.py       # 预算与间隔
└── README.md
```

跨模块时序见[当前模块时序图](../reference/runtime.md#模块时序调度)。

## 技能职责收拢增量

已将 Agent 入口中的技能目录构造、中间件中的技能提示词、SDK 技能配置和加载校验统一放入现有 runtime/skills.py，与技能快照及实时许可检查共同维护。`prepare_skills` 将本轮技能快照准备为 `PreparedSkills`，集中提供文件、路径和显式预加载名称，消除跨文件重复拼接；middleware.py 继续维护整个中间件栈的原有顺序，agent_loop.py 使用 `prepared_skills` 装配 Agent。生效分工见 [runtime 模块](../../backend/app/execution/README.md#实际动作)。

本增量只调整内部职责，不改变 SKILL.md 内容、快照协议、预加载及按需读取、共享预算、激活去重、授权或动作记录。验收使用真实 SDK 的受控模型测试，覆盖技能、流式执行、普通对话和已有 CI 路径，并执行后端静态及文档检查。

## 保留的设计取舍

后续组件层级、普通对话完整示例和数据投影增量见[对话执行过程设计](conversation-execution-display.md)；该界面草案不改变本轮已生效的内容与交付边界。

1. 使用当前 SDK 已有的 astream 接口，模型和工具往返由框架负责；不引入试验性 v3 API，也不复制工具循环。
2. 执行函数返回一次最终结果，通过 hooks 记录过程中变化，不建立通用事件类继承树或插件平台。
3. 保留已持久化快照的 SSE 协议。SDK 片段先合并，网页替换当前值；刷新无需事件重放。
4. 草稿可能在本轮后续工具调用出现时收起，页面标明生成中；最终答案只有一份。
5. 动作状态由中间件记录，不能把工具请求当作工具成功；思考仅来自模型返回内容。
6. CI 仍使用专业执行适配，报告校验完成后整体发布。统一到标准 Skill/MCP 循环另行实施。

## 实施顺序与后续边界

本轮按故障修复、职责整理、数据及后端流、页面展示、全量回归和文档同步完成。具体方法和结果见验收记录。

通用知识库、MCP、标准技能包、CI 循环统一、持久等待及多进程调度不属于本轮实现。特定供应商的思考字段需要相应模型适配器和真实上游验收；不因展示接口存在便宣称兼容所有模型。
