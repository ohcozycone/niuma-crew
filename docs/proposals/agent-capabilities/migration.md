# 能力后续阶段迁移与验收计划

设计状态：草案。实施状态：标准技能/MCP、知识和评测增量未实施。更新日期：2026-10-24。当前基线为 0001 的十一张业务表、schema 1 与 SDK checkpoint，事实见[当前数据模型](../../reference/data-model.md)，本文件不预占未来迁移号。

## 阶段与职责

| 阶段              | 增量                                                    | 权威设计与退出边界                                                                                                               |
| ----------------- | ------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| P2 标准内容与工具 | 标准内容制品、获准目录、工具连接与员工许可，CI 配置归位 | [标准技能与 MCP](../skills-and-mcp/README.md)、[CI 连接迁移](../skills-and-mcp/ci-connection-migration.md)；按 S1/S2/S3 分步验收 |

| P4 混合检索       | embedding 适配、匹配索引与诊断                          | 同一资料可比较全文与混合结果；连接检查不代表索引就绪                                                                             |
| E 考核            | 用例、预期、评分及历史证据                              | 按业务验收增量定义，不以系统提示词或模型自评代替结果                                                                             |

## 实施约束

1. 每阶段先核对真实 head、ORM、权限和资源归属，再新增正式迁移；当前基线不改写。不为未实施实体预建表或占位外键。
2. 新结构、服务与 DTO 在同一可验收增量完成，前后端同批切换。字段和参数只有一个写入来源，秘密不进入运行快照、步骤或公开响应。
3. 配置许可与接受时固定的内容各司其职；每次真实动作复查启停、关系及连接修订。新能力不授予 SDK 默认文件、脚本或外部工具权限。
4. 有存量部署时，以该阶段明确的数据保留要求制定映射、停写、备份和回退；本次开发库重建不构成未来可以隐式清空数据的许可。
5. checkpoint 继续拥有完整消息和图状态，业务库保存稳定引用与执行依据；新增知识或工具不重新引入业务消息正文表。

## 验收

真实 Alembic 升级、字段与约束、幂等、参数校验、权限拒绝、跨库失败与重启；当前普通聊天、CI、取消、预算、SSE 及历史投影继续可用。涉及外部调用时分别记录替身验证与真实上游结果。未完成阶段不勾选通过，不把当前已实现的配置能力计为后续阶段验收。
