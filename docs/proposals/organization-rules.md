## 多份规则建议（待确认，未实现）

用户提出希望评估按主题拆分规则、在已有规则之外继续新建。本节为建议，不属于本轮入口整合的实现承诺。当前仍是一条 singleton 记录，无新建多份能力。

建议采用“规则列表 → 新建/编辑规则”，每份维护名称、Markdown 正文、启用状态和版本；可命名为“行为准则”“信息保密”“越界回应”。先保持所有启用规则全员生效，避免首轮同时引入员工或部门的作用域和豁免。普通业务制度文档仍属于知识资料，不因名称含有“制度”而升级为工作指令。

列表可以新增、独立编辑、停用；按一个明确、固定的顺序组合，顺序用于稳定装配，不承诺“后面的规则自动覆盖前面的规则”。冲突应修改正文解决。拆成多份改善维护，不会自动降低同时注入的上下文成本。后续实施需要定义规则集合的并发版本、原子读取和总输入预算，在每次 run 中快照全部生效规则的 ID、名称、版本与正文及最终提示词；旧单份正文迁为一份“公司规章制度”，旧快照保持可读。

参考依据（2026-10-22 核对官方文档）：

- [Codex 官方 AGENTS.md 指南](https://learn.chatgpt.com/docs/agent-configuration/agents-md)：全局和项目目录链可加载多份指令，同一目录最多选择一个约定文件；并非把同目录任意多份 Markdown 自动全部加载。
- [Claude Code 官方规则组织](https://code.claude.com/docs/en/memory#organize-rules-with-clauderules)：支持 `.claude/rules/` 按主题组织多个 Markdown 文件，并支持限定匹配路径。本产品建议借鉴独立维护和明确加载机制，不直接照搬编码工具的目录作用域。
